## 4. 사용자 결정 대기

측정은 끝났고 판단만 남은 것들이다. **혼자 정하지 않았다.**

**열린 것과 닫힌 것은 각 항목의 ✅ 표시가 말한다 — 여기 다시 세지 않는다.**
✅가 아닌 행만 훑으면 열린 것이 나온다.

2. ✅ **닫힘 — 예약어 검사 범위 (2026-09-02, 사용자 결정: 대상별 검사, 아래).** 원문: 내부 함수의
   파라미터 `unit`이 "Pascal 예약어"로 거부된다 — 내부 이름은 Delphi 유닛에 나가지 않는데도. Pascal은 `unit`·`type`·`set`·`file`·`string`·`record`·`to`·`in`·
   `at`·`on`·`end` 같은 흔한 말을 예약한다. **권고:** 이름이 **실제 도달하는 대상만** 검사(export
   파라미터=전 대상, 내부 파라미터·지역 변수=Rust만). **반론:** C-emit 백엔드가 생기면 다시 좁혀야 한다.

   > **2026-09-02 갱신 — 이 항목의 절반이 저절로 닫혔다.** #101의 래퍼 리팩터로 **함수 이름**은
   > 검사 대상에서 빠졌다(`ml_fn_<name>`으로 방출되어 어떤 대상 언어에도 raw로 닿지 않는다).
   > 남은 것은 **파라미터와 지역 변수**뿐이고, 그것들은 여전히 raw로 방출되므로 질문 자체는
   > 그대로다 — 다만 범위가 좁아졌고, `reserving_targets`의 호출부도 이제 두 곳뿐이다.
   (SPEC-calls DP-C5가 열어 둔 항목.)

   ✅ **닫힘 — 대상별 검사 (2026-09-02, 사용자 결정).** 먼저 **실측했다**:
   `export fn price_of(quantity: i32, discount_rate: f64)`는 `.pas`에
   `function mlx_price_of(quantity: Integer; discount_rate: Double)`로 **그대로 나가고**,
   내부 `fn`의 파라미터와 지역 변수는 `.h`·`.pas`에 **각각 0회** 나온다. 그래서:
   - **export 파라미터·모듈 이름** = Rust + C + Pascal (지금까지와 같다)
   - **내부 파라미터·지역 변수** = **Rust + C만**
   >
   > **권고안과 한 군데 다르다.** 원래 권고는 내부 이름을 "Rust만"이었지만 **C를 남겼다** —
   > D19가 **C-emit 백엔드 슬롯을 열어 두고 있고**, 그 백엔드에서 내부 이름은 C 식별자가 된다.
   > 반대로 **Pascal은 어떤 계획된 백엔드에서도 내부 이름에 도달할 수 없다**(Delphi는 *바인딩*
   > 대상이지 codegen 대상이 아니다). 그래서 "나중에 다시 좁혀야 한다"는 반론이 C에는 적용되지만
   > Pascal에는 적용되지 않는다. 진단 메시지도 **도달하는 대상만** 말한다.

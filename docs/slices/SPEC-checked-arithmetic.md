## 0. 왜 — 측정부터

### 0.1 가장 넓은 조용한 오답 (2026-09-26, E2)

§7 2라운드(72규칙, 통일 기준 + 귀속 대조)에서 i32 wrap이 **7개 도메인**에서 status 0의 그럴듯한 값을 냈다:

| 규칙 | 입력 | 나온 값 | 맞는 값 |
|---|---|---|---|
| 근로소득공제 상한 | 총급여 20억 | 9,800,328 | 20,000,000 |
| VIP 10% 할인 | 단가 3억 × 1 | 312,949,672 | 270,000,000 |
| 일당(시급 × 분) | 시급 1,000만 | 8,417,211 | 80,000,000 |
| 수도 요금 누진 | 5,500,000 m³ | 50,021,704 | (i32 밖 — 실패여야) |

귀속 대조는 **기본으로 켜진 체크드**일 때만 통과했다 — 옵트인 도구(체크드 내장 함수)라면 저자가 가드를
빠뜨리듯 옵트인도 빠뜨린다.

### 0.2 시험 구현으로 잰 것 (E2, 로컬 브랜치 `exp/checked-arith-local`, 머지 안 함)

| 626행(규칙 × 입력) | A | **A + `as i32`** |
|---|---|---|
| 조용한 오답 161행 중 status가 됨 | 84 | **101** |
| 여전히 조용함 | 77 | 60 |
| 맞던 답이 실패가 됨(오탐) | 8 — 현실적 입력은 1 | 9 |
| 참값이 i32에 드는데 실패가 됨 | 41 | 43 |
| 기존 오라클 테스트의 **동작** 변화 | 0 | 0 |

남는 60행: 무한(`-> i32`) 헬퍼 16 · 무한 export 본문 4 · f64 절삭·NaN 14 · 산술이 아닌 것 25 · 하류 저장 상태 1.

### 0.3 정직한 반론 (기록)

- **틀린 답이 정답이 되지는 않는다.** 43행은 참값이 i32에 드는데도 실패가 된다(중간값만 넘친다). 이 슬라이스의
  입장은 *"그럴듯한 오답보다 실패"* 이고, 정답을 주는 것은 i64뿐이다 — 별도 후보로 남긴다.
- **같은 `a * b`가 시그니처에 따라 다르게 동작한다** — `!` 본문에서는 실패하고, 무한 함수에서는 wrap한다.
  무한 함수에는 실패를 알릴 채널이 없다(D17). 그 대가를 숨기지 않고 `LANGUAGE.md`에 적는다.
- **같은 소스를 다시 컴파일하면 답이 바뀐다**(wrap 값 → `-3`). 지문은 바뀌지 않는다 — §2.6.

## 1. 범위

**포함** — 실패 가능 함수(`-> T!` · `-> string!` · `-> [T]!`)의 **본문 안에서**:

1. i32 `+` `-` `*`, 단항 `-`, `/`의 `i32::MIN / -1`이 i32를 넘으면 **`ML_ST_OVERFLOW`(`-3`)** 로 실패한다.
2. `f64 as i32`가 NaN이거나 0 방향 절단 뒤 i32 밖이면 같은 status로 실패한다.
3. 그 status를 낼 수 있는 모듈의 `.h`·`.pas`가 `ML_ST_OVERFLOW`를 선언한다(`-2`와 같은 방식).
4. `HOST_ABI.md` status 표 · `LANGUAGE.md`의 wrap 문단과 공백 블록 · 수용 D(C 호스트).

**미포함 (명시)**

- 무한 함수(`!` 없음)의 산술과 변환 — **wrap·포화 그대로**(DP-I4 · §2.3이 그 범위에서는 유지된다).
- `!`를 강제하는 설계(A2) · i64 · 옵트인 체크드 내장 함수 · 상수식 오버플로의 컴파일 진단.
- `%`(§2.2) · `/ 0`(DP-N4 그대로 `0`) · f64 산술의 `inf`/NaN · `fixed`의 `-2`.
- `DECISIONS.md` — D17이 음수를 이미 예약했다.

## 2. 계약

### 2.1 어디서, 무엇이

| 연산 | `!` 본문 | 무한 함수 |
|---|---|---|
| i32 `+ - *`, 단항 `-` | 넘치면 **`-3`** | wrap(오늘과 같다) |
| `i32::MIN / -1` | **`-3`**(참 몫 2^31이 i32 밖) | wrap |
| `x / 0`, `x % 0` | `0`(DP-N4) | `0` |
| `i32::MIN % -1` | **`0`** — 참 나머지이고 i32 안이다(DP-O5) | `0` |
| `f64 as i32` | NaN · 절단 뒤 범위 밖이면 **`-3`**, 아니면 절단 | 절단 + 포화, NaN → 0 |

**피연산자는 왼쪽부터 평가되고**(LANGUAGE.md) 검사는 그 연산 자리에서 한다 — 먼저 평가된 부분식의
효과(배열 경계 검사의 `-2` 등)가 먼저다.

**리터럴·상수만으로 된 식도 같다**(DP-O9): `!` 본문의 `2147483647 + 1`은 컴파일 시점에 접히지 않고 **실행할 때
`-3`** 이다. 상수는 리터럴로 접히지만(SPEC-constants DP-K5) 그 뒤의 산술은 다른 식과 똑같이 검사된다. 그런 식을
컴파일 에러로 만드는 진단은 §5의 별도 후보다.

### 2.2 `%`를 넣지 않는 이유 (DP-O5)

Rust의 `checked_rem`은 `i32::MIN % -1`에서 `None`을 준다(나눗셈이 넘치므로). 그러나 **참 나머지는 `0`이고 i32에
든다.** 시험 구현은 `checked_rem`을 썼고 그것은 맞는 답을 실패로 바꾼다 — `%`는 `wrapping_rem` 그대로 둔다.

### 2.3 status — `ML_ST_OVERFLOW = -3` (DP-O3)

*"이 연산의 i32 결과(또는 `f64 as i32`의 값)가 없다 — NaN 포함."* 뜻은 **값의 부재**이고, `-2`(경계 밖 접근)와
다르다. 호스트 규칙은 그대로다: **`status != 0`이면 out·버퍼를 읽지 않는다**(DP-E3). 재시도 조건은
여전히 `status == ML_ST_INSUFFICIENT_BUFFER`뿐이다 — `-3`에 다시 불러도 같은 답이 온다.

### 2.4 `result` 뒤 (DP-O6)

`-> [T]!`에서 `result n` 뒤에 넘치면 `-2`와 **똑같이** 다룬다: 그 시점에 `*ml_needed`가 쓰였을 수 있고 버퍼 내용은
정의되지 않는다(`HOST_ABI.md` Q12 표의 "그 밖의 예약 음수" 행이 이미 그렇게 말한다). `result` 뒤의 **정적**
실패(`fail`·`try`) 거부(DP-R9)는 그대로다 — 오버플로는 입력에 달린 동적 실패이고, 범위 밖 인덱스와 같은 부류다.

### 2.5 바인딩

- `compiler/src/abi.rs`에 `ML_ST_OVERFLOW: i32 = -3`.
- **선언은 낼 수 있는 모듈에만**: `ir.rs`에 `can_fail_overflow`(실패 가능 본문에 i32 `+ - * /`·단항 `-`·`f64 as i32`가
  있는가)를 두고, `.h`는 `#ifndef ML_ST_OVERFLOW` 가드로(`-2`와 같은 이유 — 여러 헤더가 같은 정의를 낸다), `.pas`는
  `const`로 선언한다. **두 바인딩이 한 술어를 읽는다**(#238의 규칙).
- 생성 `.pas`의 문구는 그 status를 한 줄로 설명한다.

### 2.6 지문과 ABI 버전 — 바뀌지 않는다 (DP-O4)

예약 음수는 D17상 **ABI의 것**이고, 호스트는 모르는 음수를 *"이 호스트보다 새로운 이유의 실패"* 로 다뤄야 한다
(`runtime/ml_abi.h`: `-2 .. -255`는 예약). 지문은 본문이 어느 예약 음수에 닿는지 보지 않는다(`iface.rs`). 그래서
`ML_MODULE_ABI_VERSION`도 매니페스트도 바꾸지 않는다 — 기존 모듈 전부의 지문이 그대로다.

DP-O1·O2는 방향 확인 때, DP-O3~O9는 이 표 그대로 **사용자 확인**을 받았다(2026-09-26).

|---|---|---|---|
| **DP-O1** 범위 | `!` 본문만(A) | 산술이 있으면 `!` 강제(A2) | **사용자 확인**(2026-09-26, A+as). A2는 export의 C 시그니처를 바꾸고, `/0`에서 같은 모양이 기각됐다(SPEC-division-guard-operands) |
| **DP-O2** 연산 | `+ - *`, 단항 `-`, `MIN/-1`, **`f64 as i32` 포함** | `as` 제외(A) | **사용자 확인**(2026-09-26, A+as). 실측 101 대 84 |
| **DP-O3** status | **새 `-3` `ML_ST_OVERFLOW`** | `-2` 재사용(`fixed`의 DP-M4처럼) | 호스트가 경계 밖과 값 부재를 구별한다. Grok plan은 처음 **`-2`**를 골랐다(#238이 잰 비용) — 그런데 `-2`를 재사용해도 `-2` 선언 술어가 산술을 봐야 해서 **그 비용 대부분이 두 안에 같다**(Grok verify CONFIRMED). 남는 차이는 상수 하나다 |
| **DP-O4** 지문·ABI | **둘 다 불변** | 매니페스트 플래그 · ABI 버전 올림 | 예약 음수는 ABI의 것(D17, `ml_abi.h`). 올리면 모든 모듈이 거짓 거부된다. Grok plan: 불변 |
| **DP-O5** `%` | **`wrapping_rem` 유지** — `MIN % -1 = 0` | `checked_rem` → `-3` | 참 나머지 0이 i32에 든다. 시험 구현의 `checked_rem`은 맞는 답을 실패로 바꿨다. Grok plan: 유지 |

## 5. 범위 밖 / 미검증 (명시)

- **무한 함수의 오버플로**(남는 20행) — 채널이 없다. `!`를 붙이면 이 슬라이스가 덮는다는 것이 저자의 탈출구다.
- **i64**(정답을 주는 유일한 안), **옵트인 내장 함수**, **상수식 오버플로 진단** — 별도 후보.
- **성능·`.text` 크기** — 체크 분기가 는다. `protection.rs`의 크기 가드는 `discount.dll`(무한 함수만)을 재므로 영향이
  없을 것으로 본다(E0). 구현에서 오버플로가 있는 모듈의 크기 변화를 **재서 적는다**(가드로 만들지는 않는다).
- `runtime/ml_abi.h`는 `-1`만 정의하고 `-2`도 생성 헤더에만 있다 — 이 슬라이스는 그 배치를 따른다.

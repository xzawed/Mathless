# Slice SPEC — 명시적 `out` 파라미터 (스칼라)

> **상태: 확정(accepted) · 구현 대기** — 2026-08-31.
> **DP-O1 = 선언 out 먼저, `out_value` 언제나 마지막.** **DP-O2 = 정상 반환 경로마다 대입 강제.**
> 둘 다 권고안 그대로 사용자 승인. O3~O6은 그에 따라 함께 확정된다.
> **§5.2를 승인의 일부로 읽을 것:** 이 슬라이스는 **Q12를 닫지 않는다.**
> **근거 수준:** §1이 **E2 실측**(오늘의 언어로 쓴 업무 규칙 6개 + 생성 헤더), §4가 E0.
> **선행:** D17 에러 경로(#15) · `i32` 나눗셈(#76). 설계 교차검토: Grok(§4의 합성 위험이 그쪽 지적).
> **D16 관련:** 이것은 D16의 "반환 = caller-allocates" 중 **스칼라 절반**이다. **Q12는 열어 둔 채로
> 닫히지 않는다** — 힙이 없기 때문이다(§5.2).

---

## 1. 목표 — 스칼라 규칙의 진짜 벽은 `else`가 아니라 "값 두 개"

`STATUS.md` §3b는 다음 후보로 `else` · `break`/`continue` · 복합 대입 · `for`를 나열해 왔다.
**§7대로 실제 업무 규칙을 오늘의 언어로 써 봤더니 그 넷은 아프지 않았다.**

| 규칙 | 결과 |
|---|---|
| 계층 수수료(3구간) | ✅ 컴파일 — 조기 `return`이 `else`를 대신한다 |
| 등급 할인 + 공통 후처리(쿠폰·하한) | ✅ 컴파일 — `let mut` + 분리된 `if` |
| 연체 이자 누적 + 법정 상한 | ✅ 컴파일 — 클램프가 `break`를 대신한다 |
| 분할 납부(`total / n`) | ✅ 컴파일 — #76이 열었다 |

**막힌 것은 이것이다:**

```mathless
// 수수료를 계산하면서, 어느 구간이 적용됐는지도 알려줘야 한다(영수증 표기).
export fn commission_and_tier(amount: f64, out_tier: i32) -> f64 { … }
```

**이건 컴파일된다. 그리고 아무 일도 하지 않는다.** `out_tier`는 값으로 받는 입력이라 쓸 수가 없다.
생성 헤더가 그대로 드러낸다:

```c
double mlx_commission_and_tier(double amount, int32_t out_tier);   /* 값이다. 포인터가 아니다 */
```

이름을 `out_`로 지어도 소용없다. **오늘 값을 두 개 돌려줄 방법이 없다.**

### 1.1 그런데 기계장치는 이미 있다

D17의 실패 가능 함수가 **정확히 caller-allocates 스칼라 out-param을 이미 쓴다**(실측):

```c
int32_t mlx_safe_div(double a, double b, double* out_value);
```
```pascal
function mlx_safe_div(a: Double; b: Double; out out_value: Double): Integer; cdecl;
```

**Delphi 바인딩은 이미 `out`이라는 낱말을 방출하고 있다.** 이 슬라이스는 새 ABI를 만들지 않는다 —
**암묵적으로 하나만 생기던 것을 명시적으로 여러 개 선언할 수 있게 하는 일반화**다.

## 2. 계약 (Contracts)

### 2.1 문법

```text
param := 'out'? ident ':' type
```

`out`은 파라미터 앞에 붙는다(Pascal·C#과 같은 자리). 예:

```mathless
export fn commission(amount: f64, out tier: i32) -> f64 {
  if amount < 1000000.0 { tier = 1  return amount * 0.03 }
  tier = 2
  return amount * 0.07
}
```

### 2.2 타입·의미 규칙

- `out` 파라미터의 타입은 **스칼라만**(`f64`/`bool`/`i32`). 오늘 다른 타입이 없다.
- **쓰기 전용이다**(DP-O4). 함수 안에서 `out` 파라미터를 **읽으면 거부**한다 — 호스트가 초기화되지
  않은 메모리를 넘겼을 수 있고, 그것을 읽는 것은 언어가 막을 수 있는 실수다.
- **정상 반환 경로마다 모든 `out`이 대입돼 있어야 한다**(DP-O2). "모든 경로 return"과 같은 검사이며,
  같은 자리(typeck)에서 한다.
- `fail`로 끝나는 경로에는 강제하지 않는다(DP-O3). 그 경우 호스트는 **아무 out도 읽지 않는다** —
  D17의 DP-E3을 그대로 확장한다.
- **`export fn`에만 붙는다**(DP-O5). 내부 `fn`은 호출식이 포인터를 넘길 문법이 없다. `-> T!`가
  export 전용인 것과 같은 이유이며, 푸는 것은 가산적 변경이다.
- 이름은 기존 검사를 그대로 받는다(예약어·중복·`out_value` 금지 — 실패 가능 함수에서는
  `out_value`가 이미 예약이다).

### 2.3 ABI — 선언 순서대로, `out_value`는 언제나 마지막

```mathless
export fn f(a: f64, out t: i32) -> f64          // 순수
export fn g(a: f64, out t: i32) -> f64!         // 실패 가능
```
```c
double  mlx_f(double a, int32_t* t);
int32_t mlx_g(double a, int32_t* t, double* out_value);
```

**DP-O1 권고:** 선언한 `out`들이 선언 순서대로 오고, D17의 암묵적 `out_value`가 **맨 마지막**이다.
근거는 읽기 쉬움이다 — "반환값은 마지막"이라는 한 문장으로 규칙이 끝난다.

Delphi 쪽은 `out t: Integer`로 나간다(생성기가 이미 `out`을 쓴다).

### 2.4 codegen

`out p: T`는 `p: *mut T`로 방출하고, 대입은 `unsafe { *p = … }`다 — **D17의 `out_value`가 이미
하는 것과 똑같다.**

### 2.5 export 집합 — 변화 없음

시그니처만 바뀐다. export 개수·이름·`ml_module_abi_version`은 그대로. **ABI 버전은 올리지 않는다:
기존 함수의 시그니처는 바뀌지 않고**, `out`을 쓰는 함수는 새로 쓰는 것이다.

## 3. 수용 기준 (측정 가능)

- **A. 컴파일:** `examples/commission.mls`(§1의 그 규칙) → `mlc build`.
- **B. 로드·호출(오라클):** `commission(500000, &t) == 15000.0` 이고 `t == 1`;
  `commission(9000000, &t) == 630000.0` 이고 `t == 2`.
- **B2. 실패 가능 + out 합성:** `-> f64!` + `out t`인 함수에서 성공 시 **둘 다** 기록되고,
  `fail` 시 **둘 다 손대지 않는다**(호출 전 값 그대로).
- **C. 보호:** export 집합·개수 불변. 크기는 재서 기록(고정하지 않음).
- **D. 수용 D(실제 C 호스트):** `hosts/c-host/host.c`에 B·B2 추가. 스택 변수 주소를 넘긴다.
- **E. 부정 케이스:** `out`을 **읽기**(DP-O4) · 정상 경로에서 **대입 누락**(DP-O2) ·
  내부 `fn`의 `out`(DP-O5) · `out`에 비-스칼라 타입 · 실패 가능 함수에서 `out out_value` ·
  `out` 파라미터를 두 번 선언.
- **F. 바인딩:** 생성 `.h`가 `T*`, 생성 `.pas`가 `out p: T`.

## 4. 설계 제안 (DP — **미확정, 사용자 확인 필요**)

| DP | 선택지 | 권고 | 근거 |
|----|--------|------|------|
| **O1 `-> T!`와 합성 순서** | 선언 out 먼저 + `out_value` 마지막 / `out_value` 먼저 | **선언 out 먼저, `out_value` 마지막** | "반환값은 마지막"으로 규칙이 한 문장에 끝난다. Grok 지적: 두 규약이 갈라지면 안 된다 — 갈라지지 않게 하는 가장 단순한 배치다 |
| **O2 대입 강제** | **정상 경로마다 강제** / 강제 안 함 | **강제** | 정적으로 판정 가능하고("모든 경로 return"과 같은 분석), 안 하면 호스트가 초기화 안 된 값을 읽는다. 저장소 선례: 막을 수 있으면 막는다 |
| **O3 `fail` 경로** | 강제 / **비강제 + 계약** | **비강제.** 호스트는 `status != 0`이면 out을 읽지 않는다 | D17 DP-E3의 확장이다. 버퍼링해서 원자적으로 커밋하는 대안은 비용을 내고 계약 하나를 없앨 뿐이다 |
| **O4 읽기** | 허용 / **거부** | **거부(쓰기 전용)** | 호스트가 초기화 안 된 메모리를 넘겼을 수 있다. 읽고 싶으면 입력 파라미터를 따로 받으면 된다 |
| **O5 범위** | export 전용 / 내부 `fn`도 | **export 전용** | 호출식에 포인터를 넘길 문법이 없다. `-> T!`와 같은 선례(#67), 푸는 것은 가산적 |
| **O6 NULL 검사** | 모듈이 검사 / **호스트 계약** | **호스트 계약**(검사하지 않음) | D16이 이미 "인자 포인터는 호출 기간만 유효"를 호스트에 요구한다. 그리고 검사는 완전할 수 없다 — 정렬 안 된·해제된 포인터는 NULL이 아니다. **오늘 `out_value`도 검사하지 않는다**(§5.1) |

### DP-O1이 왜 진짜 결정인가

`-> T!`는 **이미 마지막 자리를 쓰고 있다.** 여기서 잘못 고르면 규약이 둘로 갈라지고, 그 뒤로는
"이 함수는 out이 몇 개인가"를 세어야 시그니처를 읽을 수 있게 된다. 권고안은 세지 않아도 되게 한다:
**선언한 순서 그대로, 그리고 실패 가능하면 맨 뒤에 반환값 하나.**

## 5. 범위 밖 / 위험

- **문자열·구조체·배열** — 힙이 필요하고 **Q12**(소유권)를 열어야 한다. 이 슬라이스는 스칼라만
  다루므로 Q12를 건드리지 않는다.
- **context handle**(D16의 나머지) — 모듈 수명 상태. 별개 슬라이스.
- **`out` 인자를 내부 호출로 넘기기** — DP-O5로 제외.

### 5.1 물려받는 위험: NULL out-param은 오늘도 UB다

`unsafe { *out_value = … }`는 호스트가 NULL을 넘기면 UB다. **이 슬라이스가 만든 위험이 아니라
D17이 이미 갖고 있는 것**이며, out 파라미터 개수만큼 늘어난다. DP-O6은 검사하지 않는 쪽을 권한다 —
검사가 완전할 수 없기 때문이다. **대신 `HOST_ABI.md`에 계약으로 명문화한다**(오늘 DP-E3의
out-param 계약도 슬라이스 SPEC에만 있고 거기 없다 — `STATUS.md` §5-5 항목 5. 이 슬라이스가 같이 갚는다).

### 5.2 이 슬라이스는 Q12를 닫지 않는다

D16은 "반환 데이터 = caller-allocates out-buffer"를 정했고, **Q12는 힙 데이터의 소유권**을 묻는다.
스칼라 out에는 할당이 없다 — 호스트의 스택 변수 주소일 뿐이다. **그러므로 Q12는 열린 채로 남고,
이 슬라이스를 그 답으로 인용하면 안 된다.**

### 5.3 `&&` 단락 평가 부채(§5-1)도 갚지 않는다

`out` 대입은 함수 몸통의 문이지 식이 아니다. 식 자리에 부작용이 생기지 않으므로 관측 수단은
여전히 없다. (#76 때와 같은 이유로 미리 적어 둔다.)

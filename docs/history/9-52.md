### 9-52. 비ASCII 리터럴 구현 (2026-09-14, E2) — **§9-46의 R6이 닫혔다**

사용자가 DP-U1~U6을 확인했고(방향은 *"반환 자리에서만"*, 갈리는 하나는 **DP-U4 — DP-K9 문장을
고치고 진행**), 구현했다. **§9-46의 여섯 규칙 중 마지막 하나가 컴파일된다.**

```
status_label("AP") → status 0, needed 7, "승인"
account_label("0881234567") → status 0, needed 14, "088번 계좌"
```

`examples/claim.mls`가 그 규칙이고 **C 호스트 게이트가 부른다**(모듈 19 → **20**개).

#### 9-52.1 C4819는 진짜였다 — **다만 다른 파일에서**

DP-S4가 든 경고가 이번에 **실제로 났다**:

```
host.c(516): warning C4819 … current code page (949)  [/WX → error]
```

**모듈 리터럴 때문이 아니라 내가 `host.c` 주석에 한글을 붙여서다.** §9-51이 잰 그대로 —
C4819는 **손으로 쓴 C**에 적용되고, **모듈의 리터럴은 C 컴파일러가 읽는 산출물에 닿지 않는다.**
호스트 주석을 ASCII로 고쳐 게이트를 통과시켰고, 그 주석이 이 사실을 적는다.

#### 9-52.2 실측

| | |
|---|---|
| 생성 Rust | `b"\xEC\x8A\xB9\xEC\x9D\xB8\0"` — **이스케이프**, 날바이트 아님 |
| `.h` · `.pas` | **순수 ASCII**, 그리고 **UTF-8 고지 한 줄** |
| 기존 모듈 골든 | **+171/-0 · +69/-0 · +66/-0** — **삭제 0줄**, 새 모듈만 |
| 호스트가 받는 값 | 바이트 단위로 정확 (`needed`가 문자가 아니라 **바이트**) |
| 문자 수로 크기를 잡으면 | **거부**(`cap=4` → `-1`), 조용한 절단이 아니다 |
| export·import | **무변경** — UTF-8 바이트도 그냥 바이트다 |

#### 9-52.3 클레임 하나를 의도적으로 고쳤다

`a_literal_must_be_plain_ascii_and_unescaped`의 절반이 더 이상 참이 아니다. **그런데 그 테스트는
계속 통과했다** — 새 진단이 *"the non-ASCII literal … may only be RETURNED"* 이고, 소문자로 하면
needle `"ascii"`에 걸린다. §7-3이 적은 **"다른 메시지가 needle을 만족시킨다"** 그대로다.

이름을 `a_literal_may_not_contain_an_escape_or_a_control_character`로 바꾸고 **남은 절반만**
주장하게 했다. 비ASCII의 **위치** 규칙은 새 테스트가 맡는다.

#### 9-52.4 그리고 절반만 풀었다 (적어 둔다)

동기가 된 **한국어 코드-라벨 표**는 `c == "승인"`이 필요한데, 그것이 정확히 이 슬라이스가 막는
자리다. 모듈이 **라벨을 내보내는 것**은 되고, **라벨로 분기하는 것**은 안 된다.

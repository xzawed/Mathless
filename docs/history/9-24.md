### 9-24. `PByte` 후보를 재서 죽였다 (2026-09-10, E2) — **경고를 없애는 거래였다**

§9-23이 후보를 하나 남겼다: 문자열 **입력** 파라미터를 `.pas`에서 `PByte`로 내보내면, 반환 버퍼가
T3에서 그랬듯 틀린 철자들이 **컴파일 에러**가 되지 않겠는가. Grok이 착수 계획에서 `PByte(S)`는
여전히 조용할 것이라고 짚었고, **SPEC을 쓰기 전에 쟀다.**

Delphi CE 37.0 Win64, 컴파일러에게 직접 물었다:

```
B1 := PByte(PAnsiChar(A));   무진단
B2 := PByte(A);              무진단
B3 := PByte(S);              무진단          <- UnicodeString을 그대로
B4 := PByte(Pointer(S));     무진단
NativeUInt(B3) - NativeUInt(B4) = 0          <- B3과 B4는 같은 포인터다
```

**`PByte` 캐스트는 넷 다 아무 말도 듣지 않는다.** 그리고 `PAnsiChar` 인자를 `PByte` 파라미터에
넘기는 것은 실제로 에러다 — Delphi에서는 산출물도 전사도 남기지 않고 멈추고(에러 시 `bds -b`의
모양), Free Pascal이 같은 소스에 읽을 수 있는 문장을 준다:
`Incompatible type for arg no. 1: Got "PChar", expected "PByte"`. 그러므로 T3의 주장 자체는 맞다.

**그런데 입력 파라미터에서는 그 맞는 주장이 손해다.**

| | 오늘 (`PAnsiChar`) | 제안 (`PByte`) |
|---|---|---|
| 올바른 철자 | `PAnsiChar(AnsiString(S))` — 무언 | **컴파일 에러**. 호스트가 캐스트를 하나 더 붙여야 한다 |
| 자연스러운 오답 | `PAnsiChar(MyString)` → **W1044** | `PByte(MyString)` → **무진단** |
| 조용한 오답 | `PAnsiChar(Pointer(S))` → 무진단 | `PByte(Pointer(S))` → 무진단 |

**오늘 존재하는 유일한 진단을 없애고**, 올바른 철자에 에러를 붙여 호스트를 `PByte(S)` 쪽으로
민다 — 그게 바로 조용한 오답이다. **순손해다.**

**T3가 틀린 것은 아니다. 비대칭이 있을 뿐이다.** 반환 버퍼에서 호스트가 자연스럽게 쓰는 것은
`@Buf[0]`이고 그건 캐스트가 아예 필요 없다. 그래서 거기서는 `PByte`가 오답만 막는다. 입력에서는
호스트가 **반드시 무언가를 변환**해야 하므로, 파라미터 타입이 그 변환을 어느 쪽으로 미느냐가
전부다. **후보 닫음.**

## 1. 목표 — 곱셈을 하려고 루프를 써야 한다

이번엔 후보를 나열하는 대신 **실제 업무 규칙(계층 할인 가격 계산)을 오늘의 언어로 작성해 봤다.**
컴파일은 되지만, 가장 기본적인 산술에서 막혔다:

```text
export fn f(each: f64, qty: i32) -> f64 { return each * qty }
```
```
mlc: type error: operator Mul expects two f64 or two i32 operands, found f64 and i32
```

**단가 × 수량이 안 된다.** DP-I2가 암시적 혼합을 금지했는데(옳은 결정), **변환 수단을 주지 않았다.**
그 결과 소계를 이렇게 쓸 수밖에 없었다 — 실측된 우회 코드다:

```text
fn subtotal(each: f64, qty: i32) -> f64 {
  let mut total = 0.0
  let mut i = 0
  while i < qty {          // 곱셈을 루프로 흉내낸다
    total = total + each
    i = i + 1
  }
  return total
}
```

업무 규칙 언어에서 이것은 받아들일 수 없다. 이 슬라이스는 **명시적 변환**을 추가한다:

```text
export fn line_total(each: f64, qty: i32) -> f64 {
  return each * (qty as f64)
}
```

## 2. 계약 (Contracts)

### 2.1 문법

```text
unary := ('-' | '!') unary | cast
cast  := primary ('as' TYPE)*
```

`as`는 새 키워드다. 좌결합이며 단항보다 강하게 결합한다 — `-x as f64`는 `(-x) as f64`가 아니라
**`-(x as f64)`** 로 읽히지 않도록 §3에 파싱 케이스를 고정한다(권장: `as`가 더 강하게 결합해
`-(x as f64)`).

### 2.2 변환 규칙

| 변환 | 의미 | 손실 |
|------|------|------|
| `i32 as f64` | 정확 | **없음** — f64의 가수는 53비트라 모든 i32를 정확히 표현한다 |
| `f64 as i32` | **0 방향 절단** 후 **포화(saturate)** | 있음 — §2.3 |
| `T as T` | 항등(허용) | 없음 |

`bool`은 변환 대상이 아니다(`true as i32` 금지) — 숫자를 진리값으로 쓰지 않는 기존 태도와 같다.

### 2.3 `f64 as i32`의 경계 — **언어 규칙이지 "타깃이 하는 대로"가 아니다**

- **절단:** 0 방향으로 자른다. `3.9 as i32 == 3`, `-3.9 as i32 == -3`.
- **범위 초과:** **포화**한다. 아주 큰 양수 → `i32::MAX`, 아주 큰 음수 → `i32::MIN`.
- **NaN:** `0`.

이 값들은 §3에서 **측정한다**(NaN·inf는 `a / 0.0`로 도달 가능함을 실측 확인).

> **후속 백엔드 주의:** 이것은 **Mathless의 규칙**이지 "대상 언어의 캐스트가 하는 대로"가 아니다.
> 현재 lowering인 Rust `as`가 마침 이 의미(절단+포화, NaN→0)를 갖지만, **C의 캐스트는 범위 초과 시
> UB**다. D19가 열어 둔 C-emit 백엔드는 이 의미를 **명시적으로 구현해야 한다**(단순 `(int)x` 금지).

### 2.4 ABI — **변화 없음**

식 수준 변경이다. export 집합·시그니처·바인딩은 그대로다.

## 3. 수용 기준 (측정 가능)

- **A. 컴파일:** `examples/line_total.mls` → `mlc build`.
- **B. 로드·호출(오라클):** `mlx_line_total(2.5, 4) == 10.0`.
- **C. 보호:** export 2개, strip 유지.
- **D. 수용 D(실제 C 호스트):** `hosts/c-host/host.c`에 추가한다.
- **경계 실측(§2.3을 값으로 고정):** 오라클이 다음을 확인한다.
  - `3.9 as i32 == 3`, `-3.9 as i32 == -3` (0 방향 절단)
  - 큰 양수 → `i32::MAX`, 큰 음수 → `i32::MIN` (포화)
  - `(0.0 / 0.0) as i32 == 0` (NaN)
  - `i32::MAX as f64`가 정확히 `2147483647.0`
- **부정(타입체크) 케이스:**
  - `true as i32` / `1 as bool` → 에러
  - 여전히 암시적 혼합 금지: `each * qty` → 에러(변환은 **명시적으로만**)

## 4. 설계 제안 (DP — **확인됨 2026-08-29**)

| DP | 선택지 | 권장 | 근거 |
|----|--------|------|------|
| **N1 문법** | `x as f64` vs `f64(x)` | **`x as f64`** | **실측:** 호출식이 들어온 뒤(#57) `f64(x)`는 *호출*로 파싱된다 — 오늘 `unknown function 'f64'`가 난다. 캐스트로 쓰려면 타입 이름을 마법 함수로 특별 취급해야 하고, 사용자가 그 이름을 못 쓰게 된다. `as`는 모호성이 없고 키워드 하나면 된다 |
| **N2 `f64 as i32`** | 절단+포화 vs 반올림 vs 거부 | **절단 + 포화, NaN→0** | 결정적이고 트랩이 없다. 반올림은 은행가 반올림 등 또 다른 선택을 부른다. **거부**(실패 가능 변환)는 D17 status를 식 자리에 끌고 들어와 DP-C1과 충돌한다 |
| **N3 `i32 as f64`** | — | **정확, 무손실** | f64 가수 53비트 > 32비트. 결정할 것이 없다 — 문서화만 |
| **N4 범위** | 캐스트만 vs `i32 /`·`%` 포함 | **캐스트만** | `i32 /0`은 `no_std`+`panic=abort`에서 **호스트를 죽인다**. 재귀 금지와 같은 등급의 위험이며 자체 설계(실패 가능 나눗셈? 정의된 결과?)가 필요하다 — 별도 슬라이스 |
| **N5 암시적 확장** | 금지 유지 vs `i32`→`f64` 자동 | **금지 유지** | DP-I2를 뒤집지 않는다. 이 슬라이스는 "혼합 금지"를 유지한 채 **표현 수단**만 준다 |

## 5. 범위 밖 / 미검증

- `i32` 나눗셈·나머지(DP-N4 — 별도 슬라이스), 다른 정수 폭, `bool` 변환.
- **단락 평가 부채는 그대로다.** `i32 /`가 들어오는 슬라이스가 그 관측 수단을 만들 후보다.
- 어떤 항목도 측정 전까지 "확정/동작"으로 서술하지 않는다.

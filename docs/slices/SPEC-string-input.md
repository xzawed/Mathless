# Slice SPEC — 문자열 **입력** 파라미터와 비교

> **상태: ✅ 구현 완료** — 2026-08-31 (SPEC #88 / 구현 #89). §3 수용 A~F 전부 측정.
> **DP-S1 = NUL 종료 `const char*`.** **DP-S2 = 불투명 바이트**(비교는 바이트 동등성).
> 둘 다 권고안 그대로 사용자 승인. S3~S5는 그에 따라 함께 확정된다.
> **§5.2를 승인의 일부로 읽을 것:** Delphi `UnicodeString` 오전달은 모듈이 막을 수 없고 E1이다.
> **근거 수준:** §1이 **E2 실측**(오늘의 언어로 쓴 업무 규칙 3개 + 진단), §2가 E0 + 기존 결정 인용.
> **선행:** `out` 파라미터(#80) · Q12 확정(2026-08-31) · D16 (1) 인자=빌림.
> **Q12와의 관계: 이 슬라이스는 Q12를 쓰지 않는다.** 문자열 **입력**은 빌린 인자이므로 할당이 없다.
> 문자열 **반환**이 Q12를 쓰는 슬라이스이며, 여기 포함하지 않는다(§5.1).

---

## 1. 목표 — 업무 규칙이 문자열을 필요로 하는 방향은 하나였다

Q12가 닫히면서 세 슬라이스(고정 struct · 문자열 · 배열)가 열렸다. **§7대로 다시 재 봤더니
문자열이 필요한 방향이 갈렸고, 필요한 쪽은 Q12를 쓰지 않는다.**

### 1.1 측정한 것 — 전부 같은 모양이다 (E2)

| 업무 규칙 | 시그니처 | 오늘 |
|---|---|---|
| 국가 코드별 부가세율 | `vat_rate(country: string) -> f64` | ❌ `parse error … unexpected character '"'` |
| 카드 BIN으로 발급사 판정 | `issuer_of(bin: string) -> i32` | ❌ 같은 에러 |
| 품목 코드가 수출품인가 | `is_export_item(code: string) -> bool` | ❌ 같은 에러 |

**셋 다 문자열 IN · 스칼라 OUT이다.** 호스트가 코드를 주고, 모듈이 그것으로 분기해 숫자를 돌려준다.
이것이 규칙 엔진이 텍스트를 쓰는 지배적인 방식이다.

### 1.2 모듈이 문자열을 **만들어야** 하는 규칙은 나오지 않았다

그리고 이 저장소는 **이미 그 방향으로 결정한 적이 있다.** D17은 에러를 **정수 status**로 넘기고,
헤더에 `ML_ERR_<NAME>` 상수를 방출한다 — **문구는 호스트가 만든다.** 모듈은 코드만 준다.

> 문자열 반환이 불필요하다는 말이 아니다. **덜 급하고, 더 비싸고(Q12 프로토콜), 이미 선례가
> 호스트 쪽을 가리킨다**는 뜻이다. §5.1에서 후속으로 분리한다.

### 1.3 왜 struct나 배열이 아닌가

- **고정 레이아웃 struct** — 가장 작지만 **실측 수요가 사실상 0**이었다. 값 두 개가 필요했던
  경우는 전부 `out` 파라미터(#80)가 닫았다. 지금 만들면 "있어서 나쁠 것 없는" 기능이다.
- **배열** — 실측 수요는 가장 크다(두 번의 3라운드에서 **네 번** 벽). 그러나 이 슬라이스에
  **원소 타입 이야기와 Q12 반환 프로토콜이 더 얹힌다.** 프로토콜에 결함이 있다면
  **문자열에서 찾는 편이 배열에서 찾는 것보다 훨씬 싸다.**

## 2. 계약 (Contracts)

### 2.1 타입과 문법

```mathless
export fn vat_rate(country: string) -> f64 {
  if country == "KR" { return 0.1 }
  if country == "JP" { return 0.08 }
  return 0.0
}
```

- 새 타입 이름 **`string`**. **파라미터 위치에만** 쓸 수 있다(§2.5).
- 새 리터럴 `"…"`. 렉서에 없다(실측: `unexpected character '"'`).
- 연산은 **`==` · `!=` 뿐이다.** 순서 비교(`<`)·길이·연결·부분문자열은 범위 밖(DP-S3).

### 2.2 ABI — NUL 종료 `const char*` (DP-S1 권고)

```c
double mlx_vat_rate(const char* country);
```
```pascal
function mlx_vat_rate(country: PAnsiChar): Double; cdecl; external ML_MODULE;
```

> ⚠ **Delphi 함정을 여기 적어 둔다.** Delphi의 기본 `string`은 **UTF-16 `UnicodeString`**이다.
> `PAnsiChar`에 그것을 그대로 넘기면 **틀린 바이트를 보낸다.** 호스트는 `AnsiString`으로 변환하거나
> `UTF8String`을 써야 한다. D14의 플래그십 호스트이므로 바인딩 주석에도 넣는다.

### 2.3 값 규칙 — 바이트 동등성

- `a == b`는 **NUL까지의 바이트열이 정확히 같은가**이다. 대소문자 구분한다. 정규화하지 않는다.
- **인코딩을 확정하지 않는다**(DP-S2 권고). 모듈은 비교만 하므로 바이트가 같으면 같다.
  **호스트와 소스가 같은 인코딩을 쓰는 것은 호스트 계약이다.**
- **비교는 CRT를 부르지 않는다.** `strcmp`를 import하면 모듈의 import 집합이 늘어난다
  (보호 프록시 D04/D05에 잡히는 값). 대신 바이트 루프를 방출한다 — `no_std`에서 몇 줄이다.

### 2.4 리터럴

- 생성 Rust에 **정적 NUL 종료 바이트 배열**로 방출한다. **할당 없음**, `no_std` 유지.
- **ASCII만 허용한다**(DP-S4). 비-ASCII는 거부한다.
  근거: `STATUS.md` §6의 **"생성 산출물은 ASCII로 유지"** — 비-ASCII가 MSVC에서 C4819를 내고
  `/WX` 빌드를 깬다(실측). 리터럴은 오늘 헤더에 닿지 않지만, **규칙을 좁게 지키는 편이 싸다.**
- **이스케이프 없음.** `\`가 들어오면 "아직 지원하지 않는다"로 거부한다 — 조용히 다른 뜻이 되게
  두지 않는다. 따라서 리터럴에 `"`를 넣을 수 없다. 업무 코드에는 필요 없다.

### 2.5 범위 제한

- **파라미터 위치 전용.** `-> string` 반환도, `let s = …` 지역 변수도 없다.
  둘 다 "그 문자열이 어디 사는가"를 열고, 반환은 Q12 프로토콜을 쓴다 — 별도 슬라이스(§5.1).
- `out string` 도 없다. 같은 이유다.

### 2.6 NULL (DP-S5)

호스트가 `NULL`을 넘기는 것은 **정의되지 않은 동작**이다. 모듈은 검사하지 않는다 —
`out` 파라미터의 DP-O6과 같은 태도이고, 같은 이유다(검사는 완전할 수 없고 호출마다 분기를 늘린다).
`HOST_ABI.md`에 계약으로 적는다.

## 3. 수용 기준 (측정 가능)

- **A. 컴파일:** `examples/vat.mls`(§1.1의 규칙) → `mlc build`.
- **B. 로드·호출(오라클):** `vat_rate("KR") == 0.1` · `vat_rate("JP") == 0.08` · `vat_rate("US") == 0.0`.
- **B2. 바이트 동등성의 경계:** `vat_rate("kr") == 0.0`(대소문자 구분) · `vat_rate("") == 0.0` ·
  `vat_rate("KRW") == 0.0`(접두어가 같아도 다름) · `vat_rate("KR")`에서 **뒤에 쓰레기가 있는 버퍼**를
  넘겨도 NUL까지만 본다.
- **C. 보호:** export 집합 불변. **import 집합 불변**(§2.3 — `strcmp`를 부르지 않는다는 것을 측정).
  크기는 재서 기록.
- **D. 수용 D(실제 C 호스트):** `hosts/c-host/host.c`에 B·B2 추가. C 리터럴을 그대로 넘긴다.
- **E. 부정 케이스:** `-> string` 반환 · `let s = "x"` · `out s: string` · `string`끼리 `<` ·
  `string`과 `i32` 비교 · 비-ASCII 리터럴 · `\` 포함 리터럴 · 닫히지 않은 리터럴.
- **F. 바인딩:** `.h`가 `const char*`, `.pas`가 `PAnsiChar`, 그리고 **`.pas`에 UnicodeString 경고 주석**.

## 4. 설계 제안 (DP — **미확정, 사용자 확인 필요**)

| DP | 선택지 | 권고 | 근거 |
|----|--------|------|------|
| **S1 ABI 형태** | **NUL 종료 `const char*`** / 포인터+길이 | **NUL 종료** | C 관용구 그대로이고 Delphi `PAnsiChar`에 직결된다. 포인터+길이는 **모든 호출자가 길이를 계산해 넘겨야** 하는데, 실측한 세 규칙은 전부 리터럴이나 고정 버퍼를 넘긴다. 대가: 임베디드 NUL 불가, 길이가 O(n) |
| **S2 인코딩** | UTF-8 확정 / **불투명 바이트** | **불투명** | 모듈은 비교만 한다 — 바이트가 같으면 같다. UTF-8을 확정하면 **강제할 수도 측정할 수도 없는 주장**이 된다(검증 코드가 없다). 대신 **호스트 계약으로 명문화**한다 |
| **S3 연산** | `==`/`!=`만 / 길이·부분문자열 포함 | **`==`/`!=`만** | 실측한 세 규칙이 요구한 전부다. 우회가 없는 것만 넣는다(DP-R4와 같은 태도) |
| **S4 리터럴 문자 집합** | ASCII만 / 임의 바이트 | **ASCII만** | `STATUS.md` §6의 기존 규칙을 좁게 지킨다. 넓히는 것은 가산적 |
| **S5 NULL** | 모듈이 검사 / **호스트 계약** | **호스트 계약** | DP-O6과 같다. 검사는 완전할 수 없다 |

### DP-S1이 왜 진짜 결정인가

**바꾸기 어렵다.** 시그니처가 `const char*`인지 `(const char*, int32_t)`인지는 **모든 호스트의 모든
호출부**에 나타나고, 나중에 바꾸면 조용히 깨지는 게 아니라 시끄럽게 깨지지만 **전부 고쳐야 한다.**
지금 정하는 편이 싸다.

### DP-S2에 대한 반론 (기록)

"불투명 바이트"는 결정을 미루는 것처럼 보인다. 그렇지 않다 — **비교의 의미를 바이트 동등성으로
확정하는 것**이 결정이다. 다만 **나중에 대소문자 무시 비교나 정규화가 필요해지면 인코딩을 알아야
하고, 그때 이 결정을 다시 열어야 한다.** 그 시점에 열릴 것을 알고 지금은 닫는다.

## 5. 범위 밖 / 위험

### 5.1 문자열 **반환**은 이 슬라이스가 아니다

Q12가 정한 프로토콜(호스트 버퍼 + 용량, 절단은 음수 status)을 쓰는 **첫 슬라이스**가 될 것이다.
여기서 하지 않는 이유는 셋이다: **실측 수요가 없었고**, D17의 선례가 텍스트를 호스트 쪽에 두며,
**프로토콜의 결함은 더 작은 슬라이스에서 찾는 편이 싸다.**

### 5.2 이 슬라이스가 만드는 새 위험 — 조용한 오답의 다섯 번째 후보

**Delphi 호스트가 `UnicodeString`을 `PAnsiChar` 자리에 넘기면 비교가 조용히 실패한다.**
컴파일도 되고, 크래시도 없고, 그냥 **아무 코드에도 안 맞는다** — 이 저장소가 네 번 만난 그 모양이다.
막을 방법이 모듈 쪽에는 없다(바이트만 보인다). 그래서 **§2.2와 생성 `.pas` 주석 양쪽에** 적는다.
`dcc64`가 없어 **E2로 확인할 수 없다** — 이것은 E1(Embarcadero 문서)이며, 그렇게 표시한다.

### 5.3 `&&` 단락 평가 부채(§5-1)는 갚지 않는다

문자열 비교는 부작용이 없다. 관측 수단은 여전히 생기지 않는다.

> **DP-S1·DP-S2 확인 완료(2026-08-31, 사용자 승인 = 둘 다 권고안).** WS1~WS8 **전부 완료**(#89).
>
> **§5.2를 구현 중에 좁혔다(정정).** "UnicodeString을 넘기면 아무 코드에도 안 맞는다"는 **한 가지
> 철자에만 참이다.** `PAnsiChar(Pointer(S))`는 UTF-16 바이트를 재해석해 조용히 틀리지만,
> `PAnsiChar(S)`는 암시적 캐스트 경고와 함께 ANSI 코드 페이지로 **변환**된다(ASCII는 살아남는다).
> `HOST_ABI.md`와 생성 `.pas`에 세 철자를 구분해 적었다. 여전히 **E1이고 미측정**이다.
>
> **구현하며 바뀐 것 둘:**
> 1. **§2.5의 제한은 *위치*이지 *가시성*이 아니다.** 내부 `fn`도 `string` 파라미터를 받는다 —
>    빌린 포인터를 헬퍼에 넘기는 것은 새 질문을 열지 않는다. 처음 쓴 테스트가 SPEC보다 엄격했다.
> 2. **§3-C의 "import 집합 불변"은 절대 주장으로 쓸 수 없다.** 모든 cdylib이 DllMain 발판 때문에
>    CRT 시동 함수와 `vcruntime140!memcpy`를 이미 import한다(측정: 25개). 그래서 수용 C는
>    **문자열 없는 대조 모듈을 같은 방식으로 빌드해 집합이 정확히 같은지**를 본다.
>    그러려면 PE 리더에 import 테이블 읽기가 필요했고, `dumpbin /imports`와 교차 확인한다.

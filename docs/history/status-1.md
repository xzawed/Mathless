## 1. 현재 상태 (실측, `main`)

- **저장소는 공개다 (2026-08-30).** `https://github.com/xzawed/Mathless` — 익명 접근 `HTTP 200`,

  `clippy -D warnings`·`fmt`도 종료 코드 0.

  > 적혀 있는 동안 §9-25는 이미 **466**을 적고 있었고, 같은 파일 안에서 두 값이 갈렸다.
  > **원천은 실행 결과다**(전역 규칙의 SSOT). 오늘 값이 필요하면 위 명령을 돌리고,
  > **파이프 없이 `$?`를 본다**(↓ 경고). 날짜 붙은 값은 §9-N 기록에 남는다.
  이력: 409 → 436은 전수 코드 감사(§9-4), 436 → 441은 그 감사의 **근본 원인 분석**(§9-5),
  441 → 444는 **§9-6 하나가** 더한 것이다(`is_terminator` 단위 테스트 둘 + `return try`의 DP-O2 —
  전부 #177 한 커밋이다. §9-7·§9-8·§9-9는 테스트를 더하지 않았다). 444 → 466은 **배열 입력**(§9-25).

  > `$?`는 **`tail`의 0**이었다 — 바로 아래 경고가 `fmt`에 대해 적어 둔 그것이다. 파이프를 걷고
  > 다시 돌린 값이 위 숫자다. **경고를 읽은 뒤에도 다시 밟았다**는 것이 이 항목의 값어치다.

  > **파이프라인의 종료 코드(=`tail`의 0)** 를 보므로 언제나 "clean"을 찍는다 — 실제로 그렇게 통과시킨
  > 커밋이 CI에서 잡혔다(2026-09-02). 실패할 수 없는 가드는 아무것도 증명하지 않는다.

## 2. 오늘 컴파일되는 언어

정본은 `docs/LANGUAGE.md`의 "현재 구현된 표면". 요약:

- **내장 함수**(#83) `floor`·`ceil`·`round`·`trunc` — `f64 -> f64`, **C `<math.h>`와 정확히 같다**
  (0 부호·NaN·inf 포함, 실제 C 호스트에서 대조). 키워드가 아니라 **내장 시그니처**라
  `let round = 0`은 계속 합법이고, 동명 함수 선언은 거부된다
- **문자열 입력**(#89) `export fn f(code: string) -> f64` — **파라미터 위치 전용**, 연산은
  **`==`·`!=` 뿐**, 의미는 **NUL까지의 바이트 동등성**. C는 `const char*`, Delphi는 `PAnsiChar`.
  비교가 **CRT를 부르지 않음을 측정**했다(import 집합이 문자열 없는 모듈과 동일)
- **문자열 반환**(#92) `-> string!` — Q12 프로토콜. 호스트가 버퍼와 용량을 주고 모듈이 채운다.
  **절단은 실패**(음수 status)이고 그때 버퍼는 **한 바이트도 쓰이지 않는다**. probe(`ml_cap = 0`,
  버퍼 NULL 가능)는 **항상 2회에 수렴**. 반환값의 재료는 리터럴·`string` 파라미터에 더해
  **연결 `+`**(#108) · `i32 as string` · `fixed(x, places)` · `byte_slice(...)`까지다
  — 자세한 범위는 바로 아래 문단들과 `docs/HOST_ABI.md`가 정본이다
- 타입 `f64` / `bool` / `i32` / `string`(파라미터 + `-> string!` 반환), 명시적 변환 `e as T`(암시적 혼합은 여전히 금지).
  **`as`는 단항보다 느슨하게 묶는다**(Rust 계열, #68) — `-x as f64` = `(-x) as f64`
- `export fn` / **`fn`(내부 함수)** + 호출식 — **재귀는 금지**(직접·상호)
- **`out` 파라미터**(#80) `export fn f(a: f64, out t: i32) -> f64` — 값을 여러 개 돌려주는 수단.
  C는 `T*`, Delphi는 `out p: T`. **쓰기 전용**, **정상 반환 경로마다 대입 강제**, `export fn` 전용.
  실패 가능 함수와 합칠 때 `out_value`가 **언제나 마지막**이다(DP-O1)
- **실패 가능 함수 호출**(#98·#99) `let x = try f(a)` · `x = try f(a)` · `return try f(a)` — 피호출자의
  status가 **그대로** 전파된다. **`try`는 문장 전용**이라 식 안에 못 들어간다. 호출자도 `-> T!`여야
  하고, v1의 피호출자는 **내부 `fn`만**이다. **C ABI 무변경**(테스트로 못박음)
- 실패 가능 함수 `-> T!` + `error NAME = N` + `fail NAME`(D17: i32 status + out-param).
  **`export fn`에만 붙는다**(#67) — D17은 호스트 경계 규약이고 내부 호출 규약은 없다
- `if`(**`else` 없음**) / `while` / `return`
- `let`(불변) / `let mut` + 대입문
- 단항 `-` `!`, 이항 `+ - * / %`, 비교, `&&` `||`.
  **`i32`의 `/`·`%`는 전역(total)**(#76) — `x / 0` = `x % 0` = `0`, `i32::MIN / -1`은 wrap.
  `%`는 i32 전용. 리터럴 `/ 0`은 컴파일 에러

- **문자열 연결**(#108) `a + b` — 양변이 **둘 다 `string`**일 때만. `"x" + n`은 거부되고
  `n as string`을 쓴다(DP-K1). **`i32 as string`**도 함께 들어왔다 — `i32::MIN`까지 정확하고,
  모듈이 만드는 바이트는 **ASCII `-`·`0`–`9`뿐**이다. 결과는 **호스트 버퍼에 직접** 만들어지므로
  `-> string!`의 **`return` 자리에만** 놓을 수 있다(이름을 붙일 수 없다 — 할당자가 없다)

**없는 것:** `f64 %`, `else`, `break`/`continue`, 복합 대입(`+=`), `for`,
**문자열의 길이·부분문자열·순서 비교·지역 변수**, **`f64 as string`**, 배열, struct,
호스트 함수 import, 재귀.

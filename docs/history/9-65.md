### 9-65. STATUS를 Read 한 번에 읽히게 했다 (2026-09-25, E2) — **크기가 결함 셋을 숨기고 있었다**

사용자가 *"후속작업을 수행하기 이전에 HISTORY와 STATUS 문서가 너무 거대하다 — Claude 작업에 부정적 영향이
클 것"* 이라며, Grok과 함께 그 주장이 타당한지와 해결 방안을 검토하라고 했다. **타당했다 — STATUS는 실측으로
강하게, HISTORY는 조건부로.** HISTORY는 보관 문서라 크기 자체보다 *필수 읽기 순서 2행에 있고, 다음 할 일의
일부가 그 안에 있고, 한 번에 열리지 않는다*는 것이 문제였다. A안(구조 분리)의 PR 1을 사용자 승인으로 했다(#310).

#### 9-65.1 실측 — 도구가 직접 보고한 값

| | `STATUS.md` | `HISTORY.md` |
|---|---|---|
| 크기 | 1,943줄 · 192,147 B · **93,243 토큰**(Read가 보고) | 5,116줄 · 374 KB |
| Read 한 번(제한 없음) | **1~443행만**(25,000토큰 상한) — ▶ 블록은 1713행, 4번째 페이지 | **거부**(256 KB 상한) |

- 성장: 177줄(08-29) → 6,031줄(09-17). #265·#289의 이관 뒤에도 이틀에 +87줄 — **전체 크기를 묶는 가드가 없었다.**
- README 지도 1행 STATUS · 2행 HISTORY와 `CLAUDE.md`의 *"그 표의 순서대로 읽는다"* 를 문자 그대로 따르면 약
  27만 토큰이다(HISTORY는 STATUS의 바이트/토큰 비로 환산한 추정 — 30% 틀려도 200k 창을 넘는다).
- 외부 근거(E1): Anthropic Claude Code best practices — *"performance degrades as it fills"*.
- 검색: 내가 고른 용어 8개 표본에서 저장소 전체 매치 줄의 8~79%(중앙값 약 20%)가 두 파일에서 나왔다(`target/` 제외).

#### 9-65.2 한 것 (#310)

`STATUS.md`는 **459줄 · 41,285 B이고 Read 한 번에 통째로 반환된다**(같은 도구로 재측정). 열린 항목과 현재
사실은 전문으로 남고, 닫힌 항목은 한 줄 + 본문 링크, 날짜 기록(§3·§5b·§5c·§7-1~§7-4·§8)은 한 줄 스텁 표제다.
옮긴 절은 `docs/history/status-*.md` 8개에 **원문 스냅샷**으로 있고 `main` 대비 바이트 동일하다 — 조립
스크립트와 독립된 검증기로 확인했고, 그 검증기도 결함을 심어 FAIL을 봤다. ▶ 색인은
`docs/history/start-block-index.md`로 나왔다. 새 가드 셋(`status_fits_in_one_read` 45,000 B ·
`every_history_file_fits_in_one_read` 40,000 B · `every_status_citation_resolves` 인용 150개)과 `CLAUDE.md` 두 줄
(사용자 승인) · README 두 판본.

#### 9-65.3 크기가 숨기고 있던 것

세 결함이 전부 **다음 할 일을 정하는 구역**에 있었다: 열린 착수 대기를 세 가지로 답했고(`X1` 하나 /
`X1~X3`·`R1`·`R3` / X2 행은 "X1과 같은 상태"), X3 행에는 ✅가 없었고 빈 줄이 표를 끊어 닫힘 기록이 표 밖에
있었고, STATUS §2의 언어 요약은 `LANGUAGE.md`의 낡은 사본이었다(배열·`byte_len`·`byte_slice`를 "없는 것"으로).

그리고 **✅ 항목 다섯이 살아 있는 사실을 품고 있었다** — §5-5.10 아래의 열린 공백(`shapes.h`가 `_Generic`
오라클 밖), §5-5.6·§5-5.7의 상시 규칙(`icacls /reset` 먼저 · 크래시를 심었으면 `%TEMP%`를 센다), §5-5.3의 참인
사실(`ml_abi.h`를 아무도 include하지 않는다), §4-8의 설계 함정(Delphi 호스트는 로드 시점 바인딩). 서사를 그냥
옮겼다면 조용히 사라졌을 자리다 — 한 줄 요약에 ⚠로 남겼다.

#### 9-65.4 Grok

- **plan 2회**: 방향 **A**(구조 분리 — B 읽기 지시만 · C 요약 재작성은 기각), 세부 **S·T·K**(절별 새 파일 · 스텁
  표제 · 절 순서 유지), HISTORY 분할은 **E**(항목당 파일). 첫 plan의 산술 지적 — *"(a)+(b)만으로는 40 KB
  불가"* — 이 §1·§7 압축과 §2 정리를 설계에 넣었다.
- **verify**: **첫 라운드 3회가 무효였다.** `worktree: true`는 HEAD에서 만들어지므로 커밋 전 변경을 보지 못한다 —
  Grok 스스로 *"status-1.md is absent"*, *"past EOF"* 를 보고했다. 로컬 커밋 뒤 같은 질문으로 PASS(문서 2/2, 가드
  4/4 — 300초 타임아웃 두 번 뒤 함수 단위로 쪼갰다).
- **안 물어본 것**: 반영 넷(링크 제목이 없는 파일로 읽힘 · 예산 메시지가 상한을 과장 · 표제 매칭에 토큰 경계
  없음 · X3 ②의 표현), 경계로 기록 둘(라벨 끝 경계 · 이관 파일 속 옛 `18` — 기록 본문이 스스로 그 낡음을 적는다).

#### 9-65.5 하지 않은 것 — PR 2 (HISTORY 분할)

`HISTORY.md`는 그대로다 — 374 KB, Read가 거부한다. 방향만 정했다: **항목당 파일** `docs/history/9-N.md`
(Grok E — 끝난 항목 파일은 다시 편집되지 않고, 범위 청크는 한도를 넘을 때마다 다시 써야 한다) + `HISTORY.md` 색인.
함께 고칠 것:

- `every_cited_history_entry_has_a_heading`이 `HISTORY.md` 한 파일만 읽고, 중복 번호를 따로 센다(바닥값 `>= 62`가
  중복으로 채워질 수 있다 — Grok, 오늘은 64개 모두 고유).
- HISTORY 면제 5곳이 `path == "docs/HISTORY.md"` 정확 일치라 새 파일에 닿지 않는다.
- "▶ 블록 기록" 절은 65 KB라 날짜 항목으로 나눠야 한다.
- `docs/`에서 `docs/history/`로 옮기면 본문의 상대 링크가 한 단계 어긋난다 — #310은 원문을 지키고 머리말에 적었다.

**설계를 사용자에게 먼저 보인다.**

#### 9-65.6 PR 2 — HISTORY 분할 (같은 날, 사용자 승인 설계)

사용자가 설계를 승인했다. Grok plan은 ▶ 기록을 **P**(기록마다 파일 — 묶음은 앞에 끼워 넣을 때마다 오래된
기록까지 다시 쓴다), 링크를 **R**(다시 맞춘다 — 색인의 안내로는 링크가 죽은 채다), 배치를 **F**(평평하게 —
`status-*.md`와 같은 깊이)로 골랐다. **안 물어본 것 하나가 설계를 바꿨다**: 색인을 링크 표로 만들면 `§9-N`
인용 150개 이상이 떨어질 표제를 잃는다. 그래서 색인은 **한 줄 스텁 표제**다 — #310의 STATUS 스텁과 같은 수다.

- `HISTORY.md`는 378 KB에서 **약 13.5 KB · 123줄**이 됐고, Read 한 번에 통째로 반환된다(같은 도구로 실측 —
  전에는 읽기 자체를 거부했다). 원래 머리말, 스텁 65개, ▶ 절의 원래 머리말이 남는다.
- 원문은 `docs/history/9-1.md`…`9-65.md`와 `start-block-001.md`(2026-09-05 낮, 가장 오래된 것)…`-046.md`.
  분할 스크립트와 독립된 검증기로 **원본 범위와 바이트 동일**함을 확인했다 — 예외는 상대 링크의 `../` 접두어뿐이고
  그 개수까지 셌다(항목 3 · ▶ 기록 6 · #310 이관 파일 17). 원문 5,227줄이 전부 새 파일에 있다. 검증기에 결함 셋을
  심어 FAIL을 봤다. 검증기 자신의 결함도 하나 나왔다 — 빈 줄로 끝나는 범위를 `$(…)`가 잘라 멀쩡한 `status-8.md`를
  FAIL로 냈고, 파일 대 파일 `cmp`로 바꿨다.
- 가드: `the_history_index_fits_in_one_read`(45,000 B) · `the_history_archive_is_indexed_and_numbered`(스텁 ↔ 파일,
  ▶ 기록은 001부터 빈틈없이) — 둘 다 먼저 빨갛게, 결함 셋을 심어 다시 빨갛게. 표제 가드는 중복 번호를 한 번만
  센다. **면제는 `is_dated_record` 하나로 모았다** — 분할 직후 정확 경로로 HISTORY만 면제하던 다섯 곳이 옮긴
  기록을 못 덮어, 두 가드가 `9-21.md`·`9-26.md`(Pascal 게이트 이전의 기록)에서 빨개졌다.
- **세션 마무리 절차가 바뀌었다**: 새 기록은 **새 파일** `docs/history/9-N.md` + `HISTORY.md` 맨 위 스텁 한 줄,
  옮기는 ▶ 항목은 다음 번호의 `start-block-NNN.md` + 색인 한 줄. **이미 있는 파일은 다시 편집하지 않는다** —
  그날 쓰고 있는 자기 기록만 예외다(이 9-65.6이 그 예외다).
- `CLAUDE.md` 한 줄은 사용자가 승인한 문구 그대로 바꿨다 — *"HISTORY.md는 Read 한 번에 들어가지 않는다"* 는 이제
  거짓이라, *"색인이고 원문은 `docs/history/`에 있다"* 로.
- **스텁은 번호 내림차순이다.** 원본은 §9-53 하나가 §9-60과 §9-59 사이에 끼어 있어, 머리말의 *"가장 큰
  번호부터 9-1로 내려간다"* 가 그 한 곳에서 거짓이었다 — 분할 뒤 Grok verify가 스텁을 줄지어 읽고 찾았다. 파일은
  그대로 두고 스텁의 자리만 옮겼으며, 이제 가드가 순서를 본다(먼저 §9-53에서 빨갛게 확인했다).
- 내 실수 하나: 검사를 한 명령줄에 이어 붙여 `fmt` 실패가 **커밋을 막지 못했다.** 다음 커밋에서 `cargo fmt`로
  고쳤다 — 검사 결과를 읽은 뒤에 커밋한다.

#### 9-65.7 재발 방지 — 같은 날, 사용자가 *"시간이 지나면 또 많아질 텐데 대책이 있나"* 고 물었다

**답은 "절반"이었다.** STATUS와 HISTORY는 상한과 절차가 생겨 조용히 커질 수 없게 됐지만, 재 보니 빈틈이
넷이었다(Grok 교차 확인): 세션 시작 때 읽는 `docs/slices/README.md`에 크기 가드가 없었고(36.5 KB, 27일 동안
4.4 KB에서 하루 약 1.2 KB씩 — 닫힌 30행이 서사 26 KB를 품었다), `CLAUDE.md`에도 없었고(전역 규칙은 200줄),
HISTORY 색인이 차면 할 일이 적혀 있지 않았고, **세션 시작 문서의 합계는 무제한이었다**(Grok의 안 물어본 것 —
네 문서가 이미 110.7 KB). 재다가 하나 더 나왔다: *무엇을 먼저 읽는가*를 두 곳이 다르게 말했다 — STATUS §9
1단계는 네 문서, `CLAUDE.md`는 "지도의 순서대로"였고 문자 그대로면 16개 226 KB다.

사용자가 G·C·R과 합계 100 KB를 골랐고 설계를 승인했다(Grok plan: G · C · R, 그리고 S · R).

- **G** `the_session_start_documents_fit_in_one_read`: 목록을 STATUS §9 1단계 줄에서 **뽑는다**(손으로 적은
  목록이 슬라이스 색인을 빠뜨린 그 결함을 되풀이하지 않으려고) — 각각 45 KB, **합계 100 KB**, `CLAUDE.md`
  200줄. 처음엔 110,710 B로 빨갛고, 읽기 순서에 큰 문서를 심으면 다시 빨갛다. `CLAUDE.md`의 읽기 순서 문장은
  사용자가 승인한 대로 그 줄을 가리킨다.
- **C** 슬라이스 색인: 오래된 12행은 이미 한 줄이었고(133–361 B), 넘친 것은 최근 20행(502–2,422 B)이었다 —
  그 20행의 "무엇을 더했나" 칸만 한 줄로 접었고 제목·상태·PR 칸은 바이트 그대로다. 접기 전 절은
  `docs/history/slices-index.md`에 원문 그대로(`SPEC-` 링크 32개만 `../slices/`). 36.5 KB → 15.7 KB, 네 문서
  합계 110.7 → 약 90 KB. `every_slice_index_row_is_one_line`(행당 400 B)이 칸에 서사가 돌아오는 것을 첫 PR에서 막는다.
- **R** HISTORY 색인 굴리기: 지금 굴리지는 않았다(13.5 KB). 대신 인용 가드와 스텁 가드가 `index-NNN.md`를
  읽게 했고(번호는 페이지를 통틀어 한 번 — Grok이 짚은 위험), 스텁 사이 본문을 막았다. 임시로 굴려 초록을,
  중복·링크 누락·스텁 사이 본문을 심어 각각 의도한 메시지로 빨강을 확인했다.
- Grok의 안 물어본 것 가운데 둘은 코드로 재확인해 **결함이 아니었다**(읽기 창 밖의 호출부) — 경계로 둔다.

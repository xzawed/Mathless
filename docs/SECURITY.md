# SECURITY

## 보호 대상

배포된 **스크립트/알고리즘 구현**이 외부에서 쉽게 읽히지 않게 하는 것.  
소스 유출과 손쉬운 디컴파일·재현을 어렵게 만든다.

대상이 아닌 것(1차):

- 브라우저 XSS 모델
- 완전한 샌드박스 OS
- “리버싱 불가능”

## 위협 (우선)

1. 배포물에서 소스에 가까운 형태로 로직 복원
2. 심볼/문자열로 알고리즘 파악
3. 모듈 변조 후 재로드
4. 호스트가 의도하지 않은 API 호출 (과도한 노출)

## 단계

### P0 — MVP

- 소스 미배포
- 심볼 strip
- 최소 export만 남김
- ABI 버전 검사

**P0 실측 프록시 (2026-08-29, 수용 C).** 아래는 **프록시 수치일 뿐**이며 "리버싱 난이도"로
환산하지 않는다(D05, 규칙 6). 측정 대상은 `discount.dll`:

| 프록시 | 값 |
|--------|-----|
| export 심볼 집합 | **정확히 2개** — `mlx_discount` + `ml_module_abi_version`. 자체 PE 리더로 파싱하고, **`dumpbin /exports`와 교차 확인**(2026-08-29) — 더 이상 우리 구현 하나에만 의존하지 않는다 |
| 산출물 크기 | **9,728 B** (`no_std`+strip+lto+opt-z; std 기본 빌드 ~107,008 B 대비 ~11×↓) |
| 산출물 내 소스 | 없음 — 소스 코멘트·원본 파일명 비유출 |
| ABI 버전 심볼 | 모듈이 `ml_module_abi_version`을 export하고, 오라클이 이를 조회해 컴파일러 상수와 **일치함을 assert**(모든 오라클 테스트). ⚠ **major 불일치 시 로드 거부는 아직 미구현** — `Module::load`는 `LoadLibraryW`만 하고 버전 게이트가 없다. 거부는 D18/HOST_ABI가 호스트에 요구하는 **계약**이지 측정된 동작이 아니다. |

미구현: 무결성/서명(P1), 난독화(P2), 호스트 함수 화이트리스트(P1), **ABI major 불일치 로드 거부**(현재는 assert만).

### P1

- 모듈 무결성 해시/서명 검증
- 개발/배포 빌드 분리
- 호스트 함수 화이트리스트(명시적 등록만)

### P2

- 난독화, 제어흐름 변환
- 암호화 로딩
- 필요 시 상용 보호 도구 연동

P2를 언어 핵심에 처음부터 넣지 않는다.

## 보안과 DX

개발 중에는 디버그가 되어야 한다.  
배포물에 강한 보호를 걸수록 현장 진단은 로그·버전·제한된 텔레메트리로 대체한다.

## 능력 모델

이전 대화의 capability 아이디어는 유효하다.  
네이티브 모듈이라도 호스트가 등록한 함수만 보이게 하면 된다.

MVP: 언어에 파일/네트워크 표준 API를 넣지 않는다.  
필요하면 호스트가 준다.

## 대외 표현

사용: “분석과 변조 비용을 높인다.”  
사용 금지: “리버싱이 불가능하다.”

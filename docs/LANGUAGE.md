# LANGUAGE

## 이중 계층

| 계층 | 목표 |
|------|------|
| Surface | 폭넓은 개발자가 읽고 쓰기 쉬운 문법. Delphi `begin/end` 강요 안 함 |
| Meaning | 강한 정적 타입, 예측 가능한 실행, 네이티브로 내리기 쉬운 의미 |

표면은 마케팅/유입, 의미는 성능/보호/호스트 연동을 지탱한다.

## 표면 문법 (방향만 확정, 세부는 미정)

확정:

- Delphi 고유 문법을 그대로 쓰지 않음
- 타입을 숨기지 않음 (점진적 타입 포기 금지. 추론은 가능)
- AI가 생성하기 쉽도록 문법이 일관적이어야 함

검토한 후보 (계열은 D15로 확정 = 1번, 세부 문법만 미정):

1. C# / Java 계열 (중괄호, class, 익숙한 키워드)
2. TypeScript 계열 (더 넓은 웹/AI 훈련 데이터)
3. 간결 독자 문법 (진입은 신선, 학습 자료·AI 품질은 불리할 수 있음)

확정 방향(D15, 2026-08-28): **중괄호 기반·정적·값타입 우선의 C 계열 표면.** MVP 부분집합은 struct + 자유 함수 + 모듈이며, 아래 예시(`export fn … -> f64`)에 가깝다.  
"C#-like"는 개발자층·친숙도를 가리키는 **좁은 라벨**일 뿐, class 상속·GC·제네릭·async를 약속하지 않는다(전부 MVP 밖, `Q7`).  
이유: 값 타입/모듈이 네이티브 lowering에 직결, 넓은 친숙도와 AI 데이터, TS의 구조적 타이핑·웹 정체성 회피.

## MVP 언어 범위 (제안 — **목표**, 오늘 컴파일되는 것과 다름)

> 아래 두 목록은 MVP의 **목표 범위(제안)** 이다. **지금 실제로 컴파일되는 표면**은 다음 절
> "현재 구현된 표면"을 본다. 최신 실측의 정본은 `docs/STATUS.md`.

포함:

- 정수/실수/불리언/문자열
- 함수, 지역 변수, 상수
- if / while / for
- struct/record 수준 복합 타입
- null 안전 또는 option (둘 중 하나만)
- 모듈 단위 export/import (호스트 함수 import, 모듈 함수 export)
- 명시적 에러 처리 (예외 또는 Result. MVP는 하나만)

제외 (MVP 밖):

- 제네릭
- 본격 클래스 상속 체계 (필요 시 단순 struct + 함수부터)
- async/await
- 매크로, eval
- 동적 타입, Any 남용
- 리플렉션으로 임의 호스트 멤버 탐색

복잡한 로직·상태는 **구조체 + 함수 + 모듈 전역/컨텍스트 객체**로도 MVP에서 가능하다.

## 현재 구현된 표면 (2026-09-01 실측, E2)

실측 기준(테스트 수는 `docs/STATUS.md`가 정본). **이 목록에 없는 것은 아직 컴파일되지 않는다.**

구현됨:

- 타입: `f64`, `bool`, `i32`, `string`(**파라미터 위치 전용** — 아래)
- `export fn NAME(params) -> T { … }` — 자유 함수, 모듈 export
- **`out` 파라미터** `export fn f(a: f64, out t: i32) -> f64` — 값을 여러 개 돌려주는 수단.
  C로는 `int32_t* t`, Delphi로는 `out t: Integer`. **쓰기 전용**이고 **정상 반환 경로마다 대입이
  강제**된다. `export fn`에만 붙는다(SPEC-out-params)
- **`fn NAME(params) -> T { … }`** — `export` 없는 **내부 함수**. 호출식 `NAME(args)`로 부른다.
  export되지 않으므로 export 심볼 집합이 늘지 않는다(실측). **재귀는 금지**(직접·상호) — 스택
  오버플로가 호스트 프로세스를 죽이기 때문이며, `while`의 비종료와 달리 정적으로 판정 가능하다
- **실패 가능 함수 호출** `let x = try f(a)` · `x = try f(a)` · `return try f(a)` — 피호출자가
  실패하면 **호출자가 그 자리에서 즉시 반환**하며 status는 피호출자의 코드 **그대로**다.
  **호출자도 `-> T!`여야 한다**(status 채널이 필요하다). `try`는 **문장 형태**이므로 식 안에
  들어갈 수 없다(`1 + try f(x)`·`f(try g(x))`·`if try f(x)`는 파서가 거부). v1의 피호출자는
  **내부 `fn`만**이고, `out` 파라미터가 있거나 `-> string!`인 함수는 아직 부를 수 없다.
  **C ABI는 바뀌지 않는다** — 생성 헤더는 평범한 D17 실패 가능 export 그대로다(SPEC-fallible-calls)
- **에러 코드는 값도 유일해야 한다** — `error A = 1` + `error B = 1`은 거부된다. 헤더가 `#define`
  둘을 같은 값으로 방출하면 호스트의 `if`-체인이 언제나 첫 번째를 택해, 서로 다른 두 실패가
  호스트에서 하나로 붕괴한다. 전파가 생기면서 코드가 함수 경계를 넘게 되어 실제로 문다(DP-F9)
- **생성 헤더가 함수별로 낼 수 있는 코드를 적는다** — `/* may fail with: ML_ERR_… */`.
  `#define`은 모듈 스코프라 어느 함수가 어느 코드를 내는지 알 수 없었다(DP-F10). 주석뿐이고
  시그니처는 바뀌지 않는다
- **실패 가능 함수**: `-> T!` 표식 + `error NAME = N` 선언 + `fail NAME` 문
  (D17 lowering = i32 status 반환 + out-param, 실패 시 out 미변경).
  **내부 `fn`도 `-> T!`가 될 수 있다**(#97이 #67의 금지를 해제했다) — 다만 `try`로만 부를 수 있고,
  내부에서는 C ABI가 아니라 `Result<T, i32>`로 내려간다. `export fn`의 lowering은 D17 그대로다
- `if cond { … }` — **`else` 없음**
- `while cond { … }` — 반복. `break`/`continue`는 아직 없다(함수 탈출은 `return`)
- **단항 연산자** `-e`(f64/i32) · `!e`(bool). `-`의 오버플로는 wrap — `-i32::MIN == i32::MIN`(측정)
- **논리 연산자** `a && b` · `a || b` — 양쪽 `bool`, 결과 `bool`. `&&`가 `||`보다 강하게 결합하고
  둘 다 비교보다 느슨하다. **단락 평가로 명세**했으나 오늘은 관측 수단이 없어 미측정
- `return expr`
- **지역 변수** `let NAME = EXPR` — 블록 스코프, 타입 추론, 기본 **불변**
- **가변 지역 변수** `let mut NAME = EXPR` + **대입문** `NAME = EXPR` — 대입 대상은 `let mut` 지역만
  (파라미터·불변 `let` 거부). 대입은 **문**이지 식이 아니다(`a = b = c` 불가)
- 식: 리터럴, 파라미터·지역 변수 참조, `+ - * / %`, 비교. **`i32`의 `/`·`%`는 전역(total)**이다 —
  `x / 0`·`x % 0`은 `0`, `i32::MIN / -1`은 wrap(전부 측정). `%`는 i32 전용. 리터럴 `/ 0`은 컴파일 에러
- **이름 제약**: 파라미터·지역 변수·내부 함수 이름은 `ml_`·`mlx_`·`__`로 시작할 수 없다.
  컴파일러가 같은 범위에 생성하는 식별자와 겹치기 때문이다(겹치면 조용히 가려진다). `_x`처럼
  밑줄 하나로 시작하는 이름은 그대로 쓸 수 있다
- **문자열 입력** `export fn f(code: string) -> f64` — **파라미터 위치에만** 쓸 수 있다.
  반환·지역 변수·`out`은 거부한다(그 문자열이 어디 사는지를 여는 질문이고, Q12 프로토콜을 쓴다).
  ABI는 **NUL 종료 `const char*`**(Delphi `PAnsiChar`), 호출 동안 **빌린다**(D16 (1)).
  연산은 **`==`·`!=` 뿐**이고 의미는 **NUL까지의 바이트 동등성**이다 — 대소문자를 구분하고
  정규화하지 않으며 인코딩을 해석하지 않는다(DP-S2, 호스트와 소스가 같은 인코딩을 쓰는 것은
  호스트 계약). 비교는 **CRT를 부르지 않는다** — import 집합이 문자열 없는 모듈과 동일함을 측정했다
- **문자열 반환** `export fn f(code: string) -> string!` — **`!` 필수**(절단이 언제나 가능하므로
  항상 i32 status를 반환한다). 호스트가 버퍼와 용량을 주고 모듈이 채운다(Q12, 무할당).
  C는 `int32_t mlx_f(…, char* ml_buf, int32_t ml_cap, int32_t* ml_needed)`, Delphi는 `ml_buf: PByte`.
  `ml_cap`·`*ml_needed`는 **NUL 포함 총 바이트**이고, **절단은 성공이 아니라 실패**(음수 status)이며
  그때 버퍼는 **한 바이트도 쓰이지 않는다**. 길이를 모르면 `ml_cap = 0`(버퍼는 NULL 가능)으로
  한 번 물어보고 다시 부른다 — **항상 2회에 수렴한다**. **반환할 수 있는 것은 리터럴과 `string`
  파라미터뿐**이다(연결·포맷은 아직 없다). `export fn` 전용(SPEC-string-return)
- **문자열 리터럴** `"KR"` — **ASCII만**, **이스케이프 없음**(``가 들어오면 거부). 따라서 리터럴에
  `"`를 넣을 수 없다. 생성 산출물은 정적 NUL 종료 바이트 배열이며 할당이 없다(SPEC-string-input)
- **내장 함수** `floor(x)` · `ceil(x)` · `round(x)` · `trunc(x)` — `f64 -> f64`, **C의 `<math.h>`와
  정확히 같다**(0의 부호·NaN·inf 포함, 실제 C 호스트에서 대조). `round`는 0에서 먼 쪽 사사오입.
  **키워드가 아니라 내장 시그니처**라 `let round = 0` 같은 이름은 계속 쓸 수 있다. 동명 함수 선언은 거부
- **명시적 변환** `e as f64` / `e as i32`. 단항보다 **느슨하게**, `*`·`/`보다 **강하게** 결합한다
  (Rust·C#·Kotlin과 같다) — `-x as f64`는 `(-x) as f64`이고, 옛 의미는 `-(x as f64)`로 쓴다.
  암시적 혼합은 여전히 금지(DP-I2).
  `f64 as i32`는 **0 방향 절단 + 포화, NaN→0**(측정된 언어 규칙 — 대상 언어의 캐스트에 위임하지 않는다)

아직 아님 — **⏳ 미구현** (위 "포함" 목록 중). **언어 표면의 공백은 전부 이 블록에 있다**:

- 문자열의 **연결·포맷·길이·부분문자열·순서 비교**, 그리고 **지역 변수**(입력 파라미터·`==`/`!=`·
  `-> string!` 반환만 구현됨 — 반환값은 리터럴이나 파라미터 echo여야 한다)
- struct/record, 배열, null 안전 또는 option
- `for`, `else`, `break`/`continue`, 복합 대입, 비트 연산자
- 상수 선언, **호스트 함수 import**(현재는 모듈 export 단방향), 재귀, 실패 가능 함수 호출
- 복합 대입(`+= -= *=`) — `=`만 구현됨
- `f64` 나머지(`%`는 i32 전용 — SPEC-i32-division DP-D4), 체크드 오버플로, `bool` 변환

## 내부 의미 모델 (Delphi 방식의 의미)

“내부가 Delphi” = Delphi 컴파일러를 반드시 쓴다는 뜻이 아니다.

의미적으로 닮을 점:

- 강한 정적 타입
- 값 타입과 참조 타입 구분 가능성
- 숨은 동적 프로토타입 없음
- 컴파일 시점에 대부분의 계약 확정
- 호스트 호출은 명시적 import

닮지 않아도 되는 점:

- VCL
- unit/uses 그대로
- 문자열 내부 표현을 Delphi `UnicodeString`에 고정 (ABI에서 결정)

## 타입과 AI — ⏳ 계획, 미구현

> 아래는 **아직 만들지 않은 것**이다. 호스트 함수 import도, 인터페이스 파일도 존재하지 않는다
> (ROADMAP Phase 2). 현재 컴파일되는 것은 `docs/LANGUAGE.md`의 "현재 구현된 표면"뿐이다.

호스트 API를 기계가 읽는 인터페이스 파일로 공개하려 한다.  
예: `host.mls.d` / `host.abi.json` 같은 계약 파일.  
그러면 AI와 컴파일러가 같은 계약을 보게 된다.

## 예시 (세부 문법은 여전히 미확정 — 확장자·이름은 가칭)

아래는 **오늘 실제로 컴파일된다**(`mlc build`, 오라클 로드·호출로 E2 검증):

```text
export fn discount(price: f64, vip: bool) -> f64 {
  let rate = 0.9
  if vip { return price * rate }
  return price
}

error DIV_BY_ZERO = 1                       // i32 양수 도메인 에러

export fn safe_div(a: f64, b: f64) -> f64! {   // `!` = 실패 가능
  if b == 0.0 { fail DIV_BY_ZERO }
  return a / b
}
```

내부에서는 동일 시그니처의 네이티브 함수로 내려가고, 호스트는 C ABI로 호출한다.
실패 가능 함수는 D17대로 `int32_t mlx_safe_div(double a, double b, double* out_value)`로 내려간다
(성공=0 + out 기록, 실패=양수 코드 + out 미변경).

# OPEN QUESTIONS

구현 전에 닫아야 하는 것과, 미뤄도 되는 것을 나눈다.

## MVP 전에 닫을 것 — 닫힘 (2026-08-28 → DECISIONS D14~D18)

Q1~Q5는 사용자 승인으로 닫혔다. 세부·기각 대안은 `DECISIONS.md`의 "확정 상세" 참고.

### Q1. 주력 호스트 2개는 무엇인가? — 닫힘 → D14

Delphi(1급 데모) + C(ABI 기준). 후보였던 Delphi+C#은 Phase 4로 이연.

### Q2. 표면 문법 계열은? — 닫힘 → D15

중괄호·정적·값타입 우선 C 계열(MVP=struct+함수). "C#-like"는 좁은 라벨. 세부 문법은 계속 미정.

### Q3. 메모리 모델은? — 닫힘 → D16

소유권 3층 분리(인자=빌림 / 반환=caller-allocates / 상태=context handle), 힙 분리. 남은 하위였던 **Q12도 닫혔다**(2026-08-31, 아래).

### Q4. 에러 모델은? — 닫힘 → D17

ABI 정수 상태코드+out-param, 표면 Result는 sugar. 남은 하위 → Q13.

### Q5. 모듈 파일 포맷은? — 닫힘 → D18

표준 DLL/SO + 버전 export 심볼 + 모듈 전용 접두어. 커스텀 컨테이너는 P1. 남은 하위 → Q14.

- Q12. 반환 값 소유권 규약 — **닫힘(2026-08-31)**: 사용자 확정으로 **(a) caller-allocates out-buffer**.
  가변 길이 데이터는 **호스트가 버퍼와 용량을 주고, 모듈이 채우고, 필요한 길이를 돌려준다**.
  절단은 **D17의 음수 예약 status**로 보고한다 — "성공했는데 짧다"가 아니라 명시적 실패다.
  세부는 `DECISIONS.md` D16 파생 상세와 `HOST_ABI.md`의 "가변 길이 데이터" 절.
  - **먼저 갈라 냈다:** Q12는 두 질문을 묶고 있었다. **고정 레이아웃 struct(스칼라 필드만)는 힙이
    필요 없으므로 Q12 밖이다** — 호스트 스택의 `sizeof(T)`에 쓰는 것이고, 이미 있는 `out` 파라미터와
    같은 기계장치다. Q12가 묶는 것은 **가변 길이**(문자열·배열, 그리고 문자열을 품은 struct)뿐이다.
  - **기각 (b) 모듈 소유 + 명시 free:** 기술적으로는 된다 — `no_std`에서도 CRT의 `malloc`/`free`를
    직접 선언하면 의존성도 크기도 그대로 빌드된다(실측). 문제는 **누구의 힙인가**다. 모듈은 UCRT 힙을
    쓰고(실측: `api-ms-win-crt-heap` import가 하나 늘어난다), D16이 **"할당자 넘는 소유권 이전 금지"**를
    이미 규정했다. 결정적으로 **D14의 플래그십 호스트가 Delphi**이고 Delphi는 자기 메모리 매니저를
    쓴다 — 습관대로 `FreeMem`을 부르면 **조용히 힙이 손상된다.**
  - **기각 (c) 스칼라만 유지:** 제품이 아니라 오늘의 벽이다. 업무 규칙 두 번의 3라운드에서 배열이
    **네 번** 벽이었다(`STATUS.md` §3a-2·§3a-3).
  - **감수하는 대가:** 길이를 모르면 호스트가 한 번 더 부른다. 그리고 **호스트가 status를 무시하면
    꼬리가 조용히 잘린다** — 이 저장소가 네 번 닫은 그 모양이다. 그래서 절단을 성공이 아니라
    **음수 status**로 두는 것이 결정의 일부다.
- Q13. 에러 코드 체계 — **닫힘(2026-08-28)**: 사용자 확정으로 **평탄 i32**(`0`=OK / 양수=모듈 정의 도메인 에러 / 음수=예약 런타임·ABI). **D17 에러-경로 슬라이스로 구현·실측**(SPEC PR #14, 구현 PR #15; 오라클 로드로 status/out-param 검증). out-param 세부는 D17대로. **`DECISIONS.md` D17 확정 상세에 반영 완료**(규칙 8상 사용자 승인 후 별도 PR #30) — 이 항목은 더 이상 열려 있지 않다. 기각: HRESULT식(무겁·Windows 중심), 0/음수 무구조(의미 비트 부족).
- Q14. ABI 버전 배치(export 심볼 vs PE/ELF section)와 사용자 모듈 export 접두어 확정(`ml_`는 런타임 예약) — (D18 파생)
- Q15. **산출물의 라이선스 지위** — 저장소는 Apache-2.0/MIT 이중이지만(2026-08-29), `mlc`가 **생성하는**
  것들의 지위는 아직 정하지 않았다: 생성 Rust, `.h`/`.pas` 바인딩(문구가 `compiler/src/header.rs`의
  템플릿에서 나옴), 사용자 프로젝트에 복사되는 `runtime/ml_abi.h`. 템플릿에서 나온 텍스트가 파생저작물로
  간주되면 사용자 모듈에 라이선스 의무가 붙을 수 있다(GCC의 runtime library exception이 푸는 문제와 같은
  계열). "컴파일 산출물은 사용자의 것"이라는 명시적 예외를 둘지 결정 필요 — **소스 미배포로 알고리즘을
  보호한다**(D04)는 제품 약속과 직결된다. 법률 조언이 아니며, 문구 확정 전까지 대외 문서에 단정하지 않는다.

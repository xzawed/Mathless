# Slice SPEC — 논리 연산자 (`&&`, `||`)

> **상태:** 초안 — **사용자 확인 대기**. §4의 DP-B1~B4는 **제안**이다.
> 확인 전까지 구현 코드 착수 금지 (SDD 게이트). `DECISIONS.md`는 바꾸지 않는다.
> **근거 수준:** E0(문서 정합) + §1의 **E2 실측**. 새 측정값은 구현 후 E2.
> **선행:** 단항 `-`/`!`(#53) — `!a && b`가 자연스러우려면 `!`가 먼저 있어야 했다.
> 사용자는 **단항 → `&&`/`||` 순서로 둘 다** 진행하기로 결정(2026-08-29).

## 1. 목표 — 우회 수단이 아예 없는 유일한 부류

다른 빠진 구문들과 달리 **논리 연산자는 우회할 수 없다.** 실측(2026-08-29):

| 입력 | 현재 결과 |
|------|-----------|
| `return a && b` | **렉스 에러** — `unexpected character '&'` (토큰조차 없다) |
| `return a & b` | 동일 |
| `return a \|\| b` | `unexpected character '\|'` |

문(statement) 자리에서는 `if a { if b { … } }`로 중첩해 우회할 수 있다. 그러나 **`while` 조건에서는
불가능하다** — `while i < n && i < 5`를 쓰려면 플래그 변수를 도입해 루프 구조 자체를 바꿔야 한다.
`while`이 방금 들어왔으므로(#49) 이 구멍이 가장 아프다.

기준 함수:

```text
export fn count_bounded(n: i32, cap: i32) -> i32 {
  let mut i = 0
  while i < n && i < cap {
    i = i + 1
  }
  return i
}
```

## 2. 계약 (Contracts)

### 2.1 문법 — 비교보다 느슨한 두 층

```text
expr    := or
or      := and ('||' and)*
and     := compare ('&&' compare)*
compare := add (('<'|'>'|'<='|'>='|'=='|'!=') add)*
```

즉 `a > 0 && b > 0 || c` 는 `((a > 0 && b > 0) || c)`다. 단항 `!`는 여전히 가장 강하게 결합하므로
`!a && b` 는 `(!a) && b`다.

### 2.2 타입 규칙

- `&&`/`||` 의 **양쪽 피연산자는 `bool`이어야 하고 결과는 `bool`**이다.
- 숫자를 진리값으로 쓰지 않는다(`1 && true` → 에러). 현재 `if`/`while` 조건 규칙과 동일한 태도.

### 2.3 단락 평가(short-circuit) — **명세하되, 오늘은 측정할 수 없다**

`&&`/`||`는 **단락 평가**한다: 왼쪽이 결과를 결정하면 오른쪽을 평가하지 않는다.

**정직한 단서:** 지금 이 차이를 **관측할 방법이 없다.** 표면에 호출 식이 없어(AST에 호출 노드 0개,
실측) 부작용이 없고, `f64` 0 나눗셈은 트랩이 아니라 inf이며(실측), `i32` 나눗셈은 아직 없다. 따라서
이 슬라이스는 단락 평가를 **명세하고 그 lowering을 선택**하되, **"단락 평가를 측정했다"고 주장하지
않는다.** 관측 가능한 구문(호출, 실패 가능 연산)이 생기는 슬라이스에서 그때 측정한다.

명세하는 이유는 §4 DP-B2에 적는다.

### 2.4 IR · codegen

- `IrBinOp::{And, Or}`를 추가한다(기존 이항 연산자와 같은 노드).
- codegen은 Rust `&&`/`||`로 내린다 — Rust가 단락 평가를 보장하므로 §2.3의 명세와 lowering이 일치한다.
  (후속 C 백엔드도 C의 `&&`/`||`가 같은 성질을 가진다.)

### 2.5 ABI — **변화 없음**

식 수준 변경이다. export 집합·시그니처·헤더/유닛 텍스트는 그대로다.

## 3. 수용 기준 (측정 가능)

- **A. 컴파일:** `examples/count_bounded.mls` → `mlc build`.
- **B. 로드·호출(오라클):** `mlx_count_bounded(10, 3) == 3`(cap이 먼저 막음),
  `(3, 10) == 3`(n이 먼저 막음), `(0, 5) == 0`, `abi == 1`.
- **C. 보호:** export 2개, strip 유지.
- **D. 수용 D(실제 C 호스트):** `hosts/c-host/host.c`에 추가한다.
- **부정(타입체크) 케이스:**
  - `1 && true` / `a && 1` → 에러(양쪽 bool)
  - `x && y` (둘 다 f64) → 에러
  - `a && b` 결과를 i32에 반환 → 반환 타입 불일치
- **파싱 케이스:**
  - `a > 0 && b > 0 || c` → `((a>0 && b>0) || c)` 스냅샷
  - `!a && b` → `(!a) && b`
  - `a & b` / `a | b` → **"`&&`를 의도했나?"** 취지의 명확한 에러(DP-B3)

## 4. 설계 제안 (DP — 확인 대기)

| DP | 선택지 | 권장 | 근거 |
|----|--------|------|------|
| **B1 범위** | `&&`/`||`만 vs 비트 연산(`&`,`|`,`^`) 포함 | **논리 연산자만** | 비트 연산은 MVP 밖이고 정수 의미론(부호·시프트)을 함께 정해야 한다. 지금 필요한 것은 조건식이다 |
| **B2 단락 평가** | 명세한다 vs "순서 미지정" | **명세한다** | 오늘 관측 불가라는 게 "미지정으로 두라"는 뜻은 아니다. lowering이 Rust `&&`이므로 **구현은 이미 단락 평가한다** — 문서만 침묵하면 실제 동작과 문서가 어긋난다. 또한 나중에 호출·실패 가능 연산이 들어올 때 "미지정 → 단락"으로 바꾸면 그 사이에 쓰인 코드의 의미가 바뀐다. 대신 §2.3에서 **측정하지 않았음을 명시**한다 |
| **B3 단일 `&`/`|`** | 렉서가 토큰으로 배우기 vs 문자 에러 유지하되 **메시지만** 특화 | **메시지만 특화** | 쓰지도 않을 토큰을 문법에 들이지 않는다. `unexpected character '&'`는 이 슬라이스에서 가장 흔할 오타에 대한 나쁜 진단이므로, 렉서의 미지원 문자 경로에서 `&`·`|`만 골라 "`&&`/`||`를 의도했는가"로 답한다 |
| **B4 우선순위 층수** | 두 층(`&&` > `||`) vs 한 층(괄호 필수) | **두 층** | D15가 C 계열 표면이다. C/C++/Rust/C#/Java가 전부 `&&` > `||`이고, 한 층으로 두면 나중에 고칠 때 **의미가 바뀌는 파괴적 변경**이 된다. 비용은 문법 층 하나 |

## 5. 범위 밖 / 미검증

- 비트 연산자, `^`, 시프트, 숫자의 진리값 취급(truthiness).
- **단락 평가의 실측** — 관측 수단이 없다(§2.3). 호출 또는 실패 가능 연산 슬라이스에서 측정한다.
- `else`, `break`/`continue`, 복합 대입.
- 어떤 항목도 측정 전까지 "확정/동작"으로 서술하지 않는다.

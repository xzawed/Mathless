# Slice SPEC — 문자열 **반환** (Q12 프로토콜의 첫 사용자)

> **상태: 초안(draft) · 사용자 확인 대기** — 2026-08-31.
> **DP-T1~DP-T8은 미확정이다.** §4 표를 보고 확인해 주기 바란다. 특히 **DP-T2는 Q12가 이미 정한
> 표를 손대자는 제안**이므로 명시적 승인 없이 진행하지 않는다.
> **근거 수준:** §1이 **E2 실측**(오늘의 언어로 쓴 업무 규칙 6개 + 호스트 드리프트 실험),
> §2가 E0 + 확정 결정 인용, §4의 ABI 관용구 비교가 **E1**(외부 API 문서).
> **선행:** Q12 확정(#87) · 문자열 입력(#89) · `out` 파라미터(#80) · D17.

## 0. 먼저 읽을 것 — 이 슬라이스의 정당화는 처음 생각과 다르다

제가 이전 세션 말미에 적은 근거는 **"문자열 반환이 다음 벽"** 이었다. §7 방식으로 실제로 재 봤더니
**그 근거는 약하다.** 정직하게 옮긴다.

- 업무 규칙 6개를 오늘의 언어로 썼다. **4개는 i32 코드로 오늘 이미 된다**(측정 — 컴파일되고 옳은
  값을 낸다). 그중 하나(R4)는 우회가 아니라 **D17 그 자체**다.
- 정수 코드로 **환원 불가능한 것은 2개뿐**이다(R2 영수증 줄, R6 이름 결합).
- **그리고 이 슬라이스는 그 2개를 해결하지 않는다**(§2.4 — v1이 반환할 수 있는 것은 리터럴과
  입력 파라미터 echo뿐이다).

그러므로 **"측정된 수요"를 헤드라인 근거로 쓰지 않는다.** 진짜 근거는 두 개다.

### 0.1 근거 A — 코드 우회는 이 프로젝트의 핵심 약속을 갉아먹는다 (E2, 측정)

`ARCHITECTURE.md:68` — **"모듈 교체 = 파일 교체 + 재로드. 호스트 재빌드 없음."**

호스트를 **한 번만** 빌드하고 모듈만 바꿔 재봤다:

```
--- 호스트 1회 빌드, 모듈 v1 ---
UPSN -> code 1 -> "UPS Ground"
DHLE -> code 0 -> "Unassigned"
--- 같은 호스트 exe, 모듈 v2 (한 줄 추가: DHLE -> 4) ---
DHLE -> code 4 -> "<<< UNKNOWN CARRIER CODE - host is out of date >>>"
```

대조군(같은 고정 호스트, 임계값만 `30/15/6 → 22/12/4`로 조정):

```
--- v1 ---  density 25 -> 70 -> "CLASS 70"    density 13 -> 125
--- v2 ---  density 25 -> 50 -> "CLASS 50"    density 13 -> 70
```

**갈리는 것은 규칙별이 아니라 변경별이다:** *임계값* 변경은 모듈 교체로 나가고, **케이스 집합의
확장은 호스트 재빌드를 요구한다.** 코드 우회는 규칙의 **어휘**를 보호된 모듈 밖으로 옮기고,
업무 규칙이 실제로 늘어나는 곳이 바로 그 어휘다.

> `SPEC-string-input.md` §1.2는 D17의 선례가 "텍스트를 호스트 쪽에 둔다"고 했다. **문구에 대해서는
> 참이고, 케이스 집합에 대해서는 거짓이다.** 그 구분을 그 SPEC은 긋지 않았다. 여기서 긋는다.

### 0.2 근거 B — Q12 프로토콜의 결함을 **가장 싸게** 찾는 자리다

`SPEC-string-input.md` §1.3의 논리 그대로다. 프로토콜을 처음 쓰는 슬라이스는 문자열 아니면 배열인데,
배열에는 **원소 타입 이야기가 더 얹힌다.** 결함이 있다면 여기서 찾는 편이 싸다.

**이 근거를 채택하면 수용 기준의 무게중심이 바뀐다:** 값이 맞는지보다 **프로토콜의 경계**(절단·probe·
빈 문자열·NULL·용량 0)를 재는 쪽이 중요하다. §3이 그렇게 짜여 있다.

### 0.3 정직한 반론 (기록)

**배열이 근거 A에서 같거나 더 높은 점수를 받을 수 있다** — `STATUS.md` §3b가 배열을 네 번의 벽으로
기록한다. 그럼에도 문자열을 먼저 두는 이유는 근거 B(더 싸다)뿐이며, 근거 A는 둘 다에 해당한다.
**이 슬라이스를 미루고 배열로 가는 것은 합리적인 선택지다**(§4의 DP-T0).

## 1. 목표

호스트가 준 버퍼에 모듈이 문자열을 **써서** 돌려준다. 모듈은 **할당하지 않는다**(Q12/D16).

```mathless
error E_UNKNOWN_SCAC = 1

export fn carrier_name(scac: string) -> string! {
  if scac == "UPSN" { return "UPS Ground" }
  if scac == "FDEG" { return "FedEx Ground" }
  if scac == "ZZZZ" { return scac }        // 입력 echo도 합법
  fail E_UNKNOWN_SCAC
}
```

```c
int32_t mlx_carrier_name(const char* scac, char* ml_buf, int32_t ml_cap, int32_t* ml_needed);
```

## 2. 계약 (Contracts)

### 2.1 ABI — **Q12가 이미 확정했다. 새로 정하는 것이 아니다**

`HOST_ABI.md`의 "가변 길이 데이터" 절이 정본이다:

```c
int32_t mlx_name(int32_t id, char* buf, int32_t cap, int32_t* needed);
```

| status | 뜻 | `buf` | `*needed` |
|---|---|---|---|
| `0` | 성공 | 채워짐(NUL 종료) | 쓴 길이 |
| **음수** | **용량 부족 = 절단** | **건드리지 않음** | 필요한 길이 |
| 양수 | 모듈 정의 도메인 에러(D17) | 건드리지 않음 | 건드리지 않음 |

**이 슬라이스가 여기에 더하는 것은 넷이다:** 단위(§2.2) · 표면 문법(§2.3) · 반환 가능한 값(§2.4) ·
NULL 예외(§2.6). **DP-T2는 위 표의 "건드리지 않음"을 바꾸자는 제안이므로 별도 승인 대상이다.**

### 2.2 단위 — `cap`과 `*needed`는 **NUL을 포함한 총 바이트**다 (DP-T4)

**모든 결과에서 같은 단위다.** 그래서 재시도가 `malloc(n)` + `cap = n`으로 정확히 맞고,
2회 호출이 **항상 2회에 수렴한다.** `+1`도, 두 배씩 늘리는 루프도 없다.

- 빈 문자열은 `*needed == 1`이다(NUL 한 바이트). `*needed == 0`은 성공·절단 어느 쪽에서도 나올 수 없다.
- 근거(E1): `GetEnvironmentVariableA`가 성공과 실패에서 **단위를 바꾸는** 것이 이 부류의 고전적 결함이다.

### 2.3 표면 문법 — **`-> string!` 만** (DP-T1)

- 문자열을 반환하는 함수는 **반드시 `!`** 를 단다. 절단이 모든 호출에서 가능하므로 **언제나 i32
  status를 반환**하고, `!`는 "status를 확인해야 한다"는 표면의 유일한 표식이다.
  **`!` ⟺ C에서 `int32_t` 반환**이라는 규칙이 갈라지지 않는다.
- 맨 `-> string`은 **계속 거부**하되, 메시지가 `-> string!`을 가리킨다.
- **`export fn` 전용**이다(내부 `fn`은 `-> T!`와 같은 이유로 거부 — DP-O5).
- 선언된 스칼라 `out`과 공존한다. **DP-O1이 그대로 산다:** 선언된 out이 순서대로, **반환값이 마지막**.
  반환값이 슬롯 1개에서 3개로 넓어질 뿐이다.

```c
int32_t mlx_carrier_label(const char* scac, int32_t* tier,
                          char* ml_buf, int32_t ml_cap, int32_t* ml_needed);
```

### 2.4 v1이 반환할 수 있는 값 — **리터럴과 입력 파라미터뿐** (DP-T5)

- 문자열 **리터럴**(`"UPS Ground"`) 또는 **`string` 파라미터 그대로**(`return scac`).
- **연결·포맷·부분문자열·길이는 범위 밖.** 따라서 §0의 R2·R6은 **여전히 컴파일되지 않는다.**
- 이 제한이 지키는 것: 반환되는 모든 바이트가 **ASCII 소스 리터럴**이거나 **호스트가 직접 넘긴
  바이트**다. 그래서 **DP-S2("불투명 바이트")가 문자 그대로 참으로 남는다.**
  모듈이 바이트를 *만들기* 시작하는 순간 DP-S2는 다시 열린다(§5.2).

### 2.5 절단은 실패다 (Q12 확정)

`*needed > cap`이면 **음수 status**다. `cap == *needed`(딱 맞음)는 **성공**이다.
모듈은 **쓰기 전에 길이를 먼저 센다** — 소스 바이트를 두 번 훑는다(count → copy). 할당자가 없으므로
임시 버퍼는 쓸 수 없고, "절단이면 한 바이트도 쓰지 않는다"를 지키려면 2패스가 강제된다.

### 2.6 NULL — **`cap == 0`일 때만 예외** (DP-T7)

**정확히 말하면 문자 그대로의 모순은 아니다.** `HOST_ABI.md`의 "NULL을 넘기지 마라"는 두 곳에만
있다 — `:78`(스칼라 out-param 계약)과 `:98`(문자열 **입력** 계약). **Q12의 `buf` 행에는 없다.**
그러나 `buf`는 out-param이므로 `:78`이 자연스럽게 확장되고, 같은 문서가 **probe 관용구**
("`cap = 0`으로 한 번 불러 `*needed`를 받는다")를 규정한다 — 그 호출에는 호스트에 버퍼가 없다.
**즉 규정된 관용구와 확장된 금지가 부딪친다.**

호스트가 `cap = 0`에 **NULL이 아닌 더미 포인터**를 넘겨 양쪽을 다 만족시킬 수도 있다. 그래서
이것은 "모순 해소"가 아니라 **둘 중 하나를 고르는 일**이고, SPEC이 골라야 한다.

**고른다: `buf`는 `cap == 0`일 때에 한해 NULL일 수 있다. 그 밖의 NULL은 정의되지 않은 동작이다.**
근거는 두 가지다 — (1) `snprintf(NULL, 0, …)`과 MSVC가 문서화한 `count == 0` probe가 같은 형태다(E1),
(2) 더미 포인터를 요구하면 Delphi 호스트가 **쓰지도 않을 배열을 발명**하게 된다. `needed`는 **절대
NULL일 수 없다**(probe의 전부가 그것이므로 예외 없음). DP-O6/DP-S5의 진짜 예외이니 예외로 적고,
**§3-B3에서 실제로 NULL을 넘겨 실행해 확인한다** — 기억된 계약이 아니라 측정된 계약으로 만든다.

### 2.7 `cap`이 음수면 `0`으로 본다

절단으로 보고하고 아무것도 쓰지 않는다. **부호 없는 거대한 값으로 해석하지 않는다** — MSVC가
`_snprintf(count < 0)`에서 정확히 그 오버런을 문서화한다(E1).

## 3. 수용 기준 (측정 가능) — 무게중심은 **프로토콜의 경계**다

- **A. 컴파일:** `examples/carrier.mls` → `mlc build`.
- **B. 값(오라클):** `carrier_name("UPSN", buf, 64, &n)` → status `0`, `buf == "UPS Ground"`, `n == 11`.
- **B2. 절단:** `cap = 4` → 음수 status, `n == 11`, **버퍼의 모든 바이트가 canary 그대로.**
- **B3. probe 2회 호출:** `(NULL, 0, &n)` → 음수 status, `n == 11`, 크래시 없음 →
  `malloc(11)` + `cap = 11` → status `0`. **정확히 2회에 수렴함을 측정.**
- **B4. 딱 맞음:** `cap == 11` → **성공**(절단 아님). `cap == 10` → 절단.
- **B5. 빈 문자열:** `""`를 반환하는 규칙에서 `cap = 1` → status `0`, `buf[0] == 0`, `n == 1`.
  `cap = 0` → 절단, `n == 1`.
- **B6. 도메인 에러:** `fail` 경로 → 양수 status, `buf` canary 그대로, `*needed` canary 그대로(H13).
- **B7. canary 버퍼(이 슬라이스의 핵심 도구):** 0xAA로 채운 버퍼 + `cap` 뒤에 canary.
  **B2·B4·B6·D를 한 번의 바이트 비교로 잡는다.** `SPEC-D17-error-abi.md` §3-B의 SENTINEL과 같은 역할.
- **C. 보호:** export 집합 불변. **import 집합은 문자열 없는 대조 모듈과 비교해 측정**하고 결과를
  **기록한다** — 바이트 복사는 rustc가 `memcpy`로 낮추고 그것은 이미 baseline에 있다(#89의 교훈).
  "새 import 없음"을 절대 주장으로 쓰지 않는다.
- **D. 수용 D(실제 C 호스트):** B·B2·B3·B5·B6을 `hosts/c-host/host.c`에. `_Static_assert`/`_Generic`로
  3연 슬롯의 타입을 컴파일 타임에 고정.
- **E. 부정 케이스:** 맨 `-> string` · 내부 `fn -> string!` · `return "a" + "b"` · `let s = …` ·
  `out s: string` · `cap`/`needed`/`buf` 이름 충돌.
- **F. 바인딩:** `.h`가 `char*`+`int32_t`+`int32_t*`, `.pas`가 DP-T3의 형태 + **출력 방향 경고**.
- **G. 행 아님:** `cap = -1` 호출이 **끝난다**(패닉은 `ml_panic`의 `loop {}`에서 스레드를 매단다 —
  §5-4). 타임아웃 있는 테스트로 잰다.

## 4. 설계 제안 (DP — **미확정, 사용자 확인 필요**)

### DP-T0. 그래서 이 슬라이스를 지금 하는가

| 선택지 | 장점 | 단점 |
|---|---|---|
| **(a) 지금 한다 (권고)** | 근거 A(드리프트)가 **측정됐다**. 근거 B대로 Q12 결함을 가장 싸게 찾는다. 배열보다 작다 | 측정된 수요는 2/6이고, **그 2개조차 v1이 해결하지 못한다** |
| (b) 배열을 먼저 | 실측 벽이 네 번으로 가장 많다. 근거 A도 똑같이 적용된다 | 원소 타입 + Q12 프로토콜을 **동시에** 연다. 결함이 있으면 더 비싸게 찾는다 |
| (c) 둘 다 미루고 표현력(연결·포맷)을 먼저 | R2·R6을 **실제로** 해결하는 유일한 길 | 반환 프로토콜 없이는 만든 바이트를 **내보낼 수단이 없다.** 순서상 불가능 |

### DP-T1~T8

| DP | 선택지 | 권고 | 근거 |
|----|--------|------|------|
| **T1 표면 문법** | **`-> string!`(필수 `!`)** / 저자가 직접 `out s: string, cap: i32` | **`-> string!`** | 세 독립 제안이 모두 여기로 수렴했다. `!` ⟺ `int32_t` 반환이 갈라지지 않고, DP-O1의 한 문장("반환값이 마지막")이 그대로 산다. 저자가 3연을 직접 쓰면 순서·단위를 매번 틀릴 수 있다 |
| **T2 실패 시 버퍼** ⚠ | **Q12 그대로(건드리지 않음)** / **`buf[0]='\0'` 안전장치**(Annex K) | **판단 보류 — 사용자 결정** | 안전장치는 status를 무시한 호스트가 **자기 스택 쓰레기 대신 빈 문자열**을 읽게 한다(H9·H2 방어). 그러나 **Q12가 이미 정한 표를 바꾸는 것**이고, `cap>=1` 확인 후 역참조하므로 §2.6의 NULL 예외와 맞물린다. 규칙 8에 따라 승인 없이 바꾸지 않는다 |
| **T3 Delphi 버퍼 타입** | `ml_buf: PAnsiChar`(값) / **`ml_buf: PByte`** | **`PByte`** | `PByte`면 `PAnsiChar(S)`(UnicodeString) 오전달과 `PAnsiChar(Pointer(S))`가 **컴파일 에러(E2010)** 가 된다 — #89가 주석으로만 막던 함정이 **소리를 낸다**. 대가: `.h`와 `.pas`의 철자가 벌어진다. **`out ml_buf:`는 절대 금지** — 그건 `PAnsiChar*`라 모듈이 호스트의 포인터 변수를 덮어쓴다(H11) |
| **T3b `.pas`에 실행 코드** | 넣는다(생성 `AnsiString` 래퍼) / **주석만** | **주석만** | 래퍼는 편하지만 **`dcc64`가 없어 한 줄도 컴파일된 적이 없다.** 문법 오류면 모든 Delphi 빌드를 막고, 논리 오류면 **주석보다 나쁘다**(호스트가 믿는다). 검증 수단이 생기면 그때 넣는다 |
| **T4 `cap`/`needed` 단위** | payload / **NUL 포함 총 바이트** | **NUL 포함** | 모든 결과에서 같은 단위 → 재시도가 정확하고 2회에 수렴. `GetEnvironmentVariableA`의 단위 전환이 이 부류의 고전적 결함(E1) |
| **T5 반환 가능한 값** | 리터럴+파라미터 echo / 연결·포맷 포함 | **리터럴+echo** | DP-S2가 문자 그대로 참으로 남는다. 연결·포맷은 §0의 R2·R6을 여는 **별도 슬라이스**이며, 프로토콜과 표현력을 한 슬라이스에 겹치지 않는다 |
| **T6 절단 상수** | `ML_ERR_TRUNCATED = -1` / **`ML_ST_INSUFFICIENT_BUFFER = -122`** | **`ML_ST_` + `-1`** | 이름은 `ML_ERR_` 밖에 둔다(Q14의 모듈 접두어 충돌을 **깊게 하지 않는다**). 값은 `-1`을 권한다 — `-122`는 Windows 냄새가 나고 이 ABI는 `GetLastError`를 부르지 않는다. `#ifndef` 가드로 두 모듈 헤더 공존 |
| **T7 NULL** | 전면 금지 / **`cap == 0`일 때만 허용** | **`cap == 0`일 때만** | probe 관용구가 그 호출을 **규정하므로**, 금지하면 문서가 스스로 모순된다(H9). 예외를 예외로 적고 **§3-B3로 실행해서 확인**한다 |
| **T8 도메인 에러 시 `*needed`** | **Q12 그대로(건드리지 않음)** / `0` | **그대로 + canary 테스트** | `0`으로 쓰면 "빈 문자열"과 구분이 안 된다(H13). 건드리지 않는 편이 낫고, 대신 호스트가 0으로 초기화하고 읽는 실수를 **테스트로 못박는다** |

## 5. 범위 밖 / 위험

### 5.1 R2·R6은 이 슬라이스가 해결하지 않는다

§0.1의 정직한 결론이다. **연결(`a + b`)·숫자 포맷은 후속 슬라이스**다. 이 슬라이스는
**프로토콜을 사고, 표현력은 사지 않는다.** SPEC 본문에서 반대로 읽히지 않게 §2.4에 못박았다.

### 5.2 DP-S2("불투명 바이트")는 **유예됐지 닫히지 않았다**

`SPEC-string-input.md`는 "모듈은 비교만 하므로 바이트가 같으면 같다"로 DP-S2를 정당화했다.
모듈이 바이트를 **만들기** 시작하면 그 정당화가 사라진다. v1이 살아남는 이유는 §2.4의 제한뿐이다.
**재개 트리거는 대소문자 무시 비교가 아니라 첫 연결·첫 포맷이다** — 그 SPEC의 예상보다 가깝다.

### 5.3 모듈이 막을 수 없는 것 (호스트 계약)

- **버퍼와 맞지 않는 `cap`**(`char buf[8]`에 `cap = 64`). 모듈에서 보이지 않는다.
  `sizeof(buf)` 매크로를 헤더에 **넣지 않는다** — 배열엔 맞고 **포인터엔 조용히 8을 준다**(같은 부류의 함정).
- **`buf`가 `string` 인자와 겹치는 것**(aliasing). 전방 복사라 덮어쓴 바이트를 읽을 수 있다.
- **Delphi `SetLength(A, needed)`** 는 모듈의 NUL을 AnsiString 안에 남긴다 → `Length(A)`가 1 크고
  이후 비교가 조용히 false. **E1이고 `dcc64` 없이 확인 불가**(H12).

### 5.4 갚지 않는 부채

- **H4 스칼라 절반**: 선언된 `out t: i32`를 `fail` 앞에서 쓰면 그대로 남는다 — #90이 **측정하고
  문서화**했으나 컴파일 타임에 막지는 않았다(DP-O3가 그렇게 정했다). 이 슬라이스는 갚지 않는다.
  문자열 채널에는 이 결함이 **구조적으로 생길 수 없다**(쓰는 자리가 `return` 하나뿐이다).
- **Q14**(모듈 접두어 없는 `ML_ERR_*`): `ML_ST_`는 그 이름공간을 피할 뿐 풀지 않는다.
- **`&&` 단락 평가**(§5-1): 문자열 반환에도 관측 수단이 없다.

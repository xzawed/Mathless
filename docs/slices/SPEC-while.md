> **선행:** `let mut` + 대입(PR #39) — 루프 본문이 할 일이 생겼다. 설계 교차검토: Grok.

## 1. 목표

**`while cond { … }`** 을 추가한다. `let mut`가 먹여 살리려던 바로 그 구문이다 — 가변 지역 변수와
대입은 있지만 반복이 없어 지금은 누산기를 돌릴 수 없다.

기준 함수(현재 언어로만 작성 — 복합 대입·`!`·`&&` 없이):

```text
export fn sum_to(n: i32) -> i32 {
  let mut total = 0
  let mut i = 1
  while i <= n {
    total = total + i
    i = i + 1
  }
  return total
}
```

`sum_to(10) = 55`, `sum_to(0) = 0`(조건이 처음부터 거짓 → 본문 0회).

## 2. 계약 (Contracts)

### 2.1 표면 `.mls`

- **`while EXPR { STMT* }`** — 새 키워드 `while`. 문법은 `if`와 동일한 모양(조건에 괄호 없음, 본문은 블록).
- 조건은 **`bool`이어야 한다**(`if`와 같은 규칙). `while 1 { }`은 타입 에러.
- 본문은 블록이며 **블록 스코프**를 따른다(`let`/`let mut`의 기존 규칙 그대로). 본문에서 **바깥
  `let mut`에 대입**할 수 있고, 그것이 이 슬라이스의 요점이다.
- 본문 안의 `return`/`fail`은 지금도 그렇듯 **함수를 빠져나간다**. 루프만 빠져나오는 수단은 없다(DP-W1).

### 2.2 타입체크 · IR

- `IrStmt::While { cond, body }`. 조건 타입은 `bool`로 강제.
- **`while`은 종결 문이 아니다**(DP-W3): 0회 실행될 수 있으므로 `block_always_returns`는 `while`로
  끝나는 블록을 거부한다 — `else` 없는 `if`와 동일한 취급.

### 2.3 codegen

- Rust `while <cond> { … }`로 그대로 내려간다. 생성 크레이트는 이미 `no_std` + `panic = "abort"`다.

### 2.4 ABI — **변화 없음**

지역 변수·제어 흐름은 내부 사항이다. export 집합, 시그니처, D17 status/out-param 규약, 헤더/유닛
텍스트는 **바뀌지 않는다**. 수용 C의 프록시(export 2개)도 그대로여야 한다.

## 3. 수용 기준 (측정 가능)

- **A. 컴파일:** `examples/sum_to.mls` → `mlc build` → `sum_to.dll`.
- **B. 로드·호출 (오라클):** `mlx_sum_to(10) == 55`, `mlx_sum_to(0) == 0`(본문 0회), `abi == 1`.
- **C. 보호:** export = 정확히 `mlx_sum_to` + `ml_module_abi_version`. strip 유지.
- **D. 수용 D(실제 C 호스트):** `hosts/c-host/host.c`에 `sum_to`를 추가해 **새 구문도 실제 C 호스트에서**
  호출되게 한다. (수용 D는 이제 닫혀 있으므로, 새 구문이 그 커버리지 밖으로 새지 않게 유지한다.)
- **부정(타입체크) 케이스:**
  - `while 1 { }` → 조건이 bool 아님 (에러)
  - `export fn f() -> i32 { let mut x = 0 while x < 1 { x = 1 } }` → "모든 경로 return" 거부
    (`while`은 종결이 아님)
  - `return while x { }` → 파싱 에러(`while`은 식이 아니다)
  - 본문에서 선언한 지역 변수는 밖으로 새지 않는다: `while b { let r = 1 } return r` → 미정의
  - 본문에서 바깥 `let mut`에 대입 가능(양성) · 불변 `let`/파라미터 대입은 기존대로 거부

## 4. 설계 제안 (DP — **확인됨 2026-08-29**; Grok 권장안 그대로 채택)

| DP | 선택지 | 권장 | 근거 |
|----|--------|------|------|
| **W1 범위** | `while`만 vs `break`/`continue` 포함 | **`while`만** | 누산기·카운터는 `let mut` + 대입으로 이미 가능하고, 함수 탈출은 `return`이 한다. `break`/`continue`는 타입체크에 루프 내 상태가 필요 → 별도 슬라이스 |
| **W2 `while true`** | 특수 처리(종결로 인정) vs 특수 처리 없음 | **특수 처리 없음** | 상수 폴딩 + "발산은 bottom 타입" 규칙이 필요해지고, `while 1 == 1`은 여전히 어긋난다. MVP에 넣을 함정 |
| **W3 종결 여부** | `while`을 종결로 인정 vs 인정 안 함 | **인정 안 함** | 0회 실행 가능. `else` 없는 `if`와 같은 취급 |
| **W4 본문 스코프** | 블록 스코프(기존 규칙) vs 별도 규칙 | **기존 블록 스코프 그대로** | `if`·`let`과 일관. 새 규칙을 만들 이유가 없다 |

## 5. 범위 밖 / 미검증

- `break` / `continue`, `for`, 복합 대입(`+= -=`), 단항 `!`, `&&`/`||`, `else`.
- 루프 불변식·종료 증명 같은 정적 분석.
- 어떤 항목도 측정 전까지 "확정/동작"으로 서술하지 않는다.

### 5.1 이 슬라이스가 **새로 들이는 위험**: 호스트 스레드 정지

**지금까지 Mathless 함수는 전부 반드시 종료했다.** 호출 문법이 없어 재귀가 불가능하고(파서에 호출
식이 없다), 반복 구문도 없었기 때문이다. 그래서 "export를 호출하면 언젠가 돌아온다"는 것을 지금까지는
모든 호스트가 **공짜로** 보장받았다 — Rust 오라클도, 새로 닫은 C 호스트도, 앞으로의 Delphi도.

`while`은 그 성질을 깨는 **첫 구문**이다. 끝나지 않는 루프는 C ABI를 건너 **호스트 스레드를 정지시킨다.**
생성 모듈은 `no_std` + `panic = "abort"`라 언와인딩도, 타임아웃도, 취소 지점도 없다.

**MVP가 정직하게 할 수 있는 일은 "문서화"뿐이다**(Grok 교차검토 동의):

- 연료(fuel)/타임아웃 계수기는 **인터프리터/VM이 필요**하다 — R01 기각·D11(컴파일 타임 변환만)과 정면 충돌.
- `while true` 거부는 **불완전하다**(`while 1 == 1`, 조건 변수 등으로 즉시 우회된다).
- 밖에서 스레드를 죽이는 것은 **UB**다.

따라서 이 슬라이스는 다음을 **함께** 산출한다:

- `docs/HOST_ABI.md`에 **호스트 생존성(liveness) 계약**을 명시: *모듈 export 호출은 반환하지 않을 수
  있다. 모듈은 신뢰되는 코드로 취급되며, 호스트가 응답성을 보장해야 한다면 워커 스레드에서 호출하라.*
- `docs/SECURITY.md`에는 **넣지 않는다.** SECURITY의 보호 대상은 배포된 알고리즘이지 호스트 생존성이
  아니다. 모듈을 신뢰할 수 없는 코드로 다루는 것은 별개의(그리고 지금 하지 않는) 위협 모델이다.

> **확인됨(2026-08-29).** 사용자가 이 트레이드오프를 승인했다: `while`을 넣고, 호스트 생존성은
> **계약 문서화로만** 다룬다. 우회 가능한 반쪽 방어를 넣어 안전하다고 말하지 않는다.

#### 9-63.1 문서를 재려다 나온 제품 결함 — `STATUS.md` §5-6

`SPEC-numeric-conversion` §5가 *"`i32 /`가 단락 평가의 관측 수단을 만들 후보다"* 라고 적어 둔 것을
정정하려고 **실제로 무엇이 방출되는지** 읽었다. `#76`의 전역화 보호막이 이런 모양이다:

```rust
{ let __d = <rhs>; if __d == 0 { 0i32 } else { (<lhs>).wrapping_div(__d) } }
```

**왼쪽 피연산자가 `else` 안에 있다.** 식 자리에서 조기 반환하는 표현은 오늘 정확히 둘인데
(배열 인덱싱 `codegen.rs:771` · 문자열 부분 비교 `:1017`) `i32`를 내는 것은 인덱싱뿐이고,
그 경계 검사가 `<lhs>` 안이다. **제수가 0이면 검사가 실행되지 않는다.**

실제로 빌드한 모듈을 로더로 호출해 쟀다(`return xs[i] / d`, 원소 3개):

| 호출 | status | 값 |
|---|---|---|
| `pick(i=1, d=2)` | `0` | `10` |
| `pick(i=999, d=2)` | **`-2`** | — (대조군: 검사는 작동한다) |
| `pick(i=999, d=0)` | **`0`** | `0` |
| `pick(i=-1, d=0)` | **`0`** | `0` |

범위도 쟀다: `/`·`%`만 해당하고, `*`는 아니며(피연산자가 무조건 평가), 인덱스가 **오른쪽**이면
아니고(`__d`로 먼저 묶인다), `try f(x) / d`는 파서가 거부한다.

**고치지 않았다.** 왼쪽을 끌어올릴지 DP-N4가 닫은 "정의된 결과"를 다시 열지는 설계 질문이고,
방법론이 SPEC 없는 착수를 금한다. `STATUS.md` §5-6에 부채로 기록했고 방출 모양에 가드를 걸었다.

> **그리고 2026-09-01에 누군가 이미 적어 뒀다.** `SPEC-fallible-calls` §5.3이
> *"`i32` 나눗셈의 오른쪽-먼저 평가 — §2.2가 도달 불가능하게 만들 뿐. 식 위치를 여는 날 먼저
> 고쳐야 한다"* 고 남겼다. **맞는 예견이었고 문이 예상한 쪽에서 열리지 않았다** — `try`가 식 자리에
> 온 것이 아니라 `#200`의 배열 인덱싱이 왔다. §5-1이 다섯 슬라이스에 걸쳐 열려 있던 것과 **같은
> 실패다**: 부채가 무엇이 오면 달라지는지를 적어 뒀고, 그것이 왔을 때 그 줄을 다시 읽은 사람이 없었다.

#### 9-63.2 "가드의 범위도 주장이다"가 하루에 세 번 더 났다

이 저장소는 그 문장을 **가드 주석에 직접 적어 두었다** — `STATUS.md`가 두 파일짜리 검사 범위 밖에서

- **export 집합**(2026-09-02에 하나 늘었다)을 검사하는 가드가 **둘이나** 있는데 둘 다 문서 목록이
  손으로 적혀 있었다. 밖의 **열 파일 열두 줄**이 아직 옛 집합을 완전한 것으로 적고 있었고, 그중
  하나는 `protection.rs:1`이 **자기 권위로 인용하는** 수용 기준이었다(#283).
- `#277`이 기준선 명령을 `CONTRIBUTING.md`에서 고치고 가드 범위를 그 파일로 적었다. **새 세션이

  검사하지 않았다**(#285).

셋 다 이제 **전 `.md`를 돌고 탐지기를 좁히는** 형태다. 교훈은 *"복제를 지우면 같은 PR에서 생존자에
가드를 건다"* 로, 그 자리에서 실제로 그렇게 했다.

> *(2026-09-23: 이 표의 머리말이 처음에 **"넷 다 쓰지 않았다"** 고 적었다. Grok 검증이 짚었고
> 맞다 — 셋째·넷째는 기각이 아니라 축소다. 고친 이유는 문장이 틀려서만이 아니다: **"측정하면

> **그래서 중요하다:** 이 머신에서 **전체 게이트 한 번 초록은 보이는 것보다 약한 증거다.**
> 이번 여섯 PR의 강한 신호는 **CI 두 잡**이고(다른 머신, 여섯 PR 전부 초록), 로컬 실행은 그보다
> 빠른 되먹임일 뿐이다. 실패를 봤을 때 **먼저 원인을 읽는다** — 위 둘은 제품 결함이 아니었고,
> 그렇게 읽지 않았으면 문서 변경만 든 브랜치에서 회귀를 찾느라 시간을 썼을 것이다.
>
> 고치지 않았다. 컴파일러가 이미 호출마다 고유 임시 트리를 쓰고 정리하므로 이것은 **저장소가
> 아니라 이 머신의 사실**이고, D3(크기가 머신마다 다르다)와 같은 자리에 적는다.

**#287이 드러낸 것은 결함이 하나가 아니라 둘이라는 점이다.** `*`·`+`·`-`를 나란히 읽으니

없다**: `__d`를 먼저 묶은 것은 0 검사를 위한 것이지 순서를 정한 것이 아니었다. 권고안 한 줄이

> **상시 대기 표(N·D·X·R·A)** 까지 삼켰는데, `X1`~`X3`는 외부 조건을 `R1`·`R3`는 아직 없는 재현을
> 기다린다. **조용한 손실이었을 것이다** — 행의 내용은 어느 파일에 있든 같아서 *여기 없다*는 것만이
> 신호다. Grok 검토가 잡았고, 되돌린 뒤 **그 실수를 그대로 재현해 심어** 가드가 `X1`을 이름으로
> 잡는 것을 확인했다.
>
> **교훈은 §9-63.2의 뒷면이다.** 거기서는 *복제를 지우면 생존자에 가드를 건다*였고, 여기서는
> **옮기기 전에 옮기는 것이 기록인지 목록인지 가른다**. 날짜가 붙은 것은 기록이고, 열린 행을 가진
> 표는 목록이다.

**#288에서도 같은 `find` 첫-위치 결함이 세 번째로 나왔다**(#280·#282에 이어, 셋 다 Grok의 UNASKED).
그리고 그 가드의 첫 판은 **방금 고친 줄조차 잘못된 이유로 통과**시켰을 것이다 — ASCII `.`이
구분자가 아니라 뒤에 `STATUS.md`가 있으면 `contains`가 참이 된다. 이제 lead 뒤 **첫 문서 이름**을
본다.

##### 가드 둘이 이 슬라이스에서 자기 결함을 드러냈다

**① `#281`의 방출-모양 가드가 침묵했다.** *"모양을 바꾸는 사람이 고쳐야 할 문단을 지목받는다"*
고 약속했는데 **조각 넷**(`let __d =` · `if __d == 0 { 0i32 } else {` · `wrapping_div` ·
`wrapping_rem`)을 고정했고 **새 모양에 넷 다** 들어 있었다. 그것을 "증명"했던 심기는 **조건
뒤집기** — 아무도 하지 않을 변화다. 이제 템플릿 **전체**를 §5-6의 코드 블록과 대조한다.
규칙 둘이 `§7-1` 원인 3에 들어갔다: **심을 것은 예상되는 변화** · **조각이 아니라 모양 전체**.

**② `#289`의 ▶ 블록 예산이 잘못된 것을 쟀다.** 슬라이스를 기록하자 202줄로 발화했고, 재 보니
**항목 48줄 · 색인 150줄**이었다. 색인은 **세션당 한 줄씩 유계**이고 759줄로 자란 것은 서사 쪽이다
— 즉 예산이 **달아날 수 없는 쪽을 벌주고** 있었다. 이제 서사만 재고 여유가 **72줄**이다.

> **두 결함의 모양이 같다:** 가드가 *자기가 막겠다고 적은 것*이 아니라 *자기가 재기 쉬운 것*을
> 재고 있었다. 첫 번째는 조각을, 두 번째는 블록 전체를. 둘 다 **그 가드를 실제로 시험하는 변화가
> 왔을 때** 드러났다 — 만들 때가 아니라.

##### Grok — 네 라운드, UNASKED가 네 번 다 실질적

`i32 /` 실패 단언이 **status만** 읽어 out-param 미변경(D17)을 안 본 것(sentinel로 고치고 실패
경로가 쓰게 심어 확인) · §5 등록부 6번이 아직 미해결인 것 · 그것을 고치자 드러난 **두 SPEC이
아직 열린 것으로 적는 것과 `no_spec_calls_a_paid_debt_open`이 `미해결`을 모르는 것** · 그리고
이 항목을 쓰기 전 `850`을 써 둔 것(실측 759).

##### 하지 않은 것

수용 A의 **코퍼스 예제**를 넣지 않았다. 착수 시 비용을 다시 재자 답이 뒤집혔다 — 예제 하나가
세 문서의 `로드하는 모듈 21개`와 다섯 게이트를 움직이는데, C 호스트가 새로 잴 것(`-2`가 ABI를
건너옴)은 **기존 배열 예제들이 매 실행 이미 잰다.** SPEC §3-예제에 날짜와 함께 적었다 —
적지 않으면 다음 감사가 "수용 A 미충족"으로 읽는다.

##### 그리고 두 번 틀렸다

로컬 `main`에 wip 커밋 둘을 올렸다(**푸시 전에 발견**해 브랜치로 옮기고 `origin/main`으로 되돌렸다).
`.text` before/after를 `git stash`로 재려 했는데 **codegen 수정이 이미 커밋돼** 양쪽 다 새 코드였다.
`git stash`는 **커밋되지 않은 것만** 되돌린다 — 그래서 "무변경"이 나온 것은 당연했고 아무것도
증명하지 않았다. `git checkout main -- compiler/src/codegen.rs`로 다시 재서 **before/after 둘 다
10,240 B**를 얻었다(위 문단의 수치가 이것이다).

> **교훈은 "stash를 쓰지 마라"가 아니다.** 두 상태를 비교할 때는 **무엇이 상태를 결정하는지**를
> 먼저 본다 — 커밋된 변경에 `stash`는 아무 일도 하지 않고, **무변경이라는 답이 그럴듯해서
> 의심하지 않게 된다.** 기대하는 답이 나왔을 때가 되묻기 가장 어려운 자리다.

#### 9-63.9 다음 슬라이스를 골랐더니 **"없다"가 답이었다** (#294·#295·#296)

`CLAUDE.md`가 *"표의 근거를 인용만 하고 착수하지 말 것"* 이라 적었으므로 §7 방식을 돌렸다 —
**실제 업무 규칙을 오늘의 언어로 써 보는 것**이다. 열두 개를 썼다: 4대보험 공제 · 운임 구간
요율표 · 연체 이자 · 등급 산정 · 환불 규정 · 견적 합계 · 견적 한 줄 문자열 · 다중 반환 ·
2키 요율 조회 · 필터 · 가중 평균 · 누진 과세.

**12/12 컴파일된다.** 이어서 모서리 열다섯을 찔렀고 거부된 것은 전부 **이유가 문서에 적힌 의도된
공백**이었다(문자열 지역 변수 · 조립한 문자열 비교 · 일반 `f64 as string` · `f64 %` · `else` ·
복합 대입). **하드 브레이크가 없다**는 것이 결과이고, 후보 표(struct · 복합 대입 · context
handle · 콜백 · C# 호스트) 중 **아무것도 고르지 않았다** — 측정이 지지하지 않기 때문이다.

> **그래서 부채 목록으로 전환했다.** 강제되는 슬라이스가 없는 날의 다음 행동은 그것이다.

##### §5-5.7을 갚았다 — 세는 것을 CI에 넣어서 (#294)

근거가 *"누가 손으로 세어 봤다"* 뿐이었다. 이제 `compiler/tests/cli_temp_trees.rs`가 `mlc`를
자식으로 띄워 **그 자식의 pid로 이름 붙은** 트리만 센다(같은 바이너리의 병렬 테스트와 경쟁하지
않는다). **다섯 경우 중 둘만 실제로 잰다** — 정리를 꺼서 심었더니 **뒤의 둘만** 빨개졌다.
못 재는 것(`remove_dir_all` 자체 실패 — 경쟁 상태 필요)도 파일에 적었다.

⚠ **그 테스트가 Windows 게이트 없이 푸시됐고 ubuntu 잡이 24초에 잡았다.** 모듈을 빌드하는
테스트는 Windows 전용이다(D22 갭). **메모에 문장 그대로 적혀 있던 것을 적용하지 않았다.**
그래서 `every_module_building_test_is_windows_gated`를 만들었다 — **형태가 둘**이고 그것은
심기가 증명했다: 라이브러리 진입점(`emit_artifacts`·`build_cdylib`, `unwrap_err` 호출은 제외 —
`diagnostics.rs`는 거부를 기대하므로 정당하게 크로스 플랫폼이다)과 **CLI를 띄우는 형태**.
후자가 없으면 **이 가드를 만든 실수 자체를 못 잡는다.**

> **심기 둘이 먼저 실패했고 각각 진짜 구멍이었다.** needle이 `cfg(windows)`를 **주석 산문**에서
> 찾아 진짜 속성을 지워도 초록이었고, 부정 판별이 `.success()` 앞 아무 데서나 `!`를 찾는데
> `assert!`가 항상 하나를 준다 — 실은 *"assert 안에 있는가"* 를 재고 있었다.

##### 로컬 Delphi 게이트를 돌렸더니 게이트 자신의 구멍이 나왔다 (#295)

X1·X2가 *"로컬 자동화는 반복 가능하다"* 고 적는데 **이 세션에서 아무도 돌리지 않았다.**
돌렸더니 통과한다(`GATE_DELPHI_OK`, `bds.exe -b` 폴백 — 이 에디션의 `dcc64`는 명령줄 빌드를
거부한다고 스스로 찍는다). **인용이 실측이 됐다.**

그리고 `host.dpr`의 `W1044` 경고 **셋**이 보였다. 셋은 의도된 것이지만, 게이트가 세 방향 중
**둘만** 묻고 있었다 — *"표시된 줄이 경고를 받는가"* 와 *"조용한 줄이 조용한가"* 는 묻고,
**"그 밖의 줄에 경고가 없는가"** 는 묻지 않았다. **의도된 셋이 우연한 네 번째가 숨을 자리다.**

##### 착수 대기 표를 전부 다시 쟀다 (#296)

| 행 | 결과 |
|---|---|
| **R1** | ✅ 닫힘 — 지시가 *"손대기 전에 재라"* 였고 #294가 그것을 CI에 넣었다 |
| **§5-5.10** | ✅ — 빠진 것은 **일이 아니라 표시**였다(하위 둘 다 상환인데 부모에만 없었다) |
| **R3 / §5-5.6** | won't-do **유지, 다만 논증이 시도가 됐다** |
| **X3** | **하나 반증**(포크 PR 승인 정책은 API로 읽힌다) · **하나 미판정**(계정 설정, GET 없음) |
| **X1 / X2** | 변화 없음 — CI의 Delphi는 여기서 못 닫는다 |

**§5-5.6이 가장 값어치 있었다.** *"파일시스템 배치로는 도달할 수 없다"* 는 **논증**이었는데,
`rollback`의 자기 주석이 *"디렉터리로 대체된"* 을 들고 디렉터리는 이 저장소가 이미 쓰는
기법이다. 그래서 **해 봤다** — 성공한 빌드 뒤 두 번째·세 번째·네 번째 목적지를 각각 디렉터리로
막고 다시 빌드했다. **셋 다 `Io`이고 `RollbackIncomplete`가 아니다**: 막은 자리에서 앞 이동이
먼저 실패하므로 되돌릴 것은 이 프로세스가 방금 놓은 평범한 파일뿐이다. **won't-do는 유지되고,
이제 시도된 결과다.**

##### 만들지 않은 가드 하나 — 다음 세션이 다시 시도하지 않도록

§5-5의 **6번과 10번이 같은 모양**이었다(하위는 상환, 부모에 표시 없음). 기계로 잡으려고 규칙을
재 봤는데 **두 사례 모두 안 잡힌다**: 6번은 하위 불릿이 아예 없고(내용이 인용 블록이다),
10번은 하위 셋 중 하나가 상태가 아니라 **출처 주석**이라 *"하위가 모두 상환"* 이 거짓이 된다.
**하위 불릿이 상태와 산문을 섞어 쓰기 때문이고**, 그것을 기계로 가르는 것이 이 가드의 값어치보다
비싸다. **이번 세션에서 측정이 죽이거나 좁힌 설계가 다섯 번째다.**

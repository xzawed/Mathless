## 0. 왜 — 측정부터

### 0.1 벽은 모듈 안이 아니라 경계에 있었다 (2026-09-26, E2)

주문 수명주기를 오늘의 언어로 썼다. 자연스러운 첫 형태 `const PAID = 2`는 파서가 거부했다 —
*"constant declarations are not in Mathless yet"*. 우회는 0-인자 내부 `fn`이고, **모듈 안에서는 값이 전부
맞다**(`mlprobe`, 그리고 `order_state_machine.rs`). 깨지는 것은 호스트 쪽이다:

| 실측 | 값 |
|---|---|
| 헤더에 이름이 나가는 저자 정의 정수 | `error` 코드 둘뿐 — 상태 1~6·이벤트 1~5는 없다 |
| `paid()`를 2 → 7로 바꾼 뒤 `order.h` | **바이트 단위로 같다** |
| 그 뒤 `ML_ORDER_IFACE_HASH` | 둘 다 `0x796C5E8CDC313B47` |
| 그 뒤 `next_state(1, 1)` | `7` |

옛 번호로 빌드된 호스트는 **로드 게이트를 통과하고** 답을 잘못 읽는다. 지문이 막으려고 만든 바로 그
상태다(`HOST_ABI.md` "인터페이스 지문"의 파라미터 교체 실측과 같은 모양). 호스트는 번호를 손으로 옮겨 적어야
하고, 그 사본이 낡아도 아무것도 알려 주지 않는다.

### 0.2 모듈 안쪽의 수요도 이미 적혀 있다

2026-09-13 감사(§9-38)의 표에 *"세율 상수 | ❌ `const` 없음 | ✅ 내부 `fn`"* 이 있다 — `f64` 상수이고 호스트에
나갈 필요가 없는 것이다. 이쪽은 **가독성 비용**이지 결함이 아니다. 그래서 이 슬라이스는 둘을 같은 문법에
태우되 **경계를 넘는 것은 `export const`만**으로 가른다(DP-K1).

### 0.3 정직한 반론 (기록)

- **"호스트가 번호를 옮겨 적는 것은 문서로 된다."** 된다. 그러나 §0.1의 실패는 **게이트를 통과하고
  조용하다**. 이 저장소가 지문을 도입한 이유(파라미터 교체가 `33 → 0`을 조용히 냈다)와 같은 등급이다.
- **"`enum`이 더 맞다."** 타입이 상태와 이벤트를 구분해 주므로 더 강하다. 그러나 새 타입·ABI 매핑·완전성
  검사를 여는 일이고, `const`는 그 위에 나중에 얹을 수 있는 **가장 작은 한 걸음**이다(§7 "프로토콜을 여는
  슬라이스는 가장 작은 것으로"). §5에 남긴다.

## 1. 범위

**포함**

1. 최상위 선언 `const NAME = <리터럴>`(모듈 내부)과 `export const NAME = <리터럴>`(호스트 가시).
2. 상수 이름을 **식 자리에서 값으로** 쓴다 — 그 리터럴과 똑같이 동작한다(§2.4).
3. `export const`를 C 헤더와 Delphi 유닛에 **`ML_<MODULE>_CONST_<NAME>`** 으로 방출한다.
4. `export const`를 **지문 매니페스트**에 넣는다. 없는 모듈의 지문은 바뀌지 않는다.
5. `examples/order.mls`를 `export const`로 다시 쓰고, §0.1의 조용한 오독이 **거부**로 바뀌는 것을 C 호스트에서 잰다.

**미포함 (명시)**

- `enum` · 타입 있는 상수 집합 · 상수 식(`const A = 1 + 1`, `const B = A`) · `export const`의 `f64`/`bool`/`string`.
- 상수의 export **심볼**. 상수는 에러 코드처럼 호스트의 **컴파일 시점** 값이다 — export 집합은 그대로다.
- `DECISIONS.md`. 이름 규칙은 Q14의 모양을 따를 뿐이라 `HOST_ABI.md` "네이밍 규약"에 한 줄로 더한다.

## 2. 계약

### 2.1 문법

```text
const RATE = 0.1           // 모듈 내부 — i32 · f64 · bool
const STRICT = true
export const PAID = 2      // 호스트 가시 — i32만
export const NONE = -1
```

- 값은 **리터럴 하나**다. 정수·실수 앞에 `-` 하나를 붙일 수 있다. `i32`는 전 범위(`-2147483648`까지).
- 선언은 최상위 어디에나 올 수 있고 **순서와 무관하게** 모든 함수에서 보인다(`error`와 같다).
- `const`는 **최상위 자리에서만** 의미를 갖는다 — 오늘 `fn const()`가 컴파일되고(실측), 그대로 합법이다.

### 2.2 타입

| 형태 | 허용 타입 | 타입을 정하는 것 |
|---|---|---|
| `const` | `i32` · `f64` · `bool` | 리터럴 모양(`2` · `2.0` · `true`) — 암시적 변환은 없다(DP-I2) |
| `export const` | **`i32`만** | 헤더의 `#define`과 Pascal `const`가 정수로 정확히 옮겨지는 유일한 타입이다 |

### 2.3 이름

- 상수끼리 **대소문자를 무시하고** 유일하다(Pascal 유닛 — `error`와 같은 이유).
- **`error` 이름과 같을 수 없다**(대소문자 무시). 한 이름, 한 뜻.
- **파라미터·지역 변수가 상수 이름을 가릴 수 없다** — 같은 이름이면 거부한다. 조용한 가림은 오답의 모양이다.
- 상수는 **대입할 수 없다.** `result`라는 이름의 상수는 거부한다(배열 반환 함수에서 그 이름은 출력이다).
- 상수 **값의 유일성은 요구하지 않는다** — 상태 `CREATED = 1`과 이벤트 `PAY = 1`이 같은 값인 것이 정상이다.
  에러 코드(DP-F9)와 다른 이유: status는 호스트가 **값으로 이름을 되찾지만**, 상수는 호스트가 **이름으로 값을 쓴다**.

### 2.4 의미 — 이름 붙은 리터럴

상수는 컴파일 시점에 **그 리터럴로 접힌다**. 생성 Rust에 상수 기호는 없고 export 집합도 그대로다.
그리고 **리터럴에 거는 컴파일 시점 검사는 상수에도 걸린다** — `x / ZERO`(`const ZERO = 0`)는 `x / 0`과
같은 컴파일 에러, `xs[NEG]`는 음수 리터럴 인덱스와 같은 컴파일 에러, `fixed(x, P)`의 자리수 범위도 같다.
⚠ 오늘 0 제수 검사는 AST에서, 음수 인덱스 검사는 IR에서 돈다(`typeck.rs`) — 접는 자리가 한쪽이면 다른 쪽이
새므로, 이것은 구현 세부가 아니라 **수용 기준**이다(§3 B).

### 2.5 바인딩

| 산출물 | 방출 |
|---|---|
| C 헤더 | `#define ML_<MODULE>_CONST_<NAME> <값>` — 음수는 `(-1)`처럼 괄호, `i32::MIN`은 `(-2147483647 - 1)`. `#ifndef` 가드 없음(Q14 — 충돌은 시끄러워야 한다) |
| Delphi 유닛 | 같은 이름으로 `const` 블록에 `ML_<MODULE>_CONST_<NAME> = <값>;` — 음수는 `-1`, `i32::MIN`은 `-2147483648`(수용 C가 FPC로 컴파일해 잰다) |
| 내부 `const` | **어디에도 나가지 않는다** |

`<MODULE>`은 헤더 가드·지문·에러 상수가 쓰는 **같은 변환**이고, `<NAME>`은 에러 상수처럼 **그대로** 쓴다.
선언 순서대로 방출한다.

### 2.6 지문

매니페스트(`compiler/src/iface.rs`의 `manifest`)는 `err` 줄 뒤에 `export const`마다 한 줄을 더한다:
`const NAME=VALUE`. `VALUE`는 **부호 있는 십진수 그대로**다 — `-1`, `-2147483648`. 헤더의 괄호 표기는
바인딩의 사정이지 계약이 아니므로 매니페스트에 들어가지 않는다(표기가 바뀌면 지문이 바뀐다). **정렬은 이름의
바이트 순이다 — 렌더된 줄이 아니다**(숫자가 `=`(0x3D)보다 작아 `E_10`의 줄이 `E_1`의 줄 앞에 오던 실측이
`err` 줄에 있다). **있을 때만** 방출하므로 `export const`가 없는 모듈의 지문은 바이트 하나
바뀌지 않는다 — `ml-iface/1`도 그대로다. 내부 `const`는 본문이다: 임계값을 바꾸는 편집은 오늘처럼 **파일
교체로** 나간다(`HOST_ABI.md` — 본문만 바뀐 모듈은 지문이 같다).

| **DP-K7** 지문 | `const NAME=VALUE`(부호 있는 십진수), **이름 바이트 순**, 있을 때만 | 렌더된 줄 정렬 · 헤더 표기 · 매니페스트 버전 올림 | 정렬은 `err` 줄의 실측 결함(`E_1`/`E_10`)을 되풀이하지 않기 위해, 표기는 바인딩이 바뀌어도 지문이 그대로이게 하려고(둘 다 Grok 지적). 버전을 올리면 **모든** 모듈의 지문이 바뀐다 — 거짓 거부 |

## 5. 범위 밖 / 미검증 (명시)

- **`enum`**(§0.3). `export const`의 **`f64`·`bool`·`string`** — 실수 표기의 정확성과 Pascal 쪽 타입을 재야 한다.
- **경계의 나머지 모양은 그대로다**: 함수가 **돌려주는 값**으로 약속한 코드(상수를 거치지 않은 리터럴 `return 7`)는
  여전히 본문이고 지문 밖이다. 이 슬라이스는 저자가 이름을 붙인 것만 경계에 올린다.
- **모듈 사이 이름 충돌**: 모듈 `a`의 상수 `ERR_Q`와 모듈 `a_const`의 에러 `Q`는 둘 다 `ML_A_CONST_ERR_Q`다.
  Q14가 에러 상수에 이미 가진 모양이고(모듈 `a`의 `ERR_X` / 모듈 `a_err`의 `X`), 가드가 없어 값이 다르면
  **C4005로 시끄럽다**(값이 같으면 같은 정의라 합법이고 오답도 아니다).
- C# 등 다른 바인딩 — 아직 없다.

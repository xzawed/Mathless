### 9-68. 상수 선언 슬라이스 (2026-09-26, E2) — **조용한 오독이 거부가 됐다**

사용자가 §9-67의 권장안(호스트에 나가는 상수 선언)을 골랐고, 이어 SPEC의 DP-K1~K8을 제안대로 확인했다. SPEC 한 PR과
구현 두 PR로 닫았다(#325 · #326 · #327).

#### 9-68.1. 설계 — Grok과 사용자

- Grok plan 게이트에 모양을 바꾸는 셋을 라벨 + `CHOICE`로 보냈다: 가시성(K1) · 타입(K2) · C/Pascal 이름(K3) → **B · B · B**.
  묻지 않은 줄이 넷째를 더했다 — 매니페스트의 `const` 줄은 **렌더된 줄이 아니라 이름 바이트 순**으로 정렬한다(`err` 줄의
  `E_1`/`E_10` 실측). DP-K7이 됐다.
- SPEC verify가 SPEC의 결함 둘을 잡았다: 정렬 이유를 거꾸로 적었다(숫자가 `=`보다 **작다**), 매니페스트 값의 표기가
  비어 있었다(헤더의 `(-1)`이 들어가면 바인딩이 바뀔 때 지문이 움직인다).
- 핵심 판단은 K1이다: **모든** 상수를 지문에 넣으면 임계값을 상수로 쓴 순간 그 조정이 호스트 재빌드를 강제한다 —
  "파일만 바꾸면 된다"를 새 기능이 깬다. 그래서 `export const`만 경계를 넘는다.

#### 9-68.2. 구현 1 — 컴파일러 (#326)

- **접는 자리를 재고 골랐다.** 리터럴 검사가 두 층에 갈려 있었다 — 0 제수는 AST(`Expr::Int(0)`), 음수 인덱스와
  `fixed` 자리수는 IR(`i32_literal`). 한쪽에서만 접으면 다른 쪽이 이름 하나로 샌다. typeck 입구에서 **AST를 접은 사본**을
  만들어 둘 다 막았다(DP-K5, `fold_constants`).
- **음수 리터럴은 codegen을 고치지 않았다.** 음수 `ConstI32`가 처음 생기므로 `-1i32.wrapping_add(x)`를 의심했지만,
  i32 연산은 이미 `({}).wrapping_add({})`로 피연산자를 감싸 방출하고 있었다. 추측으로 고치지 않고 오라클에 맡겼다 —
  `NONE + x`가 4, `LOW - 1`이 `MAX`로 wrap(실측).
- **`i32::MIN`은 오늘 소스로 쓸 수 없는 값이었다** — `-2147483648`은 `2147483648`이 먼저 범위 검사에 걸린다. 상수는
  부호를 선언에서 적용하므로 처음으로 그 값을 이름으로 준다.
- 문서가 이 PR로 당겨졌다: `language_gaps.rs`가 공백 블록을 **같은 변경에서** 고치라고 요구하고, HOST_ABI의
  "상수 선언이 없다"가 머지 순간 거짓이 된다. SPEC §6을 그렇게 고쳤다.
- 첫 Red 8개를 메시지로 읽고 needle 둘을 조였다(`"error"`는 모든 `"parse error"`가 만족한다 · **사용된** 범위 밖 상수는
  함수 안 리터럴 검사가 같은 문구를 낸다). 결함 여섯을 심어 전부 빨개짐을 확인했다.

#### 9-68.3. 구현 2 — 예제와 호스트 (#327)

| 무엇 | 실측 |
|---|---|
| C 호스트가 헤더 이름으로 부른다 | `ok   an order paid for is PAID - by the header's names, not retyped numbers` |
| 번호를 바꾼 `order`(PAID 2 → 7) | `refuse order_drift.dll: interface 06CED1D6360435A6, header pinned F1C03F4F38B372F9` |
| 그 거부가 실패할 수 있나 | 매니페스트에서 `const` 줄을 뺀 결함 → `FAIL the gate refuses …`, `c_host` 빨강 |
| C의 `i32::MIN` 표기 | `_Generic(…, int: 1)` + `== INT32_MIN` `_Static_assert` — `/W4 /WX` 통과 |
| Pascal의 `-2147483648` | FPC `-Mdelphi`·`-Mdelphiunicode`, **Delphi `bds.exe -b`(로컬)** 모두 `Low(Integer)` |
| export 집합 | `mlx_*` 넷 + 예약 둘 — 상수는 심볼을 더하지 않는다 |

전체 게이트(`MATHLESS_GATE_D/FPC/FPC_HOST=require`): exit 0 · 672 passed · 0 failed · 0 ignored. 골든은 `order`와
`shapes`만 바뀌었다 — 나머지 예제의 헤더와 지문은 바이트 그대로다.

#### 9-68.4. 검증이 찾은 것 (Grok)

- 구현 두 PR의 verify 여섯 라운드: 다섯이 PASS, 주장 18개 중 17개 CONFIRMED. 남은 하나(#326의 문서 라운드)는
  아래 DISCREPANCY다.
- 묻지 않은 줄: HOST_ABI 한 문장이 두 절반(0-인자 함수 · 내부 `const`)을 주장하며 한 테스트만 인용했다 → 둘 다 인용.
  기준선 테스트 설명의 "passes the gate"가 단언보다 넓었다 → 좁혔다.
- DISCREPANCY 둘은 결함이 아니었다: `체크드 오버플로`의 공백 행 부재는 `language_gaps.rs`가 의도로 적어 둔 것이고,
  DP 표의 한 행이 본문의 Delphi 표기를 되풀이하지 않는 것은 한 사실 한 집 원칙이다.

#### 9-68.5. 제 실수 둘

- `python -c` 안에서 `\n`을 이스케이프한 플랜트가 문자열을 깨뜨렸다. `assert`가 먼저 막아 파일은 그대로였다 —
  `CLAUDE.md`의 규칙대로 `chr(92)`로 만든 스크립트 파일로 다시 했다.
- `gh pr merge --delete-branch`가 쌓아 둔 브랜치의 **기준 브랜치를 로컬에서 지웠고**, 이름으로 건 rebase가 실패했다.
  작업 트리를 stash로 지키고 `origin/main`으로 맞춘 뒤 되돌렸다 — squash 커밋과 원래 두 커밋의 트리가 같음을
  `git diff`로 확인하고 나서.

## 0. 왜 — 측정부터

### 0.1 §9-46이 "모듈 안"으로 분류한 우회가 **조용히 틀린다** (E2)

§9-46은 R5(금액 포맷)를 *"우회가 모듈 안에 있다"* 로 적고 결합이 아니므로 후보에서 내렸다.
그 우회를 실제로 써 보고 **값을 쟀다**:

```mls
let cents = round(won * 100.0) as i32
return (cents / 100) as string + "." + (cents % 100) as string
```

| 입력 | 나온 것 | 맞는 것 |
|---|---|---|
| `1234.50` | `"1234.50"` | ✅ |
| **`1234.05`** | **`"1234.5"`** | `"1234.05"` — 10전 미만이면 0이 사라진다 |
| **`-1234.05`** | **`"-1234.-5"`** | `"-1234.05"` |
| **`-0.07`** | **`"0.-7"`** | `"-0.07"` — **부호가 통째로 사라진다** |
| **`50000000`** | **`"21474836.47"`** | `"50000000.00"` |

**셋 다 status 0이고 경고가 없다.** 마지막 줄이 가장 나쁘다 — 5천만 원은 예외적인 금액이 아니다.

> **원시 연산은 전부 규격대로다.** `as i32`의 포화는 `SPEC-numeric-conversion`의 **기록된 결정**이고,
> `round`의 방향도 측정돼 있다. **틀린 것은 조립이다** — 그리고 조립은 저자가 한다.

### 0.2 잣대가 이 부류를 못 본다

§9-38이 세운 잣대는 *"우회가 호스트로 일을 밀어내는가"* 이고, §9-46은 그대로 적용해 R5를 내렸다.
**그 이분법에 이 경우가 들어갈 칸이 없다** — 우회가 모듈 안에 있으면서 **틀린** 경우.

이것이 이 슬라이스의 진짜 근거이고, 잣대의 보강이다:

| 우회의 모양 | 슬라이스 근거 |
|---|---|
| 모듈 안, 맞음 | 없음 |
| 호스트로 민다 | **결합**(§9-38) |
| **모듈 안, 조용히 틀림** | **이 줄이 없었다** — 지금 생긴다 |

### 0.3 그리고 이번 표본에서 결합 후보는 **닫힌 문이었다**

같은 실행에서 유일한 결합 후보는 문자열 순서 비교(`a < b`)였는데, **`[string]`이 양방향 모두
없다**(실측). 그러면 `<`만 열어도 모듈은 이름 목록을 들 수도 돌려줄 수도 없고, 호스트가 술어를
**N log N번** 부르게 된다 — **지금보다 나쁜 결합**이다. 논의도 같은 결론이었다.

## 1. 목표

```mls
export fn amount(won: f64) -> string! {
  return fixed(won, 2)     // "1234.05" · "-0.07" · "50000000.00"
}
```

**하지 않는 것**: 일반 `f64 as string`, 천 단위 구분, 통화 기호, 로케일, 지수 표기, 반올림 모드 선택.

---

## 2. 계약 (Contracts)

### 2.1 무엇을 돌려주나

`fixed(x, places)`는 **십진 고정 소수 표기**를 만든다:

- 정수부는 **항상 한 자리 이상** (`0.07` → `"0.07"`, `"`.07`"` 아님)
- 소수부는 **정확히 `places` 자리**, 0으로 채운다 (`1234.5` → `"1234.50"`)
- `places == 0`이면 **점이 없다** (`"1234"`)
- 음수는 **맨 앞에 한 번** `-` (`"-0.07"`) — §0.1이 잰 `"0.-7"`이 이 줄의 이유다
- **`-0`은 만들지 않는다**: 반올림 결과가 0이면 `"0.00"`

### 2.2 반올림 — `round`와 **같은 방향** (DP-M3)

0에서 먼 쪽(half away from zero). `round`가 이미 그렇고(실측: `1235.5 → 1236`), **한 모듈 안에
두 반올림 규칙이 있는 것이 이 저장소가 세 번 데인 모양**이다(`ml_cap` 단위, `ml_needed` 포함/제외,
`byte_len` vs `len`).

### 2.3 i32를 거치지 않는다 — **포화가 이 슬라이스에 없는 이유** (DP-M4)

§0.1의 마지막 줄은 `as i32`의 포화 때문이다. 그래서 **lowering이 i32를 쓰지 않는다**: 스케일링과
자릿수 분해를 **i64**로 한다(생성 Rust 안의 타입이고 ABI에 나가지 않는다). f64의 가수는 53비트라
**9×10^15**까지 정확하고, 금액에 필요한 범위를 한참 넘는다.

**그래도 한계는 있다**(적어 둔다): `x * 10^places`가 i64 범위를 넘으면 결과가 정의되지 않는다.
그 경계를 **수용 E가 측정**하고, 넘는 경우는 §2.4가 status로 만든다.

### 2.4 실패 — **조용하지 않다** (DP-M4)

| 조건 | 결과 |
|---|---|
| `places`가 0..=9 밖 | 리터럴이면 **컴파일 에러**, 아니면 `ML_ST_INDEX_OUT_OF_RANGE`(`-2`) |
| `x`가 NaN 또는 ±무한 | **`-2`** — 십진 표기가 없다 |
| `x * 10^places`가 i64 밖 | **`-2`** |
| 버퍼가 모자람 | Q12 그대로: `-1`, `*ml_needed`에 정확한 크기 |

> **`-2`를 재사용한다** — 새 예약 음수는 문서·헤더·가드를 끌고 온다(#238이 잰 대가). 뜻도 맞는다:
> *"값 밖의 것을 달라고 했다."* **`#238`의 규칙대로 바인딩이 그 이름을 준다** —
> `can_fail_out_of_range`가 이 구성도 답해야 한다.

### 2.5 이름 — `fixed` (DP-M2)

**고정 소수점**을 말한다. 후보와 기각 사유:

| 후보 | 기각 |
|---|---|
| `f64 as string` | 정밀도를 정하지 않는다. `0.1+0.2`를 `"0.30000000000000004"`로 낼 것인가를 매번 묻게 된다 |
| `money(x)` | 도메인을 이름에 박는다. 세율·비율에도 쓰인다 |
| `format(x, n)` | 너무 넓다 — 다음에 천 단위·통화를 여기 밀어 넣게 된다 |

### 2.6 DP-K9 — 이미 열려 있다

모듈이 만드는 바이트에 `.`가 더해진다. `-`와 `0`–`9`는 이미 있고, **`.`도 모든 후보 인코딩에서 같은
바이트**다. `HOST_ABI.md`의 그 줄에 한 글자를 더한다(2026-09-14에 이미 UTF-8 때문에 손댄 줄이다).

## 3. 수용 기준 (측정 가능)

**모두 로드된 모듈에서 잰다(E2).** `mlprobe`로도 같은 값을 확인한다.

- **A. §0.1의 표가 전부 맞는다.** `1234.05`→`"1234.05"`, `-1234.05`→`"-1234.05"`,
  `-0.07`→`"-0.07"`, `50000000`→`"50000000.00"`.
- **B. `places` 경계.** `0`→점 없음, `9`→아홉 자리. `10`은 리터럴이면 **컴파일 에러**.
- **C. 반올림이 `round`와 같다.** `1.005`·`2.675`·`-1.005`를 **같은 모듈의 `round`와 나란히** 재
  방향이 일치함을 보인다(부동소수 표현 때문에 직관과 다른 값도 **그대로 적는다**).
- **D. `-0`을 만들지 않는다.** `-0.004`, `places=2` → `"0.00"`.
- **E. i64 경계.** `x * 10^places`가 넘는 값에서 **`-2`**, 그리고 **한 자리 아래에서는 정상**.
- **F. NaN·무한.** 둘 다 `-2`, 버퍼 **미변경**(canary).
- **G. Q12.** `cap=0` probe → `-1`과 정확한 `*ml_needed`, 재시도 성공.
- **H. 바인딩이 `-2`를 이름으로 준다**(#238의 규칙) — `fixed`만 쓰는 모듈의 `.h`·`.pas`.
- **I. 보호 프록시 무변경.** export 3개, import 집합이 대조 모듈과 동일 — **CRT 포맷을 부르지 않는다.**
- **J. 호스트 두 곳.** 오라클 + 실제 C 호스트.
- **K. 거부.** `fixed("x", 2)` · `fixed(1.0, 2.0)` · `places` 리터럴 범위 밖 · 이름 충돌.

## 5. 범위 밖 / 위험

### 5.1 하지 않는 것

- 천 단위 구분·통화 기호·로케일 — 전부 **호스트의 표현 문제**이고, 인코딩(DP-S2)을 건드린다.
- 일반 `f64 as string` — DP-M1이 미룬다.
- 반올림 모드 선택 — DP-M3.

### 5.2 새 위험

| 위험 | 막는 것 |
|---|---|
| **부동소수가 직관과 다르다**(`2.675`) | **수용 C가 값을 그대로 적는다.** 숨기지 않는다 |
| **i64 경계에서 조용히 틀림** | **수용 E**가 경계 양쪽을 잰다 |
| **CRT 포맷이 끌려온다** | **수용 I**가 import 집합으로 잰다 |
| **`-2`가 또 이름 없이 나간다** | **수용 H** + `can_fail_out_of_range`가 이 구성도 답한다 |

## 7. 정직한 반론 (기록)

- **결합 잣대로는 이것이 1순위가 아니다.** §9-38의 이분법에서 이 우회는 "모듈 안"이다.
  **그 이분법이 못 보는 칸**이 이 문서의 근거이고, 그것 자체가 §9-38의 보강이다.
- **이 표본에서 결합 후보는 하나였고 그것은 닫힌 문이었다**(§0.3). 그래서 남은 최상위가 이것이다.
- **저자가 고칠 수 있었다.** 조건부로 `"0"`을 붙이고, 부호를 따로 빼고, i32를 피하면 된다.
  **세 군데를 전부 맞춰야 하고, 하나라도 틀리면 조용하다** — 그것이 내장이 있어야 하는 이유다.

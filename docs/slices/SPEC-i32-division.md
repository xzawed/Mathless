# Slice SPEC — `i32` 나눗셈과 나머지 (`/`, `%`)

> **상태: 초안(draft) · 사용자 확인 대기** — 2026-08-31.
> §4의 **DP-D1**(0으로 나눌 때의 규칙)이 이 슬라이스의 유일한 진짜 결정이다. 나머지 DP는 그것에 따라온다.
> **근거 수준:** §1이 **E2 실측**(오늘의 언어로 쓴 실제 업무 규칙 + 로드된 모듈의 반환값), §4가 E0.
> 구현 후의 완료 검증은 E2다(§3).
> **선행:** `i32`(#31) · `as`(#59, 결합은 #68) · 내부 함수(#57) · D17 에러 경로(#15).
> 설계 교차검토: Grok(§4에서 (a)·(c)를 기각한 논거가 그쪽에서 왔다).

## 1. 목표 — 구멍은 "안 된다"가 아니라 "되는데 조용히 틀린다"

`STATUS.md` §3a는 이 슬라이스를 "정수 산술이 안 된다"로 정당화해 왔다. **저장소 방식대로 실제 업무
규칙을 오늘의 언어로 써 보니 그 서술이 정확하지 않았다.**

낱개 수량을 박스와 낱개로 나누는 규칙이다. 직설적으로 쓰면 거부된다:

```mathless
export fn boxes(qty: i32, per_box: i32) -> i32 {
  return qty / per_box          // ← typecheck 에러
}
```

그런데 **컴파일러가 우회로를 알려주고, 그 우회로는 컴파일된다**:

```mathless
export fn boxes(qty: i32, per_box: i32) -> i32 {
  return (qty as f64 / per_box as f64) as i32
}
```

### 1.1 그 우회로가 실제로 반환하는 값 (E2 — 로드된 모듈)

| 호출 | 우회로 | Rust `i32 /` |
|---|---|---|
| `boxes(17, 5)` | `3` | `3` ✅ |
| `boxes(100, 10)` | `10` | `10` ✅ |
| `boxes(-17, 5)` | `-3` | `-3` ✅ (둘 다 0 방향 절단) |
| `boxes(2147483647, 3)` | `715827882` | `715827882` ✅ |
| **`boxes(17, 0)`** | **`2147483647`** | 패닉 |
| **`boxes(-17, 0)`** | **`-2147483648`** | 패닉 |
| **`boxes(0, 0)`** | **`0`** | 패닉 |
| **`boxes(i32::MIN, -1)`** | **`2147483647`** | 오버플로 |

**정상 값에서는 정확하다.** `i32 as f64`는 무손실이고, 몫의 반올림 오차가 절단 경계를 넘을 수 없다 —
다음 정수까지의 간격이 최소 `1/b`인데, 이 크기대에서 f64의 상대 엡실론보다 훨씬 크다.

**보존되지 않는 것은 실패다.** 0으로 나누면 `inf`/`-inf`/`NaN`이 되고 곧바로 `i32::MAX`/`i32::MIN`/`0`
으로 포화한다(§SPEC-numeric-conversion 2.3의 규칙 그대로). **박스 크기 0에 낱개 17개를 넣으면
2,147,483,647박스가 나온다.** 업무 규칙 언어에서 이건 오답 중에서도 나쁜 종류다 — 그럴듯해 보인다.

> 진단이 이 우회로를 권하면서 함정을 말하지 않고 있었다. **#74에서 진단 문구를 고쳤다** —
> 이 슬라이스가 확정되기 전까지의 지혈이다.

### 1.2 그래서 이 슬라이스가 정말로 해결하는 것

표현력이 아니라 **실패의 소재(所在)**다. 오늘은 실패가 `as`의 포화 규칙 안에 숨는다. 이 슬라이스
이후에는 나눗셈 자신의 규칙이 되고, 그 규칙이 **명세되고 측정된다.**

## 2. 계약 (Contracts)

### 2.1 문법

```text
mul := cast (('*' | '/' | '%') cast)*
```

`%`는 **새 토큰**이다(오늘 렉서에 없다 — `Percent` 없음, 실측). `*`·`/`와 같은 층, 좌결합.
`f64 %`는 **이 슬라이스에서 다루지 않는다**(§5).

### 2.2 타입 규칙

- `i32 / i32 -> i32`, `i32 % i32 -> i32`.
- 혼합은 여전히 거부(DP-I2 불변). `f64 / f64 -> f64`는 그대로.
- `f64 % f64`는 **거부**한다 — 부동소수 나머지는 별개의 의미 논쟁이다(§5).

### 2.3 값 규칙 — **이 슬라이스의 핵심** (DP-D1 확정 시 채워짐)

권고안 기준으로 적는다. 사용자 확인 전까지는 **제안**이다.

| 입력 | `a / b` | `a % b` |
|---|---|---|
| 보통의 값 | 0 방향 절단 | `a - (a / b) * b`, 부호는 `a`를 따른다 |
| **`b == 0`** | **`0`** | **`0`** |
| **`a == i32::MIN && b == -1`** | **`i32::MIN`**(wrap) | **`0`** |

두 경계 모두 **전역(total)** 이다 — 트랩도, 패닉도, 정의되지 않은 동작도 없다. 근거는 §4 DP-D1.

`i32::MIN / -1`이 `i32::MIN`으로 감기는 것은 **이미 측정된 이웃 규칙과 같은 태도**다:
`-i32::MIN == i32::MIN`(SPEC-unary, 실측). DP-I4가 `+ - *`를 wrap으로 두었으므로 `/`만 다르게
둘 이유가 없다.

### 2.4 codegen — 전역성은 공짜가 아니다

Rust의 `i32 /`는 `b == 0`에서도, `i32::MIN / -1`에서도 **패닉한다.** 후자가 중요하다 — 흔히 릴리스
에서는 오버플로 검사가 꺼지니 괜찮다고 생각하지만 **아니다**. 나눗셈 오버플로의 패닉은
`overflow-checks`와 무관하다. `rustc -O -C overflow-checks=off`로 실측:

| 식 | 결과 |
|---|---|
| `i32::MIN / -1` | **패닉** — `attempt to divide with overflow` |
| `17 / 0` | **패닉** — `attempt to divide by zero` |
| `i32::MIN.wrapping_div(-1)` | `-2147483648` |
| `i32::MIN.wrapping_rem(-1)` | `0` |
| `17i32.checked_div(0)` | `None` (→ `wrapping_div`도 0에서는 패닉한다) |

**즉 생성 모듈에서 이 두 식은 `loop {}` 패닉 핸들러로 들어가 호출 스레드를 멈춘다.** 그러므로
순진하게 `/`를 방출할 수 없다. 방출 형태:

```rust
if b == 0 { 0 } else { a.wrapping_div(b) }     //  /
if b == 0 { 0 } else { a.wrapping_rem(b) }     //  %
```

`wrapping_div`/`wrapping_rem`이 `i32::MIN / -1`을 처리하고, 0 검사가 나머지 하나를 처리한다.
둘 다 `core`에 있어 `no_std`에서 쓸 수 있다(구현 시 확인한다).

**대가: 나눗셈마다 비교와 분기 하나.** 이 슬라이스는 그것을 감수한다 — 대안이 호스트 스레드를
멈추는 것이기 때문이다(§4).

### 2.5 ABI — **변화 없음**

식 수준 변경이다. export 집합·시그니처·헤더·유닛 모두 그대로. 크기 프록시(9,728 B)는 분기가
늘어난 만큼 움직일 수 있다 — §3-C에서 **다시 측정한다**(고정하지 않는다).

- **B. 로드·호출(오라클):** `boxes(17,5)==3` · `loose(17,5)==2` · `boxes(-17,5)==-3` ·
  `loose(-17,5)==-2` · `boxes(2147483647,3)==715827882`.

  **모두 실제 로드된 모듈에서 잰다.** 호출은 반드시 **반환**해야 한다(멈추지 않는다) — 그것이
  §1의 위험에 대한 답이다.
- **C. 보호:** export 정확히 2개, strip 유지. **크기는 재서 기록한다**(변할 수 있다).

- **E. 부정 케이스:** `f64 % f64` 거부 · `i32 % f64` 거부 · `a % b`의 비-정수 피연산자 거부.
- **F. 부채 상환(§5-1):** 이 슬라이스가 오면 `&&`의 단락 평가를 **처음으로 관측 가능**해지는지
  확인한다. → **아니다.** §5.2를 볼 것.

## 4. 설계 제안 (DP — **미확정, 사용자 확인 필요**)

| DP | 선택지 | 권고 | 근거 |
|----|--------|------|------|
| **D1 `b == 0`** | (a) 실패 가능 나눗셈 / (b) **정의된 결과** / (c) 호출자 사전 검사 + 트랩 | **(b) `x / 0 = 0`, `x % 0 = 0`** | 아래 상세 |
| **D2 `i32::MIN / -1`** | 포화 / **wrap** / 실패 | **wrap → `i32::MIN`** | DP-I4가 `+ - *`를 wrap으로 두었고 `-i32::MIN == i32::MIN`이 이미 실측돼 있다. `/`만 다르게 둘 이유가 없다 |
| **D3 `%`의 부호** | 피제수 부호 / 항상 양수 | **피제수 부호** | C·Rust·Delphi가 모두 그렇다. C ABI 경계 언어가 여기서 튀면 안 된다 |
| **D4 `f64 %`** | 포함 / **제외** | **제외** | 부동소수 나머지는 별개의 의미 논쟁이다(`fmod` vs IEEE remainder). 이 슬라이스의 논점이 아니다 |
| **D5 리터럴 `/ 0`** | 허용 / **컴파일 에러** | **컴파일 에러** | 정적으로 판정 가능하고 실수일 가능성이 100%다. "막을 수 있으면 막는다"(§3a)가 여기서는 값싸게 성립한다 |

### DP-D1 상세 — 왜 (a)도 (c)도 아닌가

**(a) 실패 가능 나눗셈 (`-> T!`, D17 재사용) — 기각.**
D17의 `fail`은 **문**이고 `export fn`에만 붙는다. 나눗셈은 **식**이다. (a)를 하려면 식 자리의
`fail`과 모듈 내부 fallible 호출이 둘 다 필요한데, **오늘 둘 다 없다**(후자는 #67이 오히려
명시적으로 막았다). 이건 이 슬라이스가 아니라 **다른 슬라이스**다.

**(c) 호출자 사전 검사 강제 + 트랩 — 기각.**
"트랩"이 오늘 무엇인지가 문제다. 생성 모듈의 `#[panic_handler]`는 `loop {}`이므로 **트랩 = 호출
호스트 스레드가 영원히 도는 것**이다(`STATUS.md` §5-4). 그건 `while`의 비종료와 **같은 등급**이고,
저장소는 그것을 메커니즘이 아니라 `HOST_ABI.md`의 **생존성 계약**으로 처리하기로 이미 결정했다.
연산자 하나의 기본 동작으로 호스트를 멈추는 것은 그 결정과 어긋난다.

**(b) 정의된 결과 — 권고.**
결정적이고, 전역이고, 측정 가능하다. 정수 `+ - *`가 이미 wrap으로 전역이므로(DP-I4) **태도가
일관된다.** 그리고 도메인 에러를 원하는 사용자는 **오늘의 언어로 이미 쓸 수 있다** — 경계에서:

```mathless
error E_DIV0 = 1

export fn boxes(qty: i32, per_box: i32) -> i32! {
  if per_box == 0 { fail E_DIV0 }
  return qty / per_box
}
```

`if`·비교·export의 `fail` 모두 오늘 있다. **즉 (b)는 (a)를 막지 않는다** — 실패를 원하는 쪽에
그것을 표현할 자리를 남겨 두고, 언어의 기본값만 전역으로 둔다.

### DP-D1에 대한 반론 (기록)

`x / 0 = 0`도 **조용한 오답**이다. 박스 크기 0에 낱개 17개를 넣으면 이제 `2147483647`이 아니라
`0`이 나온다 — 여전히 틀렸고, 여전히 조용하다. 이 SPEC은 그것을 **개선이라고 주장하지 않는다.**
주장하는 것은 두 가지뿐이다: **(1)** 그 값이 이제 `as`의 포화 규칙에서 파생된 부작용이 아니라
나눗셈 자신의 명세된 규칙이고, **(2)** DP-D5가 리터럴 `/ 0`을 컴파일 타임에 잡으며, 변수 제수는
경계에서 `fail`로 올릴 수 있다.

**대안을 원한다면 지금이 말할 때다** — 예를 들어 `x / 0`을 항상 컴파일 에러로 두고 제수가 상수가
아닐 때는 명시적 가드를 **강제**하는 안(= (c)의 정적 버전, 트랩 없음)도 가능하다. 다만 그건
데이터 흐름 분석이 필요해 MVP 범위를 넘는다.

## 5. 범위 밖 / 위험

- **`f64 %`** — DP-D4로 제외.
- **다른 정수 폭**(`i64`/`u32`), 체크드 산술 — 별개.
- **상수 폴딩** — `4 / 2`를 컴파일 타임에 접지 않는다. DP-D5의 리터럴 `0` 검사는 폴딩이 아니라
  **문법적 검사**다.

### 5.1 이 슬라이스는 호스트를 멈추지 않는다 — 그것이 요점이다

`while`(#49)과 재귀(#57)는 각각 "정지 불가"와 "프로세스 종료"를 다뤘다. **나눗셈은 셋 중 어느 쪽도
아니게 만들 수 있다** — 런타임에 판정 가능하기 때문이다. 그래서 계약으로 미루지 않고 **연산자
정의로 닫는다.** 재귀와 갈리는 지점은 결과의 심각도가 아니라 **판정 시점**이다(정적 vs 런타임).

### 5.2 `&&` 단락 평가 부채(§5-1)는 **이 슬라이스로도 갚지 못한다**

`STATUS.md` §3a와 `SPEC-calls` §5.2가 "트랩 가능한 첫 연산이 생기므로 처음으로 관측 가능해진다"고
적어 두었다. **DP-D1이 (b)로 가면 그 기대는 사라진다** — 전역 연산에는 트랩이 없으므로
`false && (x / 0 == 0)`은 여전히 아무것도 관측하지 못한다.

**이 SPEC은 그 부채를 갚지 않는다고 명시한다.** DP-D1이 (a)나 (c)로 결정되는 경우에만 관측 수단이
생긴다. 갚는 척하지 않는 편이 낫다(§5-1이 존재하는 이유가 그것이다).

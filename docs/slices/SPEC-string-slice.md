# SPEC — 부분문자열 `byte_slice(s, from, to)`

- **상태: 확정 · 구현 완료 (2026-09-13).** **DP-B1~B6을 사용자가 확인했다** — 여섯 다 권고대로다.
  - 갈리는 둘을 따로 물었다: **DP-B2 반열림 `(from, to)`**, **DP-B3 내장 함수**.
    나머지 넷(바이트 · `-2` 실패 · 빌트 문자열 · 바인딩 무변경)은 살아 있는 대안이 없어 함께 확인됐다.
  - **수용 A~L 전부 닫혔다 — 그리고 이번에는 L까지 실제로 쟀다.** 지난 슬라이스가 수용 D를
    재지 않고 "전부"라고 적었으므로(§9-41), 각 기준이 **어느 테스트로** 닫혔는지 §3에 적는다.

  > **📌 구현 중 §2.5의 서술 하나를 정정했다.** 이 문서는 *"기본값이 틀린 경로가 둘"* 이라고
  > 적었는데, 실제로는 **컴파일러가 둘 다 강제했다** — `IrStmt::Return`도 `piece_kind`도
  > `_` 포괄이 아니라 **손으로 적은 팔**이라, 새 변종을 넣자 **여덟 곳이 컴파일 에러**가 됐다.
  > 위험은 *조용히 샌다*가 아니라 **그 여덟 곳에서 내가 틀리게 답한다**였다. 저장소가 포괄 팔을
  > 지운 이유가 바로 이것이고, `IrStmt::Return`의 주석은 이 사고를 **미리 적어 두고 있었다** —
  > *"a new string-shaped one would be handed to `ml_strout` as if it were an address."*
- 선행: `SPEC-string-input.md`(#88/#89 — DP-S1 NUL 종료 · **DP-S2 불투명 바이트** · **DP-S3 연산 범위**) ·
  `SPEC-string-return.md`(#91/#92 — **Q12 caller-allocates**) ·
  `SPEC-string-concat.md`(#107/#108 — DP-S3를 **연결에 대해** 열었다) ·
  `SPEC-string-length.md`(#223/#224 — **`byte_len`이 이미 있다**)
- 관련 결정: **D16**(인자=빌림, 할당자 없음) · **Q12**(caller-allocates) · **D17**(i32 status) ·
  **DP-S2**(인코딩 미확정) · **DP-S3**(문자열 연산 범위)
- 발단: **2026-09-13 감사**(`STATUS.md` §9-38·§9-41) — 표본에서 **호스트 결합이 남은 마지막 규칙**

## 0. 왜 — 측정부터

### 0.1 감사 표본에 남은 마지막 하나 (E2)

§9-41이 감사의 다섯 규칙을 `byte_len` 머지 뒤에 다시 돌렸다.

| 규칙 | 우회 | 지금 |
|---|---|---|
| 사업자번호 10자리 | 호스트가 잰다 | ✅ `byte_len`으로 닫혔다 |
| **계좌 앞 3자리** | **호스트가 자른다** | ❌ **남았다 — 이 슬라이스** |
| 금액 소수 · 세율 상수 · 첫 항목 중단 | 전부 모듈 안 | ❌ 그대로(결합 아님) |

§9-38의 잣대는 *"우회가 호스트로 일을 밀어내는가"* 였고, 그런 것이 **둘**이었다. 하나가 닫혔고
**이것이 마지막이다.** `SPEC-string-return` §0.1이 *줄이려는 결합*이라고 이름 붙인 바로 그것이다.

### 0.2 **`SPEC-string-length` §0.2의 예측을 정정한다** (E2)

그 문서가 부분문자열을 미루며 이렇게 적었다:

| | 반환 | 프로토콜 |
|---|---|---|
| `byte_len(s)` | `i32` | 없다 |
| `s[a..b]` | `string` | ~~**Q12 caller-allocates 전체** — 삼총사·절단·probe~~ |

**틀리지 않았지만 오해를 부르는 표현이었다. 재 보니 프로토콜은 *만드는 것이 아니라 물려받는 것*이다.**
`-> string!`(#92)과 연결(#108)이 이미 두 패스를 방출한다 — 1패스가 `*ml_needed`를 채우고,
`cap < needed`면 **한 바이트도 쓰지 않고** 실패를 돌려준다(`ml_strout`·`emit_concat_return` 실측).

**부분문자열이 새로 가져오는 것은 프로토콜이 아니라 writer 하나다**(§2.5). 그리고 그것이
이 슬라이스의 진짜 위험이다.

### 0.3 사전 검증이 전제 셋 중 하나를 뒤집었다 (E2)

SPEC을 쓰기 전에 기둥 세 개를 검증에 걸었고 **FAIL**이 났다.

| 전제 | 판정 |
|---|---|
| 할당자가 필요 없다 — 기존 두 패스가 호스트 버퍼에 직접 쓴다 | ✅ CONFIRMED |
| `let t = <빌트 문자열>`은 **`reject_built_string`이** 이미 막는다 | ❌ **DISCREPANCY** |
| `s[0..3]`은 **렉서**가 막는다(타입체커가 아니라) | ✅ CONFIRMED |

**둘째가 틀렸다.** `let t = s + "x"`가 죽는 이유는 *빌트 문자열이라서*가 아니라
**`string` 지역 변수가 전부 금지**라서다(`typeck.rs`의 `Let` 팔, `value.ty == IrType::Str`).
`let t = s`도 같은 이유로 죽는다. 결론(부분문자열 지역 변수는 거부된다)은 유지되지만
**기제가 다르고, 그 차이가 §2.6을 만든다** — `reject_built_string`이 지키는 것은 `let`이 아니라
**인자 자리와 `byte_len`**이다.

> 그리고 검증이 **묻지 않은 것 중 가장 위험한 것**을 댔다:
> *"`ml_strout`/`ml_wstr` copy until the source NUL, so a substring treated as a borrowed
> pointer would silently return the suffix, not the span."*
> **코드로 재확인했다. 맞다.** §2.5가 그것이다.

## 1. 목표

`s`의 일부를 **모듈 안에서** 잘라 `-> string!`로 돌려준다. 오늘 호스트가 하는 일을 모듈이 한다.

```mls
export fn bank_prefix(acct: string) -> string! {
    if byte_len(acct) < 3 { fail SHORT_ACCT }
    return byte_slice(acct, 0, 3)
}
```

**하지 않는 것**: 지역 변수에 담기, 문자 단위 자르기, 탐색(`index_of`), 대소문자 변환, 포맷.

## 2. 계약 (Contracts)

### 2.1 단위 — **바이트** (DP-B1)

DP-S2가 인코딩을 정하지 않았으므로 **다른 선택지가 없다.** `byte_len`과 같은 공간에서 센다:
`byte_slice(s, 0, byte_len(s))`가 **문자열 전체**다.

**대가는 `byte_len`과 같고, 더 날카롭다.** `byte_len`은 틀린 *수*를 주지만
`byte_slice`는 **깨진 문자**를 준다 — UTF-8 `"한국"`에서 `byte_slice(s, 0, 3)`은 3바이트,
즉 `한` 하나다. `byte_slice(s, 0, 2)`는 **글자의 절반**이고 그것을 호스트가 출력한다.
이름이 `byte_`로 시작하는 이유이며, **수용 H가 측정한다.**

### 2.2 인자 모양 — **`(s, from, to)` 반열림** (DP-B2)

`to`는 **끝 오프셋이고 포함하지 않는다.** 길이가 아니다.

| 쓰는 법 | 뜻 |
|---|---|
| `byte_slice(s, 0, 3)` | 앞 3바이트 |
| `byte_slice(s, 2, byte_len(s))` | **2바이트째부터 끝까지** |
| `byte_slice(s, 0, byte_len(s))` | 전체 |

**왜 길이가 아닌가**: `to`를 쓰면 `byte_len(s)`를 **그대로** 끝에 넣을 수 있다. 길이 방식이면
같은 것을 `byte_slice(s, 2, byte_len(s) - 2)`로 써야 하고, **그 `- 2`를 빠뜨리는 것이 오버런이다.**
`to`는 `byte_len`이 이미 세는 공간의 값이므로 **두 내장이 같은 단위를 쓴다.**

> ⚠ **그래도 이것이 이 슬라이스의 함정이다.** `byte_slice(s, 2, 3)`은 **1바이트**이지
> 3바이트가 아니다. 이 저장소가 *"같은 이름, 다른 단위"* 로 세 번 데인 그 자리다
> (`ml_cap` 바이트 vs 원소 · `ml_needed` NUL 포함 vs `byte_len` NUL 제외). 완화책 둘을 둔다:
> **(1)** 이름이 `to`라고 말한다(생성 `.h` 주석에도), **(2)** `from`·`to`가 **둘 다 리터럴**이고
> `to < from`이면 **컴파일 타임에 거부**한다(수용 E).

### 2.3 표면 — **내장 함수이고 `s[a..b]`가 아니다** (DP-B3)

실측: `s[0..3]`은 **렉서**가 막는다 — *"ranges are not in Mathless yet — `..` is not part of
the language"*. 즉 `s[a..b]`를 열려면 **언어 전체에 `..`를 들이는** 결정이 된다(`for` 범위,
배열 슬라이스가 따라온다). 그것은 이 슬라이스보다 훨씬 큰 결정이다.

선례도 같은 방향이다: `byte_len`도 `s.len`이 아니라 **내장**으로 갔고, 이유는 같았다 —
**이름이 설계이고, 문법을 열면 되돌리기 어렵다.**

`s[i]`도 그대로 둔다(오늘 *"'s' is string, not an array"* 로 거부된다).

### 2.4 범위 밖 — **실패한다, 자르지 않는다** (DP-B4)

| 조건 | 결과 |
|---|---|
| `from < 0` 또는 `to < from` | **`ML_ST_INDEX_OUT_OF_RANGE`** (리터럴이면 컴파일 타임, §2.2) |
| `to > byte_len(s)` | **`ML_ST_INDEX_OUT_OF_RANGE`** |
| `from == to` | **성공**, 빈 문자열, `*ml_needed = 1`(NUL) |

**자르지 않는(clamp) 것이 결정의 일부다.** clamp는 이 저장소가 네 번 닫은 **조용한 오답**이고,
D17이 음수 status를 둔 이유다. 상수는 **배열 인덱싱과 같은 것을 재사용한다**(`= -2`) — 뜻이
같다(*"값 밖의 것을 달라고 했다"*), 호스트 문서·헤더·가드가 이미 그것을 안다.

> **검사가 쓰기보다 먼저다.** 범위 검사는 **1패스**에서 끝난다. Q12는 실패한 호출이
> 버퍼를 건드리지 않게 하고, `SPEC-array-return`의 `result n`이 같은 이유로 존재한다.
> **canary 전 바이트로 측정한다**(수용 D).

### 2.5 **길이로 끊는 writer가 필요하다** — 이 슬라이스의 진짜 위험

오늘 방출되는 writer는 **전부 소스의 NUL에서 멈춘다**:

| 헬퍼 | 멈추는 조건 |
|---|---|
| `ml_strout(src, …)` | `src`의 NUL |
| `ml_wstr(buf, off, src, cap)` | `src`의 NUL **또는** `cap - 1` |

**그래서 `byte_slice`를 "빌린 포인터 `s + from`"으로 낮추고 기존 writer를 재사용하면
`to`가 무시되고 접미사 전체가 나간다.** status는 `0`, 경고 없음 — **조용한 오답**이고,
`SPEC-array-return`의 `[bool]` 폭 결함(`TFFF`)과 같은 모양이다.

따라서 **새 헬퍼**를 방출한다: `ml_wsub(buf, off, src, from, n, cap)` — **`n`바이트를 복사하고
NUL을 보지 않는다.** 1패스의 길이 기여분도 `to - from`이지 *"NUL까지 세기"* 가 아니다.

> ⚠ **기본값이 틀린 경로가 둘이다 (실측).** 새 IR 종류를 추가하고 아무것도 더 하지 않으면
> **두 곳 모두 조용히 접미사를 낸다**:
>
> | 경로 | 오늘의 기본값 | 낳는 것 |
> |---|---|---|
> | `return byte_slice(…)` | `IrStmt::Return`의 **포괄 팔**이 `ml_strout`으로 보낸다 | 접미사 |
> | `return byte_slice(…) + "-"` | `piece_kind`의 **포괄 팔**이 `PieceKind::Bytes` → `ml_wstr` | 접미사 |
>
> **두 팔을 다 쪼개야 한다.** 하나만 고치면 나머지 하나가 초록으로 남는다.

**수용 C와 J가 이 오답을 각 경로에서 겨냥한다**: 둘 다 **슬라이스보다 긴 소스**를 쓰고
결과 길이를 값으로 확인한다.

### 2.6 **빌트 문자열이다** — `is_built_string`에 반드시 넣는다 (DP-B5)

`is_built_string`은 **빠짐없는 match**이고 모든 팔이 일부러 손으로 적혀 있다. 새 IR 종류가
거기서 **`true`를 답하지 않으면** `reject_built_string`이 지키는 자리가 전부 뚫린다 —
인자 자리와 `byte_len`.

**이것은 #224에서 실제로 난 구멍이다**: `byte_len`이 `reject_built_string`을 부르지 않아
`byte_len(x as string)`이 **`.dll`까지 컴파일됐다.** 같은 자리이므로 **수용 K가 거부를 못박는다.**

### 2.7 위치 — `return` 자리 (기존 규칙 상속, 단 기제는 더 넓다)

`let t = byte_slice(...)`는 거부된다. **§0.3이 정정한 대로** 그 거부는 `reject_built_string`이
아니라 **`string` 지역 변수 전면 금지**에서 온다. 새 규칙을 만들지 않는다.

합성은 된다: `return byte_slice(s, 0, 3) + "-"` — 연결의 두 패스에 조각 하나로 들어간다(수용 J).

## 3. 수용 기준 (측정 가능)

**모두 실제 로드된 모듈에서 잰다(E2).** 논증으로 닫지 않는다 — `SPEC-string-length`가
수용 D를 그렇게 닫았다가 정정했다(§9-41).

- **A. 값.** `byte_slice(c"1234567890", 0, 3)` → `"123"`, status `0`.
- **B. 끝까지.** `byte_slice(s, 7, byte_len(s))` → 마지막 3바이트.
- **C. 접미사가 아니다.** 긴 문자열에서 `byte_slice(s, 0, 3)`의 결과 **길이가 3**이다.
  (§2.5의 조용한 오답을 정면으로 겨냥한다. 이 하나가 없으면 잘못된 lowering이 초록으로 통과한다.)
- **D. 범위 밖은 한 바이트도 쓰지 않는다.** `to > byte_len(s)` → `-2`, **버퍼 전 바이트 canary 유지**.
- **E. `to < from`.** 리터럴이면 **컴파일 거부**(진단이 두 값을 다 말한다), 변수면 `-2`.
- **F. 빈 슬라이스.** `from == to` → `""`, status `0`, `*ml_needed == 1`.
- **G. Q12 probe.** `ml_cap = 0` → `-1`이고 `*ml_needed`가 **정확**하며, 그 값으로 재시도하면 성공.
- **H. 바이트는 문자가 아니다.** `"한국"`에서 `byte_slice(s, 0, 3)`은 **3바이트**(`한`),
  `byte_slice(s, 0, 2)`는 **깨진 2바이트**. DP-B1의 대가를 **측정**한다.
- **I. 보호 프록시 무변경.** export **3개**, import 집합이 스칼라 베이스라인과 **동일**
  (`strlen`·`memcpy`가 늘지 않는다). **테스트로 고정한다** — 일회성 `dumpbin`은 가드가 아니다.
- **J. 합성 — 그리고 여기서도 소스가 슬라이스보다 길다.** `byte_slice(s, 0, 3) + "-"`가
  `"123-"`이고 **길이 4**다. **소스를 슬라이스보다 길게 두는 것이 수용 기준의 일부다** —
  `byte_slice(c"123", 0, 3)`처럼 딱 맞는 소스를 쓰면 **NUL로 끊는 writer도 같은 답을 내므로
  J가 초록인 채 연결 경로만 틀려 있을 수 있다**(검증이 짚었다). C가 독립 경로를, J가 연결
  경로를 맡는다.
- **K. 거부(§3.1).**
- **L. 호스트 두 곳.** 오라클 + **실제 C 호스트**(수용 D 게이트)에서 같은 값.

> **닫힌 자리 (2026-09-13 실측).** 지난 슬라이스가 수용 하나를 재지 않고 "전부"라고 적었으므로,
> 각 기준을 **무엇이** 닫았는지 적는다.
>
> | 수용 | 닫은 것 |
> |---|---|
> | A·B·F | `a_span_is_the_bytes_between_the_offsets` (오라클) |
> | **C·J** | `a_span_is_not_the_suffix` — **소스가 스팬보다 길다**, 독립·연결 두 경로 |
> | D·E(런타임) | `an_out_of_range_span_writes_nothing` — canary 전 바이트 + `*ml_needed` 미변경 |
> | E(컴파일 타임) | `a_literal_backwards_span_is_refused_before_it_runs` (컴파일러) |
> | G | `the_probe_protocol_works_for_a_span` — `cap=0` probe → 정확한 `needed` → 재시도 성공 |
> | H | `a_span_cuts_bytes_not_characters` — `한국`에서 2바이트는 **UTF-8이 아니다**(실측) |
> | I | `a_span_adds_no_import_over_a_concatenating_baseline` — **테스트로 고정**, 일회성 덤프 아님 |
> | K | `byte_slice_refuses_*` 넷 (컴파일러) |
> | **L** | **`hosts/c-host/host.c`의 `account.dll` 블록** — 게이트 모듈 18 → **19**개 |

### 3.1 반드시 거부되는 것

| 소스 | 이유 |
|---|---|
| `let t = byte_slice(s, 0, 3)` | `string` 지역 변수 (§2.7) |
| `byte_len(byte_slice(s, 0, 3))` | 빌트 문자열을 읽으려 한다 (§2.6) |
| `g(byte_slice(s, 0, 3))` | 빌트 문자열을 인자로 (§2.6) |
| `byte_slice(xs, 0, 3)` (배열) | 진단이 **`s`가 문자열이어야 한다**고 말한다 |
| `export fn byte_slice(...)` | 이름 충돌 — `byte_len`과 같은 검사 |
| `s[0..3]` | 그대로 렉서가 거부 (§2.3) |

## 5. 범위 밖 / 위험

### 5.1 이 슬라이스가 고치지 않는 것

- **탐색·비교·변환**: `index_of`, `starts_with`, 대소문자. DP-S3는 **한 번에 한 연산씩** 연다.
- **문자 단위**: DP-S2가 열리기 전에는 불가능하다.
- **지역 변수**: 할당자가 없다(D16). 별도 결정이다.
- **`s[a..b]` 문법**: DP-B3가 미룬다. 나중에 열더라도 §2.2의 반열림 뜻이 **같아서** 충돌하지 않는다.

### 5.2 이 슬라이스가 만드는 새 위험

| 위험 | 막는 것 |
|---|---|
| **접미사 오답** — NUL로 끊는 writer 재사용, **경로 둘** | §2.5의 `ml_wsub` + **수용 C**(독립) + **수용 J**(연결, 소스가 더 길 것) |
| **오버런** — `to`를 길이로 읽음 | §2.2의 이름 + 리터럴 거부 + **수용 E** |
| **깨진 문자** — 바이트 경계 | **수용 H**가 재고 `LANGUAGE.md`가 적는다 |
| **빌트 문자열 누수** — `is_built_string` 누락 | §2.6 + **수용 K** (#224의 재발 방지) |
| **부분 쓰기** — 실패했는데 버퍼가 더럽다 | **수용 D**의 canary |

## 6.1 구현 중 실측이 잡은 것 (2026-09-13, E2)

넷이다. **전부 "그럴 것이다"로 적고 재지 않은 자리**이며, 이번에는 **하나도 초록으로 새지 않았다**
— 넷 중 셋을 컴파일러·테스트가 먼저 잡았다.

| # | 무엇 | 어떻게 드러났나 |
|---|---|---|
| 1 | **`-1`은 `ConstI32`가 아니다.** 파서가 **단항 부정**으로 만든다(`(1i32).wrapping_neg()`) | DP-B2의 컴파일 타임 완화가 `byte_slice(s, -1, 2)`를 **통과시켰다.** 테스트가 빨개졌고, 부정 하나를 접는 것으로 고쳤다. 런타임은 원래 안전했지만 **진단이 status로 강등돼 있었다** |
| 2 | **반환 문자열 모양 검사를 빠뜨렸다.** WBS가 세 자리를 적었는데 넷째가 있었다 | `a returned string must be a literal, a string parameter, or a concatenation…` 이 `byte_slice`를 거부했다. 컴파일 에러가 아니라 **테스트 실패**로 나왔다 |
| 3 | **거부 needle이 §7-3의 함정에 걸려 있었다.** `contains("byte_slice")`는 *"unknown function 'byte_slice'"* 도 만족한다 | **첫 Red의 메시지를 읽어서** 잡았다 — 개수만 봤으면 구현 없이 초록이 될 자리가 있었다. 모든 거부에 `!contains("unknown function")`을 더했다 |
| 4 | **`memcpy`는 베이스라인에도 있다.** 모든 cdylib의 DllMain 뼈대다 | import 금지 목록에 넣었다가 **정상 모듈에서 빨개졌다.** 집합 동일성이 진짜 가드이고 금지 목록은 덤이라는 것을 주석에 적었다 |

### 6.2 접미사 오답을 **심어 봤다**

§2.5가 이 슬라이스의 진짜 위험이라고 적은 것을, 방출기를 NUL 기준으로 되돌려 실제로 만들어 봤다:

```
__n += ml_slen(__s0);                         (틀린 1패스)
__o = ml_wstr(ml_buf, __o, __s0, ml_cap);     (틀린 2패스)
```

**오라클 6개 중 4개가 빨개졌고**, `a_span_is_not_the_suffix`가 정확히 그 문장으로 실패했다 —
*"a NUL-bounded writer would size this at 11 — the whole string plus its NUL"*.

> **그리고 둘은 초록으로 남았다**(범위 테스트와 import 테스트). **검증이 짚은 그대로다**:
> 소스가 스팬보다 **길어야만** 이 오답이 보인다. C 호스트 게이트도 같은 방식으로 깨 봤다 —
> 기대값을 접미사로 바꾸니 `FAIL bank_code cuts three bytes, not the whole string`.

## 7. 정직한 반론 (기록)

- **§7은 이것을 강제하지 않았다.** 감사 표본에서 **결합** 잣대로 열리는 것이지, 능력 잣대로
  강제되지 않는다. `SPEC-string-length` §0.3과 같은 단서다.
- **DP-S3를 세 번째로 여는 것이다**(연결 #108, 길이 #224, 그리고 이것). 범위는 여전히
  **한 번에 한 연산씩** 넓힌다 — 그 규율이 이 문서의 §5.1이다.
- **`byte_slice(s,2,3)` 함정은 완화되지만 없어지지 않는다.** 리터럴만 컴파일 타임에 잡히고,
  변수는 런타임 `-2`다. 이것을 **대가로 적는 것**이 DP-B2의 조건이다.

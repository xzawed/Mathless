## 1. 목표

부호 있는 32비트 정수 타입 **`i32`**를 `f64`/`bool` 옆에 추가한다. C `int32_t` / Delphi
`Integer` / Rust `i32`로 매핑되는 FFI-안전 스칼라. Grok 권장대로 `i32`를 대입(`let mut`)보다 먼저
넣는다 — 더 작은 슬라이스이고, D17 status가 이미 `i32`라 ABI에 얹혀 있으며, 이후 `let mut`을
타입 있게 만든다.

기준 함수:

```text
export fn add(a: i32, b: i32) -> i32 {
  let sum = a + b
  return sum
}
```

## 2. 계약 (Contracts)

### 2.1 표면 `.mls`

- **타입 `i32`**를 파라미터·반환·지역 변수 위치에 사용.
- **정수 리터럴**(숫자, 소수점 **없음**) → `i32`. **실수 리터럴**(소수점 있음, 예 `0.9`) → `f64`. (DP-I1)
- `i32` 산술 `+ - *`과 비교(`< > <= >= == !=`). **`i32` 나눗셈 `/`는 이 슬라이스에서 타입체크가
  명시적으로 거부**한다(codegen이 Rust `i32 /`를 방출하지 못하게 — DP-I3: `i32 /0`은 abort).
  안전한 `/`는 D17 실패 경로와 함께 후속. (`f64 /`는 그대로 허용 — `f64 /0`은 `inf`로 정의됨.)
- **암시적 `i32`↔`f64` 변환 없음**: 한 연산자에 두 타입을 섞으면 타입 에러(DP-I2). 캐스트는 후속.

### 2.2 모듈 ABI

- `i32` → C `int32_t`, Delphi `Integer`, Rust `i32`. FFI-안전.
- `-> i32`는 값을 직접 반환. `-> i32!`(실패 가능)는 D17대로 `int32 status` + `int32_t* out_value`.
- **오버플로는 wrap**(release/opt-z 기본 — overflow-checks off, MVP). 체크드 산술은 후속(DP-I4).
- 기존 `f64`/`bool` 경로·export·strip 프록시는 **불변**(소수점 리터럴은 여전히 `f64`).

### 2.3 리터럴 규칙 변경 명시

- 지금까지 소수점 없는 숫자(`100`)는 `f64`로 취급됐다. **이 슬라이스부터 소수점 없는 리터럴은
  `i32`**가 된다(DP-I1). 현재 `.mls` 예제·테스트는 f64에 항상 소수점을 쓰므로(`0.9`, `100.0`은
  Rust 호출 측) 회귀는 없으나, 이 의미 변경을 명시한다.

## 3. 수용 기준 (측정 가능)

- **A. 컴파일:** `examples/add.mls` → `mlc build` → `add.dll`.
- **B. 로드·호출 (오라클):** `mlx_add(2, 3) == 5`, `mlx_add(10, -4) == 6`(음수 리터럴 경유), `abi==1`.
- **C. 바인딩·보호:** `.h`에 `int32_t mlx_add(int32_t a, int32_t b);`, `.pas`에 `Integer`.
  export = 정확히 `mlx_add` + `ml_module_abi_version`. strip 유지.
- **부정(타입체크) 케이스:**
  - `i32`와 `f64` 혼합: `export fn f(a: i32) -> i32 { return a + 1.0 }` → 타입 에러(혼합)
  - 반환 타입 불일치: `export fn f() -> i32 { return 1.0 }` → 에러(f64를 i32 위치에)
  - `i32` 나눗셈 거부: `export fn f(a: i32) -> i32 { return a / 2 }` → 타입 에러(이 슬라이스 `i32 /` 미지원)
  - `f64` 경로 유지: `export fn g(x: f64) -> f64 { return x * 0.9 }` 정상(`f64 /`도 허용)
- **D. D14 게이트:** i32는 스칼라 → 별개, 수용 D는 BLOCKED로 무관.

## 4. 설계 제안 (DP — **확인됨**; Grok 권장안 그대로 채택, PR #31로 구현)

| DP | 선택지 | 권장 | 근거 |
|----|--------|------|------|
| **I1 리터럴 타입** | 소수점無=i32 / 有=f64 vs 접미사(`1i32`/`1.0f64`) vs 문맥 추론 | **소수점 유무** | C 유사·접미사 없음·단순. 소수점 없는 리터럴의 의미 변경은 §2.3에 명시 |
| **I2 혼합** | 암시적 변환 없음(혼합=에러) vs 자동 승격 | **혼합 에러** | 명확·안전; 캐스트는 별도 후속 슬라이스 |
| **I3 나눗셈 `/`** | 이 슬라이스 포함 vs **제외** | **제외** | `i32 /0`은 Rust에서 패닉→abort(호스트 크래시). 안전 `/`는 D17 실패 경로와 함께 후속 |
| **I4 오버플로** | wrap(release, MVP) vs 체크드 | **wrap + 명시** | opt-z 기본 동작; 체크드/새추라팅은 후속 |

## 5. 범위 밖 / 미검증

- `i32`↔`f64` 캐스트, `i32` 나눗셈 `/`·나머지 `%`, `i64`/`u32` 등 다른 폭, 체크드 오버플로.
- 어떤 항목도 측정 전까지 "확정/동작"으로 서술하지 않는다.

**D17 확정 상세에 반영된 문구(Q13):**

> D17 status 체계 = **평탄 i32**: `0`=성공 / **양수**=모듈 정의 도메인 에러 / **음수**=예약(런타임·ABI).
> 실패 가능성은 **명시적 `!` 표식**(`-> T!`)으로 시그니처에 고정. 도메인 코드는 `error NAME = N`
> (양수) 선언 + `fail NAME` 문. 실패 시 out-param 미변경(호스트는 status≠0이면 out 미판독).
> 기각: HRESULT식(무겁·Windows 중심), 0/음수 무구조(의미 비트 부족). (2026-08-28 사용자 확정,
> D17 슬라이스로 구현·실측: SPEC #14 / 구현 #15.)

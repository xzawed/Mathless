# Slice SPEC — 나눗셈 가드가 왼쪽 피연산자를 건너뛴다

> **상태: 초안 · 사용자 확인 전** — §4의 DP-G1~G5가 확인되면 §6 WBS로 착수한다.
> **근거 수준:** §0이 **E2 실측**(방출된 Rust + 실제로 빌드해 로더로 호출한 모듈, 대조군 포함).
> **선행:** `#76`(`i32 /`·`%` 전역화) · `#200`(배열 입력 — 식 자리 조기 반환을 들여온 것) ·
> `STATUS.md` **§5-6**(이 결함의 실측 기록) · `SPEC-fallible-calls` §5.3(2026-09-01의 예견).
> **이 슬라이스는 언어 표면을 넓히지 않는다** — `.mls` 문법은 한 글자도 바뀌지 않는다.

관련: **D17**(status/에러) · **DP-N4**(`i32 /0`은 정의된 결과) · **DP-I4**(i32 산술은 wrap).

---

## 0. 왜 — 측정부터

### 0.1 한 자리에 결함이 둘 있다 (E2, 2026-09-23)

`#76`이 `i32`의 `/`·`%`를 **전역(total)** 으로 만들며 0 제수를 막는 보호막을 넣었다.
`compiler/src/codegen.rs`가 방출하는 모양:

```rust
{ let __d = <rhs>; if __d == 0 { 0i32 } else { (<lhs>).wrapping_div(__d) } }
```

같은 파일의 `*`·`+`·`-`는 이렇게 낸다:

```rust
(<lhs>).wrapping_mul(<rhs>)
```

**둘을 나란히 놓으면 `/`·`%`만 다른 것이 둘이다.**

1. **오른쪽을 먼저 평가한다.** `__d`가 먼저 묶인다. `wrapping_mul` 쪽은 왼쪽이 **수신자**라
   Rust가 왼쪽부터 평가한다 — 소스 순서와 같다. `/`·`%`만 뒤집혀 있다.
2. **왼쪽을 건너뛸 수 있다.** 왼쪽이 `else` 안에 있으므로 **제수가 0이면 평가되지 않는다.**

`#200` 전에는 둘 다 관측 불가능했다. 식 자리에서 **조기 반환할 수 있는 표현이 없었기** 때문이다.
오늘은 있다 — 배열 인덱싱이 `ML_ST_INDEX_OUT_OF_RANGE`를 식 자리에서 반환한다.

### 0.2 그래서 오늘 호스트가 받는 것

```text
export fn pick(xs: [i32], i: i32, d: i32) -> i32! { return xs[i] / d }
```

실제로 빌드한 모듈을 로더로 호출했다(`xs`는 원소 3개):

| 호출 | status | 값 | |
|---|---|---|---|
| `pick(i=1, d=2)` | `0` | `10` | 정상 |
| `pick(i=999, d=2)` | **`-2`** | — | **대조군 — 경계 검사는 작동한다** |
| `pick(i=1, d=0)` | `0` | `0` | DP-N4대로 |
| `pick(i=999, d=0)` | **`0`** | **`0`** | ← **결함** |
| `pick(i=-1, d=0)` | **`0`** | **`0`** | ← **결함** |

**대조군이 요점이다.** 같은 인덱스가 제수 2에서는 거부되고 제수 0에서는 거부되지 않는다.
호스트가 보는 것은 *"성공했고 답은 0"* 이다 — `SPEC-iface-hash` §0.1이 슬라이스 하나를 열게
만든 **그럴듯한 오답**의 모양이고, 이번에는 인터페이스가 아니라 **한 식 안에서** 생긴다.

### 0.3 범위 — 넓지 않다 (E2)

방출된 Rust를 읽어 확인했다:

| 자리 | 오늘 | 근거 |
|---|---|---|
| `xs[i] / d` · `xs[i] % d` | **영향받는다** | 경계 검사가 `else` 안 |
| `xs[i] * d` · `+` · `-` | 영향 없다 | 피연산자가 수신자·인자로 **무조건** 평가된다 |
| `n / xs[i]`(인덱스가 오른쪽) | 영향 없다 | `__d`로 **먼저** 묶이므로 검사가 실행된다 |
| `try f(x) / d` | 해당 없다 | 파서가 거부한다(`try`는 식이 아니다) |

그리고 식 자리에서 조기 반환하는 표현은 오늘 **정확히 둘**이다 —
배열 인덱싱(`codegen.rs:771`)과 문자열 부분 비교(`:1017`). **`i32` 값을 내는 것은 인덱싱뿐**이므로
`/`·`%`의 왼쪽에 올 수 있는 것도 인덱싱뿐이다.

### 0.4 이 부채는 2026-09-01에 이미 적혀 있었다

`SPEC-fallible-calls` §5.3:

> *"`i32` 나눗셈의 오른쪽-먼저 평가: §2.2가 **도달 불가능**하게 만들 뿐 고치지는 않는다.
> 식 위치를 여는 날 먼저 고쳐야 한다."*

**맞는 예견이었고, 문이 예상한 쪽에서 열리지 않았다.** 그 줄은 `try`가 식 자리에 오는 날을
기다렸는데, 실제로 연 것은 `#200`의 배열 인덱싱이었다. `STATUS.md` §5-1이 다섯 슬라이스에 걸쳐
열려 있던 것과 **같은 모양의 실패**다 — 부채가 *무엇이 오면 달라지는지*를 적어 뒀고, 그것이
왔을 때 그 줄을 다시 읽은 사람이 없었다.

---

## 1. 목표

1. `i32`의 `/`·`%`가 **왼쪽 피연산자를 항상 평가한다.** 제수가 0이어도 마찬가지다.
2. 피연산자 평가 순서가 **소스 순서(왼쪽 → 오른쪽)** 가 된다 — 다른 산술 arm과 같아진다.
3. **DP-N4는 그대로다.** 0 제수는 여전히 정의된 값 `0i32`를 내고 패닉하지 않는다.
4. 위 §0.2의 두 줄이 **`-2`로 바뀌는 것을 실측으로 보인다.**

**목표가 아닌 것:** `/0`을 실패 가능 연산으로 바꾸는 것(§4 DP-G1이 기각한다), 다른 정수 폭,
`f64` 나눗셈(포화·`inf`이므로 이 결함이 없다).

## 2. 계약 (Contracts)

### 2.1 표면 `.mls` — **변화 없음**

문법도, 타입 규칙도, 진단도 바뀌지 않는다. **오늘 컴파일되는 프로그램은 전부 계속 컴파일된다.**

### 2.2 의미

- **피연산자는 왼쪽부터 평가한다.** 이항 연산 `a OP b`에서 `a`가 먼저, 그다음 `b`다.
  이것은 이미 `*`·`+`·`-`·비교의 동작이며, 이 슬라이스가 `/`·`%`를 거기에 맞춘다.
- **`&&`·`||`는 예외다** — 단락 평가는 명시된 설계이고(`SPEC-logical-ops` §2.3) 바뀌지 않는다.
- **`/`·`%`의 0 제수는 `0` 이다**(DP-N4). 바뀌지 않는다.
- 따라서 **왼쪽 피연산자의 조기 반환은 제수와 무관하게 일어난다.**

### 2.3 codegen

```rust
{ let __l = <lhs>; let __d = <rhs>; if __d == 0 { 0i32 } else { __l.wrapping_div(__d) } }
```

`%`도 같은 모양(`wrapping_rem`). 바뀌는 것은 **왼쪽을 `__d` 앞에서 묶는 것 하나**다.

### 2.4 ABI — **변화 없음**

export 집합·시그니처·헤더·유닛 텍스트는 그대로다. `.text`는 바뀔 수 있고(§3-F), **크기를
주장하지 않고 기록만 한다**(`SPEC-export-wrappers` DP-W5와 같은 태도).

> 예제들이 이미 매 실행 측정하고 있다. 이 슬라이스가 바꾼 것은 **언제 왼쪽을 평가하는가**이고
> 그것은 **codegen 층의 성질**이지 ABI 층의 성질이 아니다.
>
> **그래서 실측은 두 층에 둔다:** 값은 `hosts/rust-oracle/tests/division_guard_operands.rs`가
> 실제 모듈을 로드해 대조군과 함께 재고(Windows), 방출 모양과 순서는
> `compiler/tests/division_guard.rs`가 잰다(**양쪽 CI 잡**, 모듈을 빌드하지 않는다).
>
> **적어 두는 이유:** 하지 않은 것을 적지 않으면 다음 감사가 "수용 A가 미충족"으로 읽는다.
- **B. 결함이 사라진다(오라클):** `pick(xs, 999, 0)`·`pick(xs, -1, 0)`이 **`-2`** 를 반환한다.
  오늘은 둘 다 `0`이다 — **일부러 깨서 빨간 것을 먼저 본다.**
- **C. 대조군 셋이 그대로다:** `pick(xs, 1, 2)` = `10`/status 0 · `pick(xs, 999, 2)` = `-2` ·
  `pick(xs, 1, 0)` = `0`/status 0(**DP-N4가 유지된다는 증거**).
- **D. `%`도 같다:** 위 B·C를 `%`로 한 번 더.
- **E. 순서는 방출 텍스트로 고정한다.** 값으로는 순서를 구별할 수 없다 — 오늘 식 자리의 실패는
  `-2` 하나뿐이라 왼쪽·오른쪽 어느 쪽이 먼저 실패해도 같은 status다. 그래서 `__l`이 `__d`보다
  **앞에 묶이는지**를 생성 Rust 골든으로 단언한다. *(값으로 재지 못한다는 것을 적어 두는 이유는
  §7 "없는 측정을 테스트로 만들지 않는다" 때문이다.)*
- **F. ABI 불변 + `.text` 기록:** 예제 전부의 `.h`·`.pas` 바이트 동일, export 집합 동일.
  `.text` 증가분은 **기록만** 한다.
- **G. 부정 케이스(컴파일 타임):** 없다. **타입체커·파서의 거부 집합이 한 건도 바뀌지 않는다** —
  오늘 컴파일되는 프로그램은 전부 계속 컴파일되고, 새로 거부되는 소스는 없다. 그것 자체가 확인
  대상이다.
  > **축을 나눠 적는 이유:** 이 문서는 **런타임 status `-2`도 "거부"** 라고 부른다(§0.2의 표).
  > 그쪽 거부는 **늘어나는 것이 목표**다(§3-B). 두 축을 한 단어로 쓰면 G가 B와 어긋나 읽힌다 —
  > 검증이 짚었고 맞다.

> **가드 하나를 같이 고쳐야 한다.** `doc_claims.rs`의

## 5. 범위 밖 / 미검증

- **`f64` 나눗셈.** `0.0`으로 나누면 `inf`·`NaN`이고 조기 반환이 없다 — 이 결함이 성립하지 않는다.
- **다른 정수 폭.** 오늘 `i32`뿐이다.
- **문자열 부분 비교가 조기 반환하는 자리.** `bool`을 내므로 `/`·`%`의 피연산자가 될 수 없다.
  `&&`·`||`의 피연산자는 될 수 있고, 거기서는 **단락 평가가 명시된 설계**다
  (`SPEC-logical-ops` DP-B2 — *"오늘 관측 불가라는 게 미지정으로 두라는 뜻은 아니다"*).
- **평가 순서를 값으로 재는 것.** §3-E에 적은 대로 오늘은 불가능하다. 식 자리의 실패가 둘 이상
  생기는 날 다시 볼 수 있다 — 그날 이 문단을 다시 읽으라고 적어 둔다.
- 어떤 항목도 측정 전까지 "확정/동작"으로 서술하지 않는다.

### 9-50. 이번 세션이 만든 것을 감사했다 (2026-09-14, E2) — **약속보다 적게 말하는 바인딩**

사용자가 *"발견된 내용을 보강 또는 취약점을 해소"* 하라고 했다. 이번 세션이 **적어만 두고 닫지
않은 자리**를 재니 셋이 나왔고, 그중 하나는 **호스트 대상 계약이 실제보다 좁게 말하고 있었다.**

#### 9-50.1 `-2`를 내는데 바인딩이 그 이름을 안 준다 (실측 → 고침)

```
export fn is_ab(c: string) -> bool! { return byte_slice(c,0,2) == "AB" }
```

| 무엇 | 실측 |
|---|---|
| 이 함수가 내는 status | **`-2`** (`mlprobe`로 확인) |
| `.h` 안의 `ML_ST_INDEX_OUT_OF_RANGE` | **0개** |
| `.pas` 안의 그것 | **0개** |

헤더 자신의 주석이 이 상황을 이미 비판하고 있었다 — *"A host that had to retype `-2` is a host
holding a number the header never promised."*

**원인은 게이트의 질문이었다.** 두 바인딩이 *"이 모듈이 배열을 인덱싱하는가"* 로 물었는데, 그것이
*"이 모듈이 `-2`를 낼 수 있는가"* 와 같은 질문이기를 **#235가 그만두게 했다.** 하나의 술어
(`can_report_out_of_range`)로 합쳐 둘이 **같은 모듈에 대해 다른 약속을 할 수 없게** 했다.

#### 9-50.2 `result` 이후의 `-2` — "유일한"이 처음부터 틀렸다

`SPEC-array-return` DP-R9가 *"남는 유일한 런타임 실패는 `result[i]` 범위 이탈"* 이라고 적었고
`HOST_ABI.md` 각주가 *"남는 것은 자기가 선언한 길이 밖에 쓰는 저자의 버그뿐"* 이라고 안심시켰다.
**셋이다:**

| 자리 | 언제부터 |
|---|---|
| 선언한 길이 밖에 쓰기 | 처음부터 |
| **입력 배열**을 범위 밖에서 읽기(`result[0] = xs[99]`) | **처음부터** — 열거가 **쓰일 때 이미 좁았다** |
| **스팬 비교**가 문자열 밖 | 2026-09-13 (#235) |

규칙을 **목록에서 성질로** 바꿨다: *"`result` 뒤에 평가되는 경계 검사 연산은 무엇이든 `-2`를 낼
수 있다."* 목록은 낡지만 성질은 낡지 않는다.

#### 9-50.3 그리고 검증이 **내 발견보다 날카로운 것**을 댔다

> *"status 표가 모든 음수를 절단으로 이름 붙이고 `*needed`를 재시도 크기로 제시하므로,
> `result n` 이후의 `-2`는 '`*ml_needed`만큼 할당해 재시도하라'처럼 보인다."*

**실측했다.** `status = -2`, `needed = 2`이고, **`needed`만큼 할당해 다시 불러도 똑같다.**
즉 `status < 0`으로 분기하는 호스트는 **수렴하지 않는 재시도 루프**에 들어간다.

`an_out_of_range_after_result_is_not_a_short_buffer`가 그것을 **측정으로** 못박는다 —
세 경로 전부, 그리고 재시도가 같은 답을 준다는 것까지. **재시도 조건은 `status < 0`이 아니라
`status == ML_ST_INSUFFICIENT_BUFFER`다.**

#### 9-50.4 보강 둘

| 무엇 | 그 전 | 지금 |
|---|---|---|
| `mlprobe`의 지문 검사 | 심볼이 **있는지**만 봤다 | **값을 비교**한다. 깨서 확인: 지문을 `^1` 하자 `interface 0x…8A != … 0x…8B` |
| `ml_subeq`의 파라미터 길이 불일치 | 수용 B가 **리터럴로만** 쟀다 | 파라미터로 양방향 + 빈 문자열까지 |

#### 9-50.5 첫 수정이 **여전히 좁았다** — 검증이 둘을 더 댔다

> *"The new single predicate still ignores `return byte_slice` and `result[i]` OOR, so both
> bindings can still omit the name of a `-2` the module returns."*

**둘 다 실측으로 확인됐다**(`.h`에 `-2`가 **0개**인데 함수는 낸다):

| 빠진 구성 | `-2`를 내는 자리 |
|---|---|
| `return byte_slice(s,0,3)` | `emit_concat_return`의 `ml_sublen` bail |
| `result[9] = 1` | `ResultSet`의 경계 검사 — **SPEC이 THE 예로 든 바로 그것** |

**게이트를 넓히는 대신 질문을 바꿨다.** `ir.rs`의 `can_fail_out_of_range`가
**IR에 대해 빠짐없이** 답한다 — 새 변종이 `-2`를 낼 수 있으면 **크레이트가 빌드되지 않는다.**
`Cargo.toml`이 `wildcard_enum_match_arm`을 deny한 이유와 같은 기계다.

**가정이 아니었다**: 골든이 두 모듈을 고쳤고 그중 하나가 **출하되는 예제 `schedule`** 이다 —
`-2`를 낼 수 있는데 바인딩이 그 이름을 주지 않고 있었다.

그리고 검증의 마지막 한마디(*"`result n` 이후의 `-2`는 호스트 버퍼가 이미 0으로 채워진 상태인데
그 테스트가 그것을 안 본다"*)도 측정에 넣었다 — 계약이 *"쓰이지 않는다"* 가 아니라
**"정의되지 않는다"** 인 이유가 그것이다.

> **이번 감사에서 배운 것**: 결함 다섯이 전부 *"그 구성이 답해야 할 게이트를 하나 빠뜨렸다"* 는
> 같은 모양이다 — 헤더 게이트(두 번), 문서의 열거, 지문 검사, 그리고 미측정 경로.
> **#235가 컴파일러 안에서는 여덟 곳을 강제로 답하게 했지만, 바인딩과 문서는 컴파일러가 묻지
> 않는다.** 그래서 이번에 한 일은 **바인딩의 질문을 IR 위로 옮겨** 컴파일러가 묻게 만든 것이다.

# HOST ABI

> **이 문서는 합의된 ABI 설계를 현재형으로 기술한다. 전부 구현된 것은 아니다.**
> 오늘 실제로 존재하는 경계는 아래 "현재 구현된 경계" 절이 정본이고, 아직 만들지 않은 항목에는
> **⏳ 미구현**을 붙였다. 결정(D16·D18 등)의 기록으로 남기려고 문장을 미래형으로 바꾸지는 않았다.

## 원칙

밖으로 나가는 유일한 1급 경계는 **C ABI**다.  
언어별 바인딩은 그 위의 얇은 래퍼다.

## MVP에서 호스트가 하는 일

1. 런타임/로더 초기화
2. 모듈 파일 로드
3. export 함수 조회
4. 호출
5. (선택) 호스트 함수를 모듈에 등록 — **⏳ 미구현**
6. 언로드

## 현재 구현된 경계 (2026-09-01 실측)

아래 "최소 C API 스케치"는 **⏳ 미구현**이다 — 하나도 구현되지 않았다. 지금 실제로 동작하는 경계는 그보다 얇다:

- 호스트가 OS 로더로 직접 모듈을 연다. **Windows만 실측했다** — `.so`/ELF와 `dlsym` 경로는 ⏳ 미구현(D22 미개시). (Rust 오라클은 kernel32 `LoadLibraryW`, C 호스트는
  `LoadLibraryA` + `GetProcAddress`).
  **`ml_runtime_*` / `ml_module_*` 로더 API는 없다.**
- 모듈이 export하는 것은 **`mlx_<함수명>` + `ml_module_abi_version` + `ml_iface_hash`뿐**(PE 리더로 측정).
- **모듈이 만드는 문자열 바이트는 ASCII `-`와 `0`–`9`뿐이다**(2026-09-02, 연결 슬라이스). 그 밖의
  바이트는 전부 **빌린 것**이다 — 소스 리터럴이거나 호스트가 넘긴 파라미터이며, 모듈은 해석하지 않는다.
  숫자는 모든 후보 인코딩에서 같은 바이트이므로 **인코딩은 여전히 미확정**이다(DP-S2).
- 마샬링은 **스칼라와 문자열**: `f64`/`bool`/`i32`, 그리고 아래에 적은 범위의 `string`.
  (이 줄은 "스칼라만"이었다 — 바로 아래 두 줄이 문자열 입력과 반환을 구현됐다고 적는 동안
  그대로 남아 있었다. 한 불릿이 자기 자신과 모순됐다.) 실패 가능 함수는 D17대로
  `int32_t mlx_f(<params>, T* out_value)`. **명시적 `out` 파라미터**도 스칼라로 지원한다 —
  선언 순서대로 `T*`로 나가고, D17의 `out_value`가 언제나 맨 마지막이다(SPEC-out-params DP-O1).
  **문자열 입력 파라미터**는 `const char*`(Delphi `PAnsiChar`), NUL 종료, 호출 동안
  빌림 — 아래 "문자열 파라미터 계약" 절을 읽을 것. **문자열 반환도 구현됐다** — Q12 프로토콜 그대로
  (`char* ml_buf, int32_t ml_cap, int32_t* ml_needed`, 절단은 음수 status). 아래 "가변 길이 데이터"
  절은 이제 **⏳가 아니라 실측이다.** **배열 입력도 구현됐다**(2026-09-10) — 빌린 포인터 +
  컴파일러가 붙이는 길이, 읽기 전용, 경계 검사(아래 "배열 입력" 절). **배열 반환·구조체·콜백·
  호스트 함수 등록은 ⏳ 미구현**.
- 산출물은 `.dll` + `.h`(C 헤더) + `.pas`(Delphi unit) + `.lib`(MSVC 임포트 라이브러리). **`.h`는 실제로 소비된다** — MSVC로 빌드한
  C11 호스트가 이를 컴파일하고 모듈을 로드·호출한다(수용 D, 2026-08-29). **`.pas`도 소비된다 — 한 번, 손으로**
  (2026-09-07): Delphi IDE에서 `dcc64`가 유닛을 컴파일하고 Win64 호스트가 모듈을 로드·호출해
  14개 검사를 통과했다(`GATE_DELPHI_OK`). **게이트가 로컬에서 돈다**(2026-09-09, §9-20: `bds.exe -b`로 IDE 빌드를 불러 `MATHLESS_GATE_DELPHI=require`가 통과한다). **CI에서는 아직 아니다** — 러너에 Delphi가 없다. 그전 사유: 가진 에디션이 명령줄 빌드를
  거부한다. 유닛의 머리말이 그 둘을 함께 적는다(STATUS §9-15).

## 최소 C API 스케치 (초안 — **⏳ 미구현**)

이름은 가칭.

```c
typedef struct MlRuntime MlRuntime;
typedef struct MlModule MlModule;

MlRuntime* ml_runtime_create(void);
void       ml_runtime_destroy(MlRuntime*);

MlModule*  ml_module_load(MlRuntime*, const char* path, int* err);
void       ml_module_unload(MlModule*);

void*      ml_module_get_fn(MlModule*, const char* name);

int        ml_module_set_host_fn(MlModule*, const char* name, void* fn);
```

실제 함수 시그니처 마샬링은 MVP에서 제한한다.

- 인자: 정수, 실수, bool, C 문자열 포인터 정도
- 구조체는 포인터 + 명시적 레이아웃이 합의된 것만
- 콜백은 함수 포인터 한 단계만

## 수명 (D16)

소유권을 3층으로 나눈다:

- **인자 포인터** = 호출 기간 동안만 유효(빌림). 호출 반환 후 접근 금지.
- **반환 데이터** = caller-allocates out-buffer. **스칼라는 구현됨** — 반환값, D17의 `out_value`,
  그리고 명시적 `out` 파라미터. **가변 길이 버퍼도 문자열에 대해서는 구현·실측됐다**(Q12,
  2026-08-31) — 아래 "가변 길이 데이터" 절. **배열 반환과 문자열을 품은 struct는 여전히 ⏳ 미구현**이며,
  규약은 같다. (배열 **입력**은 이 절이 아니라 빌림이다 — 5번 항목과 "배열 입력" 절.)

### out-parameter 계약 (호스트가 지켜야 할 것)

스칼라 out-param은 **호스트가 할당한다**(보통 스택 변수). 모듈은 거기에 쓸 뿐 소유하지 않는다.

1. **포인터는 호출 기간 동안 유효해야 한다**(D16). 모듈은 호출이 끝난 뒤 그것을 붙들지 않는다.
2. **NULL을 넘기지 마라.** 모듈은 검사하지 않는다 — 검사는 완전할 수 없고(정렬 안 된·해제된
   포인터는 NULL이 아니다) 호출마다 분기를 늘린다. NULL은 **정의되지 않은 동작**이다.
3. **`status != 0`이면 어떤 out-param도 읽지 마라**(D17 DP-E3 + SPEC-out-params DP-O3).
   **계약은 "모듈이 쓰지 않는다"가 아니라 "호스트가 읽지 마라"다** — DP-O3가 일부러 그렇게 정했다
   (버퍼링 후 원자적 커밋은 비용을 내고 계약 하나를 없앨 뿐이다).
   **실측(2026-08-31):** `out` 파라미터를 `fail` **앞에서** 대입하는 함수는 실패해도 그 값을
   **쓴 채로 둔다**(`order_check(250, &offending)` → status `1`, `offending == 250`).
   D17의 `out_value`만 미변경이다(반환 경로에서만 쓰기 때문). 즉 **"실패하면 아무것도 안 쓴다"는
   보장이 아니라 그 프로그램의 성질일 뿐이다.** 회귀 테스트: `hosts/rust-oracle/tests/out_params.rs`
   의 `a_failing_call_may_leave_a_declared_out_written`.
4. 성공한 호출은 선언된 모든 out-param을 쓴다(DP-O2가 컴파일 타임에 강제한다).

### 문자열 파라미터 계약 (호스트가 지켜야 할 것)

`string` **파라미터**는 C의 **NUL 종료 `const char*`**로 나간다(SPEC-string-input DP-S1).
이 절은 **입력 방향만** 다룬다 — 모듈은 이 포인터를 붙들지 않고 바이트를 해석하지도 않는다.
**반환 방향은 다른 규약이다**(위 "가변 길이 데이터" 절, `-> string!`): 모듈은 문자열을 만들지 않고
**호스트가 준 버퍼에 복사**할 뿐이며, 그쪽도 할당하지 않는다.

1. **버퍼는 호출 기간 동안만 유효하면 된다**(D16 (1) 빌림). 모듈은 호출이 끝난 뒤 접근하지 않는다.
2. **NUL로 끝나야 한다.** 모듈은 NUL까지만 읽고, 그 뒤의 바이트는 보지 않는다(실측). 끝나지 않은
   버퍼를 넘기면 모듈이 그 너머를 읽는다 — **정의되지 않은 동작**이다.
3. **NULL을 넘기지 마라.** out-param의 2번과 같은 이유이고 같은 결론이다(DP-S5).
4. **인코딩은 호스트 계약이다.** 모듈은 **바이트만** 본다 — `==`는 NUL까지의 바이트 동등성이고,
   대소문자를 구분하며 정규화하지 않는다(DP-S2). 호스트가 넘기는 바이트와 `.mls` 소스에 쓴
   리터럴의 바이트가 같은 인코딩이어야 한다. 소스 리터럴은 **ASCII만** 허용하므로, ASCII 범위에서는
   UTF-8·Latin-1·대부분의 코드 페이지가 일치한다.
5. **⚠ Delphi 함정 (E2 — 2026-09-10 실측, Delphi CE 37.0 Win64).** Delphi의 기본 `string`은
   UTF-16 `UnicodeString`이다. **어떤 캐스트를 쓰느냐가 결과를 가른다.** `"UPSN"`을 이 ABI로
   실제로 보내며 잰 것이다(`hosts/delphi-host/host.dpr`, `MATHLESS_GATE_DELPHI`):

   | 철자 | 모듈에 도착한 바이트 | 결과 | 컴파일러 |
   |---|---|---|---|
   | `PAnsiChar(AnsiString(S))` — 인자 자리에 **인라인**으로, 또는 **살아 있는 지역 `AnsiString`** 을 캐스트 | `55 50 53 4E 00` | **맞다** | 무언 |
   | `PAnsiChar(S)` | `55 00 50 00 53 00 4E 00` | **틀렸다** | **W1044** Suspicious typecast of string to PAnsiChar |
   | `PAnsiChar(Pointer(S))` | `55 00 50 00 53 00 4E 00` | **틀렸다** | **아무 말도 안 한다** |

   - `PAnsiChar(AnsiString(S))` — 맞다. **인라인으로 인자 자리에 써도 된다**(실측: status 0).
     캐스트 식이 만드는 임시값은 그 **문장**까지 살고 호출이 곧 그 문장이기 때문이다. 이 문서는
     오래 *"지역 변수에 담아 두라"* 고 적었는데, 그것은 **호출 자체의 조건이 아니다.** 진짜 규칙은
     **포인터를 문장 밖으로 들고 가지 말라**는 것이다 — `P := PAnsiChar(AnsiString(S))` 로 받아
     다음 문장에서 쓰면 임시값은 이미 죽었다. 그쪽은 **재지 않았고 잴 수도 없다**: 정의되지 않은
     동작이라 "돌아갔다"는 관측이 아무것도 증명하지 않는다. 그래서 규칙으로만 적는다.
     **살아 있는 지역 `AnsiString` 변수**를 캐스트한 포인터는 다르다 — 그 변수가 살아 있고
     재대입되지 않는 동안 유효하다. 위 표의 행이 말하는 "지역"은 그쪽이지, 캐스트가 만든
     임시값을 변수에 받아 두는 것이 아니다.
   - `PAnsiChar(S)`(UnicodeString에 직접) — **변환되지 않는다.** 이 문서는 오래 "암시적 캐스트 경고와
     함께 ANSI 코드 페이지로 변환되고 ASCII는 살아남는다"고 적었고, **그것은 틀렸다**(E1 추정이었다).
     실측하면 `PAnsiChar(Pointer(S))`와 **바이트 단위로 같은 것**을 보낸다 — 하드 포인터 캐스트다.
     모듈은 첫 NUL까지 읽으므로 **`"UPSN"`이 아니라 `"U"` 한 글자**를 본다. 다만 **조용하지는 않다**:
     `dcc64`가 `W1044`를 낸다.
   - `PAnsiChar(Pointer(S))` — **틀렸고 진짜로 조용하다.** 같은 UTF-16 바이트를 보내는데 컴파일러가
     **아무 진단도 내지 않는다**(부재로 실측: 게이트가 그 줄에 어떤 메시지도 붙지 않음을 가드한다).
     크래시도 없다. 이 저장소가 네 번 만난 그 모양이다.

   > **평범한 `string`을 쓰면 두 번째 줄에 해당한다.** Delphi에서 `string`은 곧 `UnicodeString`이므로,
   > 호스트가 가장 자연스럽게 쓰는 `PAnsiChar(MyString)`이 바로 틀린 철자다.
   >
   > **Free Pascal은 이것을 흉내 내지 못한다.** `-Mdelphi` 모드의 `string`은 `AnsiString`이라
   > **같은 소스가 거기서는 맞고 여기서는 틀리다**(양쪽 실측: FPC status 0, Delphi status 1).
   > `MATHLESS_GATE_FPC_HOST`가 `MATHLESS_GATE_DELPHI`를 대신할 수 없는 이유의 가장 선명한 사례다.
   >
   > 명시적으로 `S: UnicodeString`을 선언한 경우에는 **FPC도 같은 바이트를 보낸다**(실측). 즉 이
   > 함정 자체는 Embarcadero 고유가 아니고, **`string`의 기본 뜻이 다른 것**이 고유하다.

   생성 `.pas`가 같은 사실을 줄글로 싣는다(표가 아니라 목록이다).

### 가변 길이 데이터 — **문자열 반환·배열 반환 모두 구현·실측 완료**(Q12, 2026-08-31 / 2026-09-11)

**모듈은 할당하지 않는다.** 문자열·배열은 호스트가 버퍼와 용량을 주고, 모듈이 채우고, 필요한 길이를
돌려준다. 모듈이 힙을 잡아 호스트에 넘기는 방식은 **기각됐다** — 모듈은 UCRT 힙을 쓰고, D16이
"할당자 넘는 소유권 이전 금지"를 규정하며, Delphi 호스트는 자기 메모리 매니저를 쓴다.

```c
/* 실제 생성된 선언 (examples/carrier.mls, 2026-08-31) */
int32_t mlx_carrier_name(const char* scac, char* ml_buf, int32_t ml_cap, int32_t* ml_needed);
```

**단위는 NUL을 포함한 총 바이트다** — 성공·절단 어느 쪽에서도 같다. 그래서 재시도가
`ml_cap = *ml_needed`로 정확히 맞고 **probe는 항상 2회에 수렴한다**(실측). `*ml_needed == 0`은
나올 수 없다 — 빈 문자열도 `1`이다(NUL 한 바이트). 헤더가 `ML_ST_INSUFFICIENT_BUFFER`(= `-1`)를
`#ifndef` 가드와 함께 방출한다 — 모듈의 에러 이름공간(`ML_<MODULE>_ERR_<NAME>`) **밖**이기 때문이다.
**두 규칙이 반대인 것은 의도적이다**: 이 상수는 모든 모듈에서 값이 같은 런타임 전역이라 가드가
재정의를 무해하게 만들지만, 에러 상수는 모듈마다 의미가 달라 가드를 붙이면 **먼저 온 헤더가 이겨
조용한 오답이 된다**(Q14 / DP-Q3, 2026-09-03).

**`ml_buf`는 `ml_cap == 0`일 때에 한해 NULL일 수 있다**(probe 호출). 그 밖의 NULL은 정의되지 않은
동작이고, `ml_needed`는 **절대** NULL일 수 없다. `ml_cap`이 음수면 `0`으로 본다 — 부호 없는 거대한
값으로 해석하지 않는다(실측: `cap = i32::MIN`도 버퍼를 건드리지 않는다).

| status | 뜻 | `buf` | `*needed` |
|---|---|---|---|
| `0` | 성공 | 채워짐(NUL 종료) | 쓴 길이 |
| **음수** | **용량 부족 — 절단** | **건드리지 않음**(실측: 64B canary 전부 보존) | **필요한 길이** |
| 양수 | 모듈 정의 도메인 에러(D17) | 건드리지 않음 | 건드리지 않음 |

**배열 반환도 이 표를 쓴다(2026-09-11, 구현·실측 완료).** 다른 점은 둘이고, 둘 다 사용자 확인을
받았다(SPEC-array-return DP-R1·DP-R9):

```c
/* 실제 생성된 선언 (examples/allocate.mls, 2026-09-11) */
int32_t mlx_allocate(const int32_t* stock, int32_t stock_len, int32_t want,
                     int32_t* ml_buf, int32_t ml_cap, int32_t* ml_needed);
```

1. **단위가 원소 개수다 — 바이트가 아니다**(DP-R1). 배열 **입력**의 동반 길이와 같은 단위로 맞춘
   결과이고, **대가를 숨기지 않는다**: 호스트가 문자열 반환의 재시도 관용구를 그대로 베끼면
   (`malloc(*ml_needed)` 뒤 `ml_cap = *ml_needed`) **바이트를 잡고 원소를 약속한다** — `[f64]`에서
   8배다. 모듈은 막을 수 없다. `ml_cap`은 **호스트의 약속**이고 검증할 수단이 없다.
   올바른 재시도는 `malloc(n * sizeof *buf)` 뒤 `ml_cap = n`이며, 생성 헤더와 두 예제 호스트가
   그 곱셈을 **코드로** 보여 준다.
2. **각주 하나가 붙는다(DP-R9).** 위 표의 "건드리지 않음"은 **절단(음수)에 대해 그대로 참**이다 —
   실측으로 확인했다(canary 전 바이트 보존). 그러나 배열에는 표가 예상하지 못한 경우가 하나 있다:
   길이를 선언하는 `result n`이 성공한 **뒤**에 `result[i]`가 범위를 벗어나면, 그 시점에는 이미
   `*ml_needed`가 쓰이고 버퍼가 0으로 채워져 있다. 그때 status는 `ML_ST_INDEX_OUT_OF_RANGE`(=`-2`)이고
   **버퍼 내용은 정의되지 않는다.**
   - **저자 쪽에서 대부분 막혀 있다:** `result` 뒤의 `fail`·`try`는 **컴파일 에러**다. 남는 것은
     자기가 선언한 길이 밖에 쓰는 **저자의 버그**뿐이다.
   - **호스트 쪽 규칙은 바뀌지 않는다:** `status != 0`이면 버퍼를 읽지 마라. 이 각주는 그 규칙에
     기대는 것이지 새 규칙을 만들지 않는다.

> **⚠ status가 0이 아니면 버퍼를 읽지 마라.** 모듈은 실패 경로에서 **이 버퍼에는** 아무것도 쓰지 않는다
> (쓰는 자리가 `return` 하나뿐이라 구조적으로 그렇다 — 실측). **선언된 스칼라 `out`은 다르다:**
> `fail` 앞에서 대입했다면 그대로 남는다(DP-O3, 위 out-parameter 계약 3번). 회귀 테스트:
> `a_failing_string_return_leaves_the_buffer_alone_but_not_a_declared_out`.
> (Annex K식 `buf[0]=0` 안전장치는 SPEC-string-return DP-T2에서 **검토 후 기각**했다 — 위 표를
> 바꾸지 않기 위해서다). 그래서 초기화하지 않은 버퍼를 읽으면 **호스트가 자기 스택을 읽는다.**
> NUL이 없을 수 있어 `printf("%s")`가 폭주한다. `hosts/c-host/host.c`의 예제는 **호출 전에 버퍼를
> 반드시 초기화한다** — 보통 `0`으로, 그리고 어떤 바이트가 쓰였는지/안 쓰였는지를 봐야 하는 곳은
> `0xAA`로(NUL도 ASCII도 아니라 양쪽이 다 눈에 띈다). 문서가 아니라 예제 코드가 습관을 보여 준다.

1. **절단은 실패다, 성공이 아니다.** 음수 status로 보고한다. 호스트가 `0`만 확인하고 넘어가도
   꼬리가 조용히 잘리지 않게 하려는 것이다 — 그 조용한 오답은 이 저장소가 이미 네 번 만났다.
2. **길이를 모르면 두 번 부른다.** `cap = 0`으로 한 번 불러 `*needed`를 받고, 버퍼를 잡아 다시 부른다.
   이것은 **새 ABI가 아니라 호스트 쪽 재시도**이며, 모듈은 `no_std`·무할당으로 남는다.
3. **호스트가 준 버퍼는 호스트 것이다.** 모듈은 호출이 끝난 뒤 그것을 붙들지 않는다(D16).
4. **고정 레이아웃 struct는 여기 해당하지 않는다.** 스칼라 필드만 있는 struct는 길이가 정해져 있어
   `sizeof(T)` out-param으로 충분하다 — 위의 out-parameter 계약 그대로다.
   **경계는 "스칼라 필드만"이다:** struct가 문자열이나 배열을 품는 순간 길이가 정해지지 않으므로
   이 절의 규약으로 넘어온다.
5. **배열 입력도 여기 해당하지 않는다.** 이 절은 **모듈이 만들어 돌려주는** 데이터의 규약이다.
   호스트가 **이미 가진** 배열을 넘기는 것은 빌림이므로 D16 규칙 1이 지배하며, 문자열 입력이 그
   선례다 — 아래 "배열 입력" 절.

### 배열 입력 — 빌린 포인터 + 길이 (2026-09-10 구현·실측)

```c
/* 실제 생성된 선언 (examples/basket.mls) */
int32_t mlx_basket_total(const int32_t* qty, int32_t qty_len,
                         const int32_t* price, int32_t price_len,
                         int32_t cap, int32_t* out_value);
```

**표면 파라미터 하나가 C 파라미터 둘이다** — 포인터 다음에 길이가 오고, 선언한 자리를 지킨다.
길이는 컴파일러가 붙이며 저자가 쓰지 않는다(DP-A2).

1. **단위는 원소 개수다.** `ml_cap`·`ml_needed`가 **바이트**인 것과 다르다. 두 단위가 한 헤더에
   같이 있으므로 생성 `.h`·`.pas` 주석이 그 차이를 적는다.
2. **빌린다.** 모듈은 호출이 끝난 뒤 이 포인터에 접근하지 않고, 소유하지 않고, 해제하지 않으며,
   **쓰지 않는다** — 배열 파라미터는 읽기 전용이다(D16 규칙 1).
3. **경계는 모듈이 검사한다.** `0 <= i < len`을 벗어난 읽기는 **`ML_ST_INDEX_OUT_OF_RANGE = -2`**
   로 실패하고 **out-param을 건드리지 않는다**(D17). 이 상수는 그것을 낼 수 있는 모듈의 헤더와
   유닛이 **선언한다** — 호스트가 `-2`를 손으로 적을 일이 없다.
4. **길이는 참이어야 한다 — 이것이 이 절에서 호스트가 지는 유일한 진짜 의무다.** 모듈의 경계
   검사는 **호스트가 준 그 숫자**에 대한 검사다. `xs_len`을 실제 원소 수보다 크게 주면 검사는
   통과하고 모듈은 배열 밖을 읽는다 — **정의되지 않은 동작이며, 모듈이 잡을 수 없다**(문자열의
   "NUL로 끝나야 한다"와 정확히 같은 종류의 계약이다). 경계 검사는 **모듈의 실수**를 막는 것이지
   호스트의 거짓말을 막는 장치가 아니다.
5. **NULL도 음수 길이도 넘기지 마라.** 계약이며 모듈은 검사하지 않는다. 음수를 넘기면 모든 인덱싱이
   실패하므로 안전하지만, `len(xs)`는 **호스트가 말한 값을 그대로** 돌려준다 — 0으로 세탁하지
   않는다(DP-A6).
6. **⚠ Delphi 빈 배열 (E2 — 2026-09-10 실측).** 동적 배열을 넘기는 자연스러운 방법은
   `@Arr[0], Length(Arr)`인데, **빈 배열에는 원소 0이 없다.** 범위 검사가 꺼진 릴리스 기본값에서는
   **예외가 나지 않고** 배열 자신의 nil 포인터가 나온다 — 길이가 0이면 모듈이 역참조하지 않으므로
   그게 정확히 맞는 값이다. **`$R+`를 켜는 순간 같은 줄이 예외를 던진다.** 그래서 크래시가 아니라
   함정이다. 생성 `.pas`가 안전한 관용구를 싣고, Pascal·Delphi 호스트가 그것을 실행한다:

   ```pascal
   if Length(Arr) = 0 then P := nil else P := @Arr[0];
   ```
7. **`[bool]`은 원소당 1바이트다.** Delphi `Boolean`과 같고 `LongBool`과 다르다 — out-param에서
   2026-09-07에 실측된 함정이 배열에서는 원소마다 반복된다. 생성 유닛은 `PBoolean`을 쓴다.
- **모듈 상태** = 명시적 context handle. 생성부터 파괴까지 생존(단일 호출을 넘어감). **⏳ 미구현** — D16의 결정이며 아직 슬라이스로 만들지 않았다.

규칙:

- 모듈 힙과 호스트 힙은 분리. 서로의 할당을 free하지 않는다(할당자 불일치 = UB).
- 모듈은 호스트 메모리를 소유하지 않는다.
- 등록된 호스트 함수 포인터는 호출을 넘어 유효(콜백). 모듈 언로드 후에는 모든 함수 포인터 무효. **⏳ 미구현** — 콜백도 호스트 함수 등록도 아직 없다.
- 호스트 객체를 모듈이 보관하려면 명시적 handle로만.

## 생존성 (liveness) — 호출은 돌아오지 않을 수 있다

`while`이 들어오기 전(2026-08-29)까지 Mathless 함수는 **전부 반드시 종료했다**: 표면에 호출 식이
없어 재귀가 불가능했고 반복 구문도 없었다. 그래서 "export를 호출하면 언젠가 돌아온다"를 모든
호스트가 공짜로 보장받았다. **이제는 아니다.**

**계약:**

- **모듈 export 호출은 반환하지 않을 수 있다.** 무한 루프는 C ABI를 건너 **호출한 스레드를 정지**시킨다.
- 모듈은 **신뢰되는 코드**로 취급한다 — 호스트 개발자가 컴파일하거나 승인한 모듈이라는 뜻이다.
  신뢰할 수 없는 제3자 모듈을 안전하게 실행하는 것은 **지금의 위협 모델이 아니다**.
- **응답성이 필요한 호스트는 워커 스레드에서 호출하라.** UI 스레드에서 직접 호출하면 모듈이 멈출 때
  UI도 멈춘다.
- 호스트가 스레드를 밖에서 죽여 회수할 수 있다고 가정하지 마라 — `TerminateThread`류는 UB에 가깝다.

**모듈 쪽에서 할 수 있는 것은 지금 없다**(SPEC-while §5.1, 사용자 승인):

| 대안 | 왜 안 하는가 |
|------|--------------|
| 연료(fuel)/명령 계수기 | 인터프리터·VM이 필요 — **R01 기각**, **D11**(컴파일 타임 변환만)과 충돌 |
| `while true` 정적 거부 | **불완전하다** — `while 1 == 1`, 조건 변수 등으로 즉시 우회된다 |
| 워치독이 스레드 강제 종료 | UB. 모듈 힙·락 상태가 임의 지점에서 깨진다 |

우회 가능한 반쪽 방어를 넣고 안전하다고 말하지 않는다. 이것은 **계약이지 강제가 아니다**.

> 이 항목은 `SECURITY.md`에 넣지 않는다. 그 문서의 보호 대상은 **배포된 알고리즘**이고, 호스트
> 생존성은 다른 축이다. 모듈을 적대적 코드로 다루는 위협 모델은 지금 채택하지 않았다.

## 버전

ABI 버전은 파일 선두 커스텀 헤더가 아니라 **예약 export 심볼**로 노출한다(D18). 표준 DLL/SO는 offset 0에 PE/ELF 매직이 있어야 로더가 인식하므로 선두 헤더는 로드 불가다. 로더는 `ml_module_abi_version`을 `GetProcAddress`(Windows, 실측)로 조회한다. `dlsym` 경로는 ⏳ 미구현이다.  
호스트와 모듈의 major가 다르면 로드 실패 — 이는 **호스트에 대한 계약(요구사항)** 이다.
**참조 C 호스트에서는 2026-09-02부터 실제로 구현됐다**: 로드하는 모듈 18개 전부가 호출 이전에
게이트를 통과해야 하고, 불일치하면 `FreeLibrary` 후 거부한다. 서드파티 호스트에 대해서는 여전히 계약이다.
(이 숫자는 코퍼스를 늘리는 슬라이스마다 바뀐다 — `#105`가 13, `#108`이 `receipt.dll`을 더해 14다.
`doc_claims.rs`가 이 문장을 `host.c`의 실제 `load(dir, …)` 개수에 묶어 두므로 조용히 낡지 않는다.)

### 인터페이스 지문 (2026-09-02)

버전만으로는 부족하다는 것이 **실측됐다**. `ml_module_abi_version`은 상수이므로 **모듈의 시그니처가
바뀌어도 값이 같다.** v1 인터페이스로 한 번 빌드한 C 호스트에 시그니처가 바뀐 모듈을 준 결과:

```
boxes(items=100, per=3)   33 -> 0                 (크래시 없음, 오류 없음)
rate(code=1)              0.1000 -> CRASH 0xC0000005
ml_module_abi_version()   1 -> 1                  (가드가 작동하지 않는다)
GetProcAddress 심볼 3개    전부 성공 -> 전부 성공
```

그래서 모듈은 **`uint64_t ml_iface_hash(void)`** 를 함께 export한다. 값은 모듈의 **호스트 가시 계약**
(export 함수의 이름·파라미터 이름·타입·순서·`out` 여부·반환 타입·실패 가능성, 그리고 에러 코드 표)에서
결정론적으로 계산되며, 생성 `.h`는 같은 값을 `ML_<MODULE>_IFACE_HASH`로 박는다.

> **호스트의 의무:** 로드 직후 `ml_module_abi_version()`과 `ml_iface_hash()`를 조회해, 자신이 컴파일된
> 헤더의 값과 **다르면 모듈을 거부한다.** 지문이 다른 모듈을 호출하는 것은 정의되지 않은 동작이다 —
> 심볼 이름이 같아 해석은 성공하고, 결과는 잘못된 값이거나 접근 위반이다(위 실측).

**함수 본문만 바뀐 모듈은 지문이 같다.** 임계값 조정은 지금까지처럼 파일 교체로 나간다 —
바뀌는 것은 시그니처·에러 코드처럼 **호스트가 컴파일 시점에 알아야 하는 것**뿐이다.
반대로 파라미터를 **리네이밍**하기만 해도 지문은 바뀐다(의도 — 파라미터 순서 교체가 C 수준에서
구별되지 않기 때문이다. `SPEC-iface-hash.md` DP-H1).

⚠ **무결성이 아니다.** 이것은 사고(드리프트) 감지이며 변조 방지가 아니다(`SECURITY.md` P1).

## 네이밍 규약

- 런타임/예약 심볼: `ml_*` (예: `ml_runtime_create`, `ml_module_abi_version`).
- 사용자 모듈이 export하는 함수: 별도 접두어(예: `mlx_`) 또는 모듈명 네임스페이스. `ml_`와 충돌 금지(D18).

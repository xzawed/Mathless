# Slice SPEC — 반올림 내장 함수 (`floor` · `ceil` · `round` · `trunc`)

> **상태: 확정(accepted) · 구현 대기** — 2026-08-31.
> **DP-R1 = 시그니처 표의 내장 항목**(렉서 키워드 아님). **DP-R3 = C와 정확히 같게**(0 부호 포함).
> **이후(2026-08-31): §1이 "사용자 결정이 선행한다"고 적은 Q12가 닫혔다** — caller-allocates.
> 그 문장은 작성 시점의 사실이다.
> 둘 다 권고안 그대로 사용자 승인. R2·R4·R5는 그에 따라 함께 확정된다.
> **근거 수준:** §1이 **E2 실측**(업무 규칙 3라운드 + 로드된 모듈의 반환값), §2.4가 **E2 실측**
> (`no_std` 빌드 + std와 비트 단위 대조 18케이스), §4가 E0.
> **선행:** `as`(#59/#68) · `i32` 나눗셈(#76) · `out` 파라미터(#80).
> 설계 교차검토: Grok(슬라이스 선택·반올림 모드가 그쪽 권고와 일치, 문법은 다르게 간다 — §4 DP-R1).

## 1. 목표 — 돈 계산에는 반올림이 필요하고, 오늘은 조용히 틀린다

`STATUS.md` §3b가 권한 대로 **업무 규칙을 세 라운드 써 봤다.**

| 라운드 | 규칙 | 결과 |
|---|---|---|
| 1 급여 | 4대보험 공제 + 구간 소득세 + 공제총액 동시 반환 | ✅ 컴파일(`out` 파라미터로) |
| 2 주문 | 사유별 검증 체인(`fail` 3종) | ✅ 컴파일 |
| 2 주문 | 부분 출고 — `out` 2개 + `fail` | ✅ 컴파일 |
| 3 상환 | 잔액을 굴리는 누적 이자 루프 | ✅ 컴파일 |
| 2·3 | **라인 아이템 합계 · 상환 스케줄 표** | ❌ **배열이 없다** (두 번) |
| 1 | **원 단위 절사** | ❌ **`floor`가 없다** |

**배열이 더 큰 벽이지만 힙이 필요하고 Q12(소유권)를 연다** — 사용자 결정이 선행한다.
**반올림은 스칼라이고 Q12를 건드리지 않는다.** 그리고 지금 상태가 더 나쁘다:

### 1.1 내장 함수가 **하나도 없다**

`floor(x)`는 `unknown function 'floor'`다. `abs`·`min`·`max`는 `if`로 깔끔하게 우회되지만
(실측: 셋 다 컴파일된다) **반올림은 우회가 하나뿐이다** — `(x) as i32 as f64`.
`f64 %`는 DP-D4로 거부되므로 소수부를 얻을 다른 수단이 없다.

### 1.2 그 우회로는 `i32::MAX`에서 조용히 포화한다 (E2 실측)

`(gross * 0.045) as i32 as f64` — 국민연금 4.5% 절사:

| 급여 | 우회로 결과 | 참값 |
|---|---|---|
| 3,000,000 | 135,000 | 135,000 ✅ |
| 100,000,000 | 4,500,000 | 4,500,000 ✅ |
| 47,000,000,000 | 2,115,000,000 | 2,115,000,000 ✅ |
| **50,000,000,000** | **2,147,483,647** | **2,250,000,000** ❌ |
| **1,000,000,000,000** | **2,147,483,647** | 45,000,000,000 ❌ |

**`i32::MAX`를 넘으면 조용히 2,147,483,647이 된다.** 원화 금액에서 21억은 도달 가능한 값이다
(계약금, 부동산, 연간 급여 총액). 그리고 그 위에서는 **반올림이 아예 표현 불가능하다.**

> **이 저장소에서 같은 모양이 세 번째다.** `boxes(17,0)` → 2,147,483,647(#76이 닫음) ·
> `out_tier`가 선언되고 아무 일도 안 함(#80이 닫음) · 그리고 이것. 셋 다 **컴파일되고, 그럴듯한
> 숫자를 내고, 틀렸다.** 공통 원인도 같다: **`as`의 포화가 유일한 도구였다.**

## 2. 계약 (Contracts)

### 2.1 문법

네 개의 **내장 함수**. `f64 -> f64`.

```mathless
export fn deduction(gross: f64) -> f64 {
  return floor(gross * 0.045)
}
```

DP-R1 권고는 **렉서 키워드가 아니라 시그니처 표의 내장 항목**이다(§4). 호출식과 변수는 이미 서로
다른 이름공간이므로(`Expr::Call` vs `Expr::Var`) `let round = 1` 같은 지역 변수는 계속 합법이다 —
상환 스케줄에서 `round`(회차)는 실제로 쓰고 싶은 이름이다.

같은 이름의 **사용자 함수 선언은 거부**한다(`ml_`/`mlx_` 접두어 거부와 같은 자리·같은 태도).

### 2.2 값 규칙 — **C와 정확히 같다** (DP-R3)

| 함수 | 규칙 |
|---|---|
| `trunc(x)` | 0 방향으로 버린다 |
| `floor(x)` | 아래(−∞) 방향 |
| `ceil(x)` | 위(+∞) 방향 |
| `round(x)` | **0에서 먼 쪽으로 사사오입**(half away from zero) — C `round()`, Rust `f64::round`와 같다 |

경계도 C와 같다: `±inf`·`NaN`은 그대로 통과하고, **0의 부호가 보존된다**
(`ceil(-0.5) == -0.0`, `floor(-0.0) == -0.0`).

> **DP-N2가 미뤄 둔 결정이 여기서 닫힌다.** `SPEC-numeric-conversion` DP-N2는 `as`에 반올림을 넣지
> 않은 이유로 *"반올림은 은행가 반올림 등 또 다른 선택을 부른다"* 를 들었다. 맞는 판단이었고,
> 그 선택은 **이름 붙은 연산에서** 하는 것이 옳다. 여기서 **half away from zero**로 고른다 —
> 급여·세금 실무가 기대하는 사사오입이고, C·Rust와 같아 백엔드가 갈리지 않는다.

### 2.3 범위

- **`f64`만.** `i32`는 이미 정수다.
- **`abs`·`min`·`max`는 넣지 않는다**(DP-R4). `if` 세 줄로 깔끔히 써지고 실측으로 확인했다.
  내장 함수는 **우회가 없는 것만** 넣는다.

### 2.4 codegen — `no_std`에는 `f64::floor`가 **없다** (E2 실측)

이 슬라이스의 실제 난점이다. `x.floor()`는 `std`에 있고 생성 모듈은 `no_std`다:

```
error[E0599]: no method named `floor` found for type `f64` in the current scope
```

**`libm`을 의존성으로 넣지 않는다** — `Cargo.lock`의 서드파티 의존성 **0개**는 `STATUS.md` §1이
기록하고 §5c가 검증한 성질이다. 대신 **core 연산만으로 방출한다**:

```rust
const HUGE: f64 = 9007199254740992.0;            // 2^53 — 이 이상은 이미 정수다

fn ml_trunc(x: f64) -> f64 {
    if x != x { return x; }                      // NaN
    if x >= HUGE || x <= -HUGE { return x; }     // 이미 정수 (inf 포함)
    (x as i64) as f64                            // |x| < 2^53 이므로 i64 왕복이 무손실
}
fn signed_zero(r: f64, x: f64) -> f64 { if r == 0.0 { x * 0.0 } else { r } }
```

두 가지가 이 구현의 핵심이고, 둘 다 **틀리기 쉬운 자리**라 적어 둔다:

1. **`round`를 `floor(x + 0.5)`로 쓰지 않는다.** 그 식은 `0.49999999999999994`에서 **1**을 낸다.
   대신 소수부를 정확히 구해 비교한다(`d = x - trunc(x)`; 이 뺄셈은 |x| < 2^53에서 정확하다).
2. **0의 부호는 곱셈으로 옮긴다.** IEEE 곱셈의 부호는 두 부호의 XOR이므로 `x * 0.0`이 정확히
   "x의 부호를 가진 0"이다. 이것을 빼먹으면 `ceil(-0.5)`가 `+0.0`이 되어 C와 갈린다(실측으로 확인).

**실측(E2): std와 비트 단위로 완전히 일치한다.** 18케이스 — `2.5`/`-2.5`, `0.49999999999999994`,
`2,250,000,000`(옛 우회로가 죽던 지점), `50,000,000,000.7`, `2^53`, `±inf`, `NaN`,
그리고 `-0.0`과 `ceil(-0.5)`의 **0 부호**까지. 불일치 **0건**.

> **후속 백엔드 주의:** DP-R3대로 C와 같게 정했으므로, C-emit 백엔드는 `<math.h>`의
> `floor`/`ceil`/`round`/`trunc`를 **그대로 부르면 된다.** 규칙을 우리 것으로 따로 정했다면
> 백엔드마다 그 차이를 기억해야 했을 것이다 — 그것이 DP-R3의 값어치다.

### 2.5 ABI — 변화 없음

식 수준이다. export 집합·시그니처·바인딩 모두 그대로. 크기 프록시는 재서 기록한다(§3-C).

## 3. 수용 기준 (측정 가능)

- **A. 컴파일:** `examples/deduction.mls`(§1의 급여 규칙) → `mlc build`.
- **B. 로드·호출(오라클):** `deduction(3000000) == 135000` · `deduction(12345678) == 555555`.
- **B2. 경계 — 이 슬라이스가 존재하는 이유:** `deduction(50000000000) == 2250000000`
  (**옛 우회로는 2,147,483,647을 냈다**) · `deduction(1000000000000) == 45000000000`.
- **B3. C와 일치:** `floor`/`ceil`/`round`/`trunc`를 §2.4의 18케이스로 std와 대조 — **비트 단위**로
  (0의 부호와 NaN을 `==`로 비교하면 놓친다).
- **C. 보호:** export 집합 불변. 크기는 재서 기록(내장 함수 방출로 늘 수 있다).
- **D. 수용 D(실제 C 호스트):** `hosts/c-host/host.c`에 B·B2 추가.
- **E. 부정 케이스:** `floor(1)`(i32 인자) 거부 · `floor()` 인자 개수 · `fn floor(...)` 사용자 정의
  거부 · `floor` 를 값으로 쓰기.

## 4. 설계 제안 (DP — **미확정, 사용자 확인 필요**)

| DP | 선택지 | 권고 | 근거 |
|----|--------|------|------|
| **R1 이름 도입** | 렉서 키워드 / **시그니처 표의 내장 항목** | **내장 항목** | 키워드로 만들면 `let round = 1`(회차)도 막힌다 — 상환 스케줄에서 실제로 쓰고 싶은 이름이다. 호출식과 변수는 이미 다른 이름공간이라 모호성이 없다. **Grok은 키워드를 권했고, 여기서는 다르게 간다** |
| **R2 `round` 모드** | **half away from zero** / half to even | **half away from zero** | 급여·세금 실무의 사사오입. C `round()`·Rust `f64::round`와 같아 백엔드가 갈리지 않는다. 은행가 반올림이 필요하면 이름 붙인 별도 연산으로 후속 |
| **R3 C와의 관계** | **정확히 같게** / 우리 규칙을 따로 | **정확히 같게**(0 부호·NaN·inf 포함) | C-emit 백엔드가 `<math.h>`를 그대로 부를 수 있다. 다르게 정하면 백엔드마다 차이를 기억해야 한다 |
| **R4 함수 집합** | 4개 / `abs`·`min`·`max` 포함 | **4개만** | `abs`·`min`·`max`는 `if`로 깔끔히 써진다(실측). **우회가 없는 것만** 넣는다 |
| **R5 타입** | `f64` / `i32`도 | **`f64`만** | `i32`는 이미 정수다 |

### DP-R1이 왜 진짜 결정인가

내장 이름을 도입하는 방식은 **되돌리기 어렵다.** 키워드로 만들면 그 낱말은 영원히 변수명으로도
못 쓰고, 나중에 되돌리면 기존 코드가 조용히 의미를 바꾼다. 시그니처 표에 넣으면 **호출 자리에서만**
특별해지고, 충돌은 선언 시점에 명확한 에러로 걸린다.

## 5. 범위 밖 / 위험

- **배열·문자열·struct** — 이번 세 라운드에서 **두 번 벽이었지만** 힙과 Q12가 선행한다. 이 슬라이스는
  그 결정을 기다리는 동안 **막을 수 있는 오답 하나를 막는다.**
- `abs`·`min`·`max`(DP-R4) · 은행가 반올림 · `f64 %`(DP-D4) · 임의 자릿수 반올림
  (`round_to(x, 2)`) — 후속 후보.

### 5.1 `i64` 왕복을 쓴다는 사실

`ml_trunc`는 `x as i64`를 쓴다. **표면에는 `i64`가 없다** — 생성 Rust 안에서만 쓰는 구현 수단이다.
|x| < 2^53에서만 그 경로를 타므로 i64 범위(±9.2e18)를 절대 넘지 않고, **포화가 일어날 수 없다.**
이것이 §1.2의 `i32` 우회로와 다른 점이다.

### 5.2 `&&` 단락 평가 부채(§5-1)는 갚지 않는다

내장 함수 호출은 부작용이 없다(순수 f64 계산). 관측 수단은 여전히 생기지 않는다.
(#76·#80 때와 같은 이유로 미리 적어 둔다.)

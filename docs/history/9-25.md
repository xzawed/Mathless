### 9-25. 배열 입력 슬라이스 (2026-09-10, E2) — **근거가 능력이 아닌 첫 슬라이스**

SPEC은 자기 근거를 부정하며 시작한다. §9-9가 얼린 호스트 실험으로 **배열이 강제되지 않는다**고
다섯 번째로 결론냈고(`host_round` 5/5, `host_array` 5/5), 그 절이 남긴 두 줄 — **얼리기 전 일정
추측**과 **평문 호스트의 방법 계열 노출(D05)** — 의 값을 사용자가 인정해 열렸다. 그래서 SPEC과
예제 모두 *"배열이 있어야 이 규칙을 쓸 수 있다"* 고 **주장하지 않는다.**

**모양.** `xs: [i32]` = 빌린 포인터 + **컴파일러가 붙이는** 길이. 표면 파라미터 하나가 C
파라미터 둘이고, 단위는 **원소 개수**다(문자열의 `ml_cap`은 바이트 — 다른 단위이고 주석이 그
차이를 적는다). 읽기 전용, 스칼라 원소만, `xs[i]`는 경계 검사.

**설계의 핵심은 실패를 시그니처에 보이게 둔 것이다.** 인덱싱은 실패할 수 있고 D17은 `!` 없는
함수에 **보이지 않는 status 채널**을 붙이는 것을 금지한다. 그래서 **인덱싱하는 함수는 `-> T!`** 여야
하고, 배열을 받기만 하는 함수는 아니다(`len`은 실패할 수 없다). 범위 이탈은
**`ML_ST_INDEX_OUT_OF_RANGE = -2`**(새 예약 음수)이고 out-param은 **무기록**이다.

**구현이 작아진 이유 하나를 적어 둔다.** 경계 검사는 **조기 반환**이라 문장이 필요한데, 인덱스는
식이다. Rust의 **블록 표현식**이 값을 내면서 `return`을 담을 수 있어서 hoisting 패스 없이 인라인으로
내려간다 — 대신 `emit_expr`이 반환 ABI를 알아야 한다(fallible은 `Err(-2)`, `-> string!`은 `-2`).

**네 호스트가 부른다.** 각각이 다른 것을 답한다:

| 호스트 | 이것만 말할 수 있는 것 |
|---|---|
| rust-oracle | 값, `-2`, out 무기록, **음수 길이**(세탁하지 않는다 — 모든 인덱싱이 실패할 뿐) |
| c-host (MSVC) | **C 컴파일러가 선언을 읽는다.** 동반 파라미터를 빼면 인자가 밀리는 게 아니라 **컴파일이 안 된다** |
| fpc host | 생성 `.pas`를 빌드·실행 |
| **delphi host** | `dcc64`(IDE `bds -b`), `GATE_DELPHI_OK` |

두 바인딩이 이제 그 상수를 **선언한다** — 호스트가 `-2`를 손으로 적을 일이 없다.

**그리고 SPEC §5.2가 약속한 함정을 쟀다.** Delphi 호스트가 동적 배열을 넘기는 자연스러운 방법은
`@Arr[0], Length(Arr)`인데 **빈 배열에는 원소 0이 없다.** 범위 검사가 꺼진 **릴리스 기본값에서는
예외가 나지 않고** 배열 자신의 nil 포인터가 나온다 — 길이가 0이면 모듈이 역참조하지 않으므로
**그게 정확히 맞는 값이다.** `$R+`를 켜는 순간 **같은 줄이 예외를 던진다.** 크래시가 아니라
함정인 이유가 그것이고, 그래서 생성 `.pas`가 안전한 관용구를 싣고 호스트가 그것을 실행한다:

```pascal
if Length(Arr) = 0 then P := nil else P := @Arr[0];
```

**거부는 전부 이유를 이름으로 말한다**: 배열 반환(할당자가 없다 — Q12이고 별도 슬라이스), `out`
배열(빌림은 읽기 전용), `[string]`·`[[T]]`, `<param>_len` 충돌, i32 아닌 인덱스, `xs[i] = v`.
`f64[]`는 이제 *"배열 타입은 `[T]`로 쓴다"* 고 말한다 — 전에는 *"expected ')'"*, 참이지만 엉뚱한
것에 대한 답이었다.

전체 스위트 **466 passed / 0 failed**(네 게이트 모두 `require`). C 호스트가 게이트하는 모듈이
15 → 16이 됐고, `doc_claims`가 아직 15라고 적힌 문서 둘을 잡았다.

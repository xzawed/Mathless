### 9-61. §7을 새 도메인으로 돌렸다 (2026-09-16, E2) — **벽은 하나, 그리고 그 벽이 후보가 아니었다**

보고서에서 열려 있던 판단은 하나였다: *"다음 슬라이스는 강제되는 것이 없다."* 그 판단의 근거인
§7 실행은 **§9-53(2026-09-14)** 이고 그 뒤로 `fixed`가 들어왔다. **인용하지 않고 다시 쟀다.**

#### 9-61.1 표본 — **여신·대출** 여덟 (이전 표본이 안 건드린 도메인)

기존 표본이 쓴 곳: 할인·부가세·수수료·보험청구·계좌·창고배분·배송사·급여인사. 이번은 대출이다.

| # | 규칙 | 결과 |
|---|---|---|
| R1 | 연체이자 = 원금 × 연이율 × 일수 / 365, 원 단위 절사 | ✅ `12328.0` |
| R2 | 중도상환수수료, 총개월 0이면 실패 | ✅ `200000.0`, status 0 |
| R3 | 신용등급별 한도, 3억 상한 | ✅ `200000000` |
| R4 | DSR 판정 (연상환액 / 연소득 ≤ 0.4) | ✅ `true` |
| **R5** | **원리금균등 월납입액 `(1+r)^n`** | ❌ **`unexpected character '^'`** |
| R6 | 상환 스케줄 잔액 배열 | ✅ `[700000, 400000, 100000, 0]` |
| R7 | 점수 → 한국어 등급 라벨 | ✅ `"우량"`, `needed` 7 |
| R8 | 거절 통지 = 사유 + 금액 포맷 | ✅ `"DSR 초과, 한도 200000000원"` |

**7/8 컴파일되고 값도 맞다.** 벽은 **거듭제곱 하나**다.

#### 9-61.2 그런데 그 벽은 슬라이스 후보가 아니다

우회는 **모듈 안**이고 **맞다**: 곱셈 루프로 `(1+r)^n`을 만들면
`monthly_payment(1억, 0.05, 360) = 536821`이고 참값 `536821.62`의 절사와 **일치**한다(실측).

**그리고 `^`가 있어도 고쳐지지 않는 것이 있다.** 같은 함수를 세 입력으로 더 불렀다:

| 입력 | 나온 것 | 참값 |
|---|---|---|
| `months = 0` | **`inf`**, status 0 | 정의되지 않음 |
| **`annual_rate = 0.0`** (무이자 할부) | **`NaN`**, status 0 | `원금 / 개월수` |

**이 둘은 `^`의 부재가 만든 것이 아니다** — 공식 자체가 `r = 0`에서 특이점이고, `pow`가
생겨도 `g - 1.0`은 여전히 `0.0`이다. **벽과 위험이 같은 자리에 있는 것처럼 보였고, 아니었다.**
그래서 이 표본은 `^` 슬라이스의 근거가 **되지 못한다.**

#### 9-61.3 진짜로 나온 것 — **`f64`의 `/`만 조용하다**

위 NaN을 따라가니 언어 전체의 성질이었다. 로드된 모듈에서 잰 값:

| 식 | 호스트가 받는 값 |
|---|---|
| `1.0 / 0.0` · `-1.0 / 0.0` | `inf` · `-inf` |
| `0.0 / 0.0` | **`NaN`** |
| `floor(1.0 / 0.0)` | `inf` — **`floor`가 길들이지 않는다** |
| `(1.0 / 0.0) as i32` | `2147483647` |
| `(0.0 / 0.0) as i32` | **`0`** |

**마지막 두 줄이 이 절의 이유다.** 변환은 **기록된 규칙대로**이고(포화 · NaN→0), 그래서
결과가 **그럴듯한 숫자**다. `-> f64`·`-> i32`에는 status 채널이 없다.

**그리고 컴파일러가 한쪽만 막는다:**

| 저자가 쓴 것 | 컴파일러 |
|---|---|
| `x / 0` (i32) | **거부** — *"dividing by the literal 0 is rejected … writing the zero out is always a mistake"* |
| **`x / 0.0` (f64)** | **통과, `inf` 반환** |

#### 9-61.3a 여기서 내 첫 서술이 틀렸고, **코드가 정정했다**

처음에 나는 이것을 *"컴파일러가 한쪽만 막고 있었다"* 라고, 아무도 정하지 않은 빈틈처럼 적었다.
**아니다.** `compiler/src/typeck.rs`의 DP-D5 구현 옆에 이유가 적혀 있다:

> *"Deliberately SYNTACTIC, not constant folding … **`f64 / 0.0` also still compiles — that is
> `inf`, a defined value.**"*

**옳은 근거다 — 그런데 내가 그 근거도 한 번 틀리게 요약했고, 검증이 다시 정정했다.**
처음에 *"`i32`에는 제수 0에 옳은 답이 없고 `f64`에는 있다"* 라고 적었다. **틀렸다**: DP-D1이
`i32`의 답을 **정해 두었다**(`x / 0 = 0`, 전역). 같은 주석의 첫 문장이 그렇게 말한다 —
*"The operators are total at runtime, so this changes no value."*

**코드가 실제로 가르는 축은 다른 것이다:**

| | 런타임 값 | 그 값의 성격 | 리터럴을 쓰면 |
|---|---|---|---|
| `i32 / 0` | `0` | **규약** — 우리가 고른 것이고 수학적 값이 아니다 | **아무도 일부러 안 쓴다** → 거부 |
| `f64 / 0.0` | `inf` | **IEEE 754가 정한 값** | **일부러 쓸 수 있다** → 통과 |

*"certainly a mistake"* 대 *"a defined value"* — 주석이 쓴 두 표현이 그 축이다.
**둘 다 답이 있고, 다른 것은 저자가 그것을 의도할 수 있느냐다.**

**그래서 이 절의 발견은 결정이 없다는 것이 아니라, 결정이 있는데 그것이 아무 데도 안 나간다는
것이다.** 그 문장은 `SPEC-i32-division.md`에도 없다 — DP-D5는 `i32`만 다룬다. 있는 곳은
**컴파일러 소스의 주석 한 줄**이고, **저자도 호스트도 그 파일을 읽지 않는다.**
`LANGUAGE.md`는 `i32`의 wrap과 전역 나눗셈을 두 항목에 걸쳐 적고 *"조용하다"* 까지 쓰면서
**`f64` 쪽은 한 줄도 없었고**, `HOST_ABI.md`는 `NaN`·`inf`가 **0회**였다.

> **이것이 §7이 실제로 찾은 것이다.** 표본 여덟은 기능 공백을 하나 댔고 그건 후보가 아니었다.
> 값어치가 나온 자리는 **그 공백을 우회하다 밟은 성질**이고, 그 성질은 **결정돼 있었으나
> 기록되지 않았다.** `STATUS.md` §7이 *"주장은 측정에 묶는다"* 고 적은 것의 이면이다 —
> **결정도 읽히는 곳에 묶여야 한다.**

**저자가 막는 수단은 있다**(실측): `if raw != raw { fail … }`가 컴파일되고, NaN이면 status 1,
아니면 값을 준다. **있다는 것을 말하는 곳이 없었을 뿐이다.**

#### 9-61.4 그래서 이 세션이 한 것과 **하지 않은 것**

**한 것: 문서 두 곳.** `LANGUAGE.md`의 `i32` 문단 바로 아래에 `f64` 대응 항목(표 + 리터럴
비대칭 + `!= ` 관용구), `HOST_ABI.md`의 마샬링 절에 **호스트 규칙 한 줄**(*"받은 `double`을 쓰기
전에 유한한지 본다"*).

**하지 않은 것: 컴파일러.** 세 선택지가 있고 **전부 사용자 결정이다** — §4-12로 올렸다.
**§7은 근거를 대지 강제하지 않는다**, 그리고 여기서 §7이 댄 근거는 *"조용하다"* 이지
*"우회가 없다"* 가 아니다.

#### 9-61.5 §7의 **두 번째 질문** — 내가 모르고 우회한 것

*"막힌 것이 없다"* 는 결과의 절반이다. 내 소스를 다시 읽었다:

- **R3에서 `else`가 없어 센티넬을 썼다.** `if grade == 1 { mult = 5.0 } … if mult == 0.0 { fail }`
  — 그런데 그 센티넬은 **"모르는 등급"과 "배수가 정말 0인 등급"을 한 값으로 묶는다.**

  > **처음에 이것을 재지 않고 적었다. 같은 세션의 자기 감사가 잡았다 — 오늘 출하한 문장 중
  > 유일한 미측정 단언이었다.** 쟀다: 9등급을 *"대출 불가, 한도 0"* 으로 표에 넣으면
  >
  > | `grade` | 뜻 | status | 값 |
  > |---|---|---|---|
  > | `2` | 유효 | `0` | `200000000` |
  > | **`9`** | **유효 — 한도가 정말 0** | **`1`** | 없음 |
  > | `7` | 모르는 등급 | `1` | 없음 |
  >
  > **9와 7이 호스트에게 같은 답이다.** 정답은 *"한도 0"* 인데 *"모르는 등급"* 이라고 말한다.
  > 조용하지는 않다(둘 다 실패다) — **틀린 것은 실패의 종류**이고, 그것을 고를 권한은
  > `.mls` 저자에게 있다.
  >
  > **§9-35의 두 칸 어디에도 안 들어간다.** 그쪽은 저자가 **여집합을 손으로 쓸 때**를 쟀고
  > (스칼라=컴파일 에러 / 배열=조용한 오답), 이쪽은 저자가 **센티넬을 고를 때**다. 뿌리는
  > 같다(`else`가 없다). **새 칸이라고 적지는 않는다** — 표본 하나이고, `else`는 이미
  > `LANGUAGE.md`의 공백 목록에 있다.
- **등급 → 배수를 데이터가 아니라 `if` 사슬로 썼다.** 룩업 테이블을 쓸 수단이 없어서인데,
  **쓰려다 못 쓴 게 아니라 처음부터 그렇게 썼다.** 고정 레이아웃 struct가 후보 목록에 있는 이유가
  여기 있고, 그것이 강제된다는 뜻은 **아니다**.
- **`(days as f64)`를 자동으로 썼다.** 암시적 혼합 금지는 기록된 결정이고, 대가가 이것이다.

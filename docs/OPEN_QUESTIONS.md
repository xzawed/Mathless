### Q1. 주력 호스트 2개는 무엇인가? — 닫힘 → D14

Delphi(1급 데모) + C(ABI 기준). 후보였던 Delphi+C#은 Phase 4로 이연.

### Q2. 표면 문법 계열은? — 닫힘 → D15

중괄호·정적·값타입 우선 C 계열(MVP=struct+함수). "C#-like"는 좁은 라벨. 세부 문법은 계속 미정.

### Q3. 메모리 모델은? — 닫힘 → D16

소유권 3층 분리(인자=빌림 / 반환=caller-allocates / 상태=context handle), 힙 분리. 남은 하위였던 **Q12도 닫혔다**(2026-08-31, 아래).

### Q4. 에러 모델은? — 닫힘 → D17

ABI 정수 상태코드+out-param, 표면 Result는 sugar. 남은 하위 → Q13.

### Q5. 모듈 파일 포맷은? — 닫힘 → D18

표준 DLL/SO + 버전 export 심볼 + 모듈 전용 접두어. 커스텀 컨테이너는 P1. 남은 하위였던 **Q14도 닫혔다**(2026-09-03, 아래).

- Q12. 반환 값 소유권 규약 — **닫힘(2026-08-31)**: 사용자 확정으로 **(a) caller-allocates out-buffer**.
  가변 길이 데이터는 **호스트가 버퍼와 용량을 주고, 모듈이 채우고, 필요한 길이를 돌려준다**.
  절단은 **D17의 음수 예약 status**로 보고한다 — "성공했는데 짧다"가 아니라 명시적 실패다.
  세부는 `DECISIONS.md` D16 파생 상세와 `HOST_ABI.md`의 "가변 길이 데이터" 절.
  - **먼저 갈라 냈다:** Q12는 두 질문을 묶고 있었다. **고정 레이아웃 struct(스칼라 필드만)는 힙이
    필요 없으므로 Q12 밖이다** — 호스트 스택의 `sizeof(T)`에 쓰는 것이고, 이미 있는 `out` 파라미터와
    같은 기계장치다. Q12가 묶는 것은 **가변 길이**(문자열·배열, 그리고 문자열을 품은 struct)뿐이다.
  - **기각 (b) 모듈 소유 + 명시 free:** 기술적으로는 된다 — `no_std`에서도 CRT의 `malloc`/`free`를
    직접 선언하면 의존성도 크기도 그대로 빌드된다(실측). 문제는 **누구의 힙인가**다. 모듈은 UCRT 힙을
    쓰고(실측: `api-ms-win-crt-heap` import가 하나 늘어난다), D16이 **"할당자 넘는 소유권 이전 금지"**를
    이미 규정했다. 결정적으로 **D14의 플래그십 호스트가 Delphi**이고 Delphi는 자기 메모리 매니저를
    쓴다 — 습관대로 `FreeMem`을 부르면 **조용히 힙이 손상된다.**
  - **기각 (c) 스칼라만 유지:** 제품이 아니라 오늘의 벽이다. 업무 규칙 두 번의 3라운드에서 배열이
    **네 번** 벽이었다(`STATUS.md` §3a-2·§3a-3).
  - **감수하는 대가:** 길이를 모르면 호스트가 한 번 더 부른다. 그리고 **호스트가 status를 무시하면
    꼬리가 조용히 잘린다** — 이 저장소가 네 번 닫은 그 모양이다. 그래서 절단을 성공이 아니라
    **음수 status**로 두는 것이 결정의 일부다.
- Q13. 에러 코드 체계 — **닫힘(2026-08-28)**: 사용자 확정으로 **평탄 i32**(`0`=OK / 양수=모듈 정의 도메인 에러 / 음수=예약 런타임·ABI). **D17 에러-경로 슬라이스로 구현·실측**(SPEC PR #14, 구현 PR #15; 오라클 로드로 status/out-param 검증). out-param 세부는 D17대로. **`DECISIONS.md` D17 확정 상세에 반영 완료**(규칙 8상 사용자 승인 후 별도 PR #30) — 이 항목은 더 이상 열려 있지 않다. 기각: HRESULT식(무겁·Windows 중심), 0/음수 무구조(의미 비트 부족).
- Q14. ABI 버전 배치와 사용자 모듈 export 접두어 — **닫힘(2026-09-03, 사용자 승인 → D18 파생 상세)**.
  두 반쪽이 서로 다른 방식으로 닫혔다:
  - **ABI 버전 배치**는 구현이 답했다 — 예약 export 심볼 `ml_module_abi_version`을 `GetProcAddress`로
    조회한다(실측). 파일 선두 커스텀 헤더는 PE/ELF 매직 때문에 애초에 불가하다(D18 본문).
  - **export 접두어**는 `mlx_`로 **확정**한다. 고르는 결정이 아니라 **이미 굳은 것을 추인**하는
    결정이었다: `codegen.rs`가 무조건 `mlx_<name>`을 방출하고 `reserved.rs`가 사용자에게 그 접두어를
    금지한다. D18 본문의 "예: `mlx_`"가 코드보다 약하게 적혀 있던 것을 맞춘다.
  - **딸린 부채도 함께 닫았다** — 에러 상수가 `ML_ERR_<NAME>`으로 모듈 접두어 없이 방출되던 것을
    **`ML_<MODULE>_ERR_<NAME>`** 으로 바꿨다(`SPEC-error-prefix.md`, DP-Q1).
    **근거는 실측이다**: 두 모듈이 같은 이름을 다른 값으로 선언하게 만들면 두 헤더를 함께 include한
    호스트가 `C4005: macro redefinition` → `/WX`로 **빌드에 실패했다**(41초). 접두어를 붙인 뒤 같은
    코퍼스가 통과한다(181초). 조용한 오답 경로는 **없었다** — 시끄러운 실패였고, 그 실패를 맞는 것이
    **모듈을 함께 쓰는 사용자**라서 고쳤다.
  - 기각: **`ML_ERR_`에 `#ifndef` 가드만 붙이기.** 먼저 온 헤더가 이겨 **유일하게 시끄러운 실패를
    조용한 오답으로 바꾼다**(DP-Q3). `ML_ST_*`가 가드를 쓰는 것은 그것이 모두가 합의한 예약 코드
    하나이기 때문이며, 모듈마다 의미가 다른 에러 상수에는 같은 논리가 적용되지 않는다.
  - 기각: **`ML_ERR_<MODULE>_<NAME>`**(`SPEC-D17-error-abi.md` DP-E2가 "또는"으로 적어 둔 형태).
    그 문장은 `ML_<MODULE>_IFACE_HASH`가 생기기 **전**에 쓰였고, 이미 배포된 선례와 어간을 맞추는
    편이 한 헤더 안의 규칙을 하나로 만든다.
  - **남는 것:** 지문을 export 심볼 이름에 박아 로더가 **강제**하게 하는 것(DP-H3(b))은 Q14가 닫혀야
    열리는 **별도 슬라이스**이며 아직 하지 않았다.
- Q15. **산출물의 라이선스 지위** — 저장소는 Apache-2.0/MIT 이중이지만(2026-08-29), `mlc`가 **생성하는**
  것들의 지위는 아직 정하지 않았다: 생성 Rust, `.h`/`.pas` 바인딩(문구가 `compiler/src/header.rs`의
  템플릿에서 나옴), `runtime/ml_abi.h`. 템플릿에서 나온 텍스트가 파생저작물로
  간주되면 사용자 모듈에 라이선스 의무가 붙을 수 있다(GCC의 runtime library exception이 푸는 문제와 같은
  계열). "컴파일 산출물은 사용자의 것"이라는 명시적 예외를 둘지 결정 필요 — **소스 미배포로 알고리즘을
  보호한다**(D04)는 제품 약속과 직결된다. 법률 조언이 아니며, 문구 확정 전까지 대외 문서에 단정하지 않는다.

  > **2026-09-02 실측 — 비율이 이 질문의 핵심이다.** 생성 산출물에서 사용자의 소스에서 나온 줄과
  > 템플릿에서 나온 줄을 세어 봤다:
  >
  > | 산출물 | 전체 | 사용자 유래 | 템플릿 유래 |
  > |---|---|---|---|
  > | `discount.h` | 39줄 | **1줄**(함수 선언) | **38줄** |
  > | `discount.pas` | 19줄 | **1줄** | **18줄** |
  >
  > 사용자가 배포하게 되는 헤더는 **거의 전부 우리가 쓴 문장**이다. 그래서 이것은 이론이 아니라
  > 비율의 문제다.
  >
  > **그리고 이 항목의 서술 하나가 사실과 달랐다(정정).** "사용자 프로젝트로 **복사되는**
  > `runtime/ml_abi.h`"라고 적혀 있었지만, **아무것도 그 파일을 복사하거나 include하지 않는다**
  > (전 트리 grep = 0, `STATUS.md` §5-5.3이 이미 기록한 사실이다). 오늘 사용자에게 나가는 것은
  > 생성 `.h`·`.pas`·`.dll`뿐이다.

  ### Q15 장단점 (결정 대기 — 규칙 8)

  | 안 | 장점 | 단점 |
  |---|---|---|
  | **(a) 산출물 예외 — 권고** | "`mlc`가 생성한 산출물은 사용자의 것이며 저장소 라이선스가 산출물에 의무를 지우지 않는다"를 명시. **38/39가 우리 문장인 헤더를 사용자가 그대로 배포**할 수 있게 된다. D04의 약속("사용자의 알고리즘을 보호한다")과 결이 같다. GCC의 runtime library exception이 같은 문제를 같은 방식으로 푼다(E1, 외부 선례) | 라이선스 문구를 새로 써야 한다. **컴파일러 자체**의 라이선스까지 느슨해지지 않도록 범위를 정확히 한정해야 한다. 법률 검토가 필요하고, 우리는 법률 조언을 하지 않는다 |
  | **(b) 산출물도 Apache-2.0 OR MIT 유지** | 새 문구가 없다. 이미 관대한 라이선스이므로 실무 마찰이 작다 | **의무가 0은 아니다** — MIT·Apache 모두 고지 보존을 요구하므로, 사용자가 배포하는 `.h`마다 우리 고지가 따라붙는다고 읽힐 수 있다. "산출물은 사용자의 것"이라고 **대외적으로 말할 수 없게 된다** |
  | **(c) 미정 유지** | 지금 아무 일도 안 해도 된다 | 저장소가 **이미 공개**다. 누군가 상용 제품에 붙이기 전에 물어볼 것이고, 그때 답이 "미정"이면 채택을 막는다. 미루는 비용이 시간에 비례해 커지는 항목이다 |

  > **권고는 (a)다.** 근거는 위 비율 측정과 D04다. 다만 **문구 작성은 법률 판단**이므로, 확정 전까지
  > `LICENSE-*`·`README`·대외 문서에 **어떤 단정도 쓰지 않는다**(규칙 6). 확인해 주시면
  > `LICENSE-OUTPUT-EXCEPTION` 초안을 별도 PR로 올리고 `DECISIONS.md`는 그 뒤에 손댄다.

  ### ✅ Q15 닫힘 — (a) 산출물 예외 (2026-09-02, 사용자 승인)

  `LICENSE-OUTPUT-EXCEPTION`을 추가했다. 요지: **`mlc`가 만든 산출물(`.dll`·`.h`·`.pas`·중간 Rust)은
  사용자의 것이며, 저장소 라이선스의 의무가 산출물에 따라붙지 않는다.** 범위는 **산출물뿐**이고
  컴파일러·호스트·문서는 그대로 Apache-2.0 OR MIT다.

  두 가지를 문서 안에 명시적으로 남겼다:

  - **`runtime/ml_abi.h`는 산출물이 아니다.** 손으로 쓴 파일이고 아무것도 복사·include하지 않는다
    (실측). 사용자가 직접 자기 트리로 복사하면 그것은 저장소 라이선스 그대로다.
  - **법률 조언이 아니다.** 프로젝트가 쓴 문장이며, 의존해야 한다면 각자의 법률 검토를 받으라고 적었다.

  근거로 삼은 외부 선례는 **GCC의 Runtime Library Exception**이다(E1) — 문제의 모양이 같다.
  다만 GCC는 카피레프트라 이해관계가 훨씬 크고, 여기서는 **고지 보존 의무**가 쟁점이라는 차이를
  문서에 적어 두었다.

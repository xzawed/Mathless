### 5-6. ✅ 갚음 — `i32 /`·`%`가 왼쪽 피연산자를 건너뛰었다 (발견 2026-09-23, 상환 2026-09-23)

> **`SPEC-division-guard-operands`가 갚았다**(SPEC #287 / 구현 #291).
> 오늘 `compiler/src/codegen.rs`가 내는 모양은 이것이고, `doc_claims.rs`의
> `the_recorded_division_debt_still_matches_what_codegen_emits`가 **이 코드 블록과 방출 텍스트가
> 같은 문자열인지**를 검사한다:
>
> ```rust
> { let __l = <lhs>; let __d = <rhs>; if __d == 0 { 0i32 } else { __l.wrapping_div(__d) } }
> ```
>
> 아래는 **발견 당시의 기록**이다. 지우지 않는 이유는 §5의 요점 그대로다 — 갚은 것도 조용히
> 사라지면 안 된다.

`#76`이 나눗셈·나머지를 **전역(total)** 으로 만들면서 0 제수를 `0i32`로 되돌린다. 그 보호막이
**왼쪽 피연산자를 `else` 안으로 밀어 넣었다** — 그때 `compiler/src/codegen.rs`가 내던 모양:

```rust
{ let __d = <rhs>; if __d == 0 { 0i32 } else { (<lhs>).wrapping_div(__d) } }
```

오늘 식 자리에서 조기 반환하는 표현은 **정확히 둘**이다 — 배열 인덱싱(`codegen.rs:771`)과
문자열 부분 비교(`:1017`, `ml_sublen`이 음수면 bail). 그중 **`i32` 값을 내는 것은 인덱싱뿐**이므로
`/`·`%`의 왼쪽에 올 수 있는 것도 인덱싱뿐이다. 그 경계 검사가 `<lhs>` 안에 있고, 그래서 제수가
0이면 **검사 자체가 실행되지 않는다.**

> *(이 문단은 처음에 인덱싱이 조기 반환하는 **유일한** 식이라고 적었다. Grok이 부분 비교를
> 지적했고 코드로 확인했다 — 결론의 범위는 그대로지만, 근거가 한 칸 좁아졌다.)*

**실측 — 실제로 빌드한 모듈을 로더로 호출했다.** `export fn pick(xs: [i32], i: i32, d: i32) -> i32!`,
본문은 `return xs[i] / d`, `xs`는 원소 3개:

| 호출 | status | 값 |
|---|---|---|
| `pick(i=1, d=2)` | `0` | `10` |
| `pick(i=999, d=2)` | **`-2`** | — |
| `pick(i=1, d=0)` | `0` | `0` |
| `pick(i=999, d=0)` | **`0`** | `0` |
| `pick(i=-1, d=0)` | **`0`** | `0` |

**대조군이 요점이다.** 같은 인덱스가 제수 2에서는 `ML_ST_INDEX_OUT_OF_RANGE`를 내고 제수 0에서는
내지 않는다. 호스트가 보는 것은 "성공했고 답은 0"이다 — §0.1이 지문 슬라이스를 열게 만든 바로 그
**그럴듯한 오답**의 모양이고, 이번에는 인터페이스가 아니라 **한 식 안에서** 생긴다.

**범위도 쟀다**(같은 방법, 방출된 Rust 확인):

| 자리 | 결과 |
|---|---|
| `xs[i] / d` · `xs[i] % d` | **영향받는다** — 경계 검사가 `else` 안 |
| `xs[i] * d` | 영향 없다 — `wrapping_mul`은 피연산자를 무조건 받는다 |
| `n / xs[i]`(오른쪽) | 영향 없다 — `__d`로 **먼저** 묶이므로 검사가 실행된다 |
| `try f(x) / d` | 해당 없다 — 파서가 거부한다(`try`는 식이 아니다) |

**고치지 않았다.** 무엇이 옳은지가 설계 질문이기 때문이다 — 왼쪽을 `__d` 앞으로 끌어올려
**항상 평가**할 것인가(단락 평가가 사라지고 `/0`의 전역성은 유지된다), 아니면 `/0`을 실패 가능
연산으로 되돌릴 것인가(DP-N4가 "정의된 결과"로 닫은 것을 다시 연다). **SPEC 없이 시작하지 않는다**
(`CLAUDE.md` 개발 방법론 1).

> **§5-1이 갚은 부채의 거울상이다.** 거기서는 범위 밖 인덱스가 `&&`의 단락 평가를 **보이게** 했고,
> 여기서는 `/`가 만든 단락 평가가 그 인덱스를 **안 보이게** 한다. 같은 관측 수단이 한 번은 계기,
> 한 번은 피해자다.
>
> **그리고 누군가 이미 적어 뒀다.** `SPEC-fallible-calls` §5.3이 *"`i32` 나눗셈의 오른쪽-먼저
> 평가 — §2.2가 도달 불가능하게 만들 뿐 고치지는 않는다. **식 위치를 여는 날 먼저 고쳐야 한다**"*
> 라고 2026-09-01에 남겼다. 맞는 예견이었는데 **문이 예상한 쪽에서 열리지 않았다** — `try`가
> 식 자리에 온 것이 아니라 `#200`의 배열 인덱싱이 왔다. §5-1과 정확히 같은 실패다: 부채가 무엇이
> 오면 달라지는지를 적어 뒀고, 그것이 왔을 때 그 줄을 다시 읽은 사람이 없었다.
>
> **Grok이 찾았다.** 이 세션의 다른 검증 라운드에서 묻지 않은 결함으로 지목했고, 방출된 Rust와
> 로드한 모듈 양쪽으로 재확인했다.

## 5b. 공개 준비 — 두 번 훑었다 (2026-08-30, #63·#64)

공개 시 "계획을 구현된 기능으로 오독"하게 만드는 문장을 전수 조사했다(Grok 스윕 + 코드 대조).
문제는 부주의가 아니었다. **설계 문서는 자연히 현재형으로 쓰인다** — 내부에서는 그게 맞고,
외부 독자에게만 거짓이 된다.

그래서 설계 문서를 **미래형으로 고치지 않았다**. 그러면 "실제로 내린 결정의 기록"이라는 값이
사라진다. 대신 `ARCHITECTURE.md`·`HOST_ABI.md` 상단에 상태 배너를 달고, 미구현 항목마다
**⏳ 미구현**을 그 자리에 붙였다. 독자는 의도한 설계와 현재 상태를 **둘 다** 본다.

고친 것: 인터페이스/계약 파일(존재하지 않음), 얇은 C 런타임 로더, 무결성 검사, 호스트→모듈 함수 전달,
콜백, context handle, `.so`/`dlsym` 경로, README 파이프라인의 `.so`, "Delphi·C++·C# 호스트"가 다
동작하는 듯한 서술, `COMPETITIVE.md`의 타사 무출처 단정과 "AI 계약 파일"·"호스트가 Delphi만이 아님"
같은 미달성 우위 주장, `SECURITY.md`의 없는 "능력 모델", `ARCHITECTURE.md`의 개발/배포 빌드 구분,
`CLAUDE.md`의 "GitHub Private" 단정, 그리고 **수용 D가 아직 막혀 있다고 말하던 테스트 주석 두 개**
(#43 이후로 명백히 거짓이었다).

**부수 효과 — 다음 세션은 이걸 쓰면 된다.** 이제 `grep -rn "⏳" docs/`가 **미구현 목록의 정본**이다.
설계에는 있는데 아직 없는 것이 전부 한 곳에 모였다(계약 파일 · 무결성 검사 · 개발/배포 빌드 구분 ·
struct 반환과 caller-allocates · context handle · 콜백 · 호스트 함수 등록 · `.so`/ELF · `.mll` 컨테이너 ·
**ABI major 불일치 로드 거부** · **최소 C API 스케치 전체** · **언어 표면의 공백**).
§3b의 후보 목록보다 이쪽이 넓고 정확하다.

> **정정 (2026-08-31): 위 문장은 쓰일 당시 사실이 아니었다.** "정본"이라고 선언했지만 grep은
> 전수가 아니었다. `grep -rn "미구현\|아직 없다\|구현되지 않" docs/ | grep -v "⏳"`가 **⏳ 없이
> 미구현이라고 말하는 줄 8개**를 내놓았고, 그중 둘은 다른 어디에도 추적되지 않는 실제 미구현
> 작업이었다:
>
> - **ABI major 불일치 로드 거부** — `SECURITY.md` P0의 유일한 미충족 항목이다. 모듈은
>   `ml_module_abi_version`을 export하고 오라클은 값이 맞는지 **assert만** 한다.
>   `hosts/rust-oracle/src/lib.rs`의 `Module::load`에는 **버전 게이트가 없어서**, major가 어긋난
>   모듈도 그대로 로드된다. 거부는 D18/`HOST_ABI.md`가 호스트에 요구하는 계약일 뿐이다.
> - **`HOST_ABI.md`의 "최소 C API 스케치" 전체**(`ml_runtime_*` / `ml_module_*`) — 문서는
>   "하나도 구현되지 않았다"고 정직하게 적고 있었지만 마커가 없었다.
>
> 그리고 **언어 표면의 공백은 단 한 줄도 grep에 없었다.** §3b가 "후보를 고를 때는 그쪽을 본다"고
> 지시하는데, 정작 §3a가 권하는 `i32` 나눗셈이 거기 안 나왔다.
>
> **여덟 줄 전부에 마커를 달았다**(`HOST_ABI.md` 4 · `SECURITY.md` 3 · `LANGUAGE.md`의 "아직 아님"
> 블록 1). 사실 관계는 원래 문서에 옳게 적혀 있었다 — 없던 것은 **grep이 볼 수 있는 표식**이다.
>
> **교훈은 §5b 본문의 것과 같은 종류다.** 색인을 만들었으면 **그 색인이 전수인지도 측정해야 한다.**
> 여기서는 그 측정이 없었고, 그래서 "정본"이라는 말이 한 달 가까이 참이 아닌 채로 서 있었다.

**새 문서를 쓸 때 같은 함정을 반복하지 말 것:** 아직 없는 것을 현재형으로 적으면, 그것은 공개되는
순간 거짓이 된다.

## 5c. 공개 전 보안·개인정보 감사 — 끝났다 (2026-08-30). **다시 하지 말 것**

공개 직전에 전수 실측했고 Grok이 독립 검증으로 **PASS**를 냈다. 아래는 **그때 실제로 돌린 검사**다.
같은 것을 다시 돌리는 데 시간을 쓰지 말고, **새로 추가된 것만** 확인한다.

| 검사 | 범위 | 결과 |
|------|------|------|
| 자격증명(`ghp_`·`xai-`·`sk-`·`AKIA`·`xox`·PRIVATE KEY·password) | 작업 트리 + **142 커밋 전체** | 0건 |
| 개인 경로(`C:\Users`·`AppData`·`F:\DEVELOPMENT`·`/home/`) | 작업 트리 + 142 커밋 전체 | 0건 |

**히스토리까지 봐야 한다는 게 요점이다.** 지운 파일도 커밋에는 남으므로 체크아웃만 grep하면 부족하다:
`git grep <패턴> $(git rev-list --all)`.

**CI가 포크 PR에 안전한 이유**(공개 저장소에서 제일 흔한 사고 경로라 따로 봤다): `ci.yml`은
`pull_request`이지 **`pull_request_target`이 아니고**, `secrets.*` 참조가 없고(애초에 secret이 없다),
`${{ github.event.* }}`를 `run:`에 끼워 넣지 않는다(스크립트 인젝션 없음). 기본 워크플로 토큰 권한도
이미 **read**다. **포크 PR이 얻을 수 있는 최악은 CI 시간 소모다.** 이 세 성질을 깨는 변경을 하면
그때 다시 본다.

**남았던 것은 §4-9 하나뿐**(커밋 이메일). 파일이 아니라 git 메타데이터라 위 스캔에 잡히지 않는
자리였다. ✅ **2026-08-31에 닫혔다** — 앞으로의 커밋은 noreply 주소로 나가고, 과거는 권고대로
그대로 둔다(§4-9). GitHub Settings → Emails의 체크박스 두 개만 웹에서 켜면 된다.

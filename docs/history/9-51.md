### 9-51. DP-S4의 **근거**를 쟀다 (2026-09-14, E2) — 결정은 하지 않았다

남은 부채는 하나였다: **한국어 라벨이 모듈에 못 들어간다**(§9-46 R6). 여는 것은 사용자 자리이므로
**결정 대신 근거를 쟀다.** 문서는 손대지 않았다.

#### 9-51.1 DP-S4가 든 이유는 **리터럴에는 적용되지 않는다**

거부 메시지가 이렇게 말한다:

```
non-ASCII character '승' in a string literal —
generated artifacts stay ASCII (non-ASCII trips MSVC C4819 under `/WX`)
```

**실측: 리터럴의 텍스트는 `.h`에도 `.pas`에도 나타나지 않는다**(`approved`를 담은 모듈에서 양쪽 모두
**0회**). 두 바인딩은 이름·타입·매크로·주석만 내고 `IrExpr`을 읽지 않는다(검증 확인). 즉
**C4819는 리터럴이 ASCII여야 하는 이유가 아니다.**

#### 9-51.2 오늘 막는 것은 **MSVC가 아니라 생성 Rust**였다

검사를 잠시 풀고 빌드하니:

```
error: non-ASCII character in byte string literal
```

`ConstStr`이 `b"{s}\0"`으로 낮아지는데 **rustc가 바이트 문자열 안의 비ASCII를 거부**한다.
바이트마다 `\xNN`으로 이스케이프하면 **유효한 Rust이고, 같은 바이트를 나르며, 생성 Rust 자체가
ASCII로 남는다.** 프로브로 확인:

| | 실측 |
|---|---|
| `.h` · `.pas` | **순수 ASCII 유지** |
| 기존 모듈의 골든 | **무변경** — ASCII 리터럴에는 이스케이프가 no-op |
| 호스트가 받는 값 | `"승인"`, `needed = 7`(6바이트+NUL) — **정확** |

#### 9-51.3 조용하지 않은 성질 하나 (좋은 쪽)

컴파일러는 `.mls`를 **UTF-8로 읽는다**. CP949로 저장한 같은 소스는 **거부된다**:

```
mlc: cannot read …/cp949.mls: stream did not contain valid UTF-8
```

즉 비ASCII 리터럴이 나를 바이트는 **결정돼 있고**(UTF-8), 편집기가 무엇으로 저장했느냐에 따라
조용히 달라지지 않는다.

#### 9-51.4 진짜 대가 — 검증이 짚었다

> *"인코딩을 모르는 바이트 동등성: UTF-8 리터럴은 C/Delphi 호스트가 ANSI 코드 페이지로 보내는
> 같은 글자와 **조용히** 일치하지 않는다."*

**이 저장소가 이미 잰 함정이다.** `HOST_ABI.md` §5의 Delphi 표 — `PAnsiChar(AnsiString(S))`는
ANSI 코드 페이지 바이트를 보낸다. 그러면 `c == "승인"`은 **status 0에 false**다.

**그래서 두 방향이 같지 않다:**

| 방향 | 위험 |
|---|---|
| 모듈이 **내보낸다**(`return "승인"`) | 호스트는 바이트를 받아 자기가 해석한다. **단방향 계약**이고 문서에 적을 수 있다 |
| 모듈이 **비교한다**(`c == "승인"`) | 호스트가 무엇을 보내는지에 달렸다 — **조용한 오답**, 이 저장소가 Delphi에서 실측한 그것 |

#### 9-51.5 그리고 DP-K9가 거짓이 된다

`HOST_ABI.md`: *"모듈이 만드는 문자열 바이트는 ASCII `-`와 `0`–`9`뿐이다."* 비ASCII 리터럴을
허용하면 **그 문장이 거짓이 된다.** DP-K9가 연결 슬라이스에서 그 좁은 범위를 고른 이유가
*"모든 후보 인코딩에서 같은 바이트"* 였으므로, 이것은 **DP-S2를 부분적으로 여는 것**이다.

> **결정하지 않았다.** 위 다섯이 장단점 표의 입력이고, 표와 선택은 사용자 자리다(규칙 8).

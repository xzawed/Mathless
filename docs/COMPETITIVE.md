## 직접 참고

| 대상 | 배울 점 | 따라하지 않을 점 |
|------|---------|------------------|
| RemObjects Pascal Script | 임베딩, Inno Setup 검증, 바이트코드 배포 | 기본이 인터프리터. 회사 주력은 미들웨어(Remoting SDK)와 별개 |
| Inno Setup `[Code]` | 호스트 재빌드 없이 복잡한 설치 로직 | 설치 도구 특화, 웹/다중 호스트 아님 |
| DWScript / Lape | 현대 Object Pascal 스크립트 | 네이티브 배포·안티리버싱이 1목표가 아님 |
| AngelScript | C++-like 정적 타입 스크립트, 상용 게임 사용 | 대중 언어 아님. 웹은 실험적 |
| Lua | 임베딩의 왕, 작은 런타임 | 약한 타입, 보호 모델 다름 |
| Emscripten/Cheerp | 네이티브를 웹으로 | 스크립트 언어가 아니라 이식 툴체인 |
| AssemblyScript | 타입 + WASM | TS 계열, Delphi 탈출 서사와 다름 |

## RemObjects에 대한 정리 (우리 이해, 미검증)

우리가 아는 범위에서, RemObjects의 주력 제품군은 Remoting SDK / Data Abstract 같은 미들웨어이고,
Pascal Script는 그와 별개인 오픈소스 스크립트 엔진이며 Inno Setup이 이를 사용한다.  
이 둘을 같은 제품으로 묶어 보면 비교가 어긋난다 — 우리가 처음에 그렇게 착각했기 때문에 적어 둔다.

## Mathless가 이기려는 한 가지 (1차) — **의도이지 실적이 아니다**

기존 Pascal Script 대비 노리는 것:

- 표면 문법이 더 보편적일 것 — 방향만 확정(D15), 세부 문법은 미정
- 산출물이 네이티브 모듈일 것 — **달성**(`.dll` 산출·로드 실측)
- 호스트가 Delphi만이 아닐 것 — **아직 아니다.** 지금 실측된 호스트는 **C**이고, 정작 플래그십인
  Delphi는 미검증이다(`dcc64` 부재). 이 항목은 현재 우리의 약점이지 강점이 아니다
- 배포 보호가 설계 목표일 것 — 목표로 삼고 있고, 측정하는 것은 프록시뿐이다(export 개수·크기·소스
  부재). "보호된다"는 결론으로 쓰지 않는다

Lua/AngelScript 대비 노리는 것:

- 더 강한 타입 — 정적 타입은 있다. 다만 표면은 아직 작다(`docs/LANGUAGE.md`)
- AI 친화 계약 파일 — **⏳ 존재하지 않는다.** ROADMAP Phase 2의 계획이다
- Delphi 제품군과의 친연성 — 의미 모델 수준의 의도이며, Delphi 호스트로 검증되지 않았다

이 방향이 흔들리면 프로젝트 정체성이 흔들린다. 다만 **방향과 현재 능력을 같은 문장에 섞지 않는다.**

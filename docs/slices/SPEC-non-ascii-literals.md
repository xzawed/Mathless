# SPEC — 비ASCII 문자열 리터럴, **내보내는 자리에서만**

> **기록 문서다.** 이 SPEC은 닫힌 슬라이스의 설계 기록이다 — 본문은 닫힌 날의 사실이고 다시 고치지 않는다.
> 현재 상태는 [`docs/STATUS.md`](../STATUS.md)가 말한다.

- **상태: 확정 · 구현 완료 (2026-09-14).** **DP-U1~U6을 사용자가 확인했다** — 여섯 다 권고대로다.
  - **수용 A~J 전부 닫혔다.** `examples/claim.mls`가 §9-46의 R6 그 규칙이고 C 호스트가 부른다.
  - 📌 **DP-S4가 든 C4819가 구현 중 실제로 났다 — 모듈이 아니라 `host.c` 주석에서.** §9-51이
    잰 구분(손으로 쓴 C에는 적용되고, 모듈 리터럴은 C 컴파일러가 읽는 산출물에 닿지 않는다)이
    **그 자리에서 확인됐다.**
  - 방향(**반환 자리에서만**)을 먼저 골랐고, 갈리는 하나를 따로 물었다: **DP-U4 — DP-K9 문장을
    고치고 진행한다.** DP-U1·U2는 **사전 검증이 두 번 고쳐서** 이미 좁혀진 상태로 확인됐다.
- 선행: `SPEC-string-input.md`(**DP-S2 인코딩 미확정** · **DP-S4 리터럴 ASCII 전용**) ·
  `SPEC-string-return.md`(Q12) · `SPEC-string-concat.md`(**DP-K9** 모듈이 만드는 바이트는 ASCII `-`와 `0`–`9`)
- 관련 결정: **DP-S4**(이 문서가 좁게 연다) · **DP-S2**(부분적으로 열린다) · **DP-K9**(거짓이 된다)
- 발단: **2026-09-13 §7 재실행**(§9-46 R6) · **2026-09-14 근거 실측**(§9-51)

## 0. 왜 — 측정부터

### 0.1 DP-S4가 든 이유는 리터럴에 적용되지 않는다 (E2)

거부 메시지가 *"generated artifacts stay ASCII (non-ASCII trips MSVC C4819 under `/WX`)"* 라고
말하는데, **리터럴의 텍스트는 어느 바인딩에도 닿지 않는다** — `.h` **0회**, `.pas` **0회**(실측).
두 바인딩은 이름·타입·매크로·주석만 내고 `IrExpr`을 읽지 않는다.

**C4819는 MSVC가 컴파일하는 것에 관한 경고이고, 리터럴은 거기 가지 않는다.**

### 0.2 오늘 막는 것은 rustc다

`ConstStr`이 **바이트 문자열** `b"…"`로 낮아지고 rustc가 그 안의 비ASCII를 거부한다
(`error: non-ASCII character in byte string literal`). 바이트마다 `\xNN`이면 유효한 Rust이고
**생성 Rust 자체가 ASCII로 남는다.** 프로브 실측:

| | 결과 |
|---|---|
| `.h` · `.pas` | **순수 ASCII 유지** |
| 기존 모듈의 골든 | **무변경** (ASCII 리터럴에는 no-op) |
| 호스트가 받는 값 | `"승인"`, `needed = 7`(6바이트+NUL) |

### 0.3 이미 안전한 성질

`mlc`는 `.mls`를 **UTF-8로 읽는다.** CP949로 저장한 같은 소스는 **거부된다.** 그러므로 리터럴이
나르는 바이트는 **결정돼 있고**, 편집기 설정에 따라 조용히 달라지지 않는다.

### 0.4 진짜 대가 — 그리고 그것이 이 슬라이스의 **모양**을 정했다

> *"인코딩을 모르는 바이트 동등성: UTF-8 리터럴은 C/Delphi 호스트가 ANSI 코드 페이지로 보내는
> 같은 글자와 **조용히** 일치하지 않는다."* (사전 검증)

**이 저장소가 이미 잰 함정이다** — `HOST_ABI.md` §5의 Delphi 표에서
`PAnsiChar(AnsiString(S))`는 ANSI 바이트를 보낸다. 그러면 `c == "승인"`은 **status 0에 false**다.

**두 방향은 같지 않다:**

| 방향 | 누가 인코딩을 정하나 | 실패 모양 |
|---|---|---|
| 모듈이 **내보낸다** | **모듈**이 UTF-8을 낸다. 호스트는 받아서 해석한다 | **없다** — 계약을 문서에 적으면 끝 |
| 모듈이 **비교한다** | **호스트**가 무엇을 보내느냐 | **조용한 오답** |

**그래서 내보내는 자리만 연다.** 이것이 사용자가 고른 것이고, 근거는 위 표다.

## 1. 목표

```mls
export fn status_label(code: string) -> string! {
  if code == "AP" { return "승인" }     // ✅ 내보낸다
  return "심사중"                        // ✅
}

export fn is_approved(label: string) -> bool {
  return label == "승인"                 // ❌ 거부 — 호스트가 보내는 바이트에 달렸다
}
```

**하지 않는 것**: 인코딩 확정(DP-S2는 여전히 미확정), 문자 단위 연산, 대소문자, 정규화,
소스 파일 인코딩 선택(UTF-8 고정).

## 2. 계약 (Contracts)

### 2.1 규칙 — **소비하는 자리에서 거부한다** (DP-U1)

> 🔴 **초안이 이 절을 반대로 적었고, 사전 검증이 잡았다.** 처음에는 *"반환 트리 안에서만 허용"*
> 이라고 썼는데, 그 검사를 `Stmt::Return` 팔이 할 수 있다는 전제가 **틀렸다** — 그 팔은 **뿌리
> 종류만** 보고 중첩된 리터럴도, 다른 문장도 보지 않는다(검증 확인). 그래서 규칙을 뒤집었다:
> **기본은 허용이고, 바이트를 *검사하는* 자리가 거부한다.** 이 저장소에 이미 있는 모양이다
> (`reject_built_string`).

`ConstStr`이 놓일 수 있는 자리는 IR에 여섯뿐이고, 그중 **둘만** 위험하다:

| 자리 | 판정 | 왜 |
|---|---|---|
| `c == "승인"` / `!=` | ❌ **거부** | §0.4 — 호스트가 ANSI를 보내면 **조용한 오답** |
| `g("승인")` (호출 인자) | ❌ **거부** | 호출된 함수가 비교할 수 있다. **전이는 추적하지 않고 거부한다** |
| `return "승인"` | ✅ | 버퍼로 나간다 |
| `return … + "승인"` (연결 조각) | ✅ | 같은 자리 |
| `byte_len("승인")` → `6` | ✅ | **모듈 자신이 쓴 바이트**를 세는 것이다. 조용한 오답이 아니다 |
| `byte_slice("승인", 0, 3)` | ✅ | 잘라서 버퍼로 나간다. 문자 경계 문제는 **DP-B1이 이미 적은 대가**이고 새 위험이 아니다 |

> **ASCII 리터럴은 어디든 그대로다.** 이 문서는 **비ASCII에만** 두 거부를 붙인다.

### 2.2 검사는 **빠짐없는 워커 하나**로 한다 (DP-U2)

렉서는 위치를 모른다. 그러면 타입체커인데, **어떻게**가 두 번 틀렸고 두 번 다 검증이 잡았다:

| 초안 | 왜 틀렸나 |
|---|---|
| *"`Stmt::Return` 팔이 이미 모양을 보니 거기서 하면 된다"* | 그 팔은 **뿌리 종류만** 본다. 중첩 리터럴도 다른 문장도 못 본다 |
| *"`reject_built_string`처럼 소비 자리 둘에서 거부한다"* | 그 여섯 호출은 **다섯 팔**에 흩어져 있다. 그리고 **소비 자리를 열거하는 것이 바로 이번 세션이 다섯 번 만난 결함**이다 — `byte_len`이 `reject_built_string`을 빠뜨렸고(#224), 헤더 게이트가 두 번 좁았다(#238) |

> 검증의 말 그대로: *"리터럴의 성질은 `Expr::Str`에 속한다 — 소비 자리 가드를 복제하면
> `let`·`return`·연결을 놓치고 `byte_len`/`try` 구멍을 다시 만든다."*

**그래서 열거하지 않는다.** `ir.rs`에 **빠짐없는 워커** 하나를 둔다:

```rust
/// 출력 자리 밖에 있는 비ASCII 리터럴의 첫 번째를 돌려준다.
pub fn non_ascii_literal_outside_output(body: &[IrStmt]) -> Option<String>
```

- 문맥을 **아래로 들고 간다**: `Return`의 식은 허용 문맥이고, 그 안의 `Concat` 조각 ·
  `ByteSlice`의 문자열 · `ByteLen`의 피연산자도 허용. 그 밖은 전부 금지 문맥.
- **match가 빠짐없다** — 새 IR 변종은 *"이 자리는 출력인가"* 에 **답하지 않으면 크레이트가
  빌드되지 않는다.** `Cargo.toml`이 `wildcard_enum_match_arm`을 deny한 것과 같은 기계이고,
  §9-50이 *"바인딩과 문서는 컴파일러가 묻지 않는다"* 고 적은 뒤 이번에 **묻게 만드는** 쪽이다.
- 타입체커는 `first_index`가 쓰이는 그 자리에서 이 워커를 한 번 부른다 — 시그니처를 볼 수 있는 층.

**렉서**: 문자열 리터럴 안의 비ASCII를 **더 이상 거부하지 않는다**(이스케이프·제어문자 규칙 유지).

진단은 **왜**를 말한다 — C4819가 아니라 **호스트가 보내는 바이트**:

```
function 'f': a non-ASCII literal may only be RETURNED, not compared —
a host that sends the same characters in its ANSI code page would not match,
with status 0 and no warning (HOST_ABI 문자열 파라미터 계약 §5)
```

### 2.3 방출 — **생성물은 ASCII로 남는다** (DP-U3)

`ConstStr`을 낼 때 **printable ASCII 밖의 바이트를 `\xNN`으로** 쓴다. 한 자리 변경이다(검증 확인).

- 생성 Rust: ASCII
- `.h` · `.pas`: 애초에 리터럴을 담지 않는다(§0.1)
- **기존 모듈: 골든 무변경**(실측)

### 2.4 인코딩 — **UTF-8이고, 모듈이 그것을 주장한다** (DP-U4)

소스가 UTF-8이어야 하므로(§0.3) 리터럴 바이트는 UTF-8이다. **이것이 DP-S2를 부분적으로 여는
지점이다**: 오늘까지 모듈은 인코딩을 주장하지 않았다.

**정확히 무엇이 열리나:**

| | 그 전 | 이 슬라이스 뒤 |
|---|---|---|
| 모듈이 **만드는** 바이트 | ASCII `-`와 `0`–`9`뿐 (DP-K9) | **+ 반환 리터럴의 UTF-8 바이트** |
| 모듈이 **읽는** 바이트 | 불투명, 해석 없음 | **그대로** — 아무것도 안 바뀐다 |

**DP-K9의 문장이 거짓이 되므로 `HOST_ABI.md`를 고친다**(§6 W5).

### 2.5 바인딩이 **그것을 말한다** (DP-U5)

#238의 교훈 — *바인딩은 모듈이 할 수 있는 것을 이름으로 줘야 한다*. 비ASCII 리터럴을 담은 모듈의
`.h`와 `.pas`에 **한 줄**을 낸다:

```c
/* This module returns UTF-8 bytes: a string literal in its source was not ASCII.
   `ml_needed` counts BYTES, so a 2-character Korean label is 7. A Delphi host
   receiving this into an AnsiString in a non-UTF-8 code page will show mojibake. */
```

**조건부로 낸다** — 비ASCII를 담지 않은 모듈은 그대로다(#235가 남긴 과잉 방출 교훈).

### 2.6 `byte_len`의 대가는 그대로 (DP-U6)

`byte_len("승인")`은 애초에 §2.1이 거부하지만, **반환된 라벨의 길이를 호스트가 재면 6이지 2가
아니다.** DP-L2가 이미 적은 대가이고 이 슬라이스가 **더 자주 만나게** 만든다 — 수용 F가 측정한다.

## 3. 수용 기준 (측정 가능)

**모두 로드된 모듈에서 잰다(E2).** 머지 시점에 어느 테스트가 어느 기준을 닫았는지 이 표에 적는다.

- **A. 값.** `status_label("AP")` → `"승인"`, `needed = 7`. `mlprobe`로도 같은 값.
- **B. 생성물이 ASCII다.** `.h`·`.pas`·생성 Rust에 비ASCII 바이트가 **0개**.
- **C. 기존 모듈 무변경.** 골든 **diff 0줄**(ASCII 리터럴에 이스케이프는 no-op).
- **D. 비교는 거부된다.** `c == "승인"`이 **컴파일 에러**이고, 진단이 **ANSI 코드 페이지**를 이유로 댄다.
- **E. 호출 인자도 거부된다** — 그리고 **`byte_len`·`byte_slice`·연결 조각은 거부되지 않는다**
  (§2.1의 표 여섯 줄 전부, 양쪽 방향으로).
- **F. 바이트는 문자가 아니다.** 반환된 `"승인"`의 `needed`가 **7**(6바이트+NUL)임을 호스트가 본다.
- **G. 소스 인코딩.** CP949로 저장한 같은 소스는 **거부된다**(오늘 이미 그렇다 — 회귀로 못박는다).
- **H. 바인딩이 말한다.** 비ASCII를 담은 모듈의 `.h`·`.pas`에 UTF-8 주석이 있고, **안 담은 모듈엔 없다.**
- **I. 보호 프록시 무변경.** export 3개, import 집합이 대조 모듈과 동일.
- **J. 호스트 두 곳.** 오라클 + **실제 C 호스트**(수용 D 게이트)에서 같은 바이트.

### 3.1 반드시 거부되는 것

§2.1의 표 다섯 줄 전부, 그리고 **ASCII 리터럴은 어디서도 거부되지 않는다**(회귀).

## 4. 설계 결정 (DP — **확정, 2026-09-14 사용자 확인 — DP-U1~U6 전부 권고대로**)

| # | 질문 | 권고 | 대가 |
|---|---|---|---|
| **DP-U1** | 규칙의 방향 | **소비하는 두 자리에서 거부**(비교·호출 인자) — 사용자가 고른 *"내보내는 자리에서만"* 을 **실제로 구현 가능한 모양**으로 옮긴 것 | 리터럴이 **위치에 따라 다른 규칙**을 갖는다. 문자열 위치 제한이 이미 그런 언어다 |
| **DP-U2** | 검사 방법 | **빠짐없는 워커 하나**(`ir.rs`), 소비 자리 열거가 **아니다** | 렉서 메시지가 사라지고 진단이 뒤로 밀린다. 대신 **이유가 맞는 말**이 되고, 새 IR 변종이 **답하지 않으면 빌드가 안 된다** |
| **DP-U3** | 방출 | **`\xNN` 이스케이프** | 없다. 한 자리, 기존 모듈 무변경 |
| **DP-U4** | 인코딩 | **UTF-8**(소스가 UTF-8이므로) | **DP-K9가 거짓이 되고 DP-S2가 부분적으로 열린다.** 공짜가 아니다 |
| **DP-U5** | 바인딩 고지 | **조건부 한 줄** | 헤더가 한 줄 길어진다. 안 하면 #238이 고친 결함을 새로 만든다 |
| **DP-U6** | `byte_len` | **그대로**(바이트) | 라벨 길이를 재는 호스트가 6을 본다. DP-L2의 기존 대가 |

## 5. 범위 밖 / 위험

### 5.1 이 슬라이스가 하지 않는 것

- **DP-S2를 닫지 않는다.** 호스트가 보내는 바이트의 인코딩은 여전히 미확정이다.
- **비교를 열지 않는다.** 그것이 §0.4의 이유이고, 열려면 인코딩을 정해야 한다.
- **문자 단위 연산·정규화·대소문자** — 전부 밖.
- **소스 인코딩 선택** — UTF-8 고정(오늘 이미 그렇다).

### 5.2 이 슬라이스가 만드는 새 위험

| 위험 | 막는 것 |
|---|---|
| **호스트가 UTF-8인 줄 모른다** | §2.5의 바인딩 한 줄 + **수용 H** |
| **저자가 비교에 쓰려 한다** | §2.2의 거부 + 진단이 **이유를 댄다** + **수용 D** |
| **길이를 문자로 읽는다** | **수용 F**가 `needed = 7`을 못박는다 |
| **생성물에 비ASCII가 샌다** | **수용 B**가 세 산출물 전부에서 0을 단언 |

## 7. 정직한 반론 (기록)

- **§7이 강제하지 않았다.** §9-46에서 **결합** 잣대로 열리는 것이지 능력 잣대가 아니다.
- **DP-S4를 뒤집는 것이 아니라 좁게 여는 것이다.** 그 결정의 *이유*가 리터럴에 대해 틀렸다는 것을
  §9-51이 실측했고, **틀린 이유를 고치는 것과 결정을 뒤집는 것은 다르다.**
- **이 문서의 §2.2가 두 번 틀렸고 둘 다 사전 검증이 잡았다.** 구현 전에 잡혔으니 대가는 문단 하나지만,
  **같은 종류의 실수를 이번 세션에 다섯 번 했다는 것**은 적어 둔다 — 전부 *"답해야 할 자리를 손으로
  열거했다"* 였다. 그래서 DP-U2가 열거를 버리고 **컴파일러가 묻게** 한다.
- **가장 쓰고 싶은 곳을 열지 않는다.** 한국어 코드-라벨 표를 만들려면 `c == "승인"`이 필요한데
  그것이 정확히 조용한 오답 자리다. **절반만 푼다는 것을 적어 둔다.**

# HOST ABI

> **이 문서는 합의된 ABI 설계를 현재형으로 기술한다. 전부 구현된 것은 아니다.**
> 오늘 실제로 존재하는 경계는 아래 "현재 구현된 경계" 절이 정본이고, 아직 만들지 않은 항목에는
> **⏳ 미구현**을 붙였다. 결정(D16·D18 등)의 기록으로 남기려고 문장을 미래형으로 바꾸지는 않았다.

## 원칙

밖으로 나가는 유일한 1급 경계는 **C ABI**다.  
언어별 바인딩은 그 위의 얇은 래퍼다.

## MVP에서 호스트가 하는 일

1. 런타임/로더 초기화
2. 모듈 파일 로드
3. export 함수 조회
4. 호출
5. (선택) 호스트 함수를 모듈에 등록 — **⏳ 미구현**
6. 언로드

## 현재 구현된 경계 (2026-08-29 실측)

아래 "최소 C API 스케치"는 **⏳ 미구현**이다 — 하나도 구현되지 않았다. 지금 실제로 동작하는 경계는 그보다 얇다:

- 호스트가 OS 로더로 직접 모듈을 연다. **Windows만 실측했다** — `.so`/ELF와 `dlsym` 경로는 ⏳ 미구현(D22 미개시). (Rust 오라클은 kernel32 `LoadLibraryW`, C 호스트는
  `LoadLibraryA` + `GetProcAddress`).
  **`ml_runtime_*` / `ml_module_*` 로더 API는 없다.**
- 모듈이 export하는 것은 **`mlx_<함수명>` + `ml_module_abi_version`뿐**(PE 리더로 측정).
- 마샬링은 **스칼라만**: `f64`/`bool`/`i32`. 실패 가능 함수는 D17대로
  `int32_t mlx_f(<params>, T* out_value)`. **명시적 `out` 파라미터**도 스칼라로 지원한다 —
  선언 순서대로 `T*`로 나가고, D17의 `out_value`가 언제나 맨 마지막이다(SPEC-out-params DP-O1).
  **문자열은 입력 파라미터만 구현됐다** — `const char*`(Delphi `PAnsiChar`), NUL 종료, 호출 동안
  빌림. 아래 "문자열 파라미터 계약" 절을 읽을 것. **문자열 반환**·구조체·콜백·호스트 함수 등록은
  **⏳ 미구현**.
- 산출물은 `.dll` + `.h`(C 헤더) + `.pas`(Delphi unit). **`.h`는 실제로 소비된다** — MSVC로 빌드한
  C11 호스트가 이를 컴파일하고 모듈을 로드·호출한다(수용 D, 2026-08-29). **`.pas`는 여전히 미검증**
  (`dcc64` 없음) → DRAFT 표기 유지.

## 최소 C API 스케치 (초안 — **⏳ 미구현**)

이름은 가칭.

```c
typedef struct MlRuntime MlRuntime;
typedef struct MlModule MlModule;

MlRuntime* ml_runtime_create(void);
void       ml_runtime_destroy(MlRuntime*);

MlModule*  ml_module_load(MlRuntime*, const char* path, int* err);
void       ml_module_unload(MlModule*);

void*      ml_module_get_fn(MlModule*, const char* name);

int        ml_module_set_host_fn(MlModule*, const char* name, void* fn);
```

실제 함수 시그니처 마샬링은 MVP에서 제한한다.

- 인자: 정수, 실수, bool, C 문자열 포인터 정도
- 구조체는 포인터 + 명시적 레이아웃이 합의된 것만
- 콜백은 함수 포인터 한 단계만

## 수명 (D16)

소유권을 3층으로 나눈다:

- **인자 포인터** = 호출 기간 동안만 유효(빌림). 호출 반환 후 접근 금지.
- **반환 데이터** = caller-allocates out-buffer. **스칼라는 구현됨** — 반환값, D17의 `out_value`,
  그리고 명시적 `out` 파라미터. **가변 길이 버퍼는 ⏳ 미구현**이지만 **규약은 확정됐다**(Q12,
  2026-08-31) — 아래 "가변 길이 데이터" 절.

### out-parameter 계약 (호스트가 지켜야 할 것)

스칼라 out-param은 **호스트가 할당한다**(보통 스택 변수). 모듈은 거기에 쓸 뿐 소유하지 않는다.

1. **포인터는 호출 기간 동안 유효해야 한다**(D16). 모듈은 호출이 끝난 뒤 그것을 붙들지 않는다.
2. **NULL을 넘기지 마라.** 모듈은 검사하지 않는다 — 검사는 완전할 수 없고(정렬 안 된·해제된
   포인터는 NULL이 아니다) 호출마다 분기를 늘린다. NULL은 **정의되지 않은 동작**이다.
3. **`status != 0`이면 어떤 out-param도 읽지 마라**(D17 DP-E3 + SPEC-out-params DP-O3).
   **계약은 "모듈이 쓰지 않는다"가 아니라 "호스트가 읽지 마라"다** — DP-O3가 일부러 그렇게 정했다
   (버퍼링 후 원자적 커밋은 비용을 내고 계약 하나를 없앨 뿐이다).
   **실측(2026-08-31):** `out` 파라미터를 `fail` **앞에서** 대입하는 함수는 실패해도 그 값을
   **쓴 채로 둔다**(`order_check(250, &offending)` → status `1`, `offending == 250`).
   D17의 `out_value`만 미변경이다(반환 경로에서만 쓰기 때문). 즉 **"실패하면 아무것도 안 쓴다"는
   보장이 아니라 그 프로그램의 성질일 뿐이다.** 회귀 테스트: `hosts/rust-oracle/tests/out_params.rs`
   의 `a_failing_call_may_leave_a_declared_out_written`.
4. 성공한 호출은 선언된 모든 out-param을 쓴다(DP-O2가 컴파일 타임에 강제한다).

### 문자열 파라미터 계약 (호스트가 지켜야 할 것)

`string` 파라미터는 C의 **NUL 종료 `const char*`**로 나간다(SPEC-string-input DP-S1). 이것은
**입력 전용**이다 — 모듈은 문자열을 만들지도, 돌려주지도, 붙들지도 않는다.

1. **버퍼는 호출 기간 동안만 유효하면 된다**(D16 (1) 빌림). 모듈은 호출이 끝난 뒤 접근하지 않는다.
2. **NUL로 끝나야 한다.** 모듈은 NUL까지만 읽고, 그 뒤의 바이트는 보지 않는다(실측). 끝나지 않은
   버퍼를 넘기면 모듈이 그 너머를 읽는다 — **정의되지 않은 동작**이다.
3. **NULL을 넘기지 마라.** out-param의 2번과 같은 이유이고 같은 결론이다(DP-S5).
4. **인코딩은 호스트 계약이다.** 모듈은 **바이트만** 본다 — `==`는 NUL까지의 바이트 동등성이고,
   대소문자를 구분하며 정규화하지 않는다(DP-S2). 호스트가 넘기는 바이트와 `.mls` 소스에 쓴
   리터럴의 바이트가 같은 인코딩이어야 한다. 소스 리터럴은 **ASCII만** 허용하므로, ASCII 범위에서는
   UTF-8·Latin-1·대부분의 코드 페이지가 일치한다.
5. **⚠ Delphi 함정 (E1 — `dcc64`가 없어 미측정).** Delphi의 기본 `string`은 UTF-16
   `UnicodeString`이다. **어떤 캐스트를 쓰느냐가 결과를 가른다:**
   - `PAnsiChar(AnsiString(S))` — **맞다.** 단, `AnsiString`을 **지역 변수에 담아** 호출이 끝날 때까지
     살려 둘 것. 캐스트 식 안의 임시값은 그 **문장**까지만 산다.
   - `PAnsiChar(S)`(UnicodeString에 직접) — 암시적 캐스트 경고와 함께 **ANSI 코드 페이지로 변환**된다.
     ASCII는 살아남지만 그 밖은 보장되지 않는다.
   - `PAnsiChar(Pointer(S))` — **틀렸고 조용하다.** UTF-16 바이트를 그대로 재해석하므로 **아무 코드에도
     맞지 않고 크래시도 나지 않는다.** 이 저장소가 네 번 만난 그 모양이다.

   생성 `.pas`에 같은 세 줄을 넣는다. **아무것도 측정되지 않았다** — Embarcadero 문서 기준(E1)이며,
   Delphi가 붙는 날 가장 먼저 확인할 항목이다.

### 가변 길이 데이터 — **⏳ 미구현, 규약은 확정**(Q12, 2026-08-31)

**모듈은 할당하지 않는다.** 문자열·배열은 호스트가 버퍼와 용량을 주고, 모듈이 채우고, 필요한 길이를
돌려준다. 모듈이 힙을 잡아 호스트에 넘기는 방식은 **기각됐다** — 모듈은 UCRT 힙을 쓰고, D16이
"할당자 넘는 소유권 이전 금지"를 규정하며, Delphi 호스트는 자기 메모리 매니저를 쓴다.

```c
int32_t mlx_name(int32_t id, char* buf, int32_t cap, int32_t* needed);
```

| status | 뜻 | `buf` | `*needed` |
|---|---|---|---|
| `0` | 성공 | 채워짐(NUL 종료) | 쓴 길이 |
| **음수** | **용량 부족 — 절단** | **건드리지 않음** | **필요한 길이** |
| 양수 | 모듈 정의 도메인 에러(D17) | 건드리지 않음 | 건드리지 않음 |

1. **절단은 실패다, 성공이 아니다.** 음수 status로 보고한다. 호스트가 `0`만 확인하고 넘어가도
   꼬리가 조용히 잘리지 않게 하려는 것이다 — 그 조용한 오답은 이 저장소가 이미 네 번 만났다.
2. **길이를 모르면 두 번 부른다.** `cap = 0`으로 한 번 불러 `*needed`를 받고, 버퍼를 잡아 다시 부른다.
   이것은 **새 ABI가 아니라 호스트 쪽 재시도**이며, 모듈은 `no_std`·무할당으로 남는다.
3. **호스트가 준 버퍼는 호스트 것이다.** 모듈은 호출이 끝난 뒤 그것을 붙들지 않는다(D16).
4. **고정 레이아웃 struct는 여기 해당하지 않는다.** 스칼라 필드만 있는 struct는 길이가 정해져 있어
   `sizeof(T)` out-param으로 충분하다 — 위의 out-parameter 계약 그대로다.
   **경계는 "스칼라 필드만"이다:** struct가 문자열이나 배열을 품는 순간 길이가 정해지지 않으므로
   이 절의 규약으로 넘어온다.
- **모듈 상태** = 명시적 context handle. 생성부터 파괴까지 생존(단일 호출을 넘어감). **⏳ 미구현** — D16의 결정이며 아직 슬라이스로 만들지 않았다.

규칙:

- 모듈 힙과 호스트 힙은 분리. 서로의 할당을 free하지 않는다(할당자 불일치 = UB).
- 모듈은 호스트 메모리를 소유하지 않는다.
- 등록된 호스트 함수 포인터는 호출을 넘어 유효(콜백). 모듈 언로드 후에는 모든 함수 포인터 무효. **⏳ 미구현** — 콜백도 호스트 함수 등록도 아직 없다.
- 호스트 객체를 모듈이 보관하려면 명시적 handle로만.

## 생존성 (liveness) — 호출은 돌아오지 않을 수 있다

`while`이 들어오기 전(2026-08-29)까지 Mathless 함수는 **전부 반드시 종료했다**: 표면에 호출 식이
없어 재귀가 불가능했고 반복 구문도 없었다. 그래서 "export를 호출하면 언젠가 돌아온다"를 모든
호스트가 공짜로 보장받았다. **이제는 아니다.**

**계약:**

- **모듈 export 호출은 반환하지 않을 수 있다.** 무한 루프는 C ABI를 건너 **호출한 스레드를 정지**시킨다.
- 모듈은 **신뢰되는 코드**로 취급한다 — 호스트 개발자가 컴파일하거나 승인한 모듈이라는 뜻이다.
  신뢰할 수 없는 제3자 모듈을 안전하게 실행하는 것은 **지금의 위협 모델이 아니다**.
- **응답성이 필요한 호스트는 워커 스레드에서 호출하라.** UI 스레드에서 직접 호출하면 모듈이 멈출 때
  UI도 멈춘다.
- 호스트가 스레드를 밖에서 죽여 회수할 수 있다고 가정하지 마라 — `TerminateThread`류는 UB에 가깝다.

**모듈 쪽에서 할 수 있는 것은 지금 없다**(SPEC-while §5.1, 사용자 승인):

| 대안 | 왜 안 하는가 |
|------|--------------|
| 연료(fuel)/명령 계수기 | 인터프리터·VM이 필요 — **R01 기각**, **D11**(컴파일 타임 변환만)과 충돌 |
| `while true` 정적 거부 | **불완전하다** — `while 1 == 1`, 조건 변수 등으로 즉시 우회된다 |
| 워치독이 스레드 강제 종료 | UB. 모듈 힙·락 상태가 임의 지점에서 깨진다 |

우회 가능한 반쪽 방어를 넣고 안전하다고 말하지 않는다. 이것은 **계약이지 강제가 아니다**.

> 이 항목은 `SECURITY.md`에 넣지 않는다. 그 문서의 보호 대상은 **배포된 알고리즘**이고, 호스트
> 생존성은 다른 축이다. 모듈을 적대적 코드로 다루는 위협 모델은 지금 채택하지 않았다.

## 호스트별 우선순위

| 순위 | 호스트 | 방식 |
|------|--------|------|
| 1 | C / C++ | 직접 C ABI |
| 1 | Delphi | `external` / cdecl 래퍼 |
| 2 | Rust | `extern "C"` |
| 3 | C# | P/Invoke |
| 4 | Python | ctypes/cffi |

초기 공식 지원은 **Delphi + C** 두 개만 권장.

## 버전

ABI 버전은 파일 선두 커스텀 헤더가 아니라 **예약 export 심볼**로 노출한다(D18). 표준 DLL/SO는 offset 0에 PE/ELF 매직이 있어야 로더가 인식하므로 선두 헤더는 로드 불가다. 로더는 `ml_module_abi_version`을 `GetProcAddress`(Windows, 실측)로 조회한다. `dlsym` 경로는 ⏳ 미구현이다.  
호스트와 모듈의 major가 다르면 로드 실패 — 단 이는 **호스트에 대한 계약(요구사항)** 이고, 현재 Rust 오라클은 심볼을 조회해 값이 일치함을 **assert만** 한다 — **거부 경로는 ⏳ 미구현**(2026-08-29). 게이트가 없으므로 major가 어긋난 모듈도 그대로 로드된다.

## 네이밍 규약

- 런타임/예약 심볼: `ml_*` (예: `ml_runtime_create`, `ml_module_abi_version`).
- 사용자 모듈이 export하는 함수: 별도 접두어(예: `mlx_`) 또는 모듈명 네임스페이스. `ml_`와 충돌 금지(D18).

## 하지 말 것 (MVP)

- RTTI로 호스트 객체 전체를 자동 노출
- COM/IDispatch를 기본 경로로
- 예외가 ABI를 가로지르게 두기 (에러 코드 또는 명시적 변환)

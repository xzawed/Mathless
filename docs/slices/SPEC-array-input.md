# Slice SPEC — 배열 **입력** 파라미터

> **상태: 초안. 사용자 확인 전이며, 구현은 시작하지 않았다.**
> §4의 DP 항목이 확인되면 §6 WBS로 착수한다.

관련: **D16**(빌림·소유권) · **D17**(status/에러) · **D15**(표면 문법 계열) ·
**STATUS §9-9**(배열 결합도 실측) · `SPEC-string-input.md`(직접 선례).

> **Q12는 이 슬라이스를 지배하지 않는다.** Q12(caller-allocates out-buffer)는 **모듈이 만들어
> 돌려주는** 가변 길이 데이터의 규약이다. 입력 방향은 호스트가 이미 가진 메모리를 **빌리는**
> 것이므로 D16 규칙 1이 지배하며, `string` 입력 파라미터가 바로 그 선례다. 색인의 한 줄
> ("배열 IN … Q12 프로토콜을 물려받는다")은 **반환 방향에 해당하는 말**이고, 이 SPEC이 그것을
> 좁힌다 — 배열 **반환**이 Q12를 물려받는다(§5.1).

---

## 1. 목표 — **능력이 아니라 §9-9가 남긴 두 줄이다**

**이 슬라이스는 "배열이 필요해서" 열리지 않는다.** 그 반대가 실측돼 있다.

`STATUS.md` §9-9는 얼린 호스트에 `.dll`만 바꿔 끼우는 실험으로 방법 교체 생존율을 쟀고,
**일반형 fold 호스트는 전부 살아남았다**(`host_round` 5/5, `host_array` 5/5, 덜 일반적인
`host_rank`만 4/5). 결론은 명시적이다 — *"이 실험은 배열을 강제하지 않는다 — 다섯 번째로 같은
결론이다."* 그 절은 **사용자 결정**으로 넘기며 남은 차이를 두 줄로 적었고, 사용자가 그 두 줄의
값을 인정해 이 슬라이스를 골랐다(2026-09-10).

### 1.1 남은 두 줄 (§9-9 말미, 실측 기반)

1. **fold는 얼리기 전에 일정(schedule)을 맞혀야 한다.** `host_rank`는 "한 번 순위 매기면 끝"을
   전제로 얼렸고 `dhondt`에서 **크래시도 거부도 아닌 `12 12 25 88` — `biggest`의 답**을 냈다.
   네 모듈의 `ml_iface_hash`가 전부 같아 **지문 게이트가 이것을 보지 못한다.** 고치려면
   **호스트를 다시 빌드해야 한다** — `ARCHITECTURE.md`의 "호스트 재빌드 없이 모듈만 교체"가
   이 부류의 변경에는 성립하지 않는다.
2. **일반형 fold는 성능과 노출로 대가를 낸다.** 호출이 `N`번에서 `여분 × N`번으로 늘고, 평문
   호스트가 **"여분을 하나씩, 항목별 우선순위로 나눠 준다"** 는 **방법 계열을 드러낸다.**
   `host_array`는 **호출 한 번**이고 드러내는 것이 "규칙이 있다"뿐이다 — **D05 쪽 논거다.**

### 1.2 그래서 이 SPEC이 주장하지 않는 것

- "배열이 있어야 이 업무 규칙을 쓸 수 있다"고 **주장하지 않는다.** 다섯 번 반증됐다.
- 성능 수치를 주장하지 않는다. `여분 × N` 대 `1`은 **호출 횟수**이고, 그것이 시간으로 얼마인지는
  재지 않았다. 재고 싶으면 별도 측정이다.

## 2. 계약 (Contracts)

### 2.1 타입과 문법 (DP-A1)

```
export fn total(xs: [i32]) -> i32! { … }
```

- 원소는 **스칼라만**: `[i32]` · `[f64]` · `[bool]` (DP-A5).
- **파라미터 자리 전용.** 지역 변수·반환·리터럴·중첩 배열은 이 슬라이스가 아니다(§5.1).
- **읽기 전용(빌림).** `xs[i] = …` 는 컴파일 에러다 — D16 규칙 1(호출 기간 동안만 빌린다)이
  그대로 적용되고, 모듈이 호스트 메모리를 쓰기 시작하면 소유권 이야기가 다시 열린다.
- 내부 `fn`도 배열 파라미터를 받는다. `string`에서 이미 그렇게 정했다(빌린 포인터를 헬퍼에
  넘기는 것은 새 질문을 열지 않는다). `out` 파라미터의 DP-O5와 다른 이유는 **포인터를 넘기는
  문법이 이미 있기 때문**이다.

### 2.2 ABI — **빌린 포인터 + 길이 동반 파라미터** (DP-A2)

배열 파라미터 하나는 **C 파라미터 두 개**로 내려간다. 순서는 **선언 자리 그대로, 포인터 다음
길이**다:

```c
/* export fn total(xs: [i32], factor: i32) -> i32! */
int32_t mlx_total(const int32_t* xs, int32_t xs_len, int32_t factor, int32_t* out_value);
```

```pascal
function mlx_total(xs: PInteger; xs_len: Integer; factor: Integer;
                   out out_value: Integer): Integer; cdecl;
```

- **동반 파라미터는 컴파일러가 붙인다.** 저자가 `xs_len: i32`를 직접 선언하는 방식은 기각한다 —
  `-> string!`이 `ml_buf`/`ml_cap`/`ml_needed`를 붙이는 것과 같은 이유이고(T1), 저자가 직접
  쓰면 **순서와 단위를 매번 틀릴 수 있다.**
- 이름은 `<param>_len`이다. 저자가 같은 이름의 파라미터를 이미 선언했다면 **컴파일 에러**로
  거부한다(`out_value`가 예약된 것과 같은 처리).
- 단위는 **원소 개수**이고 바이트가 아니다. 문자열의 `ml_cap`/`ml_needed`가 **바이트**인 것과
  다르며, 그 차이를 `.h`·`.pas` 주석에 적는다.
- **D16은 그대로다:** 모듈은 호출이 끝난 뒤 이 포인터에 접근하지 않고, 소유하지 않으며,
  해제하지 않는다.

### 2.3 인덱싱과 경계 (DP-A3 · DP-A7)

```
let v = xs[i]        // i 는 i32
```

- 경계 검사는 **`0 <= i < xs_len`** 이다. 벗어나면 모듈은 **즉시 반환**하며
  **`ML_ST_INDEX_OUT_OF_RANGE = -2`** 를 돌려준다.
- **음수 예약 status다**(D17: 0=성공 / 양수=모듈 정의 / 음수=런타임·ABI 예약).
  `-1`은 `ML_ST_INSUFFICIENT_BUFFER`가 이미 쓰고 있으므로 `-2`를 새로 예약한다.
- **`error NAME = N`로 선언하지 않는다.** 모듈이 정의한 도메인 에러가 아니라 런타임 조건이고,
  D17이 그 자리를 음수로 이미 나눠 뒀다.
- **실패 시 out-param은 건드리지 않는다.** D17의 기존 규칙 그대로이고, 수용 기준 C가 canary로
  잰다.

### 2.4 실패 가능성은 **시그니처에 보인다**

**배열을 인덱싱하는 함수는 `-> T!`로 선언되어야 한다.** 인덱싱은 실패할 수 있고, D17은 status를
`!` 없는 함수에 **보이지 않는 채널로** 붙이는 것을 금지한다(그렇게 하면 ABI가 시그니처와
어긋난다).

- `!` 없는 함수 본문에 `xs[i]`가 있으면 **컴파일 에러**이며, 진단은 고치는 법(`-> T!`)을 이름으로
  말한다.
- **배열을 받기만 하는 것은 `!`를 요구하지 않는다.** `len(xs)`는 실패할 수 없다.
- `try` 문법은 쓰지 않는다. `try`는 **문(statement)** 이고(`return try f(x)`), 인덱싱은 `while`
  본문 안에서 **식(expression)** 으로 쓰여야 한다.

### 2.5 길이 읽기 — 내장 `len` (DP-A4)

```
len(xs)   // [T] -> i32
```

- 동반 파라미터를 그대로 읽는다. **O(1)** 이고 실패할 수 없다.
- **키워드가 아니라 내장 시그니처다** — `floor`/`round`와 같은 처리이므로 `let len = 0`은 계속
  쓸 수 있다. 동명 함수 선언은 거부한다.
- `xs.len`은 **쓰지 않는다.** `.`는 struct에게 남긴다(아직 없다).

이 둘이면 `for` 없이 순회가 된다:

```
export fn total(xs: [i32]) -> i32! {
  let mut s = 0
  let mut i = 0
  while i < len(xs) {
    s = s + xs[i]
    i = i + 1
  }
  return s
}
```

### 2.6 NULL과 음수 길이 (DP-A6)

**호스트 계약이다. 모듈은 검사하지 않는다** — `string`의 NULL 규칙과 같은 어법이다.

- **NULL을 넘기지 마라.** `xs_len == 0`이면 모듈이 포인터를 역참조하지 않으므로 실제로 터지지는
  않지만, 계약 위반이다.
- **음수 길이를 넘기지 마라.** 넘기면 `0 <= i < xs_len`이 항상 거짓이므로 **빈 배열처럼 행동**하고
  모든 인덱싱이 `-2`로 실패한다. **`len(xs)`는 호스트가 말한 값을 그대로 돌려준다** — 0으로
  세탁하지 않는다. 호스트의 거짓말을 그럴듯한 값으로 바꾸지 않는 것이 이 저장소의 규칙이다.
  (선례: 음수 `ml_cap`은 클램프되지 않고 `codegen.rs`의 `if ml_cap < __n { return -1 }`에서
  실패한다.)

### 2.7 지문 (`ml_iface_hash`)

인터페이스 매니페스트는 **표면 타입**을 적는다 — `xs: [i32]`이지 `const int32_t*, int32_t`가
아니다. 이것은 새 규칙이 아니라 기존 동작이다: `iface.rs`의 `manifest()`가 파라미터를
`{name}:{ty}`로 쓰고 그 `{ty}`는 `IrType`의 **Display**, 즉 진단이 인용하는 **표면 철자**다
(`string`·`f64`·`bool`·`i32`). 배열 타입도 같은 자리에 `[i32]`로 들어간다.

배열 파라미터를 추가하거나 원소 타입을 바꾸면 **지문이 바뀐다**(수용 기준 F가 잰다). 동반 길이
파라미터는 매니페스트에 **나타나지 않는다** — 표면에 없는 것이고, 그것이 붙는 규칙은 컴파일러가
고정하므로 지문이 따로 지킬 것이 없다.

## 3. 수용 기준 (측정 가능)

| # | 기준 | 어떻게 잰다 |
|---|------|-------------|
| **A** | 생성 시그니처가 §2.2 그대로다 | 골든 + `.h`/`.pas` 문자열 검사 |
| **B** | 오라클이 실제 배열로 부른 값이 맞는다 | `hosts/rust-oracle` 로드·호출, 기대값 대조 |
| **C** | 범위 이탈이 `-2`이고 **out은 무기록** | canary(`0xAA`)로 out 바이트 전부 확인 |
| **D** | C 호스트가 같은 값을 읽는다 | `MATHLESS_GATE_D`(MSVC `cl`) |
| **E** | Pascal 호스트가 같은 값을 읽는다 | `MATHLESS_GATE_FPC_HOST` + `MATHLESS_GATE_DELPHI`, `@arr[0]`·`Length(arr)`로 전달 |
| **F** | 배열 파라미터 추가로 **지문이 바뀐다** | 매니페스트 해시 전후 비교 |
| **G** | 거부 목록이 전부 거부된다 | frontend 단위 테스트(§3.1) |
| **H** | 빈 배열(`len == 0`)이 정상 경로다 | `while`이 0회 도는 함수가 성공을 반환 |

### 3.1 반드시 **거부**되는 것

- `!` 없는 함수 본문의 `xs[i]` — 진단이 `-> T!`를 이름으로 말한다
- `xs[i] = v` (읽기 전용)
- 지역 배열 · 배열 리터럴 · 배열 반환 · 중첩 배열(`[[i32]]`)
- 원소 타입이 `string`인 배열
- 저자가 선언한 `<param>_len` 이름 충돌
- 인덱스가 `i32`가 아닌 것(암시적 변환 금지, DP-I2 그대로)

## 4. 설계 제안 (DP — **미확정, 사용자 확인 필요**)

| ID | 질문 | 권고 | 근거 |
|----|------|------|------|
| **DP-A1** | 문법 `[i32]` / `i32[]` | **`[i32]`** | D15는 계열만 정했다. `[T]`는 타입이 왼쪽에서 끝나 파서가 단순하고, `i32[]`는 배열 지역·리터럴이 없는 지금 이득이 없다 |
| **DP-A2** | 길이 = 컴파일러가 붙임 / 저자 선언 | **컴파일러** | `-> string!`의 3연 선례(T1). 저자가 쓰면 순서·단위가 틀릴 여지가 생긴다 |
| **DP-A3** | 인덱싱은 `-> T!` 필수 / `!` 없는 함수도 트랩 | **`!` 필수** | D17이 보이지 않는 status 채널을 금지한다. 실패가 시그니처에 보이는 것이 이 프로젝트의 기본값이다 |
| **DP-A4** | `len(xs)` / `xs.len` | **`len(xs)`** | `.`는 struct에 남긴다. 내장 시그니처라 이름 공간을 뺏지 않는다 |
| **DP-A5** | 원소 타입 `i32`·`f64`·`bool` / `i32`·`f64`만 | **셋 다** | 스칼라 집합이 다른 곳과 갈라지지 않는다. 대가: `[bool]`의 Pascal 선언이 1바이트 `Boolean`이어야 한다(이미 실측·고정된 함정) |
| **DP-A6** | 음수 길이 = 그대로 보고 / 0으로 클램프 | **그대로** | 호스트의 거짓말을 세탁하지 않는다. 인덱싱이 전부 실패하므로 안전하다 |
| **DP-A7** | `ML_ST_INDEX_OUT_OF_RANGE = -2` | **`-2`** | `-1`은 `ML_ST_INSUFFICIENT_BUFFER`가 쓴다. 음수 공간은 D17 예약이다 |

## 5. 범위 밖 / 위험

### 5.1 배열 **반환**은 이 슬라이스가 아니다

Q12(호스트 버퍼 + 용량 + 필요 길이)를 그대로 물려받으면 되고, 그 프로토콜은 문자열 반환에서
이미 구현·실측됐다. 여기서 하지 않는 이유는 `SPEC-string-return` T5와 같다 — **한 슬라이스가
프로토콜과 표현력을 겹치지 않는다.**

### 5.2 이 슬라이스가 만드는 새 위험 — **Delphi 빈 배열**

Delphi 호스트가 동적 배열을 넘기는 자연스러운 방법은 `@arr[0]`과 `Length(arr)`인데,
**`arr`이 비어 있으면 `@arr[0]`이 런타임에 범위 이탈**이다(호스트 쪽에서 터진다). 문자열
슬라이스의 `PAnsiChar` 함정과 같은 부류이며, **같은 방식으로 처리한다**: 생성 `.pas` 주석에
올바른 관용구를 적고, **호스트가 그것을 일부러 밟게 해서 잰다**(수용 기준 E에 포함). 오늘은
**E1(추정)이고, 슬라이스가 끝나면 E2여야 한다.**

### 5.3 `for`·`break`·`continue`는 갚지 않는다

`while` + 가변 지역으로 순회가 되고(§2.5), 반복 구문은 배열과 독립된 표면 부채다.

## 6. WBS (확인 후 착수)

| ID | 작업 | 완료 기준(측정) | 의존 |
|----|------|------------------|------|
| **A1** | 렉서·파서: `[T]` 타입, `xs[i]` 인덱스 식 | §3.1의 문법 거부 케이스 | SPEC 확인 |
| **A2** | typeck: 원소 타입, 인덱스가 `i32`, 읽기 전용, `!` 필수 규칙 | §3.1 전부 거부, 진단이 고치는 법을 말한다 | A1 |
| **A3** | IR: 배열 파라미터 + 동반 길이, 인덱스 노드 | 단위 테스트(모양 고정) | A2 |
| **A4** | codegen: 경계 검사 → `-2` 즉시 반환, out 무기록 | 생성 Rust가 `no_std`로 빌드, canary 통과 | A3 |

# SPEC — 에러 상수의 모듈 접두어 (Q14 닫기)

**상태: 확정 · 구현 착수 (2026-09-03, 사용자 승인).**
승인된 내용: **(B) `ML_<MODULE>_ERR_<NAME>`** + **Pascal 동시 적용** + **`mlx_` 추인**.
`STATUS.md` §9 **D2** / `OPEN_QUESTIONS.md` **Q14** / `DECISIONS.md` **D18 파생**.

---

## 0. 근거 (실측)

### 0.1 한 파일이 두 규칙을 쓴다

`compiler/src/header.rs`는 같은 헤더 안에 두 종류의 상수를 낸다:

```
:176   #define ML_ERR_<NAME> <값>              접두어 없음
:137   #define ML_<MODULE>_IFACE_HASH 0x…      접두어 있음   (DP-H10)
```

**후자가 접두어를 가진 이유가 전자의 부채가 기록돼 있었기 때문이다** — §5-5.4가 그렇게 적는다
(*"이 항목이 기록돼 있었기 때문에 같은 결함을 반복하지 않았다"*). 즉 규칙은 이미 정해졌고
적용되지 않은 자리가 남아 있는 것이다.

### 0.2 실패 모드는 조용하지 않다 — 재현했다

`pack.mls`에 `error E_NEG = 7`을 더하고(`shapes.mls`는 `E_NEG = 1`) 수용 D를 돌렸다:

```
shapes.h(37): warning C4005: 'ML_ERR_E_NEG': 매크로 재정의
→ /W4 /WX → cl 실패 (36초)
```

**정정한다.** §5-5.4는 "충돌한다"고만 적었는데, 실제 등급은 이렇다:

| 경우 | 결과 |
|---|---|
| 같은 이름 · **다른 값** | **컴파일 에러**(C4005). 시끄럽다 |
| 같은 이름 · 같은 값 | 합법. 숫자도 같으므로 오답이 아니다 |
| 한 모듈 안의 값 중복 | **typeck이 이미 거부**한다(DP-F9, `typeck.rs:70`) |

**조용한 오답 경로는 없다.** 다만 그 에러를 맞는 사람은 **두 모듈을 함께 쓰는 사용자**이고,
고칠 권한은 `.mls`를 쓴 쪽에 있다. 고치는 이유는 "위험해서"가 아니라 **남의 빌드를 깨기 때문**이다.

### 0.3 Pascal은 문제가 없지만, 규칙이 갈려 있다

`ML_ERR_*`는 각 유닛의 `interface const`에 들어가므로 **유닛 스코프**다 — 충돌 자체가 불가능하다.
그런데 같은 유닛 안에서 지문은 `ML_ADD_IFACE_HASH`로 접두어가 붙고 에러는 안 붙는다
(`golden/units.pas.txt:16` vs `:53`). C만 고치면 **두 바인딩의 이름이 갈린다.**

### 0.4 개명은 지문을 바꾸지 않는다 (착수 전 확인)

지문 입력은 C 매크로 이름이 아니라 `err <NAME>=<code>`다(`iface.rs:96`).
**따라서 이 슬라이스는 어떤 모듈의 `ml_iface_hash`도 바꾸지 않으며, 어떤 호스트도 재빌드를
강요받지 않는다.** §3-D가 이것을 수용 기준으로 못박는다.

### 0.5 지금이 가장 싸다

| 소비처 | 개수 |
|---|---|
| `hosts/c-host/host.c` | 8 |
| `hosts/delphi-host/host.dpr` | 1 |
| Rust 테스트(`string_return.rs` 등) | 4 |
| 골든(`headers.h.txt` 21 · `units.pas.txt` 9) | 재생성 |
| 방출부(`header.rs`) | 6 |

**두 번째 실제 C 호스트가 생기기 전이다.** 오늘 9개 에러 이름은 7개 모듈에 흩어져 있고
**전부 다르다**(실측) — 즉 오늘 고쳐도 값이 바뀌는 사용자는 없다.

## 1. 범위

**포함**

1. C 헤더의 에러 상수를 **`ML_<MODULE>_ERR_<NAME>`** 으로 방출한다.
2. Delphi 유닛도 **같은 이름**으로 바꾼다(§0.3).
3. `mlx_` 접두어를 D18에서 **"예"가 아니라 확정**으로 승격한다.
4. Q14를 `OPEN_QUESTIONS.md`에서 닫고 `DECISIONS.md`에 파생 상세를 기록한다(규칙 8 — 사용자 승인 완료).

**미포함 (명시)**

- **DP-H3(b)** — 지문을 export 심볼 이름에 박아 로더가 **강제**하게 하는 것. Q14가 닫히면
  *열리지만*, 그것은 별도 슬라이스다(`SPEC-iface-hash.md` §5.1이 그렇게 적는다).
- `ML_ST_INSUFFICIENT_BUFFER`의 이름·가드. 그것은 **모두가 합의한 예약 코드 하나**라
  `#ifndef` 가드가 옳다(§4 DP-Q3).
- `ml_*` 런타임 네임스페이스. 이미 예약돼 있고 이 슬라이스가 손대지 않는다.

## 2. 계약

### 2.1 이름 규칙

| 무엇 | 이름 | 스코프 |
|---|---|---|
| 모듈 정의 도메인 에러 | **`ML_<MODULE>_ERR_<NAME>`** | 모듈마다 고유 |
| 인터페이스 지문 | `ML_<MODULE>_IFACE_HASH` | 모듈마다 고유 (기존) |
| 예약 런타임 status | `ML_ST_<NAME>` | 전역 · `#ifndef` 가드 (기존) |
| 예약 export 심볼 | `ml_*` | 전역 (기존) |
| 사용자 모듈 export | `mlx_*` | 모듈 (D18 — 이 슬라이스가 확정으로 승격) |

`<MODULE>`은 모듈 이름을 대문자로 올린 것이며, 헤더 가드(`ML_<MODULE>_H`)·지문 상수가
이미 쓰는 것과 **같은 변환**이다.

### 2.2 값은 바뀌지 않는다

에러 **코드 값**은 그대로다. 바뀌는 것은 C/Pascal 상수의 **이름**뿐이며, ABI(정수 status)도
지문도 export 집합도 무변경이다.

## 3. 수용 기준 (측정 가능)

- **A. 방출.** 생성 `.h` 어디에도 벌거벗은 `ML_ERR_`가 없다. 골든 전수 grep = 0.
- **B. Pascal 동시.** 생성 `.pas`도 같은 이름을 쓴다. 골든 전수 grep = 0.
- **C. 충돌이 사라진다 — 이 슬라이스의 결정적 시험.** §0.2의 실험을 그대로 다시 한다:
  두 모듈이 **같은 에러 이름을 다른 값으로** 선언해도 두 헤더가 한 번역 단위에서
  `cl /W4 /WX`를 **통과한다**. (전: C4005로 실패, 36초 실측.)
- **D. 지문 불변.** 예제 18개의 `ML_<MODULE>_IFACE_HASH`가 개명 전후로 **한 글자도 다르지 않다**
  (기준선은 착수 시점에 파일로 고정했다). 이것이 "호스트 재빌드 불필요"의 증거다.
- **E. 회귀 없음.** export 집합 3개 불변, 크기는 D3 범위 안, 수용 A/B/C/D 전부 통과.
- **F. 드리프트 가드.** `header.rs`가 접두어 없는 `ML_ERR_`를 다시 방출하면 실패하는 테스트가 있다.
- **G. 기록.** Q14가 `OPEN_QUESTIONS.md`에서 닫히고, `DECISIONS.md`에 D18 파생 상세가 붙고,
  §9 D2가 ✅가 된다.

## 4. 설계 결정

- **DP-Q1 — `ML_<MODULE>_ERR_<NAME>`, `ML_ERR_<MODULE>_<NAME>`이 아니다.** 후자는
  `SPEC-D17-error-abi.md` DP-E2가 "또는"으로 적어 둔 형태이지만, 그 문장은
  **`ML_<MODULE>_IFACE_HASH`가 생기기 전**에 쓰였다. 이미 배포된 선례와 어간을 맞추면
  한 헤더 안에서 `ML_SAFE_DIV_IFACE_HASH`와 `ML_SAFE_DIV_ERR_DIV_BY_ZERO`가 나란히 선다.
- **DP-Q2 — Pascal도 바꾼다.** 필요해서가 아니라(유닛 스코프라 안전하다) **두 바인딩의 이름이
  갈리지 않게** 하려고. 문서와 예제가 두 벌이 되는 비용이 개명 비용보다 크다.
- **DP-Q3 — `ML_ERR_`에 `#ifndef` 가드를 붙이지 않는다.** 붙이면 **먼저 온 헤더가 이기고**,
  오늘 유일하게 시끄러운 실패(C4005)가 **조용한 오답으로 바뀐다.** `ML_ST_*`가 가드를 쓰는 것은
  그것이 **모두가 합의한 예약 코드 하나**이기 때문이며, 모듈마다 의미가 다른 에러 상수에는
  같은 논리가 적용되지 않는다. (Grok이 계획 단계에서 독립적으로 같은 지적을 했다.)
- **DP-Q4 — 값은 건드리지 않는다.** 이 슬라이스는 이름만 바꾼다. ABI·지문·export 무변경이
  §3-D·§3-E로 증명된다.
- **DP-Q5 — SPEC 문서의 옛 이름은 고치지 않는다.** `slices/README.md`의 규약대로 각 SPEC은
  작성 시점의 설계 기록이다. 바꾸는 것은 **현재형으로 규칙을 말하는 문서**뿐이다.

## 5. 범위 밖 / 미검증 (명시)

- 지문 강제(DP-H3(b))는 여전히 별도 슬라이스다.
- Delphi 쪽은 `dcc64`가 없어 **이 개명도 컴파일된 적이 없다**(X1). 골든 텍스트만 바뀐다.
- `ML_ERR_` 이름이 바뀌어도 **에러 코드 체계(D17 평탄 i32)는 그대로**다 — Q13은 이미 닫혔다.
- 다중 모듈 호스트 자체는 이 저장소에 하나뿐이다(`hosts/c-host`, 18개 헤더 한 TU). 서드파티
  호스트에서의 동작은 여전히 **계약**이다.

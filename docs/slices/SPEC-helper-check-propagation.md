## 0. 왜 — 측정부터

### 0.1 체크드 산술이 닿지 못한 조용한 오답 (E2, §9-71.3)

체크드 산술은 **본문**에 규칙을 걸었다: `!` 본문의 산술은 검사하고, `!` 없는 헬퍼는 누가 불러도 wrap한다(DP-O7).
그래서 같은 식을 헬퍼로 빼면 `-3`이 그럴듯한 숫자로 돌아간다. 로컬 브랜치 `exp/wide-local`의 스위치로 이 슬라이스를
구현해 626행을 다시 쟀다:

| 625행(메모 1 제외) | 맞음 | 조용한 오답 | 참값이 드는데 `-3` |
|---|---|---|---|
| 오늘 | 496 | 60 | 52 |
| 헬퍼 체크 전파 | 505 | **44** | 59 |

바뀐 16행은 **전부 오늘 조용한 오답**이었다: 9행은 참값이 i32 밖이라 실패가 맞고(billing R4 · R6, hostdata R2),
7행은 참값이 드는데 `-3`이 된다(records R2, stateful R1). **맞던 status 0 답은 하나도 바뀌지 않았다.** 전체 스위트에서
동작이 바뀐 테스트는 DP-O7을 고정한 한 줄뿐이다.

### 0.2 코퍼스 (E2, 컴파일러 IR로 센 것)

| 코퍼스 | 무한 내부 헬퍼 | `!` 본문에서 닿음 | 그중 검사할 연산이 있음 | `!`에서 부르는 export 무한 함수 | 가장 긴 헬퍼 사슬 |
|---|---|---|---|---|---|
| `examples/` 26파일 | 2 | 1 | **0** | 0 | 1 |
| 테스트에 박힌 소스 39 | 36 | 5 | 1(DP-O7 고정의 `twice`) | 0 | 1 |
| §7 업무 규칙 83파일 | 50 | 50 | 17 | 0 | 3 |

- **의도한 wrap에 기대는 헬퍼는 어느 코퍼스에도 없다.** 있는 모듈러·체크섬·날짜 헬퍼는 현실적 입력 22개에서 전부 같은
  답이고, 극단 입력에서만 바뀌는데 거기서 오늘의 wrap은 **조용한 오답**이다(연도 214748의 쓰레기 날짜, Y2038 직전
  일일 한도 초기화). 의도한 wrap은 합성 해시·LCG로만 보였고, 그것들은 보통 입력에서 `-3`이 된다(§0.3).
- `examples/`에는 이 슬라이스가 닿는 모양이 **없다** — 수용 D(실제 C 호스트)는 예제에 헬퍼를 넣어야 잴 수 있다(§6).

### 0.3 시험 구현이 드러낸 결함 — SPEC이 고칠 것 (E2, 재현함)

| 결함 | 잰 것 |
|---|---|
| **바인딩이 `-3`을 선언하지 않는다** | `!` export가 넘치는 헬퍼를 부르면 모듈은 `-3`을 내는데 `.h`·`.pas`의 `ML_ST_OVERFLOW` 선언은 0번. 술어가 함수 **자신의** 본문만 본다(#238과 같은 부류). §7 코퍼스 83파일에는 없고, 그 변형 파일(예: 사후 가드를 단 요금 계산)에서 나타난다 |
| 쌍둥이 이름이 합법한 사용자 함수와 충돌 | `fn mul` + `fn __twin_mul` → `error[E0428]`. 함수 이름에는 접두 제약이 없다(#101) |
| 주변 `RUSTFLAGS=-D warnings`에서 빌드 실패 | `examples/discount4.mls`가 오늘은 빌드되고 시험 구현에서는 `never used`로 실패 |
| 필요 없는 쌍둥이 | 코퍼스 헬퍼 291개 중 175개가 쓸모없는 쌍둥이를 받았다(검사할 연산이 없거나 `!`에서 안 닿음) |
| **`export`가 검사를 멈춘다** | `!` 본문이 export 무한 함수 `wmul(65536, 65536)`을 부르면 status 0에 `0` — 그 아래 헬퍼까지 wrap |

### 0.4 크기와 멈춤 (E2)

- **크기**: 예제 26개는 쌍둥이를 켜도 링크 타임스탬프를 가리면 **바이트까지 같다**(26/26). 헬퍼 20개를 `!` export 10개가
  부르는 합성 모듈은 `.text` 4280 → 4696바이트(+9.7%), DLL +512(파일 정렬 한 칸).
- **멈춤이 줄어든다**: `fn grow(x, n) { let mut v = x  while v < n { v = v * 2 } return v }`를
  `export fn f(n) -> i32! { return grow(1, n) }`가 부를 때 `f(2147483647)`은 오늘 `v`가 `i32::MIN`을 거쳐 0으로 wrap해
  **끝나지 않고**(30초 타임아웃에 죽였다), 시험 구현은 즉시 `-3`이다. `f(1000)`은 둘 다 `1024`. 호스트가 직접 부르는
  무한 함수의 멈춤은 그대로다.

## 1. 범위

**포함**

1. `!` 본문이 **직접 또는 무한 함수들을 거쳐** 부르는 무한 함수(`!` 없는 함수 — 내부든 export든)의 산술과 변환이
   `SPEC-checked-arithmetic` §2.1의 `!` 열 그대로 검사되고, `-3`이 호출자에게 전파된다.
2. 바인딩 술어가 그 경로를 본다 — `.h`·`.pas`가 **한 술어**로 `ML_ST_OVERFLOW`를 선언한다.
3. 생성 Rust의 방출: 검사용 사본의 이름·범위, 참조되는 본문만 방출, 경고.
4. `LANGUAGE.md`·`HOST_ABI.md`·생성 `.h`/`.pas`의 문구, DP-O7을 고정한 테스트.
5. §9-71의 626행을 구현본으로 다시 재어 시험 구현의 표와 대조한다(기록이지 가드가 아니다).

**미포함 (명시)**

- 무한 함수를 **호스트가 직접** 부를 때 — wrap·포화 그대로(채널이 없다, D17). export 어댑터는 바뀌지 않는다.
- 넓은 중간값(WIDE) — §9-71.4의 위험을 따로 정해야 한다. i64 · 탈출구 내장 함수(§2.8).
- `-2`(경계 밖) — **무한** 헬퍼에서는 생기지 않는다: 무한 본문은 인덱스·스팬 비교가 거부되고(DP-A3) `fixed`는
  `-> string!`에서만 쓰인다. `!` 헬퍼의 `-2`는 오늘도 선언된다 — 술어가 모든 `!` 본문을 본다.
- `DECISIONS.md` — D17이 음수를 이미 예약했고 DP-O7은 슬라이스 결정이다.

## 2. 계약

### 2.1 규칙 — 본문이 아니라 호출 경로가 정한다 (DP-P1)

**`!` 함수를 위해 실행되는 산술은 어디에 쓰여 있든 검사된다.** 무한 함수 `h`를

| 부르는 쪽 | `h` 안의 i32 `+ - *`, 단항 `-`, `MIN / -1`, `f64 as i32` |
|---|---|
| `!` 본문(직접, 또는 무한 함수들을 거쳐) | 넘치면 **`-3`**, 호출자가 그 자리에서 `-3`으로 반환 |
| 무한 본문 · 호스트(export 어댑터) | wrap · 포화(오늘과 같다) |

그래서 **식을 헬퍼로 빼도 답이 바뀌지 않는다** — 오늘은 뺀 순간 `-3`이 wrap한 숫자가 된다. 대가도 적는다: **같은 헬퍼가
부르는 쪽에 따라 다르게 동작한다**(오늘도 `!`와 무한 본문 사이에서 이미 그렇다).

### 2.2 어디까지 (DP-P2, DP-P3)

- **export된 무한 함수도 포함한다**(DP-P2). `export`는 호스트에게 보이는지를 정할 뿐 내부 의미를 바꾸지 않는다 —
  빼면 *"호스트가 시험하려고 헬퍼를 export로 올리는"* 편집이 `-3`을 wrap으로 조용히 바꾼다(시험 구현에서 잰 결함).
  호스트가 부르는 어댑터는 그대로 wrap한다. `out` 파라미터가 있는 함수는 식에서 부를 수 없으므로 대상이 아니다.
- **반환 타입을 가리지 않는다**(DP-P3): `bool`·`f64`를 돌려주는 헬퍼 안의 i32 산술과 `f64 as i32`도 검사한다
  (시험 구현: `a*b > 100`을 돌려주는 `bool` 헬퍼 → `-3`, `x as i32`의 NaN → `-3`).
- **사슬 전체**: 헬퍼가 부르는 헬퍼도 같은 규칙이다. 재귀가 금지돼 있어 호출 그래프는 DAG이고 사본은 함수당 하나다.

### 2.3 실패 시점과 순서 — 체크드 산술과 같다 (DP-P4)

- **연산자에서 즉시** 실패한다(`SPEC-checked-arithmetic` §2.1과 같은 검사 자리). 헬퍼를 끝까지 wrap으로 돌린 뒤 표시하지
  않는다 — 그래서 wrap이 부르던 헬퍼 안의 무한 루프가 `-3`이 된다(§0.4).
- 헬퍼 호출은 **다른 피연산자와 같다**: 한 번, 왼쪽부터 평가되고 `&&`·`||`는 단락하며 먼저 난 실패가 이긴다.
  시험 구현이 잰 것: `false && big(x)` → 호출하지 않음 · 문자열 연결 조각의 순서쌍 · `try` 인자 안의 헬퍼가 피호출자보다 먼저.

### 2.4 `result` 뒤 — 자기 산술과 같다 (DP-P5)

`-> [T]!`에서 `result n` 뒤의 헬퍼 호출이 넘치면 `DP-O6` 그대로다 — `*ml_needed`가 쓰였을 수 있고 버퍼는 정의되지 않는다.
**새 거부 규칙은 없다**(`try`와 달리 식 안의 호출이다). 시험 구현: `result[1] = sq(x)`와 `result[1] = x*x`가 같은 상태.

### 2.5 바인딩 술어 — 한 집합 (DP-P6)

`ir.rs`에 한 집합을 둔다 — **검사 집합**: `!` 본문에서 무한 함수들을 거쳐 닿고, 자기 본문이나 그 아래에 검사할 연산이
있는 무한 함수. 이것을 **셋이 함께 읽는다**:

- codegen — 이 집합의 함수에만 검사용 사본을 방출하고, `!` 본문과 사본은 집합 안의 함수를 사본으로 부른다.
- `.h`와 `.pas` — `ML_ST_OVERFLOW`를 선언하는 조건이 *"어떤 `!` 본문이 자기 검사 연산을 갖거나, 집합 안의 함수를 부른다"* 가 된다.

한 술어를 셋이 읽는 것은 #238의 규칙이다. Grok 확인: 모듈이 `-3`을 내는 길은 `!` 본문의 연산이나 사본뿐이라 이 술어로
충분하다(`try`로 부른 `!` 함수는 그 자신이 술어에 든다).

### 2.6 방출 (DP-P7, DP-P8)

- **이름은 `ml_ck_<f>`**(DP-P7) — 사용자 함수는 언제나 `ml_fn_<이름>`이고 파라미터·지역 변수는 `ml_`로 시작할 수 없어,
  어떤 합법한 소스와도 겹치지 않는다. 시그니처는 원래 함수의 파라미터에 `Result<T, i32>` 반환.
- **참조되는 본문만 방출한다**(DP-P8): `ml_ck_<f>`는 `!` 본문이나 다른 사본이 부를 때만 있고, `ml_fn_<f>`가 빠지는 경우는
  하나뿐이다 — 검사 집합의 헬퍼를 `!` 본문과 사본만 부를 때(그 본문은 사본이 대신한다). 아무도 부르지 않는 함수는
  이 슬라이스와 무관하게 오늘처럼 방출된다(§5). `#![allow(dead_code)]`로 덮지 않는다 — 덮으면 호출자 없는 사본(과다 방출)도 숨는다(Grok).
  크레이트 머리의 `allow` 줄은 바꾸지 않는다.
- 결과: 이 슬라이스가 닿지 않는 모듈의 생성 Rust는 **글자 그대로 같다**(예제 골든 불변 — §3 H).

### 2.7 지문과 ABI 버전 — 바뀌지 않는다 (DP-P9)

`DP-O4`와 같다: 지문은 본문이 어느 예약 음수에 닿는지 보지 않는다. 시험 구현에서 모듈 9개의 `ml_iface_hash`·
`ml_module_abi_version`·export 이름 집합이 전부 같았다. 바인딩 텍스트에는 `ML_ST_OVERFLOW` 선언이 새로 붙을 수 있다
(지문 밖이다). 같은 소스를 다시 컴파일하면 답이 바뀐다(wrap → `-3`) — `DP-O8`처럼 표시 없이, 문서에 적는다.

### 2.8 탈출구 — 두지 않는다 (DP-P10)

`DP-O7`의 *"무한 헬퍼가 의도한 wrap의 탈출구"* 는 사라진다. **대신할 것을 지금 두지 않는다**: 코퍼스 어디에도 의도한 wrap에
기대는 헬퍼가 없다(§0.2). 필요해지면 `wrapping_add`/`_sub`/`_mul` 같은 내장 함수를 가산적으로 더한다 — 후보 목록에 적는다.
export를 탈출구로 남기는 안(§2.2의 반대)은 받지 않는다.

### 2.9 알려진 결과 (기록)

- 저자가 손으로 쓴 사후 가드의 **에러 코드가 바뀔 수 있다**: 헬퍼 호출 뒤 `if won < 0 { fail E_BAD_RESULT }`를 둔 모듈이
  입력에 따라 `2`에서 `-3`으로(측정) — 그리고 그 가드가 놓치던 양수 wrap(`31397270`)도 `-3`이 된다.
- 체크드 산술의 대가(참값이 드는데 중간값만 넘쳐도 실패)가 헬퍼까지 넓어진다 — 표본에서 7행(§0.1).

## 5. 범위 밖 / 미검증 (명시)

- **호스트가 직접 부르는 무한 함수의 오버플로와 멈춤** — 채널이 없다(D17). `!`를 붙이는 것이 저자의 길이다.
- **넓은 중간값**(§9-71.4) · **i64** · **탈출구 내장 함수**(§2.8) — 별도 후보.
- **성능** — 체크 분기와 `Result` 반환이 는다. 크기는 §0.4에서 쟀고, 실행 속도는 재지 않았다.
- 생성 Rust 전체의 `-D warnings` 청결 — 이 슬라이스는 **자기가 만드는 경고**(쓰지 않는 사본·본문)만 막는다. 이미 있는
  것은 그대로 두고 기록한다: 사용자 함수 이름이 snake_case가 아니면(`fn a__b`) 오늘도 주변 `RUSTFLAGS=-D warnings`에서
  `non_snake_case`로 빌드가 깨진다(측정). 크레이트에 `allow`를 더하면 모든 모듈의 생성 Rust가 바뀌어 §3 H와 부딪히므로
  따로 정한다. 다른 기존 경고(예: 쓰지 않는 문자열 헬퍼, 아무도 부르지 않는 사용자 함수)도 같다.

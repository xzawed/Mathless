# Slice SPEC — 심볼 이름에 박는 인터페이스 지문 (DP-H3(b))

> **상태: 결정됨 — (B) 지금 하지 않는다 (2026-09-05, 사용자 승인 + Grok 독립 동의).**
> **구현하지 않는다.** 이 문서는 "안 하기로 한 이유"의 기록이며, §7-1의 **재검토 조건**이
> 충족되면 그때 (C)부터 다시 연다. 결정의 근거는 측정이지 취향이 아니다(§0).
>
> Grok에게 §0.3·§0.4·§7만 주고 A/B/C 중 하나를 고르게 했더니 **독립적으로 (B)** 를 골랐고,
> 이유도 같았다 — *"이미 검사하는 호스트를 벌해서, 검사를 건너뛰는 호스트만 볼 수 있는
> 33→0을 막는 셈"*. 그리고 이 문서에 **없던 것**을 하나 보탰다: 재검토 조건(§7-1).
>
> | DP | 질문 | 권고 |
> |----|------|------|
> | **S1** | 지문을 심볼 이름에 박아 **로더가** 강제할 것인가 | **아니오 — 지금은.** §0.3의 대가가 §0.2의 이득보다 크다(§7) |
> | **S2** | 박는다면 입자는 모듈 전체인가 함수별인가 | **모듈 전체** — 매니페스트와 같은 입자(§4-S2) |
> | **S3** | 예약 심볼(`ml_iface_hash`·`ml_module_abi_version`)도 접미하는가 | **아니다** — 접미하지 않아야 진단이 남는다(§4-S3) |
> | **S4** | 소스 호환은 어떻게 | 생성 `.h`의 `#define` + **문자열 상수**(매크로는 리터럴을 바꾸지 않는다, §4-S4) |
> | **S5** | 접미 없는 별칭도 함께 export하는가 | **아니다** — 그러면 강제가 사라진다(§4-S5) |
> | **S6** | 채택한다면 전면 적용인가 옵트인 모드인가 | 채택 시 **옵트인**(§7 (C)) — 전면은 D14 플래그십을 가장 나쁜 자리에 놓는다 |
>
> **근거 수준: §0은 전부 E2다.** 2026-09-04에 이 저장소에서 새로 측정했고, 제안 메커니즘은
> **실제 DLL로 프로토타입**해 로더의 동작까지 확인했다. 인용한 수치는 없다.
> **선행:** Q14(2026-09-03 닫힘) · #105(`ml_iface_hash`) · #124~#126(`.lib`과 링크 호스트).
> **이 슬라이스는 언어 표면을 넓히지 않는다** — `.mls` 문법은 한 글자도 바뀌지 않는다.
>
> ⚠ **무결성(P1)이 아니다.** 모듈을 고치는 사람은 이 이름도 고친다. 다루는 것은 **실수**다 —
> 호스트를 다시 빌드하지 않고 모듈만 바꾸는 것. 대외 문구에 "위변조를 막는다"로 쓰지 않는다(규칙 6).

## 0. 왜 — 측정부터

`SPEC-iface-hash` §5.1이 남긴 부채는 한 문장이다: **지문을 검사하지 않는 호스트는 보호되지
않는다.** DP-H3(b)는 그 강제형이다. 아래는 전부 2026-09-04에 새로 잰 것이다.

### 0.1 오늘의 위험을 인용하지 않고 다시 쟀다

파라미터 이름만 맞바꾼 두 모듈이다. `boxes(qty, per_box)` ↔ `boxes(per_box, qty)`.

```
지문        v1=770708bffe3c765d   v2=c5f4c671db23f5df      (다르다)
export 집합 v1=v2=["ml_iface_hash","ml_module_abi_version","mlx_boxes"]   (같다)
boxes(100,3)  올바른 모듈=33    드리프트 모듈=0    크래시 없음, 에러 없음
```

**지문은 다른데 심볼은 같다.** 그래서 지문을 *부르지 않는* 호스트는 오늘도 조용한 오답을 받는다.
33이 나와야 할 자리에 0이 나오고, 그 0은 청구서에 실린다.

### 0.2 제안 메커니즘을 실제 DLL로 프로토타입했다

생성 Rust의 export 이름만 `mlx_boxes__<지문16자리>`로 바꿔 두 모듈을 다시 빌드했다.

```
v1 호스트가 찾는 이름   mlx_boxes__770708bffe3c765d   (27자)
p1 export              ["ml_iface_hash","ml_module_abi_version","mlx_boxes__770708bffe3c765d"]
p2 export              ["ml_iface_hash","ml_module_abi_version","mlx_boxes__c5f4c671db23f5df"]
드리프트 모듈이 v1 이름을 해석  false   <- 로더가 거부한다
맞는 모듈이 같은 이름을 해석    true    <- 거부가 헛돌지 않는다
임포트 라이브러리                양쪽 다 생성됨
```

**메커니즘은 동작한다.** 이것이 이 SPEC이 "된다/안 된다"를 두고 다투지 않는 이유다.

### 0.3 그리고 대가를 쟀다 — 이것이 결론을 뒤집는다

헤더를 include하고 `.lib`을 링크하는 **평범한 C 호스트**(= `hosts/c-host-link`의 형태)를
접미 이름으로 빌드해, 모듈 파일만 드리프트본으로 바꿔 넣었다.

| 상황 | 오늘 (`hosts/c-host-link`) | 접미 이름을 쓰면 |
|------|---------------------------|-----------------|
| 맞는 모듈 | 값이 맞고 exit 0 | `HOST_RAN boxes(100,3)=33`, exit 0 |
| 드리프트 모듈 | **거부 메시지 + exit 3** | **exit `0xC0000139`**(STATUS_ENTRYPOINT_NOT_FOUND), **stdout·stderr 둘 다 비어 있음** |

**프로세스가 `main`에 닿기도 전에 죽는다.** 우리 코드가 한 줄도 돌지 않으므로 "어느 지문을
기대했는지"를 말할 자리가 없다.

완화도 실측했다. `/DELAYLOAD`로 다시 빌드하면 해석이 **첫 호출 시점**으로 밀린다:

```
delay-load + 드리프트 모듈   exit 0xC06D007F   (여전히 출력 없음, 그러나 main은 돌았다)
delay-load + 맞는 모듈       boxes(100,3)=33, exit 0
```

즉 완화는 **죽는 자리를 옮길 뿐** 메시지를 돌려주지 않는다. 호스트가 직접 실패 훅이나 SEH를
써야 하고, 그것은 우리가 아니라 **호스트 저자**의 일이다.

### 0.4 누가 얻고 누가 내는가

- **얻는 쪽:** 지문을 검사하지 **않는** 서드파티 호스트. 조용한 오답이 불가능해진다.
- **내는 쪽:** 헤더를 include하고 링크하는 **성실한** 호스트. 오늘 읽을 수 있는 거부(+exit 3)를
  받던 자리에서 말 없는 `0xC0000139`를 받는다.

**그리고 D14의 플래그십이 내는 쪽에 있다.** 생성 `.pas`를 읽어 확인했다 —
`function mlx_boxes(...): Integer; cdecl; external ML_MODULE;` 로, `name` 절도 `delayed`도 없다.
**암시적 임포트 = 로드 시점 바인딩**이다. 게다가 Delphi 바인딩은 **아직 아무것도 컴파일된 적이
없다**(`dcc64` 부재). 검증된 적 없는 바인딩의 ABI 모양을, 그 바인딩이 가장 나쁜 실패를 받는
방향으로 먼저 바꾸는 셈이다.

### 0.5 이 저장소가 치를 변경 규모 (실측)

```
구체적인 mlx_ 심볼을 이름으로 적는 자리   229곳 (그중 제품 코드 30곳)
host.c의 _Generic 타입 오라클             25개
export 집합·개수를 적는 문서               4개 (SECURITY.md · STATUS.md · README.md · SPEC-iface-hash.md)
```

## 1. 목표 / 비목표

**목표(채택 시):** 호스트가 자발적으로 검사하지 않아도, **인터페이스가 다른 모듈의 함수는 아예
해석되지 않는다.**

**비목표:** 무결성(P1) · 난독화 · 변조 방지 · 언어 표면 확장 · `ml_iface_hash()` 폐지
(예약 심볼은 남는다, §4-S3).

## 2. 계약 (채택할 경우에만)

### 2.1 이름 규칙

```
mlx_<name>__<지문 16자리 소문자 hex>
```

지문은 `ml-iface/1` 매니페스트의 FNV-1a 64(= 오늘 `ml_iface_hash()`가 돌려주는 값)와 **같은 값**이다.
새 해시를 만들지 않는다.

### 2.2 예약 심볼은 접미하지 않는다

`ml_module_abi_version`·`ml_iface_hash`는 **그대로**다. 그래야 동적 호스트가 지문을 먼저 읽어
사람이 읽을 수 있는 거부를 출력할 수 있다(§0.3의 대가를 절반만이라도 되돌리는 유일한 수단).

### 2.3 생성 `.h`

```c
#define ML_PACK_IFACE_HASH 0x770708BFFE3C765DULL
#define mlx_boxes mlx_boxes__770708bffe3c765d
/* GetProcAddress 등 문자열로 찾는 호스트용 — 매크로는 리터럴을 바꾸지 않는다 */
#define ML_PACK_SYM_boxes "mlx_boxes__770708bffe3c765d"
int32_t mlx_boxes__770708bffe3c765d(int32_t qty, int32_t per_box);
```

**문자열 상수가 없으면 동적 호스트는 조용히 깨진다** — `m.symbol("mlx_boxes")`는 매크로를 거치지
않는다. Grok이 착수 검토에서 지적했고, 그것이 §2.3에 이 줄이 있는 이유다.

### 2.4 생성 `.pas`

`external ML_MODULE name 'mlx_boxes__<hash>'` 로 바꾼다. Delphi의 `name` 절이 그 자리다.
**이 줄은 오늘 컴파일해 볼 수 없다**(`dcc64` 부재) — 채택하면 미검증 항목이 하나 늘어난다.

## 3. 수용 기준 (측정 가능, 채택 시)

| # | 기준 |
|---|------|
| **A** | 드리프트 모듈이 이전 이름을 해석하지 **못한다**(실측 — §0.2에서 이미 확인) |
| **B** | 같은 모듈은 같은 이름을 해석한다 — 거부가 헛돌지 않음 |
| **C** | 예약 심볼 둘은 **양쪽 모듈에서 모두** 해석된다 |
| **D** | `#define`을 쓰는 C 호스트가 소스 변경 없이 컴파일·링크·실행된다 |
| **E** | `ML_<MODULE>_SYM_<fn>` 문자열로 찾는 동적 호스트가 동작한다 |
| **F** | 링크 호스트가 드리프트 모듈에서 죽는 코드가 문서에 **실측값으로** 적힌다(`0xC0000139`) |
| **G** | 예제 코퍼스 전부가 한 번역 단위에서 `cl /W4 /WX`를 통과한다(오늘의 게이트 유지) |

## 4. 설계 결정

**S2 — 입자는 모듈 전체.** 매니페스트가 모듈 단위이고, 함수별로 하면 **에러 표만 바뀐 모듈에서
"안 바뀐" 함수를 계속 부르는** 혼합 버전이 생긴다(DP-H6이 에러 표를 지문에 넣은 이유와 같다).
"관계없는 함수 하나 때문에 전부 개명된다"는 비용은 **오늘 모듈 전체를 거부하는 비용과 같다.**

**S3 — 예약 심볼은 접미하지 않는다.** §2.2. 접미하면 동적 호스트마저 진단을 잃는다.

**S4 — `#define` + 문자열 상수.** 매크로만으로는 `GetProcAddress("mlx_boxes")`가 깨진다.

**S5 — 별칭을 export하지 않는다.** 접미 없는 이름을 함께 내보내면 드리프트 모듈이 다시 해석되어
**이 슬라이스가 사는 이유가 사라진다.**

**S6 — 채택 시 옵트인.** §7 (C).

## 5. 위험 / 범위 밖

### 5.1 성실한 호스트가 비용을 낸다 (가장 큰 위험, 실측됨)

§0.3·§0.4. 오늘 읽을 수 있는 거부를 받는 호스트가 말 없는 종료를 받는다. **완화는 죽는 자리를
옮길 뿐이다.**

### 5.2 D14 플래그십이 가장 나쁜 자리에 있다

Delphi는 로드 시점 바인딩이고(산출물에서 확인), 아직 한 번도 컴파일된 적이 없다.

### 5.3 무결성이 아니다

모듈을 고치는 사람은 이름도 고친다. `SPEC-iface-hash` §5.4와 같은 경계다.

### 5.4 진단 문구를 우리가 통제하지 못한다

`0xC0000139`는 Windows 로더가 내는 것이다. 우리 문서가 그 코드를 설명할 수는 있어도, 사용자가
보는 첫 화면을 바꿀 수는 없다.

## 7. 권고와 대안

**(A) 전면 채택.** 모든 모듈이 접미 이름을 쓴다.
*장점:* 강제가 기본값이 된다. *단점:* §0.3의 대가를 **모든** 호스트가, 특히 Delphi가 진다.

**(B) 지금 하지 않는다 — 권고.**
*장점:* 성실한 호스트의 진단이 유지된다. 검증된 적 없는 Delphi 바인딩의 ABI 모양을 건드리지
않는다. §0.5의 229곳을 지금 흔들지 않는다. *단점:* 검사하지 않는 서드파티 호스트는 **계속**
보호되지 않는다 — 그 부채는 `SPEC-iface-hash` §5.1과 STATUS에 그대로 남는다.

**(C) 옵트인 모드** (`mlc build --strict-symbols` 같은 형태).
*장점:* 배포 상황을 아는 사람이 고른다 — 남의 호스트에 나가는 모듈은 강제, 내 호스트에 붙는
모듈은 읽을 수 있는 거부. *단점:* ABI 모양이 둘이 되어 **수용 표면이 두 배**가 된다. D13(개발/배포
보호 수준 분리)이 아직 미구현이라 선례도 없다.

**왜 (B)인가.** 이 슬라이스는 **부주의한 호스트를 지키려고 성실한 호스트에게 비용을 물린다.**
그 비용이 추측이 아니라 측정값(`0xC0000139`, 출력 없음)이고, 이득도 측정값(33→0이 불가능해짐)인데,
**오늘 이 저장소의 두 참조 호스트는 이미 거부하고 있다.** 보호되지 않는 것은 아직 존재하지 않는
서드파티 호스트뿐이다. 그 호스트가 실제로 생겼을 때 (C)로 여는 편이, 지금 (A)로 전부 바꾸는 것보다
싸다 — 그리고 그때는 **Delphi가 검증돼 있을 것**이다.

> **이 SPEC이 하지 않은 것.** (C)의 세부(플래그 이름, 두 모양의 골든 관리)는 적지 않았다.
> 사용자가 (C)를 고르면 그때 이 문서를 개정한다 — 고르지 않을 설계를 미리 쓰지 않는다.

## 7-1. 재검토 조건 — (B)는 유예가 아니라 **조건부 결정**이다

"지금 하지 않는다"를 날짜 없이 적으면 그냥 잊힌다. 그래서 **다시 여는 조건을 둘로 못박는다.**
Grok이 결정 검토에서 이 절을 요구했고, 그 지적이 옳다.

| 조건 | 왜 이것이 조건인가 | 그때의 선택 |
|------|-------------------|------------|

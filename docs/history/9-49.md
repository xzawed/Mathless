### 9-49. §7이 12일 동안 요구한 도구를 만들었다 — `mlprobe` (2026-09-13, E2)

§7이 오래 적어 둔 것:

> *"컴파일 여부가 아니라 값을 재라. … 표준 도구(스니펫 → 빌드 → 로드 → 호출 → **값 출력**)가
> 없으면 다음에도 싼 쪽만 재게 된다."*

§9-46이 그 대가를 또 치렀다(임시 테스트를 쓰고 지우고, `include_str!` 경로가 드라이브를 건너뛰어
한 번은 컴파일도 못 했다). **이제 한 줄이다:**

```
$ mlprobe --src 'export fn copay(a: f64) -> f64 { … }' copay 50000
value  = 12500.0
```

#### 9-49.1 어려운 부분을 피한 방법

임의의 C ABI 시그니처를 런타임에 부르려면 조합적 디스패치 표나 FFI 라이브러리가 필요하다.
**둘 다 안 한다** — 모듈의 **IR에서 정확한 타입을 읽어** ~40줄짜리 Rust 하네스를 **생성**하고,
`rustc` 한 번으로 컴파일해 돌린다(카고 없음, 의존성 없음 — `LoadLibraryA`/`GetProcAddress`를
스스로 선언한다). **도구는 모양을 알 필요가 없다. 컴파일러가 이미 안다.**

실측으로 확인한 ABI 모양: 스칼라 반환 · 배열 입력(+컴파일러가 붙이는 길이) · `T!` · **Q12
`string!` 삼총사** · **배열 반환** · **선언된 `out` + `out_value`** · **음수 status**.

#### 9-49.2 이 머신에서 **`probe.dll`은 만들 수 없다** (환경 사실)

첫 판이 기본 모듈명을 `probe`로 뒀더니 **`mlc build`가 `os error 5`(액세스 거부)로 실패**했다.
컴파일러 결함이 아니다 — **같은 소스를 다른 stem으로 두면 통과한다**(이름을 바꿔 가며 양쪽으로
두 번씩 재현). 엔드포인트 보안 에이전트로 보인다.

> **적어 두는 이유**: D3(크기가 머신마다 다르다)와 같은 부류의 **환경 사실**이고, 교훈은 싸다 —
> **스캐너가 싫어할 수 있는 이름을 도구에 박아 두지 않는다.** 지금은 파일 stem, 없으면 함수 이름을 쓴다.

#### 9-49.3 그리고 §5-5.7을 **세 번째로 내가 다시 냈다**

이 도구의 첫 판이 스크래치 트리를 손으로 만들고 **27개를 남겼다.** §9-48에서 열아홉 개 파일을
바로 그 패턴에서 옮긴 **같은 세션, 같은 손**이다.

**가드는 잡지 못했다 — `tests/`만 훑고 있었고 이것은 `src/bin`이다.** 즉 **결함은 가드의 범위**였다.

| 고친 것 | |
|---|---|
| 도구 | 자체 `Drop` 스크래치(테스트 헬퍼는 `tests/`에 있어 바이너리가 import할 수 없다) |
| 가드 | `compiler/src/bin`까지 훑는다 |
| 면제 | **성질로** — 같은 파일에 `impl Drop for`가 있으면 통과. 헬퍼 면제와 같은 방식 |

**깨서 확인했다**: `impl Drop`을 지우자 가드가 `compiler/src/bin/mlprobe.rs:109`를 댔다.
실측: `mlprobe_*` 잔존 **0개**.

> **세 번 같은 결함을 낸 것에서 배울 것은 "더 조심하자"가 아니다.** 두 번은 헬퍼가 없어서였고,
> 세 번째는 **가드가 그 디렉터리를 안 봐서**였다. 매번 고친 것은 주의력이 아니라 **기계**다.

#### 9-49.4 검증이 *묻지 않은 것*에서 둘을 더 댔고, 둘 다 고쳤다

> *"The generated harness `transmute`s `GetProcAddress` to that IR-derived type and calls it
> with no fingerprint or ABI-version gate, so an IR/codegen mismatch — **the class of bug this
> tool exists to catch** — is undefined behavior rather than a reported error."*

맞다. 이 저장소의 **모든 호스트가 부르기 전에 하는 그 게이트**(D18)를 하네스만 빼먹고 있었다.
넣었고, **실제로 막는지 깨서 확인했다** — codegen이 `99`를 내게 하자:

```
mlprobe: module ABI 99 != compiler 1
```

UB가 아니라 **보고된 불일치**다. 지문 export(`ml_iface_hash_<module>`)도 해석해 **이것이 IR이
설명하는 그 모듈인지** 확인한다.

> ⚠ **경계를 적는다: 시그니처는 검증하지 않는다.** C ABI 너머로는 무엇도 그럴 수 없다.
> 닫은 것은 **정체성 절반**이고, 그 이상이 아니다.

두 번째 지적: *"`impl Drop for`는 파일 전체 부분문자열이라, 무관한 Drop이 하나만 있어도 temp
검사를 건너뛴다."* 맞다 — 면제를 **`Drop` **그리고** `remove_dir_all`** 둘 다로 조였다.

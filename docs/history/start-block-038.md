> ### 2026-09-15 (4) 기준 — **짝 표가 끝났다 (§9-57)**
>
> 방출되는 가드 **27개**(헬퍼 18 + 인라인 9)를 전부 뽑아 값 짝을 확인했다. 남아 있던 셋을 닫았다:
> `result -1`(SPEC이 정하고 아무도 부른 적 없음), 배열 쪽 음수 `ml_cap`, concat 경로의 음수 cap.
>
> ⚠ **`if ml_cap < __n { return -1; }`은 용량 검사이자 NULL 탐침 계약이다.** 빼고 돌리면 오답이
> 아니라 **`STATUS_ACCESS_VIOLATION`** 이다 — DP-T7이 허용하는 `ml_buf = NULL, ml_cap = 0`이
> 그 줄 덕분에 안전했던 것이고, 어느 문서도 그 말을 한 적이 없다. §9-57.3.
>
> ⚠ **검증이 두 클램프의 *이유*를 정정했다** — 주석이 댄 MSVC의 unsigned 위험은 이 방출물에
> 없다(전부 부호 있는 비교). 클램프는 옳지만 막는 것이 다르다. §9-57.1.
>
> 📌 **이 조사 방법은 이제 끝났다.** 가드는 전부 짝이 있다. 다음 표본이 필요하면 축을 바꿔야 한다
> — 가드가 아닌 것(예: 값을 계산하는 헬퍼의 경계, 바인딩 생성기)에서 같은 질문을 한다.
>
> > **이 두 이름이 나중에 어떻게 됐나(2026-09-16 추가).** **바인딩 생성기**는 바로 다음 세션이
> > 집었고(§9-58) 결함 하나가 나왔다. **값을 계산하는 헬퍼의 경계**는 **두 세션 동안 그대로
> > 있다가** §9-60이 집었고, **writer 넷 중 둘이 경계를 받지도 않고 있었다.** 먼저 적힌 쪽이
> > 나중에 집혔다 — 목록을 위에서부터 집지 않는 습관의 대가다.
